# Обнаружение системы

На этой странице объясняется, что изменяют параметры загрузки `from`, `ip`, `cache`, `bext`, `toram` и `toram=full`. Она предназначена для настройки пользовательских вариантов загрузки, сетевой загрузки и устранения неполадок. Большинству пользователей достаточно выбрать обычный пункт в загрузочном меню без ручной установки этих параметров.

После загрузки ядра и initramfs загрузчиком, initramfs должен найти дерево данных MiniOS, которое предоставляет системные модули `.sb`. Это происходит до запуска стандартного сетевого стека пользовательского пространства, рабочего стола и постоянной сессии.

## Простыми словами

MiniOS должен найти каталог, содержащий его системные модули. Обычно он ищет подключённые диски с каталогом `minios/`. Параметр `from=` указывает на другой каталог или ISO-образ. Сетевые параметры заменяют этот локальный поиск загрузкой ISO по HTTP или через PXE.

Нахождение диска не гарантирует, что набор модулей полный, а обнаружение системных файлов не включает постоянство. Это отдельные этапы запуска.

## Пояснения к параметрам

| Параметр | Что он сообщает MiniOS | Типичное использование |
|---|---|---|
| `from=PATH` | Ищет MiniOS в определённой директории или ISO вместо принятия первого подходящего локального источника. | Загрузка ISO, сохранённого на диске, или использование нестандартной директории. |
| `from=askdisk` | Открывает интерактивный выбор раздела, который содержит MiniOS. | Несколько подключённых дисков содержат возможные источники. |
| `from=http://...` | Монтирует ISO с обычного HTTP-сервера. | Контролируемая загрузка по сети, когда работающая система может продолжать зависеть от сервера. |
| `ip=...` | Использует раннюю статическую сеть. Без HTTP `from=` выбирает загрузку PXE-данных и пропускает локальные диски. | Развёртывание через PXE или статическая адресация для HTTP ISO. |
| `cache=MB` | Выделяет httpfs-кэш для HTTP ISO. Это не гарантирует, что весь ISO будет загружен. | Снижает повторные чтения с HTTP-источника. |
| `bext=EXTENSION` | Ищет имена файлов модулей с другим расширением вместо `.sb`. | Только для специализированных образов; не преобразует модули. |
| `toram` или `toram=full` | Копирует всё найденное дерево данных MiniOS в RAM и пытается отсоединить источник. Краткая форма означает `full`. | Временная операция RAM на машине с достаточным объёмом памяти. |

Если локальная загрузка с USB останавливается до появления рабочего стола, сначала удалите пользовательские значения `from=` и `ip=`. Случайно непустой `ip=` мешает обнаружению локального диска, а неверный `from=` может привести к тому, что MiniOS будет искать несуществующий путь.

## Приоритет источников

Выбор источника происходит в фиксированном порядке:

1. Явное значение `from=http://...` выбирает HTTP ISO.
2. В противном случае любое непустое значение `ip=` выбирает загрузку по PXE.
3. Далее, `from=askdisk` или `from=askdisk:...` открывает выбор диска.
4. В остальных случаях initramfs сканирует локальные блочные устройства.

Два сетевых пути не возвращаются к локальным носителям. После попытки загрузки HTTP ISO или PXE результат возвращается именно по сети, а не с дисков; неработающий или неполный результат приведёт к ошибке проверки или дальнейшей настройке.

Этот порядок имеет два важных следствия:

- `from=http://...` имеет приоритет над `ip=`. Необязательный `ip=` затем задаёт статическую адресацию для подключения к HTTP ISO.
- Непустой `ip=` имеет приоритет над любым локальным значением `from=`, включая устройство, каталог, путь к ISO или `askdisk`. Не используйте `ip=` только для настройки сети при локальной загрузке системы.

## Локальное обнаружение

Без HTTP-источника или непустого `ip=` MiniOS выполняет 45 проходов обнаружения, примерно по одному в секунду. Каждый проход обновляет устройства, получает кандидатов блочных устройств через `blkid`, сортирует их имена и проверяет в этом порядке. Первый кандидат, содержащий подходящий источник MiniOS, сохраняется; остальные устройства не рассматриваются.

Если `from=` пуст, путь для проверки на каждой файловой системе — `minios`. Источник считается подходящим, если этот каталог или его непосредственный подкаталог `modules/` содержит хотя бы один файл с расширением по умолчанию `.sb`. Параметр `bext=` изменяет расширение для этой проверки. Обнаружение не проверяет полноту или загрузочность найденного набора модулей.

Каждый кандидат монтируется изначально только для чтения. После подтверждения MiniOS пытается сделать выбранный раздел доступным для записи, но невозможность этого не отклоняет иначе подходящий источник.

### Локальные формы `from=`

Обычный относительный или абсолютный путь интерпретируется внутри каждой файловой системы-кандидата. Начальные слэши нормализуются при построении пути, поэтому оба варианта ищут один и тот же каталог:

```text
from=minios
from=/minios
```

Если указанный путь является обычным файлом на файловой системе-кандидате, MiniOS рассматривает его как ISO-образ, монтирует его в режиме только для чтения и проверяет каталог `minios` внутри ISO:

```text
from=/images/minios.iso
```

Пути с указанием устройства поддерживают только такие формы:

```text
from=/dev/sdb1/minios
from=/dev/sr0/minios
from=/dev/disk/by-label/MINIOS/minios
```

`/dev/<name>/path` поддерживает простое имя устройства, за которым следует путь. Форма с меткой должна быть строго `/dev/disk/by-label/LABEL/path`; метка разрешается через `blkid`, затем оставшийся путь проверяется на этой файловой системе.

Нет соответствующего парсера для путей UUID, PARTUUID или by-id. Формы вроде следующих не поддерживаются:

```text
from=/dev/disk/by-uuid/UUID/minios
from=/dev/disk/by-partuuid/PARTUUID/minios
from=/dev/disk/by-id/ID/minios
```

### Интерактивный выбор

Используйте `askdisk` для выбора раздела и последующей проверки пути на нём:

```text
from=askdisk
from=askdisk:custom:dir
```

Первая форма проверяет `minios` на выбранном разделе. Во второй форме двоеточия становятся разделителями пути, поэтому `askdisk:custom:dir` проверяет `custom/dir`.
Синтаксис со слэшем, например `from=askdisk/custom/dir`, также открывает выбор, но молча теряет пользовательский путь и проверяет `minios`; не используйте его.

Список устройств обновляется, пока открыт выбор, и не включает файловые системы подкачки. При выборе всё равно выполняется стандартная проверка наличия модулей; одного выбранного раздела недостаточно.

## HTTP ISO

HTTP-источник ISO имеет следующий вид:

```text
from=http://server.example/path/minios.iso
```

Распознаётся только обычный HTTP. HTTPS и другие схемы URL не поддерживаются.
Initramfs находит первый обнаруженный не-loopback сетевой интерфейс, поднимает сеть и монтирует удалённый ISO через `httpfs2`. Выбор интерфейса не проверяет наличие линка, доступность или пригодность интерфейса на системе с несколькими NIC.

Если `ip=` отсутствует, загрузка HTTP ISO запрашивает DHCP с помощью `udhcpc`. Если присутствует `ip=`, используются статические поля, ожидаемые PXE-парсером:

```text
ip=<client-ip>:<server-ip>:<gateway-ip>:<netmask>[:<port>]
```

Для загрузки HTTP ISO URL всё равно определяет HTTP-сервер. Статические поля настраивают адрес клиента, маску подсети, шлюз по умолчанию и начальные DNS-записи; необязательное поле порта относится к загрузке файлов PXE и не заменяет порт в URL ISO.

`cache=<MB>` включает кэш httpfs заданного размера в `/tmp`. Это именно кэш, а не гарантированная полная загрузка. Рабочая система продолжает зависеть от удалённого ISO и сети, если только успешное копирование RAM не отсоединит источник.

## Загрузка данных PXE

Любое непустое значение `ip=` выбирает загрузку данных PXE, если только сначала не был выбран `from=http://...`. Поддерживаемый синтаксис:

```text
ip=<client-ip>:<server-ip>:<gateway-ip>:<netmask>[:<port>]
```

Маска подсети указывается в виде IPv4 с точками. Необязательный HTTP-порт по умолчанию — `7529`.
Общие формы ядра или dracut, такие как `ip=dhcp` и `ip=:::::eth0:dhcp`, не поддерживаются. Сама загрузка данных PXE не имеет DHCP-формы в этом парсере.

MiniOS настраивает первый обнаруженный не-loopback интерфейс без проверки рабочего линка. Сначала запрашиваются `PXEFILELIST` и перечисленные файлы MiniOS по HTTP с сервера. TFTP — ограниченный резерв: он выбирается только если первый HTTP-запрос к `PXEFILELIST` не удался. Это не является общим переключением интерфейсов, возвратом к локальным носителям или восстановлением после любой частичной неудачи HTTP-загрузки.

## Копирование и отсоединение с помощью `toram=full`

`toram=full` важен для обнаружения, так как может убрать постоянную зависимость от выбранного источника. После обнаружения MiniOS копирует дерево данных в RAM, затем пытается размонтировать источник и переместить копию RAM на его место. Только успешное размонтирование и перемещение отсоединяют локальный носитель, смонтированный ISO или HTTP ISO.

Важные ограничения:

- Нет предварительной проверки, что доступной RAM хватит для копирования.
- При запросе постоянства копия верхнего уровня `*` не включает скрытые файлы.
- Если постоянство не запрошено, запись `changes` намеренно пропускается. Эта ветка копирует другие элементы верхнего уровня, включая скрытые файлы.
- Ошибка копирования, размонтирования или перемещения может оставить исходный источник смонтированным. Не думайте, что указание `toram=full` делает безопасным извлечение носителя или потерю сети; убедитесь, что отсоединение прошло успешно.

Перед объединением `toram` с `perch` или `perchdir` ознакомьтесь с разделом [Initrd persistence](/reference/boot-process/Persistence-Internals).

## Ошибки и диагностика

Если все 45 локальных проходов неудачны, MiniOS переходит в режим фатальной ошибки и открывает оболочку initramfs вместо запуска live-системы. Сетевые пути не выполняют 45-проходный локальный поиск и не возвращаются к локальным носителям; в зависимости от частичного результата они могут привести к ошибке проверки данных или дальнейшей настройке. Выход из фатальной оболочки не исправляет отсутствие источника и может только сделать последующую ошибку менее явной.

Полезные диагностические параметры:

- `debug` включает трассировку оболочки, дополнительные диагностические сообщения и интерактивные оболочки на нескольких этапах initramfs. Для продолжения выйдите из оболочки контрольной точки.
- `timing` выводит время между этапами initramfs и итоговое время.
- `rd.break` запрашивает оболочку initramfs перед передачей управления реальному корню; для продолжения загрузки выйдите из неё.

В оболочке проверьте `/proc/cmdline`, `/proc/net/dev`, `blkid`, смонтированные файловые системы и `/var/log/livedbg`. Начните с точных значений `from=`, `ip=` и `bext=`, показанных в `/proc/cmdline`.
