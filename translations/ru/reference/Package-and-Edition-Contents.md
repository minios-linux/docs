# Состав пакета и редакций

Содержимое пакета MiniOS формируется на основе условных списков исходных пакетов. Итоговый набор зависит от дистрибутива, архитектуры, системы инициализации, рабочего окружения, локали, параметров ядра и доступности репозиториев. На этой странице документируются пользовательские пакеты, запрошенные поддерживаемыми манифестами Flux и Xfce. Сборочные цепочки и зависимости, устанавливаемые только для сборки через APT, здесь не отображаются.

`Yes` означает, что текущий манифест запрашивает пакет для данной редакции.
`Conditional` означает, что имя пакета или его включение зависит от параметров сборки или целевой платформы. Дефис означает, что редакция его не запрашивает.
Окончательный образ всегда является определяющим источником.

## Структура редакций

Поддерживаемые редакции Xfce строятся друг на друге: Standard — это компактный повседневный рабочий стол, Toolbox предназначен для профессионального администрирования, диагностики и восстановления, а Ultra превращает эту базу в полнофункциональный рабочий стол для работы, творчества и разработки. Flux — это отдельная сверхлёгкая конфигурация Fluxbox для минимального потребления ресурсов и старого оборудования; это не просто уменьшенный список пакетов Xfce.

| Редакция | Вариант пакета и окружение | Основное назначение |
|---|---|---|
| **Standard** | `standard` с `xfce` | Минимальный повседневный рабочий стол Xfce с базовой функциональностью |
| **Toolbox** | `toolbox` с `xfce` | Профессиональное администрирование, диагностика и восстановление |
| **Ultra** | `ultra` с `xfce` | Полнофункциональный рабочий стол для работы, творчества и разработки |
| **Flux** | `minimum` с `flux` | Сверхлёгкий рабочий стол Fluxbox для минимального потребления ресурсов и старого оборудования |

Другие поддерживаемые окружения имеют собственные цепочки модулей и должны проверяться отдельно. В частности, наличие пакетов в сборках LXQt или консольных вариантах не следует выводить из таблиц Xfce ниже.

## Просмотр установленных пакетов

Работающая система является источником правды о реально установленных пакетах.
Список имён и версий пакетов можно получить командой:

```bash
dpkg-query -W -f='${binary:Package}\t${Version}\n' | sort
```

## Манифесты сборки из исходников

Таблицы пакетов выше сформированы на основе [системы сборки `minios-live`](https://github.com/minios-linux/minios-live). Пути ниже указаны относительно корня этого репозитория исходников и актуальны при самостоятельной сборке или кастомизации образа:

- `linux-live/environments/<environment>/` определяет упорядоченную цепочку модулей.
- `linux-live/scripts/00-core/packages.list` определяет общий базовый набор и пакетные дополнения.
- `linux-live/scripts/01-kernel/packages.list` определяет условные пакеты ядра и DKMS.
- `linux-live/scripts/02-firmware/packages.list` определяет прошивки для конкретных дистрибутивов.
- `linux-live/scripts/03-gui-base/packages.list` определяет общую графическую базу.
- `linux-live/scripts/04-flux-desktop/packages.list` и `05-flux-apps/packages.list` определяют Flux.
- `linux-live/scripts/04-xfce-desktop/packages.list` определяет Xfce и инструменты рабочего стола MiniOS.
- `linux-live/scripts/05-apps/packages.list` определяет графические приложения Toolbox и Ultra.
- `linux-live/scripts/10-firefox/packages.list` определяет браузеры для конкретных сборок и локалей.
- Для каждого модуля файлы `install` и `skip_conditions.conf` определяют, будет ли использоваться его список пакетов и каким образом.
- `linux-live/build.conf` выбирает сборку, архитектуру, окружение, вариант пакета, систему инициализации, ядро и локаль.
- `linux-live/condinapt.map` определяет префиксы условий для списков пакетов.

Списки исходников описывают запрошенные пакеты и альтернативы. Только итоговый образ и `dpkg-query` содержат разрешённые зависимости и точные версии для конкретного релиза.

См. [Архитектура системы](/reference/System-Architecture) для порядка модулей и [CondinAPT в MiniOS](/development/CondinAPT) для выбора условных пакетов.
