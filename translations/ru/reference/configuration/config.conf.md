# config.conf

`config.conf` — основной файл преднастройки MiniOS. Обычно на стандартном носителе MiniOS он хранится как `minios/config.conf`. При загрузке initramfs синхронизирует его с `/etc/live/config.conf` в собранной системе.

Используйте этот файл для задания параметров запуска MiniOS и инициализации новой постоянной сессии. Это инструмент для администраторов, предназначенный для предварительной настройки, а не замена стандартных средств конфигурирования рабочего окружения.

## Перенастройка

В столбце **Перенастраиваемый** ниже используются следующие значения:

- **Да** — параметр можно изменить и применить повторно при следующей загрузке.
- **Только при первой загрузке** — параметр применяется при создании соответствующего постоянного состояния и обычно не применяется повторно при последующих загрузках.

Это различие важно для понимания поведения системы. Внутренние файлы состояния `live-config` являются деталями реализации и не заменяют его.

## Сгенерированная конфигурация

Текущий образ MiniOS генерирует `config.conf` с общей структурой:
```bash
# live-config settings
LIVE_CONFIG_CMDLINE="components nottyautologin"
LIVE_HOSTNAME="minios"
LIVE_USERNAME="live"
LIVE_USER_FULLNAME="MiniOS Live User"
LIVE_USER_DEFAULT_GROUPS="dialout cdrom floppy audio video plugdev users fuse plugdev netdev powerdev scanner bluetooth weston-launch kvm libvirt libvirt-qemu vboxusers lpadmin dip sambashare docker wireshark"
LIVE_USER_PASSWORD_CRYPTED='$y$...'
LIVE_ROOT_PASSWORD_CRYPTED='$y$...'
LIVE_CONFIG_NOROOT=""
LIVE_LOCALES="en_US.UTF-8"
LIVE_TIMEZONE="Etc/UTC"
LIVE_KEYBOARD_MODEL="pc105"
LIVE_KEYBOARD_LAYOUTS="us,us"
LIVE_KEYBOARD_OPTIONS="grp:alt_shift_toggle,grp_led:scroll"
LIVE_KEYBOARD_VARIANTS=","
LIVE_CONFIG_DEBUG="true"
LIVE_LINK_USER_DIRS="false"
LIVE_BIND_USER_DIRS="false"
LIVE_USER_DIRS_PATH="/minios/userdata"
LIVE_MODULE_MODE="merged"

# MiniOS LiveKit settings.
DEFAULT_TARGET="graphical.target"
ENABLE_SERVICES="ssh"
DISABLE_SERVICES=""
EXPORT_LOGS="false"
```
Конкретные значения зависят от образа и параметров сборки.

::: warning `LIVE_CONFIG_CMDLINE` — это не командная строка initramfs
`LIVE_CONFIG_CMDLINE` предоставляет опции после сборки корня MiniOS. Такие параметры, как `from=`, `load=`, `toram`, и `perchdir=` должны быть реальными параметрами загрузки ядра; если они указаны только в `LIVE_CONFIG_CMDLINE` — это слишком поздно, чтобы повлиять на initramfs. Опции storage-policy `log-storage=`, `apt-cache=`, и `browser-cache=` — исключение: `minios-boot` считывает их из `LIVE_CONFIG_CMDLINE` до запуска обычных сервисов.
:::

## Стандартные параметры

| Параметр | Можно изменить | Описание |
|---|---|---|
| `LIVE_CONFIG_CMDLINE` | Да | Дополнительные опции live-config. Фактическая командная строка ядра добавляется позже и имеет приоритет при повторяющихся опциях. |
| `LIVE_HOSTNAME` | Да | Имя хоста системы. |
| `LIVE_USERNAME` | Только при первом запуске | Имя live-пользователя, созданного при первоначальной настройке. |
| `LIVE_USER_FULLNAME` | Только при первом запуске | Полное имя live-пользователя. |
| `LIVE_USER_DEFAULT_GROUPS` | Только при первом запуске | Дополнительные группы, назначаемые при создании live-пользователя. |
| `LIVE_USER_PASSWORD_CRYPTED` | Только при первом запуске | Хеш пароля live-пользователя (crypt). |
| `LIVE_ROOT_PASSWORD_CRYPTED` | Только при первом запуске | Хеш пароля root (crypt). |
| `LIVE_CONFIG_NOROOT` | Только при первом запуске | Если включено, отключает настройку MiniOS root-пароля, sudo и привилегий PolicyKit. |
| `LIVE_LOCALES` | Да | Одна или несколько локалей системы. |
| `LIVE_TIMEZONE` | Да | Часовой пояс системы, например `Europe/Berlin` или `Etc/UTC`. |
| `LIVE_KEYBOARD_MODEL` | Да | Модель клавиатуры XKB. |
| `LIVE_KEYBOARD_LAYOUTS` | Да | Раскладки клавиатуры через запятую. |
| `LIVE_KEYBOARD_OPTIONS` | Да | Опции клавиатуры XKB. |
| `LIVE_KEYBOARD_VARIANTS` | Да | Варианты через запятую, соответствующие выбранным раскладкам. |
| `LIVE_CONFIG_DEBUG` | Да | Включает вывод отладки live-config при значении `true`. |
| `LIVE_LINK_USER_DIRS` | Да | Связывает пользовательские каталоги с выбранным расположением на доступном для записи носителе MiniOS. Недоступно в режиме bind, любом `toram` режиме или при активной сессии постоянства с шифрованием LUKS. |
| `LIVE_BIND_USER_DIRS` | Да | Монтирует каталоги пользователей в режиме bind из настроенного расположения на записываемом MiniOS носителе. Недоступно в режиме link, любом `toram` режиме или при активной сессии персистентности с шифрованием LUKS. |
| `LIVE_USER_DIRS_PATH` | Да | Расположение, используемое для режима link/bind каталога пользователя. |
| `LIVE_MODULE_MODE` | Да | Выбирает `simple` или `merged` интеграцию с модулем live-config. |
| `LIVE_LOG_STORAGE` | Да | `persistent` (по умолчанию) или `volatile` для обычных системных журналов. Диагностика загрузки сохраняется; см. [Производительность](/maintenance-and-recovery/Performance#reduce-cache-and-log-writes-with-perch). |
| `LIVE_APT_CACHE` | Да | `persistent` (по умолчанию) или `volatile` для загруженных архивов APT; состояние пакетов и списки репозиториев сохраняются. |
| `LIVE_BROWSER_CACHE` | Да | `persistent` (по умолчанию) или `volatile` для стандартных путей кэширования нативных браузеров. Профили браузеров сохраняются. |
| `DEFAULT_TARGET` | Да | Цель загрузки: `graphical.target`, `multi-user.target`, или `rescue.target`. |
| `ENABLE_SERVICES` | Да | Сервисы, включаемые при загрузке через запятую с помощью `minios-svc`. |
| `DISABLE_SERVICES` | Да | Сервисы, отключаемые при загрузке через запятую с помощью `minios-svc`. |
| `EXPORT_LOGS` | Да | Когда `true`, экспортирует MiniOS и журналы запуска live-config на записываемый MiniOS носитель. |

Сгенерированный файл не является исчерпывающим списком всего, что поддерживается в `minios-live-config`. Дополнительные переменные для предварительной настройки проводной сети, политики безопасности, хуков, preseeding, Xorg и других компонентов можно добавить вручную. См. [live-config](/reference/configuration/live-config) для полного справочника.

Компонент `user-media` отказывает в активации и копировании обратно при активной сессии персистентности с шифрованием LUKS. Используется фактическое состояние шифрования во время работы: параметр ядра `perchencrypt=luks` только запрашивает шифрование при создании новой сессии и не описывает уже существующую сессию.

## Преднастройка проводной сети

MiniOS может заранее настроить **проводную сеть IPv4** через компонент live-config `network`. Это предназначено для административной преднастройки системы до её запуска на целевом оборудовании.
Например:

```bash
LIVE_NETWORK_METHOD="static"
LIVE_NETWORK_INTERFACE="enp1s0"
LIVE_NETWORK_ADDRESS="192.0.2.10"
LIVE_NETWORK_PREFIX="24"
LIVE_NETWORK_GATEWAY="192.0.2.1"
LIVE_NETWORK_DNS="1.1.1.1,9.9.9.9"
LIVE_NETWORK_BACKEND="auto"
```

Эти параметры действуют **только при первой загрузке** для постоянной сетевой политики. После успешного применения компонент фиксирует `/var/lib/live/config/network`.
Изменение значений не перезаписывает уже настроенную постоянную сессию, если только это состояние не сброшено вручную.

`LIVE_NETWORK_METHOD=static` записывает статическую политику. `off` отключает автоматическую настройку IPv4 для выбранного интерфейса. Если значение не задано или `dhcp` оставляет сетевую конфигурацию образа без изменений. `LIVE_NETWORK_BACKEND=auto` отдает предпочтение NetworkManager и при необходимости использует ifupdown.

Этот механизм не настраивает Wi-Fi. После загрузки обычное управление проводными и беспроводными сетями осуществляет NetworkManager. См. [Сетевые подключения](/using-minios/Networking) для работы с сетью во время сеанса и [live-config](/reference/configuration/live-config) для всех сетевых переменных.

## MiniOS настройки раннего userspace

`DEFAULT_TARGET`, `ENABLE_SERVICES`, `DISABLE_SERVICES`, `EXPORT_LOGS`, и три `LIVE_*` политики хранения выше — это MiniOS параметры загрузки, а не переменные компонента live-config. MiniOS применяет их до передачи управления обычной системе инициализации; `minios-boot` владеет этими тремя политиками хранения. Все они **Можно перенастроить: Да**.

Соответствующие параметры загрузки `default-target=`, `enable-services=`, и `disable-services=` имеют приоритет для текущей загрузки. Параметр `text` принудительно устанавливает `multi-user.target`.

В актуальных сборках Toolbox и Ultra добавляется `ssh` в `ENABLE_SERVICES`. Чтобы явно отключить SSH, укажите его в `DISABLE_SERVICES`; просто удаление из `ENABLE_SERVICES` не отключает его.

С `EXPORT_LOGS="true"`, на записываемый MiniOS носитель сохраняются логи запуска ниже:

```text
minios/log/YYYYMMDD_HHMMSS/
├── minios/
└── live/
```

Соответствующие логи во время работы — это `/var/log/minios/minios-boot.log` и `/var/log/live/config.log`.

## Политика кэширования и логирования для постоянной сессии

Чтобы уменьшить количество операций записи во время `perch` сессии, добавьте настройки отдельно:

```bash
LIVE_LOG_STORAGE="volatile"
LIVE_APT_CACHE="volatile"
LIVE_BROWSER_CACHE="volatile"
```

Они также принимают `persistent`, значение по умолчанию. `minios-boot` принимает те же параметры из `/etc/live/config.conf.d/*.conf`, `LIVE_CONFIG_CMDLINE` (`log-storage=volatile`, `apt-cache=volatile`, `browser-cache=volatile`), или из параметров ядра. Поздние фрагменты заменяют более ранние, blob-параметр имеет приоритет над ключами в файлах, а реальные параметры ядра — самые приоритетные. Все три варианта независимы и сами по себе не включают постоянство. Совместимый initrd объявляет `perch-storage-v1` на `/run/initramfs/etc/minios-initramfs-storage`; Конфигуратор MiniOS предупреждает, если текущий initrd этого не объявляет.

Эти политики применяются при следующей загрузке только если постоянство действительно активировано на долговременном доступном для записи носителе. При `toram`, сбое постоянства или **Запустить без сохранения**, выбранная временная политика не считается гарантией сохранения данных. Компонент browser-cache запускается позже, чем `minios-boot`, после создания live-пользователя. Подробнее см. [Производительность](/maintenance-and-recovery/Performance#reduce-cache-and-log-writes-with-perch) для точных ограничений RAM, поддерживаемых путей браузера, условий резервирования и логов, которые остаются на носителе.

## Исходный файл, рабочая копия и приоритет

Выбранный каталог данных MiniOS обычно содержит следующие исходные файлы:

| Выбранный каталог данных | Работающая система |
|---|---|
| `config.conf` | `/etc/live/config.conf` |
| `config.conf.d/*.conf` | `/etc/live/config.conf.d/*.conf` |

На обычно смонтированных носителях они видны как `minios/config.conf` и `minios/config.conf.d/*.conf`, часто в каталоге `/run/initramfs/memory/data/` во время работы системы.

Синхронизация выполняется при загрузке; это не файловый монитор:

- Более новая копия `config.conf` выигрывает по времени изменения. Более новая копия на носителе копируется в рабочий корень. Более новая рабочая копия копируется обратно только если выбранный каталог данных MiniOS доступен для записи.
- Каждый файл `config.conf.d/*.conf` синхронизируется независимо по имени файла с использованием одинаковых правил по времени и доступности для записи. Файлы не удаляются ни с одной из сторон.
- Если время на часах меньше времени последней синхронизации, сравнение временных меток пропускается и копируются только отсутствующие файлы назначения.
- `toram=trim` копирует `config.conf` но пропускает `config.conf.d/`. Полная `toram` копирует дерево данных, но после этого синхронизация выполняется с копией RAM, а не с отсоединённым исходным носителем.
После синхронизации `live-config` читает `/etc/live/config.conf` сначала, а затем `/etc/live/config.conf.d/*.conf` в порядке, определяемом shell glob. Поэтому более поздний фрагмент может заменить значение из основного файла или предыдущего фрагмента.

Фактическая командная строка ядра добавляется к `LIVE_CONFIG_CMDLINE`. Если опция встречается несколько раз, выигрывает более позднее вхождение kernel-command-line. Для трёх политик хранения `minios-boot` читает синхронизированный основной файл, затем его фрагменты, затем blob с опциями и, наконец, фактическую командную строку ядра; последнее значение имеет приоритет.

Вы можете добавить проектные переменные окружения shell в `config.conf` или его фрагменты и читать их из рабочих копий. Значения заключайте в кавычки как строки shell и не ставьте пробелы вокруг `=`.
