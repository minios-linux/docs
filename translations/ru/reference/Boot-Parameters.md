# Параметры загрузки

## Как использовать параметры загрузки

Параметры загрузки позволяют настроить запуск MiniOS. Разделяйте параметры пробелами в командной строке ядра.

### Syslinux

- Нажмите <kbd>Esc</kbd> во время загрузки MiniOS, чтобы открыть меню загрузки.
- Нажмите <kbd>Tab</kbd> для редактирования параметров загрузки.
- Введите параметры и нажмите <kbd>Enter</kbd> для запуска.

### GRUB

- Нажмите <kbd>E</kbd> на меню GRUB.
- Отредактируйте параметры загрузки в конце командной строки.
- Нажмите <kbd>F10</kbd> для загрузки с новыми настройками.

## Параметры загрузки

В столбце «Применение» указано, какие параметры обычно используются при каждой загрузке, а какие предназначены только для первоначальной настройки учётной записи. При использовании постоянного хранения компоненты live-config обычно запускаются только один раз; подробнее см. [live-config](/reference/configuration/live-config).

Эта таблица служит краткой справкой. Приоритет источников и допустимые `from=` формы определены в [Обнаружение системы Initrd](/reference/boot-process/System-Discovery), фильтрация модулей — в разделе [Загрузка модулей Initrd](/reference/boot-process/Module-Loading), выбор постоянного хранения — в [Постоянное хранение Initrd](/reference/boot-process/Persistence-Internals), а поддерживаемые комбинации — в разделе [Режимы загрузки](/using-minios/Boot-Modes).

| Параметр | Применение | Описание | Пример |
|---|---|---|---|
| `from` | Каждая загрузка | Загружает данные MiniOS из каталога, поддерживаемого пути устройства или ISO-образа. Форматы UUID, PARTUUID и by-id не поддерживаются. Если указан только **`http://` путь,** URL имеет приоритет перед `ip=` и инициирует [сетевую загрузку](/reference/boot-process/Network-Boot) через httpfs2. | `from=/minios/`<br>`from=/Downloads/minios.iso`<br>`from=http://domain.com/minios.iso`<br>`from=/dev/sr0/minios`<br>`from=/dev/disk/by-label/MyFlash/minios`<br>`from=askdisk`<br>`from=askdisk:customdir` |
| `load` | Каждая загрузка | Оставляет только те кандидаты, путь которых соответствует расширенному регулярному выражению (без привязки к началу строки); запятые означают альтернативу, а целый возрастающий числовой диапазон разворачивается особым образом. Также фильтрует `.sb` кандидаты. Это может исключить основные или ядровые модули и сделать систему незагружаемой.`toram=trim` | `load=00-core`<br>`load=core,kernel,firmware`<br>`load=00,01,02`<br>`load=00-03` |
| `noload` | Каждая загрузка | Исключает кандидаты, путь которых соответствует расширенному регулярному выражению (без привязки к началу строки), включая из `toram=trim`; применяется после `load` и может исключать основные или ядровые модули. | `noload=05-xfce-apps`<br>`noload=xfce-apps,firefox`<br>`noload=05,06`<br>`noload=04-06` |
| `bext` | Каждая загрузка | Устанавливает расширение для пакета. По умолчанию: `sb`. Для координации с ядром по-прежнему используются буквальные имена `.sb`, поэтому пользовательское расширение не может координировать модуль `01-kernel`. | `bext=mymod` |
| `timing` | Каждая загрузка | Включает вывод времени запуска. | `timing` |
| `union` | Каждая загрузка | Выбирает union файловую систему. | `union=aufs`<br>`union=overlayfs` |
| `ip` | Каждая загрузка | Статический адрес для ранней загрузки по сети. Формат: `<client-ip>:<server-ip>:<gateway-ip>:<netmask>[:<port>]` (стандартный порт PXE HTTP **7529**). Буквальный `from=http://...` имеет приоритет над `ip=` и использует его поля адресации; иначе любой непустой `ip=` принудительно загружает данные PXE и пропускает локальные носители. Это не сессионная конфигурация NetworkManager. Подробнее см. [Загрузка по сети](/reference/boot-process/Network-Boot). | `ip=192.168.1.10:192.168.1.1:192.168.1.1:255.255.255.0` |
| `cache` | Каждая загрузка | Размер кэша httpfs в МБ для сетевой загрузки ISO через HTTP (`from=http://…`). Подробнее см. [Загрузка по сети](/reference/boot-process/Network-Boot). | `cache=512` |
| `rd.break` | Каждая загрузка | Открывает отладочную оболочку в конце этапа initramfs. | `rd.break` |
| `perchdir` | Каждая загрузка | Выбирает пронумерованную сессию персистентности или действие: `resume`, `new`, или `ask`. Несуществующий числовой селектор может использовать значение по умолчанию из метаданных; он не резервирует и не создаёт этот номер. Устройство/путь или `askdisk` форма выбирает другое место для персистентности. Для пользовательского пути используйте суффикс с разделителем «:». Без параметра персистентности MiniOS запускается с чистого состояния. | `perchdir=1`<br>`perchdir=resume`<br>`perchdir=new`<br>`perchdir=ask`<br>`perchdir=/dev/sda1/changes`<br>`perchdir=/dev/disk/by-label/MyFlash/changes`<br>`perchdir=askdisk`<br>`perchdir=askdisk:customdir` |
| `perchsize` | Каждая загрузка | Размер контейнера для `dynfilefs`, `raw` и `luks`; не применяется к `native` или `squashfs`. Простое число или `M`/`MB` значение выделяется в МБ; `G`/`GB` и `T`/`TB` преобразуются в 1000 и 1 000 000 МБ. Лимит — 1 000 000 МБ, дополнительно ограничивается доступным пространством после `perchreserve`. Менеджер сессий MiniOS ограничивает raw и LUKS-файлы 4000 МБ на FAT32; initrd LUKS применяет этот лимит, но запрос на слишком большой initrd raw может завершиться ошибкой вместо уменьшения размера. Новые raw и LUKS-контейнеры по умолчанию 4000 МБ. DynFileFS, созданный initramfs, по умолчанию использует доступную ёмкость, округлённую вниз до 1000 МБ; Менеджер сессий MiniOS по умолчанию устанавливает 4000 МБ. | `perchsize=4000`<br>`perchsize=32GB`<br>`perchsize=1TB` |
| `perchreserve` | Каждая загрузка | Порог предупреждения о нехватке места и запас по выделению в МиБ. Вычитается при расчёте размера новых или увеличивающихся контейнеров, но не является квотой во время работы и не препятствует заполнению устройства при последующих записях. По умолчанию: 256; максимум: 4096. | `perchreserve=512`<br>`perchreserve=1024` |
| `perchmode` | Каждая загрузка | Режим хранения данных.<br>`native` (по умолчанию): каталог на доступной для записи POSIX-файловой системе.<br>`dynfilefs`: расширяемый контейнер, в том числе на FAT32, NTFS или exFAT.<br>`raw`: образ ext4 фиксированного размера.<br>`luks`: контейнер ext4 с шифрованием LUKS2; создание и разблокировка происходят через консоль и требуют поддержки crypt в initramfs.<br>`squashfs`: существующий сжатый снимок, распаковываемый для текущей сессии. Менеджер сессий MiniOS может создавать и сохранять SquashFS снимки из работающей системы; initramfs может только возобновлять, но не создавать их. | `perchmode=native`<br>`perchmode=dynfilefs`<br>`perchmode=raw`<br>`perchmode=luks`<br>`perchmode=squashfs` |
| `perch` | Каждая загрузка | Включает устаревший способ восстановления постоянства. В отличие от `perchdir=resume`, не создаёт автоматически совместимую замену, если не найдено подходящей сессии по умолчанию. | `perch` |
| `toram` | Каждая загрузка | Пустой `toram` — это `full`. При использовании постоянства копия верхнего уровня full `*` не включает скрытые файлы (dotfiles); без постоянства не копирует `changes`, но копирует другие элементы верхнего уровня, включая скрытые файлы. Trim копирует необходимые `config.conf` и обычные файлы `authorized_keys`, выбранные модули верхнего уровня и рекурсивные модули, а также полный `changes/` каталог при запросе постоянства; не включает `boot/`, `kernels/`, `rootcopy/`, `config.conf.d/`, журналы, другие данные вне модулей и отдельный уровень модулей постоянства. Ни один из режимов не проверяет вместимость RAM заранее. Хранилище постоянства, скопированное в RAM, не является надёжным, и изменения не копируются обратно. Извлекайте носитель только после того, как убедитесь, что исходный диск, loop-устройства и сопоставления успешно отсоединены. | `toram`<br>`toram=trim`<br>`toram=full` |
| `text` | Каждая загрузка | Запускается в режиме текстовой консоли. | `text` |
| `automount` | Каждая загрузка | Включает автоматическое монтирование устройств хранения. | `automount` |
| `debug` | Каждая загрузка | Включает дополнительные диагностические сообщения при запуске. | `debug` |

| `zramsize` | Каждая загрузка | Устанавливает размер swap на zram в МиБ. Если не задан, MiniOS рассчитывает его исходя из общего объёма RAM. | `zramsize=512`<br>`zramsize=2048` |
| `zramcomp` | Каждая загрузка | Выбирает `lzo`, `lzo-rle`, `lz4`, `lz4hc`, или `zstd`; доступность зависит от текущего ядра. Если не указано, используется значение по умолчанию ядра. | `zramcomp=lzo`<br>`zramcomp=lz4` |

## Вопросы безопасности

Командная строка ядра хранится в открытом виде и обычно видна в настройках загрузчика, `/proc/cmdline`, а также в диагностике. Не размещайте повторно используемые секреты в `root-password=` или `user-password=`. Предпочитайте соответствующие `*-crypted` параметры, но даже открытые хэши паролей следует считать конфиденциальными.

Хуки выполняются с привилегиями загрузочного кода. `http://` хук не использует ни шифрование транспорта, ни аутентификацию сервера, поэтому любой, кто может изменить сетевой маршрут, способен его подменить. Используйте только те механизмы доставки и содержимое, которым доверяете; не применяйте неаутентифицированный HTTP-хук для запуска, связанного с безопасностью.

Команды разделяются пробелами. См. `man bootparam` справочные страницы для получения информации о дополнительных параметрах ядра, общих для всех дистрибутивов Linux.

Подробную информацию о параметрах live-config смотрите в [live-config](/reference/configuration/live-config).

Для загрузки MiniOS по сети (PXE и HTTP ISO) см. [Сетевой загрузке](/reference/boot-process/Network-Boot).
