# Параметры загрузки

## Как использовать параметры загрузки

Параметры загрузки позволяют настроить запуск MiniOS. Разделяйте параметры пробелами в командной строке ядра.

### Syslinux

- Нажмите <kbd>Esc</kbd> во время загрузки MiniOS, чтобы открыть меню загрузки.
- Нажмите <kbd>Tab</kbd> для редактирования параметров загрузки.
- Введите параметры и нажмите <kbd>Enter</kbd> для загрузки.

### GRUB

- Нажмите <kbd>E</kbd> в меню GRUB.
- Отредактируйте параметры загрузки в конце командной строки.
- Нажмите <kbd>F10</kbd> для загрузки с новыми настройками.

## Параметры загрузки

Столбец "Применение" различает параметры, которые обычно используются при каждой загрузке, и настройки учётной записи, предназначенные для первичной настройки. При использовании постоянства компоненты live-config обычно запускаются только один раз; см. [live-config](/reference/configuration/live-config).

Эта таблица служит краткой справкой. Приоритет источников и допустимые `from=` формы определены в [Обнаружение системы в initrd](/reference/boot-process/System-Discovery), фильтрация модулей в [Загрузка модулей initrd](/reference/boot-process/Module-Loading), выбор постоянства в [Постоянство initrd](/reference/boot-process/Persistence-Internals), а поддерживаемые комбинации — в [Режимы загрузки](/using-minios/Boot-Modes).

| `noload` | Каждая загрузка | Исключает кандидаты, путь которых соответствует расширенному регулярному выражению без привязки к началу строки, включая из `toram=trim`; применяется после `load` и может исключить основные или модуль ядра. | `noload=05-xfce-apps`<br>`noload=xfce-apps,firefox`<br>`noload=05,06`<br>`noload=04-06` |
| `bext` | Каждая загрузка | Устанавливает расширение для bundle. По умолчанию: `sb`. Координация с ядром по-прежнему использует буквальные имена `.sb`, поэтому пользовательское расширение не может координировать модуль `01-kernel`. | `bext=mymod` |
| `timing` | Каждая загрузка | Включает вывод времени запуска. | `timing` |
| `union` | Каждая загрузка | Выбирает объединённую файловую систему (union filesystem). | `union=aufs`<br>`union=overlayfs` |

Буквальный `from=http://...` имеет приоритет над `ip=` и использует его поля адресации; иначе любой непустой `ip=` принудительно скачивает данные PXE и пропускает локальные носители. | `perchdir` | Каждая загрузка | Выбирает номер сессии постоянства или действие. `resume` открывает совместимую сессию по умолчанию; `setup` позволяет интерактивно выбрать хранилище и создать новую сессию с номером; `new` создаёт новую сессию напрямую из выбранных/стандартных настроек `perchmode`, шифрования, сжатия и размера; `ask` предлагает сохранённые сессии и автоматически запускает настройку, если ни одной не найдено. Несуществующий числовой селектор может использоваться по умолчанию из метаданных; он не резервирует и не создаёт этот номер. Указание устройства/пути или `askdisk` формы выбирает другое место для постоянства. Для пользовательского пути используйте суффикс с разделителем ":". Без параметра постоянства MiniOS запускается с чистого состояния. | `perchdir=1`<br>`perchdir=resume`<br>`perchdir=setup`<br>`perchdir=new`<br>`perchdir=ask`<br>`perchdir=/dev/sda1/changes`<br>`perchdir=/dev/disk/by-label/MyFlash/changes`<br>`perchdir=askdisk`<br>`perchdir=askdisk:customdir` |
| `perchsize` | Каждая загрузка | Логический размер контейнера для `dynfilefs`, `dynblk`, `vmdk`, и `raw`; не применяется к `native` или `squashfs`. Число без суффикса или `M`/`MB` означает размер в MiB; значения `G`/`GB` и `T`/`TB` преобразуются в 1000 и 1 000 000 MiB соответственно. Без явного размера initrd-созданные DynFileFS, DynBlk и VMDK-сессии используют до 16 ГиБ и уменьшают этот предел, если после `perchreserve`; DynFileFS дополнительно учитывает накладные расходы индекса и лимит RAM. DynBlk запрашивает лимит установленного backend через `dynblk limits --format dynblk` (или `--format vmdk` для VMDK); отдельного лимита 512 ГиБ нет. Данные DynFileFS и DynBlk увеличиваются по мере необходимости, а DynFileFS также резервирует индексы под заявленный логический объём. Для Raw максимальный размер — 1 000 000 MiB и ограничен доступным пространством после `perchreserve`; для Raw на FAT32 лимит 4000 MiB вне зависимости от шифрования. Новые контейнеры Raw по умолчанию 4000 MiB. Менеджер сессий MiniOS также устанавливает вручную созданные контейнеры DynFileFS на 4000 MiB и DynBlk/VMDK на 16 ГиБ. Подробнее см. [Постоянство initrd](/reference/boot-process/Persistence-Internals) о работе памяти и хранилища backend. | `perchsize=4000`<br>`perchsize=32GB`<br>`perchsize=512GB` |

| `perchmode` | Каждая загрузка | Режим хранения постоянства.<br>`native` (по умолчанию): каталог на доступной для записи POSIX-файловой системе.<br>`dynfilefs`: расширяемый контейнер формата-400 на базе FUSE, включая FAT32, NTFS или exFAT.<br>`dynblk`: отдельное блочное устройство ядра формата-1 на базе thin `volumeNNN.db` файлов; фактический номер `/dev/dynblkN` выделяется динамически, возможно несколько томов одновременно.<br>`vmdk`: стандартные раздельные разрежённые файлы `volume.vmdk` / `volume-sNNN.vmdk` , предоставляемые драйвером DynBlk; без сжатия. Настройка в initrd создаёт только метаданные нулевого поколения; рабочая система создаёт первый снимок по требованию или при завершении работы. | `perchmode=native`<br>`perchmode=dynfilefs`<br>`perchmode=dynblk`<br>`perchmode=vmdk`<br>`perchmode=raw`<br>`perchmode=squashfs` |
| `perchencrypt` | Только при создании | Необязательный слой шифрования для нового `raw`, `dynfilefs`, `dynblk`, или `vmdk` сеанса. `perchencrypt=luks` требует поддержки версии `luks-layer-v1` initramfs. Для существующих сессий шифрование определяется только через `session_encryption[N]`, поэтому этот параметр не переопределяет и не конвертирует их. | `perchmode=raw perchencrypt=luks`<br>`perchmode=dynfilefs perchencrypt=luks`<br>`perchmode=dynblk perchencrypt=luks` |
| `perchcomp` | Только при создании | Выбирает сжатие backend DynBlk для нового сеанса DynBlk: `none`, `lz4`, `lz4hc`, `lzo`, `lzo-rle`, `zstd`, `deflate`, или `842`. ## Вопросы безопасности

Командная строка ядра хранится в открытом виде и обычно видна в настройках загрузчика, `/proc/cmdline`, а также в диагностике. Не размещайте повторно используемые секреты в `root-password=` или `user-password=`. Используйте соответствующие параметры `*-crypted`, но даже хэши паролей, отображаемые в явном виде, нужно считать чувствительными.

Хуки выполняются с привилегиями загрузочного кода. `http://` хук не использует шифрование транспорта и не проверяет сервер, поэтому любой, кто может изменить сетевой путь, может его подменить. Используйте только доверенные источники и способы доставки; не применяйте неаутентифицированные HTTP-хуки для запуска, где важна безопасность.

Команды разделяются пробелами. См. `man bootparam` справочные страницы для других параметров ядра, общих для всех дистрибутивов Linux.

Подробную информацию о параметрах live-config см. в [live-config](/reference/configuration/live-config).

Для загрузки MiniOS по сети (PXE и HTTP ISO) см. [Сетевая загрузка](/reference/boot-process/Network-Boot).

| Параметр | Применение | Описание | Пример |
|---|---|---|---|
| `log-storage` или `live-config.log-storage` | При каждой загрузке, с долговременным `perch` | `persistent` (по умолчанию) или `volatile`. В режиме volatile journald использует до 32 МБ RAM и обычный `/var/log` использует tmpfs размером 32 МБ. `minios-boot` и `live-config` журналы загрузки сохраняются на доступном для записи постоянном хранилище. Если файловая система журнала RAM заполнена, запись в неё прекращается, и данные не переносятся на USB-устройство. | `log-storage=volatile` |
| `apt-cache` или `live-config.apt-cache` | При каждой загрузке, с долговременным `perch` | `persistent` (по умолчанию) или `volatile` для `/var/cache/apt/archives`. Раздел RAM монтируется с размером 256 или 512 МБ, если достаточно памяти и не используется swap без zRAM; при больших загрузках он может быть исчерпан. `/var/lib/apt/lists` и состояние dpkg остаются постоянными. | `apt-cache=volatile` |
| `browser-cache` или `live-config.browser-cache` | При каждой загрузке, с долговременным `perch` | `persistent` (по умолчанию) или `volatile` для стандартных кэшей встроенных браузеров. После завершения работы live-пользователя выбранные `~/.cache` подкаталоги используют общий tmpfs на 512 МБ, а дисковое кэширование Firefox отключается с помощью управляемой политики системы, если не задан другой файл политики Firefox. Профили и кэши других приложений остаются постоянными. | `browser-cache=volatile` |

Три параметра политики хранения обрабатываются `minios-boot` до запуска основной системы инициализации, **не** селектором ранней инициализации постоянного хранилища. Они не включают `perch` и вступают в силу только после успешной активации долговременного хранения. Совместимый initrd объявляет `perch-storage-v1` на `/run/initramfs/etc/minios-initramfs-storage`. Конфигуратор и `config.conf` предоставляют те же варианты; см. [Производительность](/maintenance-and-recovery/Performance#reduce-cache-and-log-writes-with-perch) для ограничений, приоритетов и особенностей установки браузера.
