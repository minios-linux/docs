# Параметры загрузки

## Как использовать параметры загрузки

Параметры загрузки позволяют настроить запуск MiniOS. Разделяйте параметры пробелами в командной строке ядра.

### Syslinux

- Нажмите <kbd>Esc</kbd> во время загрузки MiniOS, чтобы открыть меню загрузки.
- Нажмите <kbd>Tab</kbd> для редактирования параметров загрузки.
- Введите параметры и нажмите <kbd>Enter</kbd> для загрузки.

### GRUB

- Нажмите <kbd>E</kbd> в меню GRUB.
- Отредактируйте параметры загрузки в конце командной строки.
- Нажмите <kbd>F10</kbd> для загрузки с новыми настройками.

## Параметры загрузки

В столбце «Применение» указано, какие параметры обычно используются при каждой загрузке, а какие относятся к настройкам аккаунта для первичной конфигурации. При использовании постоянного хранения компоненты live-config обычно запускаются только один раз; см. [live-config](/reference/configuration/live-config).

Эта таблица служит для быстрой справки. Приоритет источников и допустимые `from=` формы определяются в разделе [Initrd system discovery](/reference/boot-process/System-Discovery), фильтрация модулей — в разделе [Initrd module loading](/reference/boot-process/Module-Loading), выбор постоянного хранилища — в разделе [Initrd persistence](/reference/boot-process/Persistence-Internals), а поддерживаемые комбинации — в разделе [Boot modes](/using-minios/Boot-Modes).

| `load` | Каждая загрузка | Оставляет `.sb` кандидаты, путь которых соответствует нефиксированному расширенному регулярному выражению; запятые используются как альтернатива, а целый возрастающий числовой диапазон имеет специальное расширение. | `timing` | Каждая загрузка | Включает вывод времени запуска. | `timing` |
| `union` | Каждая загрузка | Выбирает union файловую систему. | `union=aufs`<br>`union=overlayfs` |
| `ip` | Каждая загрузка | Статический адрес для раннего получения по сети. Формат: `<client-ip>:<server-ip>:<gateway-ip>:<netmask>[:<port>]` (стандартный PXE HTTP порт **7529**). Буквальное значение `from=http://...` имеет приоритет над `ip=` и использует его поля адресации; иначе любой непустой `ip=` принудительно загружает данные PXE и пропускает локальные носители. Это не сессия конфигурации NetworkManager. Подробнее см. [Загрузка по сети](/reference/boot-process/Network-Boot). | `ip=192.168.1.10:192.168.1.1:192.168.1.1:255.255.255.0` |

| `rd.break` | Каждая загрузка | Открывает отладочную оболочку в конце этапа initramfs. | `rd.break` |

Несуществующий числовой селектор может использовать значение по умолчанию из метаданных; он не резервирует и не создаёт этот номер. Устройство/путь или `askdisk` форма выбирает другое место для постоянства. Для пользовательского пути используйте двоеточие в конце. Без параметра постоянства MiniOS запускается с чистого состояния. | `perchdir=1`<br>`perchdir=resume`<br>`perchdir=setup`<br>`perchdir=new`<br>`perchdir=ask`<br>`perchdir=/dev/sda1/changes`<br>`perchdir=/dev/disk/by-label/MyFlash/changes`<br>`perchdir=askdisk`<br>`perchdir=askdisk:customdir` |
| `perchsize` | Каждая загрузка | Логический размер контейнера для `dynfilefs`, `dynblk`, `vmdk`, и `raw`; не применяется к `native` или `squashfs`. Просто число или `M`/`MB` значение выделяется в MiB; `G`/`GB` и `T`/`TB` преобразуются в 1000 и 1 000 000 MiB. Без явного размера, сессии initrd-DynFileFS, DynBlk и VMDK используют до 16 ГиБ и уменьшают это значение, если после `perchreserve` остается меньше свободного места; DynFileFS дополнительно учитывает свой индекс и лимит RAM. DynBlk запрашивает лимит установленного бэкенда через `dynblk limits --format dynblk` (или `--format vmdk` для VMDK); отдельного лимита 512 ГиБ нет. Данные DynFileFS и резерв DynBlk увеличиваются по мере необходимости, а DynFileFS также резервирует индексы под объявленную ёмкость. Для Raw ограничение — 1 000 000 MiB и доступное место после `perchreserve`; Raw ограничен 4000 MiB на FAT32 вне зависимости от шифрования. Новые raw-контейнеры по умолчанию 4000 MiB. Менеджер сессий MiniOS по-прежнему вручную устанавливает размер новых контейнеров DynFileFS на 4000 MiB и DynBlk/VMDK — на 16 ГиБ. Подробнее см. [Initrd persistence](/reference/boot-process/Persistence-Internals) для особенностей работы памяти и хранилища бэкенда. | `perchsize=4000`<br>`perchsize=32GB`<br>`perchsize=512GB` |
| `perchreserve` | Каждая загрузка | Порог предупреждения о нехватке места и резерв выделения в МиБ. При расчёте размера новых или увеличиваемых контейнеров это значение вычитается, но не является квотой во время работы и не предотвращает последующие записи, которые могут заполнить устройство. По умолчанию: 256; максимум: 4096. | `perchreserve=512`<br>`perchreserve=1024` |
| `perchmode` | Каждая загрузка | Режим хранения данных.<br>`native` (по умолчанию): каталог на доступной для записи файловой системе POSIX.<br>`dynfilefs`: контейнер формата 400 с поддержкой FUSE, в том числе на FAT32, NTFS или exFAT.<br>`dynblk`: отдельное блочное устройство ядра формата 1 на основе thin `volumeNNN.db` файлов; фактическое `/dev/dynblkN` количество выделяется динамически, и несколько томов могут сосуществовать.<br>`vmdk`: стандартные раздельные разрежённые `volume.vmdk` / `volume-sNNN.vmdk` файлы, предоставляемые драйвером DynBlk; без сжатия. Требуется версия `vmdk-session-v1` initrd.<br>`raw`: образ ext4 фиксированного размера.<br>`squashfs`: сжатый снимок, распаковываемый в верхний слой на базе RAM. При настройке через initrd создаётся только метаданные нулевого поколения; первый снимок создаётся системой по требованию или при завершении работы. | `perchmode=native`<br>`perchmode=dynfilefs`<br>`perchmode=dynblk`<br>`perchmode=vmdk`<br>`perchmode=raw`<br>`perchmode=squashfs` |
| `perchencrypt` | Только при создании | Необязательный слой шифрования для вновь создаваемой `raw`, `dynfilefs`, `dynblk`, или `vmdk` сессии. `perchencrypt=luks` требует версию `luks-layer-v1` initramfs. Для существующих сессий шифрование определяется только через `session_encryption[N]`, поэтому этот параметр не переопределяет и не преобразует их. | `perchmode=raw perchencrypt=luks`<br>`perchmode=dynfilefs perchencrypt=luks`<br>`perchmode=dynblk perchencrypt=luks` |
| `perchcomp` | Только при создании | Выбирает сжатие бэкенда DynBlk для новой сессии DynBlk: `none`, `lz4`, `lz4hc`, `lzo`, `lzo-rle`, `zstd`, `deflate`, или `842`. Выбранный кодек ядра должен быть доступен. Если `perchencrypt=luks` оборачивает DynBlk, MiniOS принудительно включает сжатие DynBlk для `none`. | `perch` | Каждая загрузка | Включает устаревший путь восстановления постоянства. В отличие от `perchdir=resume`, он не создаёт автоматически совместимую замену, если не найдено подходящей сессии по умолчанию. | `perch` |
| `toram` | Каждая загрузка | Управляет копированием MiniOS **системных данных** в RAM. Пустое значение `toram`— `full`; `trim`копирует только необходимую конфигурацию и выбранный набор модулей, исключая несвязанные исходные данные. Копирование данных для постоянного хранения настраивается отдельно через `perchtoram`. Если запрошено постоянное хранение и `perchtoram`не указано, любой активный `toram`режим по умолчанию включает копирование для постоянства через `trim`. Извлекайте носитель только после того, как убедитесь, что исходные данные, циклы, сопоставления и все необходимые хранилища для постоянства успешно отключены. | `toram`<br>`toram=trim`<br>`toram=full` |

Родные данные не копируются: успешный запрос на родной RAM запускает новый пустой контейнер, кроме случая сброса, когда копирование отключается. При неудачном копировании операция на хранилище сохраняется. Изменения RAM требуют сохранения в исходное доступное для записи хранилище или как новую сессию. ## Вопросы безопасности

Командная строка ядра хранится в открытом виде и обычно видна в настройках загрузчика, `/proc/cmdline`, а также в диагностике. Не размещайте повторно используемые секреты в `root-password=` или `user-password=`. Используйте соответствующие параметры `*-crypted`, но даже хэши паролей, отображаемые в явном виде, нужно считать чувствительными.

Хуки выполняются с привилегиями загрузочного кода. `http://` хук не использует шифрование транспорта и не проверяет сервер, поэтому любой, кто может изменить сетевой путь, может его подменить. Используйте только доверенные источники и способы доставки; не применяйте неаутентифицированные HTTP-хуки для запуска, где важна безопасность.

Команды разделяются пробелами. См. `man bootparam` справочные страницы для других параметров ядра, общих для всех дистрибутивов Linux.

Подробную информацию о параметрах live-config см. в [live-config](/reference/configuration/live-config).

Для загрузки MiniOS по сети (PXE и HTTP ISO) см. [Сетевая загрузка](/reference/boot-process/Network-Boot).

## Параметры кэша и журнала для постоянных сессий

| Параметр | Применение | Описание | Пример |
|---|---|---|---|
| `log-storage` или `live-config.log-storage` | Каждая загрузка с проверенной постоянностью | `persistent` (по умолчанию) или `volatile`. В режиме volatile journald использует до 32 МБ, а обычный `/var/log` использует tmpfs размером 32 МБ. Диагностика загрузки хранится отдельно; при долговременной постоянности она остается на накопителе. Переполнение файловой системы журнала RAM не приводит к записи на USB-устройство. | `log-storage=volatile` |
| `apt-cache` или `live-config.apt-cache` | Каждая загрузка с проверенной постоянностью | `persistent` (по умолчанию) или `volatile` для `/var/cache/apt/archives`. Размер tmpfs составляет 256 МБ при наличии не менее 1 ГБ, либо 512 МБ при наличии не менее 2 ГБ. Использование swap без zRAM отключает tmpfs; большие загрузки могут исчерпать его. Списки репозиториев и состояние dpkg сохраняются в слое сессии. | `apt-cache=volatile` |
| `browser-cache` или `live-config.browser-cache` | Каждая загрузка с проверенной постоянностью | `persistent` (по умолчанию) или `volatile`. При наличии не менее 1 ГБ и отсутствии swap без zRAM стандартные каталоги кэша браузера live-пользователя используют общий tmpfs 512 МБ. Управляемая политика Firefox отключает кэширование на диск, если нет других файлов политики. Профили и не связанные с этим кэши остаются в слое сессии. | `browser-cache=volatile` |

Три параметра политики хранения анализируются `minios-boot` до запуска основной системы инициализации, **не** селектором ранней постоянности. Они не включают `perch`. Для работы требуется успешная активация на долговременном накопителе или в записываемой сессии RAM с защищённой `ram-origin` информацией; они не делают изменения RAM постоянными без сохранения. Совместимый initrd сообщает о `perch-storage-v1` по адресу `/run/initramfs/etc/minios-initramfs-storage`. Конфигуратор и `config.conf` предоставляют те же варианты; см. [Производительность](/maintenance-and-recovery/Performance#reduce-cache-and-log-writes-with-perch) для информации о лимитах, приоритетах и особенностях установки браузера.
