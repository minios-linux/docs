# Параметры загрузки

## Как использовать параметры загрузки

Параметры загрузки позволяют настроить запуск MiniOS. Разделяйте параметры пробелами в командной строке ядра.

### Syslinux

- Нажмите <kbd>Esc</kbd> во время загрузки MiniOS, чтобы открыть меню загрузки.
- Нажмите <kbd>Tab</kbd> для редактирования параметров загрузки.
- Введите параметры и нажмите <kbd>Enter</kbd> для запуска.

### GRUB

- Нажмите <kbd>E</kbd> в меню GRUB.
- Отредактируйте параметры загрузки в конце командной строки.
- Нажмите <kbd>F10</kbd> для загрузки с новыми настройками.

## Параметры загрузки

В столбце "Применение" указано, какие параметры обычно используются при каждой загрузке, а какие относятся к настройкам аккаунта для первоначальной конфигурации. При включенной персистентности компоненты live-config обычно запускаются только один раз; подробнее см. [live-config](/reference/configuration/live-config).

Эта таблица служит краткой справкой. Приоритет источников и допустимые `from=` формы определены в разделе [Обнаружение системы Initrd](/reference/boot-process/System-Discovery), фильтрация модулей — в разделе [Загрузка модулей Initrd](/reference/boot-process/Module-Loading), выбор персистентности — в разделе [Персистентность Initrd](/reference/boot-process/Persistence-Internals), а поддерживаемые комбинации — в разделе [Режимы загрузки](/using-minios/Boot-Modes).

| Параметр | Применение | Описание | Пример |
|---|---|---|---|
| `from` | Каждая загрузка | Загружает данные MiniOS из каталога, поддерживаемого пути к устройству или ISO-образа. Форматы устройств UUID, PARTUUID и by-id не обрабатываются. Буквальный **`http://` только** URL имеет приоритет над `ip=` и инициирует [сетевую загрузку](/reference/boot-process/Network-Boot) через httpfs2. | `from=/minios/`<br>`from=/Downloads/minios.iso`<br>`from=http://domain.com/minios.iso`<br>`from=/dev/sr0/minios`<br>`from=/dev/disk/by-label/MyFlash/minios`<br>`from=askdisk`<br>`from=askdisk:customdir` |
| `load` | Каждая загрузка | Оставляет `.sb` кандидаты, путь которых соответствует нефиксированному расширенному регулярному выражению; запятые используются как альтернатива, а целый возрастающий числовой диапазон имеет специальное расширение. Также фильтрует `toram=trim`. Это может исключить основные или модуль ядра и сделать систему незагружаемой. | `load=00-core`<br>`load=core,kernel,firmware`<br>`load=00,01,02`<br>`load=00-03` |
| `noload` | Каждая загрузка | Исключает кандидаты, путь которых соответствует нефиксированному расширенному регулярному выражению, в том числе из `toram=trim`; применяется после `load` и может исключить основные или модуль ядра. | `noload=05-xfce-apps`<br>`noload=xfce-apps,firefox`<br>`noload=05,06`<br>`noload=04-06` |
| `bext` | Каждая загрузка | Устанавливает расширение для бандла. По умолчанию: `sb`. Координация с ядром всё равно использует буквальные имена `.sb`, поэтому пользовательское расширение не может координировать модуль `01-kernel` ядра. | `bext=mymod` |
| `timing` | Каждая загрузка | Включает вывод времени запуска. | `timing` |
| `union` | Каждая загрузка | Выбирает union файловую систему. | `union=aufs`<br>`union=overlayfs` |
| `ip` | Каждая загрузка | Статический адрес для раннего получения по сети. Формат: `<client-ip>:<server-ip>:<gateway-ip>:<netmask>[:<port>]` (по умолчанию порт PXE HTTP **7529**). Буквальный `from=http://...` имеет приоритет над `ip=` и использует его поля адресации; иначе любой непустой `ip=` принудительно скачивает данные PXE и пропускает локальные носители. Это не сессионная конфигурация NetworkManager. Подробнее см. [Загрузка по сети](/reference/boot-process/Network-Boot). | `ip=192.168.1.10:192.168.1.1:192.168.1.1:255.255.255.0` |
| `cache` | Каждая загрузка | Размер кэша httpfs в МБ для сетевой загрузки ISO через HTTP (`from=http://…`). Подробнее см. [Загрузка по сети](/reference/boot-process/Network-Boot). | `cache=512` |
| `rd.break` | Каждая загрузка | Открывает отладочную оболочку в конце стадии initramfs. | `rd.break` |
| `perchdir` | Каждая загрузка | Выбирает сессию постоянства по номеру или действие: `resume`, `new`, или `ask`. Несуществующий числовой селектор может использовать значение по умолчанию из метаданных; он не резервирует и не создаёт этот номер. Устройство/путь или `askdisk` форма выбирает другое место для постоянства. Для пользовательского пути используйте суффикс с двоеточием. Без параметра постоянства MiniOS стартует с чистого состояния. | `perchdir=1`<br>`perchdir=resume`<br>`perchdir=new`<br>`perchdir=ask`<br>`perchdir=/dev/sda1/changes`<br>`perchdir=/dev/disk/by-label/MyFlash/changes`<br>`perchdir=askdisk`<br>`perchdir=askdisk:customdir` |
| `perchsize` | Каждая загрузка | Размер контейнера для `dynfilefs`, `dynblk`, `raw`, и `luks`; не применяется к `native` или `squashfs`. Обычное число или `M`/`MB` значение выделяется в МБ; `G`/`GB` и `T`/`TB` преобразуются в 1000 и 1 000 000 МБ. Dynblk использует тонкий профиль по умолчанию 16 ГБ и ограничение виртуальной ёмкости 512 ГБ; физический размер увеличивается по мере необходимости. Для других контейнеров размер ограничен 1 000 000 МБ и доступным пространством после `perchreserve`. Менеджер сессий MiniOS ограничивает raw- и LUKS-файлы 4000 МБ на FAT32; initrd LUKS также применяет этот лимит, но запрос на raw-файл initrd сверх лимита может завершиться ошибкой, а не уменьшением размера. Новые raw- и LUKS-контейнеры по умолчанию имеют размер 4000 МБ. DynFileFS, созданный initramfs, по умолчанию использует всё доступное пространство, округлённое до 1000 МБ; Менеджер сессий MiniOS по умолчанию устанавливает 4000 МБ. | `perchsize=4000`<br>`perchsize=32GB`<br>`perchsize=512GB` |
| `perchreserve` | Каждая загрузка | Порог предупреждения о нехватке места и запас по выделению в MiB. Вычитается при расчёте размера новых или расширяемых контейнеров, но не является квотой в реальном времени и не предотвращает заполнение устройства при последующих записях. По умолчанию: 256; максимум: 4096. | `perchreserve=512`<br>`perchreserve=1024` |
| `perchmode` | Каждая загрузка | Режим хранения данных с сохранением.<br>`native` (по умолчанию): каталог на доступной для записи файловой системе POSIX.<br>`dynfilefs`: контейнер формата-400 на базе FUSE с возможностью расширения, в том числе на FAT32, NTFS или exFAT.<br>`dynblk`: отдельное блочное устройство ядра формата-1 на базе thin `volumeNNN.db` файлов; фактическое `/dev/dynblkN` количество выделяется динамически, и несколько томов могут сосуществовать.<br>`raw`: образ ext4 фиксированного размера.<br>`luks`: контейнер ext4 с шифрованием LUKS2; создание и разблокировка требуют ввода в консоли и поддержки crypt в initramfs.<br>`squashfs`: существующий сжатый снимок, распакованный для текущей сессии. Менеджер сессий MiniOS может создавать и сохранять снимки SquashFS из работающей системы; initramfs может только восстанавливать их, но не создавать. | `perchmode=native`<br>`perchmode=dynfilefs`<br>`perchmode=dynblk`<br>`perchmode=raw`<br>`perchmode=luks`<br>`perchmode=squashfs` |
| `perch` | Каждая загрузка | Включает устаревший режим восстановления сохранённых данных. В отличие от `perchdir=resume`, не создаёт автоматически совместимую замену, если не обнаружена подходящая сессия по умолчанию. | `perch` |
| `toram` | Каждая загрузка | Минимальный `toram` — это `full`. При включённом сохранении данных, верхний уровень полного `*` копирования не включает скрытые файлы; без сохранения — не включает `changes`, но копирует другие элементы верхнего уровня, включая скрытые файлы. Обрезка копирует необходимые `config.conf`, обычные файлы `authorized_keys`, выбранные модули верхнего уровня и рекурсивные, а также полностью дерево `changes/` при запросе сохранения; не включает `boot/`, `kernels/`, `rootcopy/`, `config.conf.d/`, логи, другие не относящиеся к модулям данные и отдельный уровень модуля сохранения. Ни один из режимов не проверяет вместимость RAM заранее. Хранилище сохранения, скопированное в RAM, не является надёжным, и изменения не копируются обратно. Извлекайте носитель только после того, как убедитесь, что исходный диск, loop-устройства и маппинги успешно отключены. | `toram`<br>`toram=trim`<br>`toram=full` |
| `text` | Каждая загрузка | Запуск в текстовом консольном режиме. | `text` |

| `debug` | Каждая загрузка | Включает расширенную диагностику при запуске. | `debug` |
| `nozram` | Каждая загрузка | Отключает swap на zram. | `nozram` |
| `zramsize` | Каждая загрузка | Задаёт размер swap на zram в MiB. Если не указано, MiniOS рассчитывает его исходя из общего объёма RAM. | `zramsize=512`<br>`zramsize=2048` |
| `zramcomp` | Каждая загрузка | Выбирает `lzo`, `lzo-rle`, `lz4`, `lz4hc`, или `zstd`; доступность зависит от используемого ядра. Если не указано, сохраняется значение по умолчанию ядра. | `zramcomp=lzo`<br>`zramcomp=lz4` |

## Вопросы безопасности

Командная строка ядра хранится в открытом виде и обычно видна в конфигурации загрузчика, `/proc/cmdline`, а также в диагностике. Не размещайте повторно используемые секретные данные в `root-password=` или `user-password=`. Предпочитайте соответствующие `*-crypted` параметры, но даже хэши паролей, оказавшиеся в открытом доступе, следует считать конфиденциальными.

Хуки выполняются с привилегиями загрузочного кода. `http://`-хук не использует шифрование транспорта и не аутентифицирует сервер, поэтому любой, кто может изменить сетевой маршрут, способен его подменить. Используйте только доверенные механизмы доставки и содержимое; не применяйте неаутентифицированные HTTP-хуки для запуска, где важна безопасность.

Команды разделяйте пробелами. Дополнительные параметры ядра, общие для всех дистрибутивов Linux, смотрите в `man bootparam`справочных страницах.

Подробную информацию о параметрах live-config см. в разделе [live-config](/reference/configuration/live-config).

Для загрузки MiniOS по сети (PXE и HTTP ISO) см. [Загрузка по сети](/reference/boot-process/Network-Boot).
