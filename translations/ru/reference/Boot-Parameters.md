# Параметры загрузки

## Как использовать параметры загрузки

Параметры загрузки позволяют настроить запуск MiniOS. Разделяйте параметры пробелами в командной строке ядра.

### Syslinux

- Нажмите <kbd>Esc</kbd> во время загрузки MiniOS, чтобы открыть меню загрузки.
- Нажмите <kbd>Tab</kbd> для редактирования параметров загрузки.
- Введите параметры и нажмите <kbd>Enter</kbd> для запуска.

### GRUB

- Нажмите <kbd>E</kbd> в меню GRUB.
- Отредактируйте параметры загрузки в конце командной строки.
- Нажмите <kbd>F10</kbd> для загрузки с новыми настройками.

## Параметры загрузки

В столбце «Применение» указано, какие параметры обычно используются при каждой загрузке, а какие относятся к настройкам аккаунта для первоначальной конфигурации. При использовании персистентности компоненты live-config обычно запускаются только один раз; подробнее см. [live-config](/reference/configuration/live-config).

Эта таблица служит для быстрой справки. Приоритет источников и допустимые `from=` формы определены в [Initrd system discovery](/reference/boot-process/System-Discovery), фильтрация модулей описана в [Initrd module loading](/reference/boot-process/Module-Loading), выбор персистентности — в [Initrd persistence](/reference/boot-process/Persistence-Internals), а поддерживаемые комбинации — в разделе [Boot modes](/using-minios/Boot-Modes).

|---|---|---|---|
| `from` | Каждая загрузка | Загружает данные MiniOS из каталога, поддерживаемого пути к устройству или ISO. Форматы устройств UUID, PARTUUID и by-id не обрабатываются. Буквальный **`http://` только** URL имеет приоритет над `ip=` и запускает [сетевую загрузку](/reference/boot-process/Network-Boot) через httpfs2. | `from=/minios/`<br>`from=/Downloads/minios.iso`<br>`from=http://domain.com/minios.iso`<br>`from=/dev/sr0/minios`<br>`from=/dev/disk/by-label/MyFlash/minios`<br>`from=askdisk`<br>`from=askdisk:customdir` |
| `load` | Каждая загрузка | Оставляет `.sb` кандидатов, путь которых соответствует нефиксированному расширенному регулярному выражению; запятые заменяются на альтернативы, а целый возрастающий числовой диапазон имеет специальное расширение. Также фильтрует `toram=trim`. Может исключить основные или модуль ядра и сделать систему незагружаемой. | `load=00-core`<br>`load=core,kernel,firmware`<br>`load=00,01,02`<br>`load=00-03` |
| `noload` | Каждая загрузка | Исключает кандидатов, путь которых соответствует нефиксированному расширенному регулярному выражению, включая из `toram=trim`; применяется после `load` и может исключить основные или модуль ядра. | `noload=05-xfce-apps`<br>`noload=xfce-apps,firefox`<br>`noload=05,06`<br>`noload=04-06` |
| `bext` | Каждая загрузка | Устанавливает расширение для пакета. По умолчанию: `sb`. Координация с ядром по-прежнему использует буквальные имена `.sb`, поэтому пользовательское расширение не может координировать модуль `01-kernel`. | `bext=mymod` |
| `timing` | Каждая загрузка | Включает вывод времени запуска. | `timing` |
| `union` | Каждая загрузка | Выбирает union-файловую систему. | `union=aufs`<br>`union=overlayfs` |
| `ip` | Каждая загрузка | Статический адрес для раннего получения данных по сети. Формат: `<client-ip>:<server-ip>:<gateway-ip>:<netmask>[:<port>]` (по умолчанию порт PXE HTTP **7529**). Буквальный `from=http://...` имеет приоритет над `ip=` и использует его поля адресации; иначе любой непустой `ip=` принудительно загружает данные PXE и пропускает локальные носители. Это не конфигурация NetworkManager для текущей сессии. Подробнее см. [Загрузка по сети](/reference/boot-process/Network-Boot). | `ip=192.168.1.10:192.168.1.1:192.168.1.1:255.255.255.0` |
| `cache` | Каждая загрузка | Размер кэша httpfs в Миб для сетевой загрузки HTTP ISO (`from=http://…`). Подробнее см. [Загрузка по сети](/reference/boot-process/Network-Boot). | `cache=512` |
| `rd.break` | Каждая загрузка | Открывает отладочную оболочку в конце этапа initramfs. | `rd.break` |
| `perchdir` | Каждая загрузка | Выбирает пронумерованную сессию постоянства или действие: `resume`, `new`, или `ask`. Несуществующий числовой селектор может использовать значение по умолчанию из метаданных; он не резервирует и не создает этот номер. Устройство/путь или `askdisk` форма выбирает другое место для постоянства. Для пользовательского пути используйте суффикс с разделителем «:». Без параметра постоянства MiniOS запускается с чистого состояния. | `perchdir=1`<br>`perchdir=resume`<br>`perchdir=new`<br>`perchdir=ask`<br>`perchdir=/dev/sda1/changes`<br>`perchdir=/dev/disk/by-label/MyFlash/changes`<br>`perchdir=askdisk`<br>`perchdir=askdisk:customdir` |
| `perchsize` | Каждая загрузка | Логический размер контейнера для `dynfilefs`, `dynblk`, `vmdk` и `raw`; не применяется к `native` или `squashfs`. Простое число или `M`/`MB` значение выделяется в Миб; `G`/`GB` и `T`/`TB` преобразуются в 1000 и 1 000 000 Миб. Без явного размера контейнеры, созданные initrd (DynFileFS, DynBlk) и сессии VMDK используют до 16 ГиБ и уменьшают этот предел, если после `perchreserve` остается меньше свободного места; DynFileFS дополнительно учитывает накладные расходы индекса и лимит RAM. DynBlk запрашивает установленный лимит бэкенда через `dynblk limits --format dynblk` (или `--format vmdk` для VMDK); отдельного лимита 512 ГиБ нет. Данные payload DynFileFS и backing DynBlk растут по мере необходимости, а DynFileFS также резервирует индексы под объявленную логическую емкость. Запросы Raw ограничены 1 000 000 Миб и доступным пространством после `perchreserve`; Raw ограничен 4000 Миб на FAT32 независимо от шифрования. Новые raw-контейнеры по умолчанию имеют размер 4000 Миб. Менеджер сессий MiniOS по-прежнему устанавливает вручную созданные контейнеры DynFileFS по умолчанию на 4000 Миб, а DynBlk/VMDK — на 16 ГиБ. Подробнее см. [Initrd persistence](/reference/boot-process/Persistence-Internals) для информации о работе памяти и хранилища в бэкенде. | `perchsize=4000`<br>`perchsize=32GB`<br>`perchsize=512GB` |
| `perchreserve` | Каждая загрузка | Порог предупреждения о низком пространстве и резерв по выделению в МиБ. Вычитается при расчёте размера новых или увеличиваемых контейнеров, но не является квотой во время работы и не препятствует последующим записям, которые могут заполнить устройство. По умолчанию: 256; максимум: 4096. | `perchreserve=512`<br>`perchreserve=1024` |
| `perchmode` | Каждая загрузка | Режим хранения данных с сохранением.<br>`native` (по умолчанию): каталог на доступной для записи файловой системе POSIX.<br>`dynfilefs`: контейнер формата 400 на базе FUSE с возможностью расширения, в том числе на FAT32, NTFS или exFAT.<br>`dynblk`: отдельное блочное устройство ядра формата 1 на основе thin `volumeNNN.db` файлов; фактическое `/dev/dynblkN` количество выделяется динамически, и несколько томов могут сосуществовать.<br>`vmdk`: стандартный разделённый разрежённый `volume.vmdk` / `volume-sNNN.vmdk` файлы, предоставляемые драйвером DynBlk; без сжатия. Требуется версия `vmdk-session-v1` initrd.<br>`raw`: образ ext4 фиксированного размера.<br>`squashfs`: сжатый снимок, распаковываемый в верхний слой на базе RAM. При настройке через initrd создаются только метаданные нулевого поколения; работающая система создаёт первый снимок по требованию или при завершении работы. | `perchmode=native`<br>`perchmode=dynfilefs`<br>`perchmode=dynblk`<br>`perchmode=vmdk`<br>`perchmode=raw`<br>`perchmode=squashfs` |
| `perchencrypt` | Только при создании | Необязательный слой шифрования для нового `raw`, `dynfilefs`, `dynblk`, или `vmdk` сессии. `perchencrypt=luks` требует версию `luks-layer-v1` initramfs. Для существующих сессий шифрование определяется только через `session_encryption[N]`, поэтому этот параметр не переопределяет и не конвертирует их. | `perchmode=raw perchencrypt=luks`<br>`perchmode=dynfilefs perchencrypt=luks`<br>`perchmode=dynblk perchencrypt=luks` |
| `perchcomp` | Только при создании | Выбирает сжатие бэкенда DynBlk для новой сессии DynBlk: `none`, `lz4`, `lz4hc`, `lzo`, `lzo-rle`, `zstd`, `deflate`, или `842`. Выбранный кодек ядра должен быть доступен. Если `perchencrypt=luks` оборачивает DynBlk, MiniOS принудительно включает сжатие DynBlk для `none`. VMDK не поддерживает сжатие: при загрузке игнорируется не-`none` кодек с предупреждением. | `perchmode=dynblk perchcomp=lz4`<br>`perchmode=dynblk perchcomp=zstd` |
| `perch` | Каждая загрузка | Включает устаревший путь восстановления сессии с сохранением. В отличие от `perchdir=resume`, он не создаёт автоматически совместимую замену, если не существует подходящей сессии по умолчанию. | `perch` |
| `toram` | Каждая загрузка | Базовый режим `toram` — `full`. При использовании постоянного хранилища, копия режима full на верхнем уровне `*` не включает скрытые файлы (dotfiles); без постоянного хранилища не включает `changes`, но копирует остальные элементы верхнего уровня, включая скрытые файлы. Trim копирует только необходимые `config.conf`, обычные файлы `authorized_keys`, выбранные модули верхнего уровня и рекурсивные модули, а также полное дерево `changes/` при запросе постоянства; не включает `boot/`, `kernels/`, `rootcopy/`, `config.conf.d/`, журналы, другие данные вне модулей и отдельный уровень модуля постоянства. Ни один из режимов не проверяет вместимость RAM заранее. Хранилище постоянства, скопированное в RAM, не является надёжным, и изменения не копируются обратно. Извлекайте носитель только после того, как убедитесь, что источник, циклы и сопоставления успешно отключены. | `toram`<br>`toram=trim`<br>`toram=full` |

## Вопросы безопасности

Командная строка ядра хранится в открытом виде и обычно видна в конфигурации загрузчика, `/proc/cmdline`, а также в диагностике. Не размещайте повторно используемые секретные данные в `root-password=` или `user-password=`. Предпочитайте соответствующие `*-crypted` параметры, но даже хэши паролей, оказавшиеся в открытом доступе, следует считать конфиденциальными.

Хуки выполняются с привилегиями загрузочного кода. `http://`-хук не использует шифрование транспорта и не аутентифицирует сервер, поэтому любой, кто может изменить сетевой маршрут, способен его подменить. Используйте только доверенные механизмы доставки и содержимое; не применяйте неаутентифицированные HTTP-хуки для запуска, где важна безопасность.

Команды разделяйте пробелами. Дополнительные параметры ядра, общие для всех дистрибутивов Linux, смотрите в `man bootparam`справочных страницах.

Подробную информацию о параметрах live-config см. в разделе [live-config](/reference/configuration/live-config).

Для загрузки MiniOS по сети (PXE и HTTP ISO) см. [Загрузка по сети](/reference/boot-process/Network-Boot).
