# Параметры загрузки

## Как использовать параметры загрузки

Параметры загрузки позволяют настроить запуск MiniOS. Разделяйте параметры пробелами в командной строке ядра.

### Syslinux

- Нажмите <kbd>Esc</kbd> во время загрузки MiniOS, чтобы открыть меню загрузки.
- Нажмите <kbd>Tab</kbd> для редактирования параметров загрузки.
- Введите параметры и нажмите <kbd>Enter</kbd> для запуска.

### GRUB

- Нажмите <kbd>E</kbd> в меню GRUB.
- Отредактируйте параметры загрузки в конце командной строки.
- Нажмите <kbd>F10</kbd> для загрузки с новыми настройками.

## Параметры загрузки

В столбце «Применение» указано, какие параметры обычно используются при каждой загрузке, а какие относятся к настройкам аккаунта для начальной конфигурации. При использовании постоянства компоненты live-config обычно запускаются только один раз; подробнее см. [live-config](/reference/configuration/live-config).

Эта таблица служит для быстрой справки. Приоритет источников и допустимые `from=` формы определяются в [Обнаружение системы Initrd](/reference/boot-process/System-Discovery), фильтрация модулей — в [Загрузка модулей Initrd](/reference/boot-process/Module-Loading), выбор носителя с постоянством — в [Постоянство Initrd](/reference/boot-process/Persistence-Internals), а поддерживаемые комбинации — в [Режимы загрузки](/using-minios/Boot-Modes).

| Параметр | Применение | Описание | Пример |
|---|---|---|---|
| `from` | Каждая загрузка | Загружает данные MiniOS из каталога, поддерживаемого устройства или ISO-образа. Форматы устройств UUID, PARTUUID и by-id не обрабатываются. Буквальный **`http://` только** URL имеет приоритет над `ip=` и инициирует [сетевую загрузку](/reference/boot-process/Network-Boot) через httpfs2. | `from=/minios/`<br>`from=/Downloads/minios.iso`<br>`from=http://domain.com/minios.iso`<br>`from=/dev/sr0/minios`<br>`from=/dev/disk/by-label/MyFlash/minios`<br>`from=askdisk`<br>`from=askdisk:customdir` |
| `load` | Каждая загрузка | Оставляет кандидаты `.sb` путь которых соответствует нефиксированному расширенному регулярному выражению; запятые трактуются как альтернатива, а целый возрастающий числовой диапазон разворачивается особым образом. Также фильтрует `toram=trim`. Может исключить основные или ядровые модули и сделать систему незагружаемой. | `load=00-core`<br>`load=core,kernel,firmware`<br>`load=00,01,02`<br>`load=00-03` |
| `noload` | Каждая загрузка | Исключает кандидаты, путь которых соответствует нефиксированному расширенному регулярному выражению, включая из `toram=trim`; применяется после `load` и может исключить основные или ядровые модули. | `noload=05-xfce-apps`<br>`noload=xfce-apps,firefox`<br>`noload=05,06`<br>`noload=04-06` |
| `bext` | Каждая загрузка | Устанавливает расширение для бандла. По умолчанию: `sb`. Координация с ядром всё равно использует буквальные имена `.sb`, поэтому пользовательское расширение не позволяет координировать модуль `01-kernel`. | `bext=mymod` |
| `timing` | Каждая загрузка | Включает вывод времени запуска. | `timing` |
| `union` | Каждая загрузка | Выбирает объединённую файловую систему (union filesystem). | `union=aufs`<br>`union=overlayfs` |
| `ip` | Каждая загрузка | Статический адрес для раннего получения данных по сети. Формат: `<client-ip>:<server-ip>:<gateway-ip>:<netmask>[:<port>]` (по умолчанию порт PXE HTTP **7529**). Буквальный `from=http://...` имеет приоритет над `ip=` и использует его адресные поля; иначе любой непустой `ip=` принудительно запускает загрузку данных PXE и игнорирует локальные носители. Это не настройка NetworkManager для сессии. Подробнее см. [Сетевая загрузка](/reference/boot-process/Network-Boot). | `ip=192.168.1.10:192.168.1.1:192.168.1.1:255.255.255.0` |
| `cache` | Каждая загрузка | Размер кэша httpfs в MiB для сетевой загрузки ISO через HTTP (`from=http://…`). Подробнее см. [Сетевая загрузка](/reference/boot-process/Network-Boot). | `cache=512` |
| `rd.break` | Каждая загрузка | Открывает отладочную оболочку (debug shell) в конце этапа initramfs. | `rd.break` |
| `perchdir` | Каждая загрузка | Выбирает номер сессии с постоянством или действие: `resume`, `new`, или `ask`. Несуществующий числовой селектор может использовать значение по умолчанию из метаданных; он не резервирует и не создаёт этот номер. Указание устройства/пути или формы `askdisk` выбирает другое место для постоянства. Для пользовательского пути используйте суффикс через двоеточие. Без параметра постоянства MiniOS стартует с чистого состояния. | `perchdir=1`<br>`perchdir=resume`<br>`perchdir=new`<br>`perchdir=ask`<br>`perchdir=/dev/sda1/changes`<br>`perchdir=/dev/disk/by-label/MyFlash/changes`<br>`perchdir=askdisk`<br>`perchdir=askdisk:customdir` |
| `perchsize` | Каждая загрузка | Логический размер контейнера для `dynfilefs`, `dynblk` и `raw`; не применяется к `native` или `squashfs`. Простое число или значение `M`/`MB` выделяется в MiB; `G`/`GB` и `T`/`TB` преобразуются в 1000 и 1 000 000 MiB соответственно. Без явного размера сессии DynFileFS и DynBlk, созданные через initrd, используют до 16 ГиБ и уменьшают этот предел, если после `perchreserve` остаётся меньше свободного места; DynFileFS дополнительно учитывает накладные расходы индекса и лимит RAM. Для DynBlk максимальная виртуальная ёмкость — 512 ГиБ. Данные DynFileFS и DynBlk увеличиваются по мере необходимости, при этом DynFileFS резервирует индексы под заявленный логический объём. Raw-запросы ограничены 1 000 000 MiB и доступным пространством после `perchreserve`. Для FAT32 Raw ограничен 4000 MiB независимо от шифрования. Новые контейнеры Raw по умолчанию имеют 4000 MiB. Менеджер сессий MiniOS по-прежнему вручную задаёт DynFileFS по умолчанию 4000 MiB, а DynBlk — 16 ГиБ. Подробнее см. [Постоянство Initrd](/reference/boot-process/Persistence-Internals) для особенностей работы с памятью и хранилищем. | `perchsize=4000`<br>`perchsize=32GB`<br>`perchsize=512GB` |
| `perchreserve` | Каждая загрузка | Запас по размеру и порог предупреждения о нехватке места в MiB. Вычитается при расчёте размера новых или увеличивающихся контейнеров, но не является квотой во время работы и не предотвращает дальнейшее заполнение устройства. По умолчанию: 256; максимум: 4096. | `perchreserve=512`<br>`perchreserve=1024` |
| `perchmode` | Каждая загрузка | Режим хранения данных постоянства.<br>`native` (по умолчанию): каталог на доступной для записи POSIX-файловой системе.<br>`dynfilefs`: расширяемый контейнер формата 400 на базе FUSE, в том числе на FAT32, NTFS или exFAT.<br>`dynblk`: отдельное блочное устройство ядра формата 1, работающее на thin `volumeNNN.db` файлах; фактический номер `/dev/dynblkN` выделяется динамически, возможно одновременное существование нескольких томов.<br>`raw`: образ ext4 фиксированного размера.<br>`squashfs`: сжатый снимок, распаковываемый в верхний слой на базе RAM. Настройка через initrd создаёт только метаданные нулевого поколения; рабочая система создаёт первый снимок по требованию или при завершении работы. | `perchmode=native`<br>`perchmode=dynfilefs`<br>`perchmode=dynblk`<br>`perchmode=raw`<br>`perchmode=squashfs` |
| `perchencrypt` | Только при создании | Необязательный слой шифрования для вновь созданной `raw`, `dynfilefs` или `dynblk` сессии. `perchencrypt=luks` требует поддержки версии `luks-layer-v1` initramfs. Для существующих сессий шифрование определяется только через `session_encryption[N]`, поэтому этот параметр не меняет и не конвертирует их. | `perchmode=raw perchencrypt=luks`<br>`perchmode=dynfilefs perchencrypt=luks`<br>`perchmode=dynblk perchencrypt=luks` |
| `perchcomp` | Только при создании | Выбирает сжатие для бэкенда DynBlk при создании новой сессии DynBlk: `none`, `lz4`, `lz4hc`, `lzo`, `lzo-rle`, `zstd`, `deflate`, или `842`. Выбранный кодек ядра должен быть доступен. Если `perchencrypt=luks` оборачивает DynBlk, MiniOS принудительно устанавливает сжатие DynBlk в `none`. | `perchmode=dynblk perchcomp=lz4`<br>`perchmode=dynblk perchcomp=zstd` |
| `perch` | Каждая загрузка | Включает устаревший путь возобновления постоянства. В отличие от `perchdir=resume`, он не создаёт автоматически совместимую замену, если не найдено подходящей сессии по умолчанию. | `perch` |
| `toram` | Каждая загрузка | Голый `toram` — это `full`. При постоянстве верхнего уровня копия full `*` не включает скрытые файлы; без постоянства не включает `changes`, но копирует другие элементы верхнего уровня, включая скрытые файлы. Trim копирует необходимые `config.conf` и обычные файлы `authorized_keys`, выбранные модули верхнего уровня и рекурсивно, а также полное дерево `changes/` при запросе постоянства; не включает `boot/`, `kernels/`, `rootcopy/`, `config.conf.d/`, журналы, другие данные вне модулей и отдельный слой модуля постоянства. Ни один режим не проверяет вместимость RAM заранее. Хранилище постоянства, скопированное в RAM, не является долговечным, и изменения не копируются обратно. Извлекайте носитель только после того, как убедитесь, что исходный диск, loop-устройства и маппинги успешно отсоединены. | `toram`<br>`toram=trim`<br>`toram=full` |
| `text` | Каждая загрузка | Запускается в текстовом консольном режиме. | `text` |
| `automount` | Каждая загрузка | Включает автоматическое монтирование устройств хранения. | `automount` |
| `debug` | Каждая загрузка | Включает дополнительную диагностику при запуске. | `debug` |
| `nozram` | Каждая загрузка | Отключает swap на zram. | `nozram` |
| `zramsize` | Каждая загрузка | Устанавливает размер swap на zram в MiB. Если не задано, MiniOS рассчитывает его исходя из общего RAM. | `zramsize=512`<br>`zramsize=2048` |
| `zramcomp` | Каждая загрузка | Выбирает `lzo`, `lzo-rle`, `lz4`, `lz4hc`, или `zstd`; доступность зависит от используемого ядра. Если не указано, сохраняется значение по умолчанию ядра. | `zramcomp=lzo`<br>`zramcomp=lz4` |
| `default-target` | Каждая загрузка | Устанавливает целевой systemd по умолчанию. | `default-target=multi-user`<br>`default-target=rescue` |

| `disable-services` | Каждая загрузка | Отключает указанные сервисы systemd при загрузке. | `disable-services=apache2`<br>`disable-services=nginx` |

## Вопросы безопасности

Командная строка ядра хранится в открытом виде и обычно видна в конфигурации загрузчика, `/proc/cmdline`, а также в диагностике. Не размещайте повторно используемые секретные данные в `root-password=` или `user-password=`. Предпочитайте соответствующие `*-crypted` параметры, но даже хэши паролей, оказавшиеся в открытом доступе, следует считать конфиденциальными.

Хуки выполняются с привилегиями загрузочного кода. `http://`-хук не использует шифрование транспорта и не аутентифицирует сервер, поэтому любой, кто может изменить сетевой маршрут, способен его подменить. Используйте только доверенные механизмы доставки и содержимое; не применяйте неаутентифицированные HTTP-хуки для запуска, где важна безопасность.

Команды разделяйте пробелами. Дополнительные параметры ядра, общие для всех дистрибутивов Linux, смотрите в `man bootparam`справочных страницах.

Подробную информацию о параметрах live-config см. в разделе [live-config](/reference/configuration/live-config).

Для загрузки MiniOS по сети (PXE и HTTP ISO) см. [Загрузка по сети](/reference/boot-process/Network-Boot).
