# Параметры загрузки

## Как использовать параметры загрузки

Параметры загрузки позволяют настроить запуск MiniOS. Разделяйте параметры пробелами в командной строке ядра.

### Syslinux

- Нажмите <kbd>Esc</kbd> во время загрузки MiniOS, чтобы открыть меню загрузки.
- Нажмите <kbd>Tab</kbd> для редактирования параметров загрузки.
- Введите параметры и нажмите <kbd>Enter</kbd> для запуска.

### GRUB

- Нажмите <kbd>E</kbd> в меню GRUB.
- Отредактируйте параметры загрузки в конце командной строки.
- Нажмите <kbd>F10</kbd> для загрузки с новыми настройками.

## Параметры загрузки

В столбце «Применение» указано, какие параметры обычно используются при каждой загрузке, а какие — только при первоначальной настройке аккаунта. При использовании постоянного хранения компоненты live-config обычно запускаются только один раз; подробнее см. [live-config](/reference/configuration/live-config).

Эта таблица служит для быстрой справки. Приоритет источников и допустимые `from=` формы определены в [Обнаружение системы в initrd](/reference/boot-process/System-Discovery), фильтрация модулей — в [Загрузка модулей initrd](/reference/boot-process/Module-Loading), выбор постоянного хранения — в [Постоянное хранение initrd](/reference/boot-process/Persistence-Internals), а поддерживаемые комбинации — в [Режимы загрузки](/using-minios/Boot-Modes).

| Параметр | Применение | Описание | Пример |
|---|---|---|---|
| `from` | Каждая загрузка | Загружает данные MiniOS из каталога, поддерживаемого устройства или ISO-образа. Форматы устройств UUID, PARTUUID и by-id не анализируются. Буквальный **`http://` только** URL имеет приоритет над `ip=` и инициирует [сетевую загрузку](/reference/boot-process/Network-Boot) через httpfs2. | `from=/minios/`<br>`from=/Downloads/minios.iso`<br>`from=http://domain.com/minios.iso`<br>`from=/dev/sr0/minios`<br>`from=/dev/disk/by-label/MyFlash/minios`<br>`from=askdisk`<br>`from=askdisk:customdir` |
| `load` | Каждая загрузка | Оставляет только те кандидаты, путь которых соответствует нефиксированному расширенному регулярному выражению; запятые трактуются как альтернатива, а целый возрастающий числовой диапазон имеет специальное расширение. Также фильтрует `.sb`. Это может исключить основные или ядровые модули и сделать систему незагружаемой.`toram=trim` | `load=00-core`<br>`load=core,kernel,firmware`<br>`load=00,01,02`<br>`load=00-03` |
| `noload` | Каждая загрузка | Исключает кандидатов, путь которых соответствует нефиксированному расширенному регулярному выражению, в том числе из `toram=trim`; применяется после `load` и может исключать основные или ядровые модули. | `noload=05-xfce-apps`<br>`noload=xfce-apps,firefox`<br>`noload=05,06`<br>`noload=04-06` |
| `bext` | Каждая загрузка | Устанавливает расширение для бандла. По умолчанию: `sb`. Для координации с ядром по-прежнему используются буквальные имена `.sb`, поэтому пользовательское расширение не может координировать модуль `01-kernel`. | `bext=mymod` |
| `timing` | Каждая загрузка | Включает вывод времени запуска. | `timing` |
| `union` | Каждая загрузка | Выбирает union-файловую систему. | `union=aufs`<br>`union=overlayfs` |
| `ip` | Каждая загрузка | Статический адрес для ранней загрузки по сети. Формат: `<client-ip>:<server-ip>:<gateway-ip>:<netmask>[:<port>]` (по умолчанию порт PXE HTTP **7529**). Явное значение `from=http://...` имеет приоритет над `ip=` и использует его поля адресации; иначе любое непустое значение `ip=` принудительно загружает данные PXE и пропускает локальные носители. Это не сессия конфигурации NetworkManager. Подробнее см. [Загрузка по сети](/reference/boot-process/Network-Boot). | `ip=192.168.1.10:192.168.1.1:192.168.1.1:255.255.255.0` |
| `cache` | Каждая загрузка | Размер кэша httpfs в MiB для сетевой загрузки ISO по HTTP (`from=http://…`). Подробнее см. [Загрузка по сети](/reference/boot-process/Network-Boot). | `cache=512` |
| `rd.break` | Каждая загрузка | Открывает отладочную оболочку в конце этапа initramfs. | `rd.break` |
| `perchdir` | Каждая загрузка | Выбирает пронумерованную сессию постоянства или действие: `resume`, `new`, или `ask`. Несуществующий числовой селектор может использовать значение по умолчанию из метаданных; он не резервирует и не создает этот номер. Устройство/путь или `askdisk` форма выбирает другое место для постоянства. Для указания пользовательского пути используйте суффикс через двоеточие. Без параметра постоянства MiniOS запускается с чистого состояния. | `perchdir=1`<br>`perchdir=resume`<br>`perchdir=new`<br>`perchdir=ask`<br>`perchdir=/dev/sda1/changes`<br>`perchdir=/dev/disk/by-label/MyFlash/changes`<br>`perchdir=askdisk`<br>`perchdir=askdisk:customdir` |
| `perchsize` | Каждая загрузка | Логический размер контейнера для `dynfilefs`, `dynblk`, `vmdk` и `raw`; не применяется к `native` или `squashfs`. Простое число или `M`/`MB` значение выделяется в MiB; `G`/`GB` и `T`/`TB` преобразуются в 1000 и 1 000 000 MiB соответственно. Без явного размера контейнеры, созданные initrd (DynFileFS, DynBlk) и VMDK-сессии используют до 16 ГиБ и уменьшают этот предел, если после `perchreserve` остается меньше свободного места; DynFileFS дополнительно учитывает свой индекс и лимит RAM. DynBlk запрашивает установленный лимит бэкенда через `dynblk limits --format dynblk` (или `--format vmdk` для VMDK); отдельного лимита в 512 ГиБ нет. Данные payload DynFileFS и backing DynBlk растут по мере необходимости, а DynFileFS также резервирует индексы под объявленную логическую ёмкость. Запросы Raw ограничены 1 000 000 MiB и доступным пространством после `perchreserve`; Raw ограничен 4000 MiB на FAT32 независимо от шифрования. Новые raw-контейнеры по умолчанию 4000 MiB. Менеджер сессий MiniOS также по умолчанию создает вручную DynFileFS контейнеры размером 4000 MiB и DynBlk/VMDK — 16 ГиБ. Подробнее см. [Постоянство initrd](/reference/boot-process/Persistence-Internals) для поведения памяти и хранилища бэкенда. | `perchsize=4000`<br>`perchsize=32GB`<br>`perchsize=512GB` |
| `perchreserve` | Каждую загрузку | Порог предупреждения о нехватке места и запас по выделению в МиБ. Вычитается при расчёте размера новых или увеличивающихся контейнеров, но не является квотой в реальном времени и не препятствует последующей записи до полного заполнения устройства. По умолчанию: 256; максимум: 4096. | `perchreserve=512`<br>`perchreserve=1024` |
| `perchmode` | Каждую загрузку | Режим хранения данных.<br>`native` (по умолчанию): каталог на доступной для записи файловой системе POSIX.<br>`dynfilefs`: расширяемый контейнер формата-400 на базе FUSE, включая FAT32, NTFS или exFAT.<br>`dynblk`: отдельное блочное устройство ядра формата-1 на базе thin `volumeNNN.db` файлов; фактическое количество `/dev/dynblkN` выделяется динамически, и несколько томов могут сосуществовать.<br>`vmdk`: стандартные разделённые разрежённые `volume.vmdk` / `volume-sNNN.vmdk` файлы, предоставляемые драйвером DynBlk; без сжатия. Требуется версия `vmdk-session-v1` initrd.<br>`raw`: образ ext4 фиксированного размера.<br>`squashfs`: сжатый снимок, распаковываемый в верхний слой на базе RAM. При настройке через initrd создаются только метаданные нулевого поколения; работающая система создаёт первый снимок по требованию или при завершении работы. | `perchmode=native`<br>`perchmode=dynfilefs`<br>`perchmode=dynblk`<br>`perchmode=vmdk`<br>`perchmode=raw`<br>`perchmode=squashfs` |
| `perchencrypt` | Только при создании | Необязательный слой шифрования для вновь созданной `raw`, `dynfilefs`, `dynblk`, или `vmdk` сессии. `perchencrypt=luks` требует версию `luks-layer-v1` initramfs. Для существующих сессий шифрование определяется только через `session_encryption[N]`, поэтому этот параметр не переопределяет и не конвертирует их. | `perchmode=raw perchencrypt=luks`<br>`perchmode=dynfilefs perchencrypt=luks`<br>`perchmode=dynblk perchencrypt=luks` |
| `perchcomp` | Только при создании | Выбирает сжатие бэкенда DynBlk для вновь создаваемой сессии DynBlk: `none`, `lz4`, `lz4hc`, `lzo`, `lzo-rle`, `zstd`, `deflate`, или `842`. Выбранный кодек ядра должен быть доступен. Если `perchencrypt=luks` оборачивает DynBlk, MiniOS принудительно устанавливает сжатие DynBlk на `none`. VMDK не поддерживает сжатие: при загрузке игнорируется несоответствующий `none` кодек с предупреждением. | `perchmode=dynblk perchcomp=lz4`<br>`perchmode=dynblk perchcomp=zstd` |
| `perch` | Каждую загрузку | Включает устаревший путь восстановления постоянства. В отличие от `perchdir=resume`, не создаёт автоматически совместимую замену, если не найдено подходящей сессии по умолчанию. | `perch` |
| `toram` | Каждая загрузка | Чистый `toram` — это `full`. При включённой персистентности копия режима full на верхнем уровне `*` не включает скрытые файлы (dotfiles); без персистентности не включает `changes`, но копирует остальные элементы верхнего уровня, включая скрытые файлы. Trim копирует только необходимые `config.conf`, обычные файлы `authorized_keys`, выбранные верхнеуровневые и рекурсивные модули, а также полностью `changes/` дерево при запросе персистентности; не включает `boot/`, `kernels/`, `rootcopy/`, `config.conf.d/`, логи, другие данные вне модулей и отдельный уровень модуля персистентности. Ни один из режимов не проверяет вместимость RAM заранее. Хранилище персистентности, скопированное на RAM, не является надёжным, и изменения не копируются обратно. Извлекайте носитель только после того, как убедитесь, что исходник, loop-устройства и маппинги успешно отсоединены. | `toram`<br>`toram=trim`<br>`toram=full` |
| `text` | Каждая загрузка | Запускается в текстовом консольном режиме. | `text` |

| `zramsize` | Каждая загрузка | Устанавливает размер swap на zram в MiB. Если не указано, MiniOS рассчитывает его исходя из общего объёма RAM. | `zramsize=512`<br>`zramsize=2048` |
| `zramcomp` | Каждая загрузка | Выбирает `lzo`, `lzo-rle`, `lz4`, `lz4hc`, или `zstd`; доступность зависит от текущего ядра. Если не указано, сохраняется значение по умолчанию ядра. | `zramcomp=lzo`<br>`zramcomp=lz4` |

## Вопросы безопасности

Командная строка ядра хранится в открытом виде и обычно видна в конфигурации загрузчика, `/proc/cmdline`, а также в диагностике. Не размещайте повторно используемые секретные данные в `root-password=` или `user-password=`. Предпочитайте соответствующие `*-crypted` параметры, но даже хэши паролей, оказавшиеся в открытом доступе, следует считать конфиденциальными.

Хуки выполняются с привилегиями загрузочного кода. `http://`-хук не использует шифрование транспорта и не аутентифицирует сервер, поэтому любой, кто может изменить сетевой маршрут, способен его подменить. Используйте только доверенные механизмы доставки и содержимое; не применяйте неаутентифицированные HTTP-хуки для запуска, где важна безопасность.

Команды разделяйте пробелами. Дополнительные параметры ядра, общие для всех дистрибутивов Linux, смотрите в `man bootparam`справочных страницах.

Подробную информацию о параметрах live-config см. в разделе [live-config](/reference/configuration/live-config).

Для загрузки MiniOS по сети (PXE и HTTP ISO) см. [Загрузка по сети](/reference/boot-process/Network-Boot).
