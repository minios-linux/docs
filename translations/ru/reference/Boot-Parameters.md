# Параметры загрузки

## Как использовать параметры загрузки

Параметры загрузки позволяют настроить запуск MiniOS. Разделяйте параметры пробелами в командной строке ядра.

### Syslinux

- Нажмите <kbd>Esc</kbd> во время загрузки MiniOS, чтобы открыть меню загрузки.
- Нажмите <kbd>Tab</kbd> для редактирования параметров загрузки.
- Введите параметры и нажмите <kbd>Enter</kbd> для загрузки.

### GRUB

- Нажмите <kbd>E</kbd> в меню GRUB.
- Отредактируйте параметры загрузки в конце командной строки.
- Нажмите <kbd>F10</kbd> для загрузки с новыми настройками.

## Параметры загрузки

Столбец «Применение» показывает, какие параметры обычно принимаются при каждой загрузке, а какие параметры учётной записи предназначены для первоначальной настройки. При включённом постоянном хранении компоненты live-config обычно запускаются только один раз; см. [live-config](/reference/configuration/live-config).

Эта таблица служит кратким справочником. Приоритет источников и допустимые `from=` варианты описаны в [Обнаружение системы в initrd](/reference/boot-process/System-Discovery), фильтрация модулей — в разделе [Загрузка модулей в initrd](/reference/boot-process/Module-Loading), выбор постоянного хранилища — в разделе [Постоянное хранилище в initrd](/reference/boot-process/Persistence-Internals), а поддерживаемые сочетания — в разделе [Режимы загрузки](/using-minios/Boot-Modes).

| `perchsize` | При каждой загрузке | Логический размер контейнера для `dynfilefs`, `dynblk`, `vmdk` и `raw`; не применяется к `native` или `squashfs`. Число без единицы измерения или значение `M`/`MB` выделяется в МиБ; значения `G`/`GB` и `T`/`TB` преобразуются в 1000 и 1 000 000 МиБ. Если размер не задан, для созданных в initrd сеансов DynFileFS, DynBlk и VMDK используется до 16 ГиБ; значение по умолчанию уменьшается, если после `perchreserve` остаётся меньше свободного места. Ограничения ёмкости типа хранилища также учитываются. DynBlk запрашивает установленный предел типа хранилища с помощью `dynblk limits --format dynblk` (или `--format vmdk` для VMDK); отдельного ограничения в 512 ГиБ нет. DynFileFS и DynBlk выделяют место для данных по мере необходимости. Запрошенный размер Raw ограничен 1 000 000 МиБ и доступным местом после `perchreserve`; для Raw на FAT32 действует ограничение 4000 МиБ независимо от шифрования. Размер новых контейнеров Raw по умолчанию — 4000 МиБ. Менеджер сессий MiniOS задаёт размер 4000 МиБ для созданных вручную контейнеров DynFileFS и 16 ГиБ для DynBlk/VMDK. | `perchmode` | При каждой загрузке | Режим хранения постоянных данных.<br>`native` (по умолчанию): каталог в доступной для записи файловой системе POSIX.<br>`dynfilefs`: расширяемый контейнер FUSE формата 600, в том числе на FAT32, NTFS или exFAT.<br>`dynblk`: отдельное блочное устройство ядра формата 1 на основе разреженных `volumeNNN.db`-файлов; фактический номер `/dev/dynblkN` назначается динамически, поэтому могут одновременно существовать несколько томов.<br>`vmdk`: стандартные разделённые разреженные файлы `volume.vmdk` / `volume-sNNN.vmdk` доступны через драйвер DynBlk; сжатие не используется. Требуется версия initrd с поддержкой `vmdk-session-v1`.<br>`raw`: образ ext4 фиксированного размера.<br>`squashfs`: сжатый снимок, распаковываемый в верхний слой на основе RAM. | `perchencrypt` | Только при создании | Необязательный уровень шифрования для нового сеанса `raw`, `dynfilefs`, `dynblk` или `vmdk` . `perchencrypt=luks` требуется версия initramfs с поддержкой `luks-layer-v1`. Этот запасной вариант не меняет режим хранения существующего сеанса. Если выбран тип хранилища Persistence Plugin Ventoy, запрос постоянного хранения использует этот единственный образ ext4 вместо нумерованных сеансов; варианты сеансов `perchdir` игнорируются. См. раздел [Внутреннее устройство постоянного хранения](/reference/boot-process/Persistence-Internals).

При обычном монтировании текущий вспомогательный компонент DynFileFS автоматически преобразует форматы 400 или 500 в формат 600 на месте, если размер устаревшего разделения — чётное число МиБ. При нечётном размере разделения в МиБ преобразование отменяется без изменений. Ни один параметр загрузки не выбирает старые форматы и не включает преобразование.

## Вопросы безопасности

Командная строка ядра хранится в открытом виде и обычно видна в настройках загрузчика, `/proc/cmdline`, а также в диагностике. Не размещайте повторно используемые секреты в `root-password=` или `user-password=`. Используйте соответствующие параметры `*-crypted`, но даже хэши паролей, отображаемые в явном виде, нужно считать чувствительными.

Хуки выполняются с привилегиями загрузочного кода. `http://` хук не использует шифрование транспорта и не проверяет сервер, поэтому любой, кто может изменить сетевой путь, может его подменить. Используйте только доверенные источники и способы доставки; не применяйте неаутентифицированные HTTP-хуки для запуска, где важна безопасность.

Команды разделяются пробелами. См. `man bootparam` справочные страницы для других параметров ядра, общих для всех дистрибутивов Linux.

Подробную информацию о параметрах live-config см. в [live-config](/reference/configuration/live-config).

Для загрузки MiniOS по сети (PXE и HTTP ISO) см. [Сетевая загрузка](/reference/boot-process/Network-Boot).

## Параметры кэша и журнала для постоянных сессий

| Параметр | Применение | Описание | Пример |
|---|---|---|---|
| `log-storage` или `live-config.log-storage` | Каждая загрузка с проверенной постоянностью | `persistent` (по умолчанию) или `volatile`. В режиме volatile journald использует до 32 МБ, а обычный `/var/log` использует tmpfs размером 32 МБ. Диагностика загрузки хранится отдельно; при долговременной постоянности она остается на накопителе. Переполнение файловой системы журнала RAM не приводит к записи на USB-устройство. | `log-storage=volatile` |
| `apt-cache` или `live-config.apt-cache` | Каждая загрузка с проверенной постоянностью | `persistent` (по умолчанию) или `volatile` для `/var/cache/apt/archives`. Размер tmpfs составляет 256 МБ при наличии не менее 1 ГБ, либо 512 МБ при наличии не менее 2 ГБ. Использование swap без zRAM отключает tmpfs; большие загрузки могут исчерпать его. Списки репозиториев и состояние dpkg сохраняются в слое сессии. | `apt-cache=volatile` |
| `browser-cache` или `live-config.browser-cache` | Каждая загрузка с проверенной постоянностью | `persistent` (по умолчанию) или `volatile`. При наличии не менее 1 ГБ и отсутствии swap без zRAM стандартные каталоги кэша браузера live-пользователя используют общий tmpfs 512 МБ. Управляемая политика Firefox отключает кэширование на диск, если нет других файлов политики. Профили и не связанные с этим кэши остаются в слое сессии. | `browser-cache=volatile` |

Три параметра политики хранения анализируются `minios-boot` до запуска основной системы инициализации, **не** селектором ранней постоянности. Они не включают `perch`. Для работы требуется успешная активация на долговременном накопителе или в записываемой сессии RAM с защищённой `ram-origin` информацией; они не делают изменения RAM постоянными без сохранения. Совместимый initrd сообщает о `perch-storage-v1` по адресу `/run/initramfs/etc/minios-initramfs-storage`. Конфигуратор и `config.conf` предоставляют те же варианты; см. [Производительность](/maintenance-and-recovery/Performance#reduce-cache-and-log-writes-with-perch) для информации о лимитах, приоритетах и особенностях установки браузера.
