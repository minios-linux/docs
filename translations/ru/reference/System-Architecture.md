# Архитектура системы

MiniOS запускает операционную систему только для чтения, собранную из модулей SquashFS, и добавляет одну записываемую прослойку для текущей сессии. Initramfs отвечает за поиск носителя, выбор модулей и способа сохранения изменений, формирование корневой файловой системы, применение ранней конфигурации и передачу управления установленной системе инициализации.

## Обнаружение загрузки

Загрузчик BIOS или UEFI загружает ядро Linux и initramfs MiniOS из `minios/boot/`. Затем initramfs находит дерево данных MiniOS, содержащее live-модули. Источник может быть локальным, выбранным вручную или предоставленным по поддерживаемому сетевому пути; локальный ISO-файл монтируется через loop перед использованием его дерева данных. Точный приоритет и допустимые `from=` форматы описаны в [Обнаружение системы в initrd](/reference/boot-process/System-Discovery).

На этом же этапе обнаружения поддерживаются источники HTTP ISO и PXE. Дополнительная сетевая инициализация на раннем этапе загрузки предназначена только для **загрузки MiniOS по сети** (PXE / HTTP ISO). Это не постоянная сетевая конфигурация для сессии. Подробнее см. в разделе [Сетевая загрузка](/reference/boot-process/Network-Boot).

После обнаружения MiniOS может при необходимости подготовить копию RAM. Необходимость в исходном источнике зависит от режима копирования, наличия сохранения и успешного отсоединения. Подробнее см. в разделе [Режимы загрузки](/using-minios/Boot-Modes) для описания работы.

## Состав модулей

Каждый `.sb` файл представляет собой файловую систему SquashFS только для чтения. Встроенные модули размещаются непосредственно в `minios/`; дополнительные каталоги модулей могут участвовать в формировании итогового порядка. Initramfs выбирает, упорядочивает и монтирует итоговые слои только для чтения. Кандидатные уровни, замена базовых имён, фильтры, пользовательские расширения пакетов и согласование с работающим ядром описаны в разделе [Загрузка модулей initrd](/reference/boot-process/Module-Loading).

Типичный образ с Xfce содержит следующие роли в определённом порядке, однако точные имена и количество зависят от сборки и модулей, исключённых для данной цели:

```text
00-core-<arch>.sb
01-kernel-<version>-<arch>.sb
02-firmware-<arch>.sb
03-gui-base-<arch>.sb
04-xfce-desktop-<arch>.sb
05-apps-<arch>.sb or the next applicable module
```

Поздние модули имеют больший приоритет и могут заменять пути, предоставленные более ранними модулями. Модуль может зависеть от файлов в каждом модуле с меньшим номером, поэтому набор файлов модулей — это упорядоченная композиция, а не просто набор независимых пакетов.

## AUFS и OverlayFS

MiniOS использует union-файловую систему для объединения модулей и записываемого слоя в единый корневой раздел. При поддержке работающим ядром выбирается AUFS, иначе используется OverlayFS. `union=aufs` запрашивает AUFS, но при отсутствии AUFS всё равно переключается на OverlayFS; `union=overlayfs` выбирает OverlayFS.

У этих двух реализаций есть важное отличие в работе:

- AUFS начинает с записываемой ветки и добавляет смонтированные модули как ветки только для чтения. MiniOS может активировать или деактивировать модуль в работающем корне, если монтирование AUFS поддерживает такую операцию.
- OverlayFS получает полный упорядоченный список `lowerdir` при монтировании корня, а также `upperdir` и `workdir`. Набор нижележащих модулей нельзя изменить на лету через **Менеджер модулей MiniOS**.

**Менеджер модулей MiniOS** таким образом разделяет **Текущий запуск**, набор смонтированных модулей, и **Следующая загрузка**, модули, выбранные текущим носителем и правилами загрузки. Добавление или удаление постоянного модуля обычно влияет только на следующую загрузку. Создание или открытие модуля не активирует его. Активация и деактивация в реальном времени доступны только с AUFS.

После сборки корня и завершения ранней инициализации initrd LiveKit использует `pivot_root`, оставляет старый initrd для завершения работы при выключении и запускает init нового корня. В случае dracut итоговый корень подготавливается так же, но финальный `switch_root` этап выполняет dracut. Подробнее см. в разделе [Загрузка модулей initrd](/reference/boot-process/Module-Loading) для описания границы передачи управления.

## Записываемый слой и сессии

Без сохранения изменений записываемый слой размещается в памяти и исчезает при выключении. Вместо этого можно активировать пронумерованную сессию с поддерживаемым хранилищем. Выбор, совместимость, ошибки активации, права текущей загрузки и долговечность описаны в разделе [Сохранение в initrd](/reference/boot-process/Persistence-Internals).

| Режим | Записываемое хранилище | Примечания |
|------|------------------|-------|
| `native` | Файлы сохраняются непосредственно в каталоге сессии | Требуется файловая система POSIX с поддержкой записи и сохранением метаданных Linux. |
| `dynfilefs` | Расширяемая файловая система ext4, разбитая на резервные файлы | Поддерживаются файловые системы POSIX, а также носители FAT32, NTFS или exFAT. |
| `raw` | Фиксированный размер `changes.img` с ext4 | Поддерживаются файловые системы POSIX, а также носители FAT32, NTFS или exFAT. |
| `luks` | LUKS2 `changes.luks` с ext4 | Требуется cryptsetup и initramfs с поддержкой шифрования MiniOS. Пароль запрашивается при загрузке. |
| `squashfs` | Сжатый `changes.sb` снимок | Распаковывается в RAM для использования; при сохранении снимок пересобирается и заменяется атомарно. Файловая система для сохранения должна поддерживать метаданные Linux при сохранении. |

Активная сессия, выбранная для будущего возобновления, и реально разрешённый для текущей загрузки записываемый слой — это связанные, но разные состояния. Изменение будущего выбора не заменяет работающий записываемый слой.

Подробнее см. в разделе [Управление сессиями](/using-minios/Sessions-and-Persistence) — создание, выбор, изменение размера, шифрование, преобразование, экспорт и восстановление.

## Приоритет конфигурации

Конфигурация носителя задаётся в `minios/config.conf`, с дополнительными фрагментами в `minios/config.conf.d/`; копии для работы системы размещаются в `/etc/live/config.conf` и `/etc/live/config.conf.d/` в собранном корне.

При загрузке MiniOS сравнивает время изменения файлов и копирует более свежий файл с носителя в рабочий корень. Если носитель поддерживает запись и копия в рабочем корне новее, она возвращается на носитель. Фрагменты синхронизируются по имени файла в обе стороны. Если время на системе откатилось назад после предыдущей синхронизации, MiniOS избегает замены временных меток и только дополняет отсутствующие файлы.

Параметры ядра в командной строке имеют приоритет над соответствующими значениями из рабочей конфигурации для данной загрузки. Таким образом, итоговый порядок для явно поддерживаемой настройки: параметр загрузки, затем синхронизированная рабочая/медийная конфигурация, затем встроенное значение по умолчанию. Постоянные изменения в рабочей конфигурации могут стать конфигурацией носителя, если источник поддерживает запись; носители ISO только для чтения не могут быть обновлены.

Подробнее см. в разделе [Файл конфигурации](/reference/configuration/config.conf) и [live-config](/reference/configuration/live-config) для поддерживаемых настроек.

## Завершение работы и жизненный цикл сохранения

При штатном завершении работы система получает возможность записать данные служб и сессии. Сессия SquashFS с включённым сохранением при завершении пересобирается и проверяется перед размонтированием файловой системы. Бэкенд сохранения записывает маркер завершения именно для текущей сессии; initramfs завершения проверяет этот маркер и помечает сессию как грязную, если сохранение не удалось.

Далее initramfs завершения отсоединяет неиспользуемые loop-устройства, размонтирует старый корень и записываемый слой, отмечает успешную сессию как чистую, размонтирует носитель и закрывает LUKS-мэппинг, принадлежащий MiniOS. После этого оптический носитель можно извлечь перед выключением или перезагрузкой. Ручное и периодическое сохранение SquashFS используют тот же механизм снимков, но только выбранная политика завершения работы блокирует чистое завершение при отсутствии сохранения на этапе выключения.

## Дерево медиафайлов

Текущая структура изображений организована следующим образом. Необязательные каталоги появляются только тогда, когда соответствующая функция создала содержимое.

```text
/
|-- .disk/                         ISO metadata
|-- EFI/                           UEFI boot files
`-- minios/
    |-- 00-core-<arch>.sb          base userspace
    |-- 01-kernel-<version>-<arch>.sb
    |-- 02-firmware-<arch>.sb
    |-- NN-<name>-<arch>.sb        ordered system modules
    |-- boot/                      kernels, initramfs, GRUB, and Syslinux data
    |-- changes/                   session metadata and numbered sessions
    |-- modules/                   additional next-boot modules
    |-- config.conf                main media configuration
    |-- config.conf.d/             optional configuration fragments
    |-- kernels/                   optional inactive kernel repository
    |-- userdata/                  optional linked or bound user directories
    `-- log/                       optional exported boot logs
```

Смонтированные пути под `/run/initramfs/memory/` являются точками монтирования реализации, а не второй постоянной копией этого дерева.
