# CondinAPT

CondinAPT выбирает и устанавливает пакеты APT из списка, элементы которого могут зависеть от переменных конфигурации Bash. MiniOS использует его для проверки требований хоста, основного набора пакетов и обычных модулей SquashFS.

На этой странице описана реализация в `linux-live/condinapt`. CondinAPT не является универсальным решателем зависимостей: сначала он оценивает фильтры и доступность репозиториев, затем формирует очереди APT и устанавливает каждую выбранную очередь одним вызовом `apt-get`.

## Синопсис

```bash
sudo bash linux-live/condinapt \
  -l packages.list \
  -c system.conf \
  -m filters.map
```

Список пакетов и конфигурационный файл должны быть обычными читаемыми файлами. Файлы сопоставления и приоритетов являются необязательными.

| Опция | Значение |
| --- | --- |
| `-l`, `--package-list PATH` | Файл со списком пакетов |
| `-c`, `--config PATH` | Доверенная конфигурация Bash |
| `-m`, `--filter-mapping PATH` | Сопоставление префикса с переменной |
| `-P`, `--priority-list PATH` | Bash-выражения для извлечения приоритета |
| `-s`, `--simulation` | Выбрать и показать пакеты без установки |
| `-C`, `--check-only` | Проверить установленные имена пакетов без установки |
| `-v`, `--verbose` | Диагностика фильтрации и очередей |
| `-vv`, `--very-verbose` | Дополнительная диагностика приоритетных очередей |
| `-x`, `--xtrace` | Включить трассировку shell |
| `-f`, `--force` | Запустить `apt-get update` даже если существует `pkgcache.bin` |
| `-h`, `--help` | Показать справку |

CondinAPT запускает `apt-get update`, если не выбран режим только проверки и либо был использован `-f`, либо не существует `/var/cache/apt/pkgcache.bin`. Это включает симуляцию, поэтому `-s` не является «сухим» прогоном без побочных эффектов.

Для обычной установки требуется root. Режим только проверки можно запускать без привилегий; для симуляции root также необходим, если инициируется обновление APT. Текущая реализация не всегда корректно передаёт сбой `apt-get update`, поэтому ошибку обновления следует считать неудачным запуском, даже если CondinAPT затем возвращает `0`.

## Входные файлы

### Конфигурация

Файл `-c` подключается через Bash. Это исполняемый код, а не статический формат данных, поэтому используйте только доверенные файлы.

```bash
DISTRIBUTION="bookworm"
SYSTEM_TYPE="server"
FEATURES=(web database monitoring)
```

Индексированные массивы предоставляют фильтры по членству. Скаляра с запятыми остаётся одной строкой: `FEATURES="web,database"` не совпадает с `+feat=web`.

Текущая реализация разбирает параметры командной строки до подключения этого файла.
Конфигурационные переменные, использующие внутренние имена CondinAPT, такие как `VERBOSITY_LEVEL`, могут переопределять состояние CLI. Избегайте таких имён в универсальных конфигурациях.

### Сопоставление фильтров

Необязательный файл `-m` сопоставляет короткие префиксы с именами переменных Bash:

```text
d=DISTRIBUTION
st=SYSTEM_TYPE
feat=FEATURES
```

Формат строго соответствует `prefix=VariableName`; окружающие пробелы не обрезаются. Пустые строки и строки, где первое поле начинается с `#`, игнорируются.
Дубликаты префиксов используют последнее значение.

Если сопоставление отсутствует, сам префикс используется как имя переменной. Неустановленный скаляр ведёт себя как пустая строка. Ошибочно написанный отрицательный фильтр может незаметно включить пакет, поэтому рекомендуется использовать сопоставление и подробную симуляцию при добавлении фильтров.

### Список пакетов

Безопасная грамматика строки:

```text
[!] package[=version|==version] filters... [&& ...] [|| ...] [@release] [# comment]
```

Примеры:

```text
curl
firefox-esr +dp=debian
firefox +dp=ubuntu
tool -pv=minimum
exfatprogs -pv=minimum || exfat-utils -pv=minimum && exfat-fuse -pv=minimum
!required-package
package=preferred-version
package==strict-version
systemd-timesyncd +d=buster @buster-backports
```

Всё от первого `#` до конца строки удаляется. Оставшиеся пробелы нормализуются. Кавычки, экранирование, скобки, вложенные группы и пробелы внутри одного фильтра не поддерживаются. Неизвестные токены в конце строки не отклоняются, поэтому рассматривайте приведённую выше грамматику как ограничение, а не как разрешение на вольный разбор.

Используйте одну целевую версию на физическую строку и размещайте её в конце. CondinAPT извлекает цель до оценки альтернатив пакетов, поэтому разные значения `@release` не могут быть назначены альтернативам на одной строке.

## Фильтры

Фильтр сравнивает значение конфигурации на точное совпадение строк с учётом регистра. Если сопоставленная переменная — индексированный массив, совпадение с любым элементом массива считается успешным. Ассоциативные массивы не являются множествами для проверки членства.

| Форма | Эффект |
| --- | --- |
| `+x=value` | Включить только если совпадает `x` |
| `-x=value` | Исключить если совпадает `x` |
| `+{a|b}` | Требуется совпадение хотя бы одного элемента |
| `+{a&b}` | Требуется совпадение всех элементов |
| `-{a|b}` | Исключить если совпадает любой элемент |
| `-{a&b}` | Исключить только если совпадают все элементы |

Повторяющиеся простые положительные фильтры с одним префиксом являются альтернативами:

```text
audacity +pv=toolbox +pv=ultra
```

Положительные фильтры с разными префиксами должны пройти все. Каждый простой отрицательный фильтр — независимое вето:

```text
driver +da=amd64 -d=bookworm -d=bullseye
```

Члены группы должны использовать только один тип оператора. Не смешивайте `|` и `&` в одной группе; приоритетов и вложенности внутри групп нет. Выразите «исключить Flux или минимум Xfce» двумя фильтрами:

```text
htop -de=flux -{pv=minimum&de=xfce}
```

## Альтернативы и конъюнкции

`&&` имеет более высокий приоритет, чем `||`. CondinAPT сначала разделяет альтернативы, затем оценивает каждый элемент конъюнкции, поэтому:

```text
A || B && C
```

означает `A || (B && C)`.

CondinAPT выбирает первую альтернативу, для которой все фильтры и проверки доступности пакетов проходят успешно. Если один элемент конъюнкции не проходит, уже выбранные из этой группы пакеты откатываются, и оценивается следующая альтернатива.

Это предварительный выбор, а не повторная попытка установки или транзакция. Если последующая операция на уровне очереди `apt-get install` завершится неудачей для выбранной альтернативы, CondinAPT не возвращается к следующей ветке `||`.

Каждая альтернатива должна повторять свои фильтры:

```text
firefox-esr +dp=debian || firefox +dp=ubuntu
```

## Обязательные пакеты

`!` распознаётся только в начале полного физического выражения и применяется ко всем его альтернативам:

```text
!preferred-package || fallback-package
```

Выражение считается фатальным в обычном режиме только если ни одна альтернатива не прошла и активный пакет или строгая версия недоступны. Фильтры могут отключить обязательную строку без ошибки. Обычная ошибка установки APT прерывает очередь независимо от `!`.

В режиме симуляции ошибка доступности обязательного пакета отображается, но не останавливает обработку очереди; симуляция всё равно завершается с задокументированным ненулевым статусом.

## Версии

| Синтаксис | Поведение |
| --- | --- |
| `package=VERSION` | Предпочесть точную версию; при отсутствии — использовать любую доступную |
| `package==VERSION` | Принимать только точную версию из репозитория |

Точное совпадение определяется по полю версии из `apt-cache madison`. Если строгая версия не обязательна и недоступна, условие не выполняется; последующая альтернатива `||` может пройти, иначе строка пропускается. Добавьте в начало выражения `!`, чтобы сделать ошибку доступности активного пакета фатальной.

Когда CondinAPT устанавливает точно запрошенную версию, он назначает `apt-mark hold` после успешного завершения всей очереди APT. Уже установленная точная версия считается удовлетворяющей и не фиксируется заново. Ошибки фиксации не передаются как код возврата CondinAPT.

Для установленного пакета без версии CondinAPT сравнивает установленную версию с кандидатом из репозитория. Если кандидат отличается, пакет ставится в очередь повторно; APT вызывается с `--allow-downgrades`.

## Очереди

`---` завершает текущую обычную очередь. Каждый выбранный пакет в очереди передаётся одному неинтерактивному вызову `apt-get install` с параметрами `--force-confdef`, `--force-confold`, `--allow-downgrades` и `--no-install-suggests`.

```text
build-essential
pkg-config
---
application
```

Строки с целевым выпуском исключаются из обычного потока очередей и глобально группируются по выпуску. Строки для одного выпуска объединяются даже если их разделяет `---`.
Фактический порядок выполнения:

1. Приоритетная очередь без цели.
2. Приоритетные очереди с целевым выпуском.
3. Обычные очереди в порядке исходного списка.
4. Оставшиеся очереди с целевым выпуском в порядке первого появления.

Таким образом, строка с целью между двумя обычными строками не является барьером, а целевые очереди выполняются после всех обычных, если только не выделены как приоритетные.

Проверка доступности репозиториев на этапе предварительной проверки не учитывает цель; только финальный `apt-get install` получает `-t RELEASE`. Проверьте целевые пакеты относительно настроенных репозиториев.

## Список приоритетов

`-P` читает по одной расширенной регулярной Bash-выражении на строку. Шаблон сопоставляется с первым именем пакета в каждом выражении списка пакетов. Если совпадение есть, всё выражение, включая фильтры, альтернативы, обязательность и целевой выпуск, переносится в приоритетную очередь.

```text
^dkms$
^linux-.*
```

Шаблоны не привязаны к началу или концу строки, если не содержат якорей. Совпадение с последующим пакетом `&&` или `||` не влияет; проверяется только первый токен пакета. Извлечение приоритета также объединяет совпадения из разных обычных очередей, поэтому не используйте его для записей, где необходима исходная граница `---` для поэтапной установки зависимостей.

Приоритет означает более раннюю обработку и установку, но не гарантирует установку. Фильтры и проверки доступности всё равно применяются.

## Режимы работы и коды возврата

### Симуляция

```bash
bash linux-live/condinapt \
  -l packages.list -c system.conf -m filters.map -s -v
```

Симуляция оценивает фильтры, версии, альтернативы и очереди, затем выводит пакеты, которые будут переданы в APT. Это не гарантирует успешную последующую установку. Корректная симуляция намеренно завершает работу со статусом `1`, даже если выбор пакетов успешен.

### Только проверка

```bash
bash linux-live/condinapt \
  -l packages.list -c system.conf -m filters.map -C
```

Режим только проверки оценивает фильтры и операторы, но проверяет только, установлены ли имена пакетов через `dpkg-query`. Он не проверяет запрошенные версии, кандидатов из репозиториев или целевые выпуски. Возвращает `0`, если все активные выражения удовлетворены, и `1` в противном случае.

Выведенная команда `sudo apt install ...` — это приблизительная диагностика. Она теряет версии и целевые выпуски, может включать несколько неудачных альтернатив и не гарантирует воспроизведение исходного выражения.

### Сводка по статусу

| Случай | Статус |
| --- | --- |
| Справка | `0` |
| Успешный обычный запуск | `0` |
| Некорректный ввод, ошибка обязательной доступности или сбой очереди APT | `1` |
| Корректная симуляция | `1` |
| Только проверка с отсутствующими активными пакетами | `1` |

## Особая обработка пакетов

В реализации есть одно специальное имя пакета: `qemu-kvm`. Оно принимается, если `apt-cache show qemu-kvm` сообщает, что это чисто виртуальный пакет. Для других виртуальных пакетов универсального разрешения провайдера нет. Для переносимости рекомендуется явно указывать альтернативы провайдеров.

## Интеграция с MiniOS

### Вызов модуля

Для обычного модуля `build-modules` копирует скрипт установки в `/install`, CondinAPT в `/condinapt`, сгенерированную конфигурацию в `/minios_build.conf` и карту в `/condinapt.map`. Типовой скрипт установки:

```bash
#!/bin/bash
set -e
set -o pipefail
set -u

. /minioslib || exit 1
. /minios_build.conf || exit 1

SCRIPT_DIR="$(dirname "$(readlink -f "$0")")"
/condinapt \
  -l "${SCRIPT_DIR}/packages.list" \
  -c "${SCRIPT_DIR}/minios_build.conf" \
  -m "${SCRIPT_DIR}/condinapt.map"
```

Используйте `SCRIPT_DIR`; `$CWD` не входит в контракт обычного модуля.
`00-core` — это специальная ранняя стадия сборки и вызывает копию из исходного дерева через `/linux-live`.

Текущий сборщик обычных модулей автоматически копирует только файл с именем `packages.list`. Модули, использующие дополнительные имена файлов списков, должны явно указывать эти входные файлы; не предполагается, что каждый файл рядом с `install` окажется в корне chroot.

### Карта фильтров MiniOS

В настоящее время `linux-live/condinapt.map` определяет:

| Префикс | Переменная | Значение |
| --- | --- | --- |
| `d` | `DISTRIBUTION` | Целевой выпуск |
| `da` | `DISTRIBUTION_ARCH` | Целевая архитектура |
| `dp` | `DISTRIBUTION_PROFILE` | Семейство пакетов `debian` или `ubuntu` |
| `is` | `INIT_SYSTEM` | Выбранная система инициализации |
| `de` | `DESKTOP_ENVIRONMENT` | Окружение модуля |
| `pv` | `PACKAGE_VARIANT` | Вариант пакета |
| `ik` | `INSTALL_KERNEL` | Переключатель установки ядра |
| `kf` | `KERNEL_FLAVOUR` | Вариант ядра |
| `kp` | `KERNEL_PROVIDER` | `distribution` или `minios` |
| `ks` | `KERNEL_SERIES` | Фактическая серия ядра при выборе DKMS `01-kernel` |
| `kc` | `KERNEL_CAPABILITIES` | Обнаруженный массив возможностей при выборе DKMS `01-kernel` |
| `kbd` | `KERNEL_BUILD_DKMS` | Переключатель сборки DKMS |
| `ib` | `INITRAMFS_BUILDER` | Реализация initramfs |
| `lo` | `LOCALE` | Локаль системы |
| `ml` | `MULTILINGUAL` | Переключатель мультиязычности |
| `kl` | `KEEP_LOCALES` | Переключатель сохранения локали |

`ks` и `kc` — специальные фильтры `01-kernel`. При включённой сборке DKMS этот модуль определяет `KERNEL_SERIES` из установленного ядра и создаёт индексированный массив `KERNEL_CAPABILITIES` во временной конфигурации для выбора DKMS-пакетов. В обычных конфигурациях модулей они отсутствуют; их использование там приведёт к провалу положительных фильтров и может привести к прохождению отрицательных фильтров.
`KERNEL_SERIES` — это не предпочтение `MINIOS_KERNEL_SERIES`. В настоящее время обнаруживаемые возможности включают `aufs`, `ntfs3`, `btf_modules` и поддерживаемые встроенные драйверы `rtw88_*`.

Примеры из текущего списка пакетов ядра:

```text
pahole +kc=btf_modules || dwarves +kc=btf_modules
ntfs3-dkms -kc=ntfs3
aufs-ng-dkms +kp=distribution +ks=6.12 -da=i386 -kc=aufs
zfs-dkms +pv=toolbox +pv=ultra +da=amd64
```

## Поиск и устранение неисправностей

Используйте подробную симуляцию для анализа выбора:

```bash
tmp_list="$(mktemp)"
printf '%s\n' 'package-name +pv=standard' >"$tmp_list"
bash linux-live/condinapt \
  -l "$tmp_list" -c system.conf -m filters.map -s -vv
rm -f "$tmp_list"
```

Не используйте `/dev/stdin`; для `-l` требуется обычный файл.

- Если фильтр неожиданно проходит, проверьте точное сопоставление префикса, тип переменной, регистр и значение. Убедитесь, что переменная не пуста и не содержит опечаток.
- Если не выбирается запасной вариант, помните, что переключение происходит на этапе предварительного выбора, а не после сбоя APT на уровне очереди.
- Если не удаётся установить целевой пакет, проверьте настроенные источники и выполните `apt-cache policy PACKAGE`; предварительная проверка не применяет `-t RELEASE`.
- Если строгая версия пропущена, сравните точное поле версии с `apt-cache madison PACKAGE`.
- Если порядок очередей неожидан, учитывайте глобальное группирование по целям и извлечение приоритета до обычных очередей.

Для более широкой сборки см. [Сборка MiniOS](/development/Building-MiniOS).
