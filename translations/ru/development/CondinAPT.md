# CondinAPT

CondinAPT выбирает и устанавливает пакеты APT из списка, элементы которого могут зависеть от переменных конфигурации Bash. MiniOS использует его для проверки требований хоста, основного набора пакетов и обычных модулей SquashFS.

На этой странице описана реализация в `linux-live/condinapt`. CondinAPT не является универсальным решателем зависимостей: сначала он оценивает фильтры и доступность репозиториев, формирует очереди APT, а затем устанавливает каждую выбранную очередь за один `apt-get` вызов.

## Синопсис

```bash
sudo bash linux-live/condinapt \
  -l packages.list \
  -c system.conf \
  -m filters.map
```

Файл списка пакетов и конфигурационный файл должны быть обычными, читаемыми файлами. Файлы сопоставления и приоритетов — опциональны.

| Опция | Назначение |
| --- | --- |
| `-l`, `--package-list PATH` | Файл списка пакетов |
| `-c`, `--config PATH` | Доверенная конфигурация Bash |
| `-m`, `--filter-mapping PATH` | Сопоставление префикса с переменной |
| `-P`, `--priority-list PATH` | Регулярные выражения Bash для извлечения приоритета |
| `-s`, `--simulation` | Выбрать и показать пакеты без установки |
| `-C`, `--check-only` | Проверить установленные имена пакетов без установки |
| `-v`, `--verbose` | Диагностика фильтров и очередей |
| `-vv`, `--very-verbose` | Дополнительная диагностика очередей приоритетов |
| `-x`, `--xtrace` | Включить трассировку shell |
| `-f`, `--force` | Запускать `apt-get update` даже если `pkgcache.bin` существует |
| `-h`, `--help` | Показать справку |

CondinAPT выполняет `apt-get update` если не выбран режим только проверки и либо `-f` был использован, либо `/var/cache/apt/pkgcache.bin` не существует. Это касается и симуляции, поэтому `-s` не является полностью безопасным пробным запуском без побочных эффектов.

Обычная установка требует прав root. Режим только проверки можно запускать без привилегий; для симуляции также нужны права root, если запускается обновление APT. Текущая реализация не всегда корректно передаёт ошибку `apt-get update` обновления, поэтому рассматривайте ошибку обновления как неудачный запуск, даже если CondinAPT затем возвращает `0`.

## Входные файлы

### Конфигурация

Файл `-c` подключается через Bash. Это исполняемый код, а не пассивный формат данных, поэтому используйте только доверенные файлы.

```bash
DISTRIBUTION="bookworm"
SYSTEM_TYPE="server"
FEATURES=(web database monitoring)
```

Индексированные массивы обеспечивают фильтрацию по членству. Скаляры с запятыми — это всё ещё одна строка: `FEATURES="web,database"` не совпадает с `+feat=web`.

Текущая реализация разбирает параметры командной строки до подключения этого файла.
Переменные конфигурации, которые используют внутренние имена CondinAPT, например `VERBOSITY_LEVEL`, могут переопределять состояние CLI. Избегайте таких имён в универсальных конфигурациях.

### Сопоставление фильтров

Необязательный файл `-m` сопоставляет короткие префиксы с именами переменных Bash:

```text
d=DISTRIBUTION
st=SYSTEM_TYPE
feat=FEATURES
```

Формат точно соответствует `prefix=VariableName`; окружающие пробелы не удаляются. Пустые строки и строки, у которых первое поле начинается с `#` игнорируются.
Дублирующиеся префиксы используют последнее значение.

Если сопоставление отсутствует, сам префикс используется как имя переменной. Неинициализированный скаляр ведёт себя как пустая строка. Ошибки в написании отрицательных фильтров могут привести к тому, что пакет будет включён без предупреждения, поэтому рекомендуется использовать сопоставление и подробную симуляцию при добавлении фильтров.

### Список пакетов

Безопасная грамматика строки выглядит так:

```text
[!] package[=version|==version] filters... [&& ...] [|| ...] [@release] [# comment]
```

Примеры:

```text
curl
firefox-esr +dp=debian
firefox +dp=ubuntu
tool -pv=minimum
exfatprogs -pv=minimum || exfat-utils -pv=minimum && exfat-fuse -pv=minimum
!required-package
package=preferred-version
package==strict-version
systemd-timesyncd +d=buster @buster-backports
```

Всё от первого `#` до конца строки удаляется. Оставшиеся пробелы нормализуются. Кавычки, экранирование, скобки, вложенные группы и пробелы внутри одного фильтра не поддерживаются. Неизвестные лишние токены не отклоняются, поэтому рассматривайте приведённую выше грамматику как ограничение, а не как призыв полагаться на мягкий парсинг.

Используйте одну цель релиза на физическую строку и размещайте её в конце. CondinAPT извлекает цель до оценки альтернатив пакетов, поэтому разные значения `@release` не могут быть назначены альтернативам на одной строке.

## Фильтры

Фильтр сравнивает значение конфигурации с помощью точного, чувствительного к регистру сравнения строк. Если сопоставленная переменная — индексированный массив, совпадение с любым элементом массива считается успешным. Ассоциативные массивы не являются множествами для проверки членства.

| Форма | Эффект |
| --- | --- |
| `+x=value` | Включать только если `x` совпадает |
| `-x=value` | Исключать если `x` совпадает |
| `+{a|b}` | Require at least one member to match |
| `+{a&b}` | Требовать совпадения для каждого элемента |
| `-{a|b}` | Exclude when any member matches |
| `-{a&b}` | Исключать только если совпадают все элементы |

Повторяющиеся простые положительные фильтры с одинаковым префиксом считаются альтернативами:

```text
audacity +pv=toolbox +pv=ultra
```

Положительные фильтры с разными префиксами должны пройти все. Каждый простой отрицательный фильтр — независимое вето:

```text
driver +da=amd64 -d=bookworm -d=bullseye
```

Участники группы должны использовать только один тип оператора. Не смешивайте `|` и `&` в одной группе; приоритетов и вложенности внутри групп нет. Например, выражение «исключить Flux или минимальный Xfce» оформляется двумя фильтрами:

```text
htop -de=flux -{pv=minimum&de=xfce}
```

## Альтернативы и конъюнкции

`&&` имеет более высокий приоритет, чем `||`. CondinAPT сначала разделяет альтернативы, затем проверяет каждого участника конъюнкции, поэтому:

```text
A || B && C
```

означает `A || (B && C)`.

CondinAPT выбирает первую альтернативу, для которой все фильтры и проверки доступности пакетов проходят успешно. Если один из участников конъюнкции не проходит, уже выбранные из этой конъюнкции пакеты откатываются, и проверяется следующая альтернатива.

Это предварительный выбор, а не повторная попытка установки или транзакция. Если последующая очередь `apt-get install` завершится неудачно для выбранной альтернативы, CondinAPT не возвращается к следующей ветке `||`.

Каждая альтернатива должна повторять свои фильтры:

```text
firefox-esr +dp=debian || firefox +dp=ubuntu
```

## Обязательные пакеты

`!` распознаётся только в начале полного физического выражения и применяется ко всем его альтернативам:

```text
!preferred-package || fallback-package
```

Выражение считается критичным в обычном режиме только если ни одна альтернатива не прошла и активный пакет или строгая версия недоступны. Фильтры могут отключить обязательную строку без ошибки. Обычная ошибка установки APT прерывает очередь независимо от `!`.

В режиме симуляции ошибка доступности обязательного пакета отображается, но не останавливает обработку очереди; симуляция всё равно завершится с документированным ненулевым статусом.

## Версии

| Синтаксис | Поведение |
| --- | --- |
| `package=VERSION` | Предпочитать точную версию; при отсутствии — использовать кандидат без версии |
| `package==VERSION` | Принимать только точную версию из репозитория |

Точное совпадение проверяется по полному полю версии из `apt-cache madison`. Если нестрогая обязательная версия недоступна, условие не выполняется; следующая альтернатива `||` всё ещё может пройти, иначе строка пропускается. Чтобы сделать ошибку доступности фатальной, добавьте в начало выражения `!`.

Когда CondinAPT устанавливает точно запрошенную версию, он выполняет `apt-mark hold` после успешного завершения всей очереди APT. Уже установленная точная версия считается удовлетворяющей и не блокируется заново. Ошибки блокировки не отражаются в коде возврата CondinAPT.

Для установленного пакета без версии CondinAPT сравнивает установленную версию с кандидатом из репозитория. Если версия отличается, пакет ставится в очередь повторно; APT вызывается с `--allow-downgrades`.

## Очереди

`---` завершает текущую обычную очередь. Каждый выбранный пакет в очереди передаётся в один неинтерактивный вызов `apt-get install` с параметрами `--force-confdef`, `--force-confold`, `--allow-downgrades`, и `--no-install-suggests`.

```text
build-essential
pkg-config
---
application
```

Строки с указанием релиза исключаются из обычного потока очередей и глобально группируются по релизу. Строки для одного релиза объединяются, даже если разделены `---`.
Фактический порядок выполнения:

1. Очередь приоритетов без цели.
2. Очереди приоритетов с целевым релизом.
3. Обычные очереди в порядке исходного файла.
4. Оставшиеся очереди с целевым релизом в порядке первого появления.

Таким образом, строка с целью между двумя обычными строками не создаёт барьер, и очереди с целью выполняются после всех обычных, если только не выделены как приоритетные.

Проверка доступности репозиториев перед запуском не учитывает цели; только финальная `apt-get install` получает `-t RELEASE`. Проверьте целевые пакеты относительно настроенных репозиториев.

## Список приоритетов

`-P` читает по одной расширенной регулярной строке Bash на строку. Шаблон сопоставляется с первым именем пакета в каждом выражении списка пакетов. При совпадении всё выражение, включая фильтры, альтернативы, обязательность и цель релиза, переносится в очередь приоритетов.

```text
^dkms$
^linux-.*
```

Шаблоны не привязаны к началу строки, если только не содержат якорей. Совпадение с последующим пакетом `&&` или `||` не влияет; проверяется только первый токен пакета. Извлечение приоритета также объединяет совпадения из разных обычных очередей, поэтому не используйте это для записей, для которых важна исходная граница очереди `---`.

Приоритет означает более раннюю обработку и установку, но не гарантирует установку. Фильтры и проверки доступности всё равно применяются.

## Режимы работы и коды возврата

### Симуляция

```bash
bash linux-live/condinapt \
  -l packages.list -c system.conf -m filters.map -s -v
```

Симуляция оценивает фильтры, версии, альтернативы и очереди, затем выводит пакеты, которые будут переданы в APT. Это не гарантирует успешную установку в дальнейшем. Корректная симуляция намеренно завершает работу со статусом `1`, даже если выбор пакетов прошёл успешно.

### Только проверка

```bash
bash linux-live/condinapt \
  -l packages.list -c system.conf -m filters.map -C
```

В режиме только проверки фильтры и операторы оцениваются, но проверяется только факт установки имён пакетов через `dpkg-query`. Запрошенные версии, кандидаты из репозиториев и целевые релизы не проверяются. Возвращает `0` если все активные выражения удовлетворены и `1` в противном случае.

Выведенная команда `sudo apt install ...` — это приблизительная диагностика. Она теряет информацию о версиях и целевых релизах, может включать несколько неудачных альтернатив и не гарантирует воспроизведение исходного выражения.

### Сводка статусов

| Случай | Статус |
| --- | --- |
| Справка | `0` |
| Успешное обычное выполнение | `0` |
| Некорректный ввод, ошибка доступности обязательного пакета или сбой очереди APT | `1` |
| Корректная симуляция | `1` |
| Только проверка с отсутствующими активными пакетами | `1` |

## Особая обработка пакетов

В реализации предусмотрено одно специальное имя пакета: `qemu-kvm`. Оно принимается, если `apt-cache show qemu-kvm` сообщает, что это чисто виртуальный пакет. Для других виртуальных пакетов нет универсального поиска провайдера. Для переносимости используйте явные альтернативы провайдеров.

## Интеграция MiniOS

### Вызов модуля

Для обычного модуля `build-modules` копирует скрипт установки в `/install`, CondinAPT — в `/condinapt`, сгенерированную конфигурацию — в `/minios_build.conf`, а карту — в `/condinapt.map`. Обычный скрипт установки выглядит так:

```bash
#!/bin/bash
set -e
set -o pipefail
set -u

. /minioslib || exit 1
. /minios_build.conf || exit 1

SCRIPT_DIR="$(dirname "$(readlink -f "$0")")"
/condinapt \
  -l "${SCRIPT_DIR}/packages.list" \
  -c "${SCRIPT_DIR}/minios_build.conf" \
  -m "${SCRIPT_DIR}/condinapt.map"
```

Используйте `SCRIPT_DIR`; `$CWD` не входит в стандартный контракт обычного модуля.
`00-core` — это специальный этап ранней сборки, который вызывает копию из исходного дерева через `/linux-live` вместо этого.

Текущий сборщик обычных модулей автоматически копирует только файл с именем `packages.list`. Модули, использующие дополнительные имена файлов списков, должны явно указывать эти входные данные; не предполагается, что каждый файл рядом с `install` окажется в корне chroot.

### Карта фильтров MiniOS

`linux-live/condinapt.map` в настоящее время определяет:

| Префикс | Переменная | Назначение |
| --- | --- | --- |
| `d` | `DISTRIBUTION` | Целевая серия |
| `da` | `DISTRIBUTION_ARCH` | Целевая архитектура |
| `dp` | `DISTRIBUTION_PROFILE` | `debian` или `ubuntu` семейство пакетов |
| `is` | `INIT_SYSTEM` | Выбранная система инициализации |
| `de` | `DESKTOP_ENVIRONMENT` | Окружение модуля |
| `pv` | `PACKAGE_VARIANT` | Вариант пакета |
| `ik` | `INSTALL_KERNEL` | Переключатель установки ядра |
| `kf` | `KERNEL_FLAVOUR` | Вариант ядра |
| `kp` | `KERNEL_PROVIDER` | `distribution` или `minios` |
| `ks` | `KERNEL_SERIES` | Фактическая серия ядра во время `01-kernel` выбора DKMS |
| `kc` | `KERNEL_CAPABILITIES` | Массив обнаруженных возможностей во время `01-kernel` выбора DKMS |
| `kbd` | `KERNEL_BUILD_DKMS` | Переключатель сборки DKMS |
| `ib` | `INITRAMFS_BUILDER` | Реализация initramfs |
| `lo` | `LOCALE` | Системная локаль |
| `ml` | `MULTILINGUAL` | Переключатель мультиязычности |
| `kl` | `KEEP_LOCALES` | Переключатель сохранения локали |

`ks` и `kc` — это специальные фильтры `01-kernel`. При включённой сборке DKMS этот модуль определяет `KERNEL_SERIES` из установленного ядра и создаёт индексированный массив `KERNEL_CAPABILITIES` во временной конфигурации для выбора пакетов DKMS. В обычных конфигурациях модулей они отсутствуют; их использование там приводит к провалу положительных фильтров и может привести к прохождению отрицательных фильтров.
`KERNEL_SERIES` не является предпочтением `MINIOS_KERNEL_SERIES`. На данный момент обнаруженные возможности включают `aufs`, `ntfs3`, `btf_modules` и поддерживаемые встроенные драйверы `rtw88_*`.

Примеры из текущего списка пакетов ядра:

```text
pahole +kc=btf_modules || dwarves +kc=btf_modules
ntfs3-dkms -kc=ntfs3
aufs-ng-dkms +kp=distribution +ks=6.12 -da=i386 -kc=aufs
zfs-dkms +pv=toolbox +pv=ultra +da=amd64
```

## Устранение неполадок

Для анализа выбора используйте подробную симуляцию:

```bash
tmp_list="$(mktemp)"
printf '%s\n' 'package-name +pv=standard' >"$tmp_list"
bash linux-live/condinapt \
  -l "$tmp_list" -c system.conf -m filters.map -s -vv
rm -f "$tmp_list"
```

Не используйте `/dev/stdin`; `-l` требует обычного файла.

- Если фильтр неожиданно проходит, проверьте точное сопоставление префикса, тип переменной, регистр и значение. Убедитесь, что переменная не пуста и не содержит опечаток.
- Если запасной вариант не выбран, помните, что переключение происходит на этапе предварительного выбора, а не после сбоя очереди APT.
- Если целевой пакет не устанавливается, проверьте настроенные источники и выполните `apt-cache policy PACKAGE`; предварительный выбор не применяет `-t RELEASE`.
- Если строгая версия пропущена, сравните точное поле версии с `apt-cache madison PACKAGE`.
- Если порядок очередей неожидан, учитывайте глобальную группировку по целям и извлечение приоритетов до обычных очередей.

Для общей схемы сборки см. [Сборка MiniOS](/development/Building-MiniOS).
