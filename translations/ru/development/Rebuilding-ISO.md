# Создание ISO-образов MiniOS из командной строки

`minios-image-compose` — это консольный бэкенд, поставляемый с MiniOS Image Builder. Он заменяет устаревшую утилиту `sb2iso`. Эта команда пересобирает существующее дерево содержимого MiniOS, при необходимости изменяет набор модулей и поддерживаемую конфигурацию, проверяет результат и публикует загрузочный ISO-образ.

Для пошаговой работы над проектом используйте графический интерфейс [MiniOS Image Builder](/development/Image-Builder.md). Для скриптов, автоматизации или воспроизводимых сборок из командной строки используйте эту команду напрямую. Для полной сборки из исходников используйте [Building MiniOS](/development/Building-MiniOS.md).

## Базовое использование

В запущенной live-сессии MiniOS создайте ISO-образ с найденным исходным содержимым MiniOS и `/etc/live/config.conf`:

```bash
minios-image-compose --name ./custom-minios.iso
```

Не добавляйте в начало полной команды `sudo` или `pkexec`. Сборка, проверка и публикация выполняются от имени текущего пользователя. Только опциональный захват сессии может вызывать доверенный бэкенд `/usr/bin/savechanges` через PolicyKit.

Имя выходного файла по умолчанию — `minios-YYYYMMDD_HHMM.iso`. Если указанный файл уже существует, операция будет отклонена, если только явно не задан `--overwrite`.

## Выбор источника

Без `--source` команда определяет содержимое MiniOS, используемое текущей сессией LiveKit или dracut. Чтобы пересобрать другое смонтированное дерево MiniOS, укажите каталог, содержащий `boot/` и модули MiniOS:

```bash
minios-image-compose \
  --source /media/minios \
  --config ./config.conf \
  --name ./custom-minios.iso
```

Источник используется только для чтения и никогда не изменяется. ISO-файлы и оптические носители должны быть смонтированы перед использованием их дерева содержимого MiniOS в CLI. Графический Image Builder может монтировать такие источники через `udisksctl`.

## Выбор модулей

Дополнительные модули `.sb` указываются как позиционные аргументы:

```bash
minios-image-compose 06-development.sb 10-site-config.sb \
  --name ./minios-development.iso
```

Команда проверяет каждый модуль как читаемый файл SquashFS, не являющийся символьной ссылкой. Модули, имена которых начинаются с двух цифр и дефиса, размещаются на верхнем уровне MiniOS. Остальные добавленные модули помещаются в `minios/modules/`. Дубликаты или совпадения по имени без учёта регистра отклоняются.

Исключите исходные пути с помощью POSIX-совместимого регулярного выражения:

```bash
minios-image-compose --exclude 'firefox|libreoffice|gimp' \
  --name ./minios-lite.iso
```

Обязательные загрузочные файлы, файлы ядра и initramfs, основные модули, выбранное загрузочное меню и выбранная конфигурация не могут быть исключены.

Создавайте переиспользуемые модули до сборки ISO. См. [Создание модулей](/development/Creating-Modules.md) и [Менеджер модулей MiniOS](/administration/Module-Manager.md).

## Конфигурация и манифест

`--config FILE` устанавливает выбранный обычный файл как `minios/config.conf`. Значение по умолчанию — `/etc/live/config.conf`.

```bash
minios-image-compose --config ./config.conf \
  --manifest ./build.json \
  --volume-label 'MINIOS_LAB' \
  --name ./minios-lab.iso
```

Необязательный манифест должен быть объектом JSON. Метки томов содержат от 1 до 32 печатных ASCII-символов; метки, выходящие за пределы строгого набора ISO 9660 (заглавные буквы, цифры и подчёркивания), вызывают предупреждение.

## Захват изменений сессии

Захват сессии является опциональным и применяется к записываемому слою текущей запущенной сессии MiniOS. Он разрешён только для явного источника, если его отпечаток базового модуля совпадает с отпечатком работающей системы.

```bash
minios-image-compose --capture-changes clean \
  --name ./minios-with-software.iso
```

Доступные профили:

- `exact` захватывает все представимые изменения, включая учётные данные, личные данные, логи, состояние браузера и идентификатор машины.
- `clean` использует ограниченный список разрешённых путей, ориентированный на программное обеспечение. Это снижает риски, но не гарантирует отсутствие секретных данных в результате.
- `selected` использует инвентаризацию, подготовленную совместимым интерфейсом или рабочим процессом `savechanges`.

```bash
minios-image-compose --capture-changes selected \
  --capture-selection ./session-selection.json \
  --capture-compression zstd \
  --name ./selected-session.iso
```

Для обмена ISO-образом предпочтительнее использовать модули и декларативную конфигурацию вместо захвата сессии. Подробнее о модели приватности и процессе проверки см. в [MiniOS Image Builder](/development/Image-Builder.md).

## Настройка поведения загрузки

CLI позволяет изменять поддерживаемые схемы GRUB и SYSLINUX:

```bash
minios-image-compose \
  --boot-timeout 5 \
  --default-boot fresh \
  --kernel-args 'audit=1 mitigations=auto' \
  --menu multilang \
  --name ./custom-boot.iso
```

`--default-boot` принимает значения `resume`, `new`, `choose`, `fresh` или `toram`.
`--menu` принимает `multilang` или поддерживаемую локаль, например `en_US`, `ru_RU` или `de_DE`. Аргументы ядра проходят проверку и добавляются без интерпретации оболочкой. Неподдерживаемые или неоднозначные схемы загрузочного меню отклоняются, а не изменяются наугад.

## Добавление оформления или файловой наложки

Замените фон загрузки на проверенный PNG-файл:

```bash
minios-image-compose --boot-background ./art/boot.png \
  --name ./custom-art.iso
```

Упакуйте одну подготовленную структуру каталогов в модуль наложения файловой системы с владельцем root:

```bash
minios-image-compose --overlay-directory "$PWD/image-overlay" \
  --name ./custom-overlay.iso
```

Наложка интерпретируется относительно корня образа. Она не выполняет скрипты, не устанавливает пакеты и не открывает chroot. Небезопасные ссылки, специальные файлы, переходы между файловыми системами и конфликты назначения отклоняются.

## Проверка и публикация

Перед публикацией `minios-image-compose` проверяет дерево файловой системы ISO, метку тома, загрузочные записи BIOS и UEFI, системную область, загрузочные файлы, модули и запрошенные настройки. Сгенерированные модули наложки и захваченной сессии извлекаются и сверяются с их метаданными и контрольными суммами.

ISO-образ собирается во временном каталоге на целевой файловой системе и публикуется атомарно только после успешной проверки. Мутация входных данных, сбой проверки, отмена или недостаточно места на целевом диске препятствуют публикации. Предыдущий файл назначения остаётся без изменений, если только явно разрешённая сборка `--overwrite` не достигла атомарной публикации.

Создайте контрольную сумму и выполните отдельную загрузочную проверку после успешной сборки:

```bash
sha256sum custom-minios.iso > custom-minios.iso.sha256
sha256sum --check custom-minios.iso.sha256
```

Структурная проверка не заменяет тестирование загрузки BIOS и UEFI на виртуальной машине или подходящем оборудовании.

## Справочник команд

Для получения точной информации о версии бэкенда используйте установленное руководство и справку:

```bash
minios-image-compose --help
man minios-image-compose
```

Часто используемые опции:

| Опция | Назначение |
|---|---|
| `-n`, `--name FILE` | Указать путь к выходному файлу. |
| `-e`, `--exclude REGEX` | Исключить совпадающие исходные пути. |
| `--source DIR` | Указать явное дерево содержимого MiniOS. |
| `--config FILE` | Выбрать live-конфигурацию, встроенную в ISO. |
| `--manifest FILE` | Включить проверенный JSON-манифест сборки. |
| `--capture-changes MODE` | Захватить изменения сессии `exact`, `clean` или `selected`. |
| `--boot-timeout SECONDS` | Установить таймаут меню загрузки от 0 до 300 секунд. |
| `--default-boot MODE` | Выбрать действие по умолчанию для сессии MiniOS. |
| `--kernel-args TEXT` | Добавить проверенные глобальные параметры ядра. |
| `--boot-background PNG` | Заменить поддерживаемое оформление загрузки. |
| `--overlay-directory DIR` | Добавить один декларативный слой файловой системы. |
| `--menu TYPE` | Выбрать многоязычное или локализованное меню. |
| `--overwrite` | Явно разрешить замену существующего выходного файла. |

Команда завершает работу с ненулевым кодом возврата при ошибках источника, модуля, настройки, хранилища, проверки или публикации. Не распространяйте выходной файл, если команда не завершилась успешно и итоговая контрольная сумма и загрузка не были проверены.
