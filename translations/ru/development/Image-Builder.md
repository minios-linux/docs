# MiniOS Image Builder

MiniOS Image Builder — это приложение на GTK для ремастеринга существующего образа MiniOS. Оно выбирает содержимое из текущей сессии MiniOS, ISO-файла или оптического диска, применяет декларативные настройки и использует `minios-image-compose` для создания проверенного загрузочного ISO.

Сборщик запускается внутри MiniOS. Он не изменяет выбранный исходный носитель.

## Выберите правильный рабочий процесс

Image Builder ремастерит существующий бинарный образ MiniOS. Это не замена ни одному из следующих процессов:

- **Собрать MiniOS из исходников:** используйте систему сборки `minios-live`, если требуется изменить списки пакетов дистрибутива, конфигурацию сборки, слой ядра, загрузочные артефакты или цепочку модулей, собираемых из исходников. См. [Сборка MiniOS](/development/Building-MiniOS.md).
- **Создать повторно используемый модуль:** используйте `apt2sb`, `script2sb`, `chroot2sb` или другие инструменты для модулей, если результатом должен стать отдельный слой `.sb`. См. [Создание модулей](/development/Creating-Modules.md).
- **Ремастеринг образа:** используйте Image Builder для выбора существующих модулей, добавления готовых внешних модулей, изменения поддерживаемых настроек образа, при необходимости захвата изменений сессии и публикации нового ISO.

Слой файловой системы проекта предназначен для декларативных файлов в корне образа. Он не выполняет скрипты, не устанавливает пакеты и не открывает chroot. Программное обеспечение, предназначенное для повторного использования, должно быть подготовлено как модуль до добавления в проект Image Builder.

## Варианты источника

На странице источника принимаются:

- Текущая сессия MiniOS с LiveKit или dracut.
- ISO-файл MiniOS.
- Оптический диск MiniOS.

ISO-файлы и оптические диски монтируются только для чтения с помощью `udisksctl`. Инвентаризация источника фиксирует выпуск, версию, архитектуру, поддержку загрузчика, размер, список модулей и отпечаток источника. Если источник изменился после планирования, сборка блокируется, чтобы не продолжать с другим вводом.

Захват сессии всегда описывает изменения в текущей запущенной сессии MiniOS. При выборе ISO или оптического диска захват доступен только если отпечаток базового модуля этого источника совпадает с примонтированной базой текущей сессии. Выбор внешнего носителя не фиксирует изменения, сделанные в другой системе.

## Требования

Для работы Image Builder требуется соответствующий бэкенд `minios-image-compose`. Для источников в виде ISO-файлов и оптических дисков необходим `udisks2`. Для чтения `/etc/live/config.conf`, доступного только для root, и захвата записываемой сессии могут потребоваться `pkexec` и агент PolicyKit на рабочем столе. Для захвата сессии необходим совместимый `savechanges`, предоставляемый `minios-tools` версии 1.5.0 или новее.

Приложение и бэкенд компоновки остаются без привилегий. Авторизация ограничена фиксированным средством чтения live-конфигурации и, при необходимости, доверенными `/usr/bin/savechanges`.

## Рабочий процесс проекта

### Выбор источника

Выберите источник и дождитесь завершения инвентаризации. Проверьте его идентификатор, архитектуру, поддержку загрузки, диагностику и количество модулей. Устраните ошибки источника перед продолжением.

### Выбор содержимого

Выберите модули источника для включения и добавьте любые внешние модули `.sb`. Необходимые основные и модуль ядра заблокированы. Модули, активные в текущей сессии, но отсутствующие в выбранном источнике, отображаются отдельно и не добавляются автоматически.

Дополнительные модули должны быть читаемыми обычными файлами с корректными данными SquashFS. Дубликаты, совпадения по регистру или конфликты имён целей отклоняются, так как во время выполнения слои определяются по имени файла.

### Настройка параметров

Выберите путь для вывода и требуемую текущую конфигурацию MiniOS. Пустые поля настройки или `Keep current` сохраняют поведение источника. Настраивайте только те параметры, которые необходимо переопределить для нового образа, затем решите, нужно ли захватывать слой записываемой сессии.

Байты `/etc/live/config.conf` копируются во внутреннее хранилище сборки с правами 0600. Они не интерпретируются, не отображаются и не логируются. Текущие проекты должны включать эту конфигурацию; старый проект с явным её отключением не может перейти к этапу обзора, пока не будет исправлен.

### Проверка плана

Проверка создает новый план на основе текущих идентификаторов входных данных. Проверьте выбранные, исключённые и дополнительные модули, место вывода, оценку необходимого пространства, сводку настроек, профиль захвата, предупреждения и границу привилегий.

Проверка намеренно не отображает значения конфигурации, необработанные параметры ядра, приватные пути настройки и выбранные пути захвата. Она показывает количество, имена файлов, отпечатки и дайджесты, если этого достаточно для привязки плана.

Если выходной файл уже существует, замена требует подтверждения. Подтверждение связано с обнаруженным устройством, inode, размером, временной меткой и SHA-256 этого файла. Изменение назначения, отмена или неудачная попытка сбрасывают подтверждение, и требуется повторная проверка.

### Сборка и проверка

На этапе сборки повторно проверяются все используемые входные данные и запускается `minios-image-compose` с аргументами в приватном рабочем каталоге. ISO-файл остается приватным до успешного завершения структурной проверки. Публикация в выбранное место происходит атомарно.

Сохраните проект, если его источник, выбор модулей, выходной файл и намерения по настройке будут использоваться повторно. Файлы проектов имеют формат JSON. Несохранённые изменения требуют подтверждения перед открытием другого проекта или закрытием приложения.

## Захват сессии и конфиденциальность

Модули источника, `/etc/live/config.conf` и захват сессии — независимые входные данные. Если достаточно выбора модулей и декларативной настройки, не захватывайте записываемую сессию.

### Не включать изменения сессии

Это рекомендуемый вариант по умолчанию. Сборщик использует выбранные модули, текущую конфигурацию, загрузочные параметры и другие настройки образа без копирования слоя записываемой сессии.

### Включить все изменения сессии

Этот профиль сохраняет все поддерживаемые изменения в записываемом слое, обнаруженном через OverlayFS или AUFS. Он может включать пароли, ключи, токены, данные браузера, идентификатор машины, личные файлы, журналы и состояние удалённых файлов. Требуется явное подтверждение, и не рекомендуется использовать этот режим для образов, предназначенных для других людей, без отдельного аудита.

### Включить только повторно используемые изменения

Этот профиль использует строгий список разрешённых путей для программного обеспечения и безопасные значения по умолчанию, исключая личные, идентификационные, кэшированные и журнальные данные. Это снижает риск, но не гарантирует, что разрешённые файлы не содержат секретной информации. Проверьте готовый образ перед распространением.

### Выбрать изменения сессии вручную

Запустите `Analyze session changes`, затем выберите как минимум один нормализованный путь из инвентаризации в памяти. Выбранная директория включает все вложенные элементы. Точные или родительские исключения имеют приоритет над совпадающими включениями.

Инвентаризация содержит метаданные, включая имена файлов, и поэтому является чувствительной, даже если не содержит содержимого файлов. Она хранится только в памяти и не записывается в проект, не отображается в обзоре и не попадает в журналы. Явные правила включения и исключения отражают намерения проекта и сохраняются; в обзоре отображается только их количество и дайджест.

Запуск нового анализа, обновление или смена источника, отмена или сбой, а также открытие или создание проекта очищают инвентаризацию в памяти. Анализ и захват могут потребовать авторизации администратора, но процессы Image Builder и сборки ISO не получают повышенных привилегий.

## Настройка образа

Поддерживаемые параметры ограничиваются и проверяются на стороне бэкенда:

- **Системные настройки по умолчанию:** имя хоста, часовой пояс, целевой systemd по умолчанию, включённые или отключённые сервисы.
- **Безопасность и доступ:** разрешённые sudo, PolicyKit, SSH, XRDP, X11, режимы блокировки экрана и подсказки на экране входа.
- **Пользовательские данные:** проверяемые каталоги пользователей относительно корня с поведением либо «ссылка», либо «привязка», но не обоими одновременно.
- **Поведение при загрузке:** таймаут от 0 до 300 секунд, меню источника или сгенерированное меню, а также выбранный пункт по умолчанию.
- **Пункты загрузки:** шаблоны resume, new, choose, fresh и copy-to-RAM можно скрывать, менять порядок, дублировать и настраивать через типизированные параметры постоянства, модуля, запуска, локализации, zRAM и диагностики.
- **Экспертные параметры загрузки:** проверяемые глобальные и индивидуальные параметры ядра для опций, не представленных типизированными настройками.
- **Внешний вид:** проверяемое PNG-изображение для фона загрузки.
- **Слой файловой системы проекта:** одна реальная директория, интерпретируемая относительно корня образа и упакованная как модуль SquashFS с правами root.

Слой файловой системы поддерживает обычные файлы, безопасные относительные символьные ссылки, пустые каталоги, бит выполнения и временные метки. Узлы устройств, сокеты, FIFO, переходы между файловыми системами, абсолютные или выходящие за пределы корня ссылки и небезопасные имена отклоняются. Привилегированные биты сбрасываются, а владельцы в сгенерированном модуле нормализуются.

Настройки загрузки поддерживают распознаваемый GRUB MiniOS, нативный SYSLINUX и стандартную цепочку SYSLINUX-to-GRUB. Неподдерживаемая или неоднозначная конфигурация загрузки отклоняется, а не подбирается автоматически. Сборка без настройки загрузки может сохранить структуру источника, которую парсер настроек не распознаёт.

## Проверка результата

Перед публикацией `minios-image-compose` проверяет сгенерированный ISO, а не полагается только на успешное завершение `xorriso`. Проверяются:

- Дерево файловой системы ISO и метка тома.
- Загрузочные записи BIOS и UEFI, а также системная область.
- Необходимые загрузочные, ядерные, initramfs, конфигурационные и модульные файлы.
- Встроенные аттестации кастомизации и захвата сессии, если они есть.
- Дайджесты и структура сгенерированных модулей-оверлеев и модулей захваченной сессии.
- Целевые фоны загрузки и преобразованная конфигурация загрузки при наличии кастомизации.

Перед сборкой фиксируются идентификатор, режим, время изменения и SHA-256 входных путей. Изменяемые входные данные при возможности снапшотятся приватно с помощью reflink; иначе они проверяются на изменения до и после записи ISO. Несовпадение или сбой проверки блокируют публикацию.

После успешной сборки отдельно запишите контрольную сумму:

```bash
sha256sum custom-minios.iso > custom-minios.iso.sha256
sha256sum -c custom-minios.iso.sha256
```

Структурная проверка не заменяет тест загрузки. Запустите ISO в временной виртуальной машине и проверьте как BIOS, так и UEFI, если предполагается поддержка обоих режимов. Image Builder может сообщить об установленном QEMU или VirtualBox, но не запускает и не настраивает гипервизор.

## Безопасность и отмена

- Держите исходный носитель только для чтения и сохраняйте результат на файловую систему с достаточным свободным пространством для оценки и временного запаса.
- Не записывайте поверх единственного проверенного ISO. Используйте новое имя файла, если только замена не является намеренной и подтверждённой.
- Проверяйте внешние модули перед добавлением. Image Builder проверяет их структуру SquashFS, но не устанавливает авторство содержимого.
- Для распространяемых образов предпочтительно не захватывать сессию. Если захват необходим — проводите аудит итоговой файловой системы, а не только имени профиля.
- Считайте файлы проектов конфиденциальными, если они содержат явные пути к источникам, модулям, выходным файлам или выбранным правилам захвата.

Инвентаризация, сборка и процессы проверки выполняются в отдельных группах процессов. Запрос отмены инициирует завершение и усиливается после льготного периода. Хеширование может завершиться до того, как отмена достигнет безопасной точки, но устаревшие результаты отбрасываются. После начала атомарной публикации процесс завершается полностью, чтобы не оставить целевой файл частично записанным.

Отменённая или неудачная сборка не публикует свой приватный ISO. Любой предыдущий файл назначения остаётся на месте, если только проверенная замена не была опубликована атомарно.
