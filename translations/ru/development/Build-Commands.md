# Команды сборки

MiniOS предоставляет два интерфейса командной строки для сборки. Запускайте команды из исходного каталога `minios-live`, если не используете установленную копию.

- `minios-cmd` — это фронтенд. Он принимает стандартные параметры цели, генерирует рабочую конфигурацию и запускает полную сборку.
- `minios-live` — это поэтапный бэкенд. Он читает конфигурацию сборки и выполняет один этап, диапазон этапов или весь конвейер целиком.

Для установленной версии используйте `./minios-cmd --help`, `./minios-live --help` и активный `build.conf`. Они считаются приоритетными, если примеры или устаревшая документация расходятся. Поддерживаемые значения целей могут меняться, поэтому на этой странице не приводится матрица поддержки.

## Требования root

Для отображения справки root-права не требуются:

```bash
./minios-cmd --help
./minios-live --help
```

Операции сборки требуют root, так как используются debootstrap, chroot, монтирования и инструменты создания образов. Текущий фронтенд также проверяет наличие root до записи конфигурации с помощью `--config-only`.

```bash
sudo ./minios-cmd -d trixie -a amd64 -de xfce -pv standard
```

Бэкенд проверяет и устанавливает необходимые зависимости хоста, перечисленные в `linux-live/prerequisites.list`, если только в конфигурации не установлен `SKIP_SETUP_HOST=true`.

## Сборка во фронтенде

Обычный запуск `minios-cmd` требует всех четырёх параметров выбора цели:

- `-d`, `--distribution`
- `-a`, `--architecture`
- `-de`, `--desktop-environment`
- `-pv`, `--package-variant`

Например:

```bash
sudo ./minios-cmd -d trixie -a amd64 -de xfce -pv standard
```

К распространённым дополнительным настройкам относятся: сжатие, параметры ядра, локаль, часовой пояс, сборщик initramfs, язык загрузочного меню и каталог сборки. Проверяйте наличие опции через `./minios-cmd --help`, а не предполагая её существование.

Фронтенд копирует шаблон конфигурации, записывает указанные значения во фронтенде в копию и вызывает `minios-live -`. По умолчанию рабочая копия для этого примера:

```text
build/trixie-standard-amd64/build.conf
```

Сгенерировать конфигурацию без запуска сборки:

```bash
sudo ./minios-cmd --config-only \
  -d trixie -a amd64 -de xfce -pv standard
```

Если не указан другой путь, будет записан `build/build.conf`.

`--config-file FILE` выбирает файл конфигурации. В справке к текущей команде указано, что все остальные параметры в этом режиме игнорируются, поэтому не комбинируйте его с параметрами цели или тонкой настройки:

```bash
sudo ./minios-cmd --config-file /absolute/path/build-trixie.conf
```

В режиме опций фронтенда явно указанные значения командной строки перезаписывают соответствующие значения шаблона. В режиме файла конфигурации выбранный файл используется как входная конфигурация, и не следует пытаться переопределять его другими параметрами фронтенда.

## Конфигурация бэкенда

В исходной копии `minios-live` по умолчанию читает `linux-live/build.conf`. В установленной версии используется `/etc/minios-live/build.conf`. Бэкенд подключает выбранный файл перед вычислением путей назначения и не имеет флагов командной строки для переопределения отдельных параметров конфигурации.

Выберите другой файл через `BUILD_CONF`. Используйте абсолютный путь при переходе через границу `sudo`:

```bash
sudo env BUILD_CONF=/absolute/path/build-trixie.conf ./minios-live -
```

`BUILD_DIR` выбирает другой корень для вывода сборки:

```bash
sudo env \
  BUILD_CONF=/absolute/path/build-trixie.conf \
  BUILD_DIR=/absolute/path/minios-build \
  ./minios-live -
```

Не редактируйте сгенерированные файлы в рабочем каталоге цели вместо поддержки выбранной конфигурации. Дополнительные параметры ядра, загрузчика, локали, кэша, снимков, модулей, очистки и публикации смотрите в `linux-live/build.conf`.

## Этапы бэкенда

Этапы выполняются в следующем порядке:

1. `build-bootstrap`
2. `build-chroot`
3. `build-live`
4. `build-modules`
5. `build-boot`
6. `build-config`
7. `build-iso`
8. `remove-sources`

Скрипт принимает имена этапов с дефисами, как указано в справке.

Выполнить весь конвейер:

```bash
sudo ./minios-live -
```

Выполнить только один этап:

```bash
sudo ./minios-live build-iso
```

Выполнить диапазон этапов:

```bash
sudo ./minios-live build-chroot - build-live
```

Выполнить с первого этапа до выбранного:

```bash
sudo ./minios-live - build-live
```

Выполнить с выбранного этапа до последнего:

```bash
sudo ./minios-live build-modules -
```

В этих примерах бэкенда используется цель, выбранная в активной конфигурации. Для примеров на этой странице сначала задайте `DISTRIBUTION="trixie"`, `DISTRIBUTION_ARCH="amd64"`, `DESKTOP_ENVIRONMENT="xfce"` и `PACKAGE_VARIANT="standard"`.

## Зависимости этапов

Частичное выполнение команды не пересоздаёт выходные данные, полученные на пропущенных ранних этапах. Последующие этапы используют корневую файловую систему, модули SquashFS, загрузочные файлы и конфигурацию, созданные предыдущими этапами.

Пересборка раннего этапа может сделать устаревшими все зависящие от него выходные данные следующих этапов. Выполняйте сборку до последнего затронутого этапа и не сохраняйте модули с более высоким номером после изменения модуля, на котором они основаны. В частности, `build-iso` упаковывает ранее подготовленные данные образа; он не пересобирает эти данные.

Выполняйте полную сборку для новой цели или если необходимые выходные данные предыдущих этапов отсутствуют:

```bash
sudo ./minios-cmd -d trixie -a amd64 -de xfce -pv standard
```

## Выходные файлы и логи

В конфигурации и корне сборки по умолчанию пример trixie использует следующие проверенные пути:

- `build/trixie-standard-amd64/core/` — изменяемая основная файловая система
- `build/trixie-standard-amd64/image/` — подготовленное дерево ISO
- `build/trixie-standard-amd64/image/minios/` — сгенерированные модули и полезная нагрузка MiniOS
- `build/iso/` — ISO-файлы и их побочные файлы `.iso.sha256`
- `build/log/build-YYYYMMDD-HHMMSS.log` — сохранённый лог сборки

Все пути указываются относительно `BUILD_DIR`. Имя файла ISO включает параметры сборки и, для нерелизных сборок, временную метку; используйте путь, выведенный после успешной сборки, а не пытайтесь предсказать полное имя файла.

## Токены Ubuntu Pro

`--ubuntu-pro-token` включает использование Ubuntu Pro во время сборки во фронтенде. Код сборки подключает токен внутри chroot, затем отключает его и удаляет состояние Pro, аутентификацию репозиториев, настройки и следы ключей перед созданием образа. Эта очистка не делает токен безопасным для хранения на хосте.

Не размещайте реальный токен в документации, системе контроля версий, истории команд оболочки, CI-выводе или общей командной строке. Предпочтительно использовать приватный конфигурационный файл вне репозитория, ограничить к нему доступ только владельцу и передавать только путь к файлу:

```bash
install -m 600 linux-live/build.conf /private/path/build-trixie.conf
sudo env BUILD_CONF=/private/path/build-trixie.conf ./minios-live -
```

Укажите `USE_UBUNTU_PRO="true"` и `UBUNTU_PRO_TOKEN="..."` в этом приватном файле. Защитите и удалите любую рабочую конфигурацию на хосте, содержащую токен, когда он больше не нужен, и убедитесь, что ни токен, ни данные аутентификации Pro не попали в опубликованные артефакты.
