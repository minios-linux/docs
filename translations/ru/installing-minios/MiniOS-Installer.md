# Установщик MiniOS

Установщик MiniOS — это мастер на GTK и командная утилита для развертывания системы из работающей live-сессии MiniOS. Запись или копирование MiniOS на съемный носитель уже является методом установки; Установщик MiniOS используется для управляемого развертывания, когда требуется контролируемое размещение, настройка персистентности или опциональная конвертация в нативный режим.

## Перед началом

Неправильный выбор диска или разметки может привести к потере данных. Сделайте резервную копию важных файлов, отключите ненужные диски и определите целевой диск по пути устройства, модели и объему. Последнее подтверждение — это последний момент, когда установку можно безопасно отменить.

Диск с запущенной live-системой MiniOS исключается из выбора цели. Для общей информации о требованиях к объему см. [Руководство по совместимости оборудования](/getting-started/Hardware-Compatibility).

## Режимы установки

**Live-режим** копирует выбранные сжатые модули MiniOS и загрузочные компоненты. В результате система остается MiniOS: сохраняется модульная структура live-системы, загрузочная конфигурация MiniOS, процессы управления MiniOS и, при необходимости, персистентность сессии.

**Нативный режим** создает стандартную рабочую среду Debian из выбранного образа MiniOS. Выбранные модули разворачиваются в доступную для записи корневую файловую систему, сохраняется выбранная среда рабочего стола и обычные приложения, удаляются live-окружение MiniOS и утилиты, специфичные для live-режима, устанавливаются необходимые пакеты Debian, генерируется стандартный initramfs и устанавливается загрузчик. Установщик определяет поддержку нативного режима по загруженному образу. Если отсутствуют необходимые метаданные ядра и архитектурный контракт EFI, режим совместимости позволяет только live-установку.

::: warning В нативном режиме меняется способ управления системой
Установленная система сохраняет привычный пользовательский опыт MiniOS — внешний вид, выбранную среду рабочего стола и приложения — но больше не использует архитектуру live MiniOS. В процессе конвертации установщик удаляет `minios-*` пакеты и другие утилиты, специфичные для live-режима, поскольку сессии, `.sb` модули, модульное управление ядрами и загрузочная конфигурация live больше не применяются. После перезагрузки обслуживайте систему как обычный рабочий стол Debian с помощью APT, пакетов ядра Debian, стандартного initramfs и установленного загрузчика. См. [О MiniOS](/getting-started/About-MiniOS).
:::

Это развертывание отличается от простой записи ISO, мультизагрузки ISO-файлов Ventoy или установки live-системы на основе файлов. См. [Методы установки](/installing-minios/Installation-Methods) для подробностей.

## Запуск графического установщика

Откройте меню приложений, выберите «Система», затем выберите Установщик MiniOS. Также его можно запустить из терминала:

```bash
sudo minios-installer
```

Мастер установки собирает параметры режима установки, безопасности, локации, проводной сети, клавиатуры, учетной записи, модулей, хранилища и загрузки. Проверьте точную схему разделов и итоговое описание операций перед финальным подтверждением, после которого изменения будут необратимы.

## Размещение и схемы загрузки

Графический установщик предлагает следующие варианты размещения, если целевой диск подходит:

- Стереть всё — создает новую таблицу разделов и удаляет все данные на целевом диске.
- Свободное пространство — использует подходящее неразмеченное пространство без уменьшения существующей файловой системы.
- Рядом — уменьшает подходящий, размонтированный последний раздел ext2, ext3, ext4 или NTFS. Грязные, смонтированные, вложенные, неоднозначные и иные небезопасные схемы не поддерживаются. При необходимости установщик может запросить загрузку недостающих инструментов для работы с файловыми системами.
- Ручная разметка доступна только для нативной конвертации в графическом интерфейсе на подходящих физических дисках. Изменения применяются только после финального подтверждения.

Автоматические схемы загрузки: BIOS/MBR, UEFI/MBR и UEFI/GPT. UEFI работает с GPT или основной схемой MBR. BIOS поддерживается только на основной MBR, но не на GPT. Расширенные или логические схемы MBR не поддерживаются.

В ручном режиме можно создавать, удалять, форматировать и повторно использовать разделы; уменьшать поддерживаемую файловую систему с конца; назначать точки монтирования, EFI-раздел и swap; а также отменять или сбрасывать подготовленные изменения. Не поддерживаются LVM, RAID, нативные корни LUKS, отображаемое или вложенное хранилище, bcache, ZFS и редактирование подтомов Btrfs. Персистентность LUKS не шифрует нативную корневую файловую систему.

## Файловые системы

- Live-схемы могут использовать ext2, ext4, Btrfs, FAT32 или NTFS при наличии необходимых инструментов.
- Корневая файловая система, созданная при нативной конвертации, может использовать ext2, ext4 или Btrfs. По умолчанию используется универсальный ext4.
- Существующие файловые системы ext3 могут быть повторно использованы или уменьшены, если это поддерживается, но ext3 не предлагается для нового форматирования.
- FAT32 ограничен файлами размером до 4 ГиБ и доступен только для live-схем.
- NTFS доступен только для live-схем, хотя подходящий раздел NTFS можно уменьшить для размещения рядом.

Требуемое пространство включает выбранные данные модулей, загрузочные компоненты, запрошенную персистентность и резерв файловой системы в 25 процентов. EFI и нативный swap рассчитываются отдельно.

## Конфигурация и безопасность

Установщик может настроить локаль, часовой пояс, клавиатуру, имя пользователя, пароли, группы пользователей, имя хоста, службы, меню загрузки и выбор модулей. При выборе более высокого модуля MiniOS автоматически включаются все необходимые нижние уровни.

Профили безопасности: `convenient`, `balanced` и `strict`. По умолчанию в live-режиме используется `convenient`; при нативной конвертации начальная настройка — `balanced`. Управление SSH и XRDP осуществляется отдельно от выбранного профиля. Проверьте службы удаленного доступа до первого сетевого подключения. После нативной конвертации дальнейшая настройка безопасности выполняется стандартными средствами администрирования Debian.

Сетевые настройки включают имя хоста и проводную сеть с DHCP или статическим IPv4. Установщик не создает и не изменяет профили Wi-Fi. Для нативной конвертации и некоторых операций «рядом» может потребоваться доступ к сети (с вашего согласия) для получения GRUB, EFI, initramfs, `os-prober` или пакетов для изменения размера файловой системы до внесения изменений на диск.

## Персистентность live-сессии

Персистентность применяется только к live-установкам:

- `native` режим персистентности сохраняет изменения live-сессии напрямую на POSIX-совместимой целевой файловой системе. Несмотря на название, это **бэкенд live-персистентности** и не связан с нативной установкой. Не поддерживается на FAT32 и NTFS.
- DynFileFS использует расширяемый контейнер.
- Raw использует контейнер фиксированного размера.
- LUKS использует зашифрованный образ, создаваемый initrd при первой загрузке. Пароль запрашивается при загрузке и никогда не передается и не сохраняется установщиком.

Для контейнерных режимов по умолчанию используется 4000 МиБ. Контейнеры Raw и LUKS не могут превышать 4000 МиБ на FAT32; DynFileFS не ограничен этим лимитом на размер одного файла. LUKS доступен только при наличии необходимой поддержки шифрования как в текущем initrd, так и во всех копируемых исходных initrd.

Варианты загрузки будут использовать `perchmode` и `perchsize`. См. [Персистентность initrd](/reference/boot-process/Persistence-Internals) и [Параметры загрузки](/reference/Boot-Parameters) для их значения во время работы и условий активации.

## Развертывание через командную строку

`minios-deploy` предназначено для автоматизации, тестирования и восстановления. Ручная разметка и интерактивная настройка проводной сети доступны только в графическом интерфейсе.

Показать список дисков, доступных для установки:

```bash
minios-deploy list-disks
```

Замените `/dev/sdb` во всех примерах на проверенный целевой диск. Сначала выведите недеструктивный план:

```bash
minios-deploy plan /dev/sdb --mode live --placement free_space \
  --filesystem ext4 --persistence-mode dynfilefs --persistence-size 8000
```

Просмотрите подходящие команды развертывания без записи на диск:

```bash
sudo minios-deploy install /dev/sdb --mode live --placement free_space \
  --filesystem ext4 --persistence-mode dynfilefs --persistence-size 8000 \
  --security-profile balanced --dry-run
```

Запускайте реальную установку только после проверки плана, идентификации цели и вывода пробного запуска. `--yes` подтверждает выполнение изменений, приводящих к потере данных:

```bash
sudo minios-deploy install /dev/sdb --mode live --placement free_space \
  --filesystem ext4 --persistence-mode dynfilefs --persistence-size 8000 \
  --security-profile balanced --yes
```

Если вы намеренно хотите выполнить нативную конвертацию в существующее свободное пространство, используйте одинаковые параметры хранилища для планирования и установки:

```bash
minios-deploy plan /dev/sdb --mode native --placement free_space \
  --filesystem ext4 --boot-layout auto
sudo minios-deploy install /dev/sdb --mode native --placement free_space \
  --filesystem ext4 --boot-layout auto --security-profile balanced \
  --download-packages --yes
```

Нативная конвертация может не отображаться в справке CLI на образах без поддержки native-install. В CLI также можно указать параметры для учетных записей, локали, часового пояса, клавиатуры, имени хоста, служб и базового `config.conf`. Проверьте доступные параметры у запущенного образа:

```bash
minios-deploy install --help
man minios-deploy
```

Избегайте использования `--password` и `--root-password` в общих средах, так как аргументы командной строки в открытом виде могут попасть в историю команд или список процессов. Вместо этого используйте графический установщик или защищенный способ настройки.
