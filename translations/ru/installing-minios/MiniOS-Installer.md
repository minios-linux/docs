# MiniOS Установщик

MiniOS Установщик — это мастер на GTK и консольный бэкенд для развертывания системы из работающей сессии MiniOS в live-режиме. Запись или копирование MiniOS на съемный носитель уже является методом установки; MiniOS Установщик — это управляемый инструмент развертывания, который используется, когда вам нужен контролируемый макет целевой системы, настройка персистентности или опциональная конвертация в нативный режим.

## Перед началом

Неправильный выбор целевого диска или разметки может привести к потере данных. Сделайте резервные копии важных файлов, отключите ненужные диски и определите целевой диск по пути устройства, модели и объему. Последнее подтверждение — это финальная точка, на которой установку еще можно безопасно отменить.

Диск с запущенной live-системой MiniOS не отображается в списке доступных для установки. Для общей информации о требованиях к объему обратитесь к [Руководству по совместимости оборудования](/getting-started/Hardware-Compatibility).

## Режимы установки

**Live-режим** копирует выбранные сжатые модули MiniOS и загрузочные компоненты. Результат остается MiniOS: сохраняется модульная структура live-системы, конфигурация загрузки MiniOS, рабочие процессы управления MiniOS и, при необходимости, персистентность сессии.

**Нативный режим** создает стандартную рабочую среду Debian из выбранного образа MiniOS. Выбранные модули разворачиваются в доступную для записи корневую файловую систему, сохраняется выбранная рабочая среда и обычные приложения, удаляются live-окружение MiniOS и специфичные для live-режима утилиты, устанавливаются необходимые пакеты Debian, генерируется стандартный initramfs и устанавливается загрузчик. Установщик определяет поддержку нативного режима по загруженному образу. Если отсутствуют необходимые метаданные ядра и архитектурный контракт EFI, режим совместимости разрешает только live-установку.

::: warning Нативный режим меняет способ управления системой
Установленная система сохраняет привычный опыт использования MiniOS рабочего стола — его внешний вид, выбранную среду и стандартные приложения — но больше не использует архитектуру MiniOS live. В процессе конвертации установщик удаляет пакеты `minios-*` и другие утилиты live-режима, поскольку сессии, модули `.sb`, модульное управление ядром и конфигурация загрузки live больше не применяются. После перезагрузки систему можно обслуживать как обычный рабочий стол Debian с помощью APT, пакетов ядра Debian, стандартного initramfs и установленного загрузчика. Подробнее см. [О MiniOS](/getting-started/About-MiniOS).
:::

Это развертывание отличается от простой записи ISO, мультизагрузочной настройки ISO-файлов Ventoy или установки live-системы на основе файлов. Для различий см. [Методы установки](/installing-minios/Installation-Methods).

## Запуск графического установщика

Откройте меню приложений, выберите раздел "Система", затем — "Установщик MiniOS". Также его можно запустить из терминала:

```bash
sudo minios-installer
```

Мастер установки собирает параметры режима установки, безопасности, местоположения, проводной сети, клавиатуры, учетной записи, модулей, хранилища и загрузки. Перед финальным подтверждением внимательно проверьте схему разделов и сводку операций.

## Размещение и схемы загрузки

Графический установщик предлагает следующие варианты размещения, если целевой диск подходит:

- Стереть все — создает новую таблицу разделов и уничтожает все данные на целевом диске.
- Свободное пространство — использует подходящее неразмеченное пространство без уменьшения существующей файловой системы.
- Рядом — уменьшает подходящий, размонтированный финальный раздел ext2, ext3, ext4 или NTFS. Грязные, смонтированные, вложенные, неоднозначные и иные небезопасные схемы не поддерживаются. Установщик может запросить разрешение на загрузку недостающих инструментов для работы с файловыми системами.
- Ручное разметка доступна только для нативных конверсий в графическом интерфейсе на подходящих прямых дисках. Изменения применяются только после окончательного подтверждения.

Автоматические схемы загрузки: BIOS/MBR, UEFI/MBR и UEFI/GPT. UEFI работает с GPT или основной MBR-схемой. BIOS поддерживается только на основной MBR, не на GPT. Схемы с расширенными или логическими разделами MBR не поддерживаются.

В ручном режиме можно создавать, удалять, форматировать и повторно использовать разделы; уменьшать поддерживаемую файловую систему с конца; назначать точки монтирования, раздел EFI и swap; а также отменять или сбрасывать подготовленные изменения. Не поддерживаются LVM, RAID, нативные корни LUKS, отображаемое или вложенное хранилище, bcache, ZFS и редактирование подтомов Btrfs. Персистентность сессии LUKS не шифрует корневую файловую систему в нативном режиме.

## Файловые системы

- Live-схемы могут использовать ext2, ext4, Btrfs, FAT32 или NTFS при наличии необходимых инструментов.
- Корневая файловая система, созданная при нативной конверсии, может быть ext2, ext4 или Btrfs. По умолчанию используется ext4 как универсальный вариант.
- Существующие файловые системы ext3 могут быть повторно использованы или уменьшены там, где это поддерживается, но ext3 не предлагается для нового форматирования.
- FAT32 ограничен файлами размером до 4 ГиБ и доступен только для live-схем.
- NTFS доступен только для live-схем, хотя подходящий раздел NTFS может быть уменьшен для размещения рядом.

Требуемое пространство включает выбранные данные модулей, загрузочные компоненты, запрошенную персистентность и резерв файловой системы в 25 процентов. EFI и swap в нативном режиме рассчитываются отдельно.

## Конфигурация и безопасность

Установщик может настроить локаль, часовой пояс, раскладку клавиатуры, имя пользователя, пароли, группы пользователей, имя хоста, службы, загрузочное меню и выбор модулей. Выбор более высокого модуля MiniOS включает все необходимые нижележащие слои.

Профили безопасности: `convenient`, `balanced` и `strict`. В live-режиме по умолчанию используется `convenient`; при нативной конверсии стартует с `balanced`. Управление SSH и XRDP осуществляется отдельно от выбранного профиля. Проверьте службы удаленного доступа перед первым сетевым подключением. После нативной конверсии последующая настройка безопасности выполняется по стандартному административному процессу Debian.

Настройка сети включает имя хоста и проводной DHCP или статический IPv4. Установщик не создает и не изменяет Wi-Fi-профили. Для нативной конверсии и некоторых операций "рядом" может потребоваться доступ в интернет (с вашего согласия) для получения GRUB, EFI, initramfs, `os-prober` или пакетов для изменения размера файловой системы до внесения изменений на диск.

## Персистентность live-сессии

Персистентность применяется только к live-установкам:

- Режим персистентности `native` сохраняет изменения live-сессии напрямую на целевой файловой системе с поддержкой POSIX. Несмотря на название, это **бэкенд live-персистентности** и не связан с нативной установкой. Не поддерживается на FAT32 и NTFS.
- DynFileFS использует расширяемый контейнер.
- Raw использует контейнер фиксированного размера.
- LUKS использует зашифрованный образ, который создается initrd при первой загрузке. Пароль запрашивается при загрузке и никогда не передается и не сохраняется установщиком.

Для контейнерных режимов по умолчанию используется 4000 МиБ. Контейнеры Raw и LUKS не могут превышать 4000 МиБ на FAT32; DynFileFS не ограничен этим лимитом на размер одного файла. LUKS предлагается только если и работающий initrd, и каждый копируемый исходный initrd поддерживают необходимое шифрование.

В результате в загрузочных опциях используются `perchmode` и `perchsize`. Подробнее о работе и требованиях к активации см. [Персистентность initrd](/reference/boot-process/Persistence-Internals) и [Параметры загрузки](/reference/Boot-Parameters).

## Развертывание из командной строки

`minios-deploy` предназначен для автоматизации, тестирования и восстановления. Ручная разметка и интерактивная настройка проводной сети доступны только в графическом интерфейсе.

Список дисков, распознанных как доступные для установки:

```bash
minios-deploy list-disks
```

Замените `/dev/sdb` в каждом примере на проверенный целевой диск. Сначала выведите недеструктивный план:

```bash
minios-deploy plan /dev/sdb --mode live --placement free_space \
  --filesystem ext4 --persistence-mode dynfilefs --persistence-size 8000
```

Просмотрите соответствующие команды развертывания без записи на диск:

```bash
sudo minios-deploy install /dev/sdb --mode live --placement free_space \
  --filesystem ext4 --persistence-mode dynfilefs --persistence-size 8000 \
  --security-profile balanced --dry-run
```

Запускайте реальную установку только после проверки плана, выбранного диска и вывода пробного запуска. `--yes` подтверждает выполнение деструктивных изменений:

```bash
sudo minios-deploy install /dev/sdb --mode live --placement free_space \
  --filesystem ext4 --persistence-mode dynfilefs --persistence-size 8000 \
  --security-profile balanced --yes
```

Если вы намеренно хотите выполнить нативную конверсию в существующее свободное пространство, используйте одинаковые параметры хранилища для планирования и установки:

```bash
minios-deploy plan /dev/sdb --mode native --placement free_space \
  --filesystem ext4 --boot-layout auto
sudo minios-deploy install /dev/sdb --mode native --placement free_space \
  --filesystem ext4 --boot-layout auto --security-profile balanced \
  --download-packages --yes
```

Нативная конверсия может не отображаться в CLI-подсказке для образа без поддержки native-install. В CLI также поддерживаются параметры для настройки учетных записей, локали, часового пояса, раскладки клавиатуры, имени хоста, служб и базового `config.conf`. Точные параметры, доступные в текущем образе, можно посмотреть так:

```bash
minios-deploy install --help
man minios-deploy
```

Избегайте использования `--password` и `--root-password` в общих средах, так как аргументы командной строки в открытом виде могут быть видны в истории shell и списке процессов. Используйте графический установщик или защищенный процесс настройки.
