# Установщик MiniOS

Установщик MiniOS — это мастер на базе GTK и командная утилита для развертывания системы из работающей live-сессии MiniOS. Запись или копирование MiniOS на съемный носитель уже является методом установки; Установщик MiniOS используется для управляемого развертывания, когда требуется контролируемая структура разделов, настройка персистентности или опциональная конвертация в нативный режим.

## Перед началом

Неправильный выбор целевого диска или разметки может привести к потере данных. Сделайте резервные копии важных файлов, отключите ненужные диски и определите целевой диск по пути устройства, модели и объему. Последнее подтверждение — это последняя возможность безопасно отменить установку.

Диск, на котором запущена live-система MiniOS, исключается из выбора цели. Для общей информации о требуемом объеме см. [Руководство по совместимости оборудования](/getting-started/Hardware-Compatibility).

## Режимы установки

**Live-режим** копирует выбранные сжатые модули MiniOS и загрузочные файлы. Результат остается MiniOS: сохраняется модульная структура live-системы, загрузочная конфигурация MiniOS, процессы управления MiniOS и, при необходимости, персистентность сессии.

**Нативный режим** создает классическую рабочую среду Debian из выбранного образа MiniOS. Выбранные модули разворачиваются в доступную для записи корневую файловую систему, сохраняются выбранная среда рабочего стола и обычные приложения, удаляются live-окружение MiniOS и специфичные для live-режима утилиты, устанавливаются необходимые пакеты Debian, генерируется стандартный initramfs и устанавливается загрузчик. Установщик определяет поддержку нативного режима по загруженному образу. Если отсутствуют необходимые метаданные ядра и архитектурная поддержка EFI, в режиме совместимости доступна только установка в live-режиме.

::: warning Нативный режим меняет способ управления системой
Установленная система сохраняет привычный пользовательский опыт MiniOS — внешний вид, выбранную среду рабочего стола и стандартные приложения — но больше не использует архитектуру live-системы MiniOS. Во время конвертации установщик удаляет `minios-*` пакеты и другие утилиты, связанные с live-режимом, так как сессии, `.sb` модули, модульное управление ядром и загрузочная конфигурация live больше не применяются. После перезагрузки обслуживайте систему как обычный рабочий стол Debian с помощью APT, пакетов ядра Debian, стандартного initramfs и установленного загрузчика. Подробнее см. [О MiniOS](/getting-started/About-MiniOS).
:::

Это развертывание отличается от простой записи ISO, мультизагрузки ISO-файла Ventoy или установки live-системы на основе файлов. Подробнее см. [Методы установки](/installing-minios/Installation-Methods) для различий.

## Запуск графического установщика

Откройте меню приложений, выберите «Система», затем выберите Установщик MiniOS. Также его можно запустить из терминала:

```bash
sudo minios-installer
```

Мастер установки собирает параметры режима установки, безопасности, местоположения, проводной сети, клавиатуры, учетной записи, модулей, хранилища и загрузки. Проверьте точную схему разделов и итоговое описание операций перед окончательным подтверждением, которое приведет к необратимым изменениям.

## Размещение и схемы загрузки

Графический установщик предлагает следующие варианты размещения, если целевой диск подходит:

- «Стереть всё» создаёт новую таблицу разделов и уничтожает все данные на целевом диске.
- «Свободное пространство» использует подходящий неразмеченный участок без уменьшения существующей файловой системы.
- «Рядом» уменьшает подходящий, размонтированный последний раздел ext2, ext3, ext4 или NTFS. Грязные, смонтированные, вложенные, неоднозначные и иные небезопасные схемы отклоняются. При необходимости установщик может запросить загрузку недостающих инструментов для работы с файловыми системами.
- Ручное разметка доступна только для нативных конвертаций в графическом интерфейсе на подходящих физических дисках. Изменения применяются только после окончательного подтверждения.

Автоматические схемы загрузки: BIOS/MBR, UEFI/MBR и UEFI/GPT. UEFI работает с GPT или основной MBR-разметкой. BIOS поддерживается только на основной MBR, не на GPT. Расширенные или логические MBR-схемы не поддерживаются.

В ручном режиме можно создавать, удалять, форматировать и повторно использовать разделы; уменьшать поддерживаемую файловую систему с конца; назначать точки монтирования, EFI-раздел и swap; а также отменять или сбрасывать подготовленные изменения. Не поддерживаются LVM, RAID, нативные корни LUKS, отображаемое или вложенное хранилище, bcache, ZFS и редактирование подтомов Btrfs. Шифрование LUKS2 для live-персистентности не шифрует корневую файловую систему в нативном режиме.

## Файловые системы

- Live-схемы могут использовать ext2, ext4, Btrfs, FAT32 или NTFS при наличии необходимых инструментов.
- Корневая файловая система, созданная при нативной конвертации, может быть ext2, ext4 или Btrfs. По умолчанию используется ext4 как универсальный вариант.
- Существующие файловые системы ext3 могут быть повторно использованы или уменьшены, если это поддерживается, но ext3 не предлагается для нового форматирования.
- FAT32 ограничен файлами размером до 4 ГиБ и доступен только для live-схем.
- NTFS доступен только для live-схем, однако подходящий раздел NTFS может быть уменьшен для размещения рядом.

Требуемое пространство включает данные выбранных модулей, загрузочные файлы, запрошенную персистентность и резерв файловой системы в 25 процентов. EFI и swap в нативном режиме рассчитываются отдельно.

## Конфигурация и безопасность

Установщик может настроить локаль, часовой пояс, клавиатуру, имя пользователя, пароли, группы пользователей, имя хоста, службы, меню загрузки и выбор модулей. При выборе более высокого модуля MiniOS автоматически добавляются все необходимые нижние уровни.

Профили безопасности: `convenient`, `balanced`, и `strict`. По умолчанию в live-режиме используется `convenient`; при нативной конвертации начальная настройка — `balanced`. Управление SSH и XRDP осуществляется отдельно от выбранного профиля. Проверьте службы удаленного доступа до первого сетевого подключения. После нативной конвертации дальнейшая настройка безопасности выполняется стандартными средствами администрирования Debian.

Сетевые настройки включают имя хоста и проводную сеть с DHCP или статическим IPv4. Установщик не создает и не изменяет Wi-Fi-профили. Для нативной конвертации и некоторых операций «рядом» может потребоваться доступ в сеть (с вашего согласия) для получения GRUB, EFI, initramfs, `os-prober`, или пакетов для изменения размера файловой системы до внесения изменений на диск.

## Персистентность live-сессии

Персистентность применяется только к live-установкам. Когда `minios-session` доступна, Установщик MiniOS может создать и активировать настоящую нумерованную сессию непосредственно на целевом диске до завершения установки. **Автоматическая настройка при первой загрузке** пропускает этот шаг; MiniOS затем сможет создать хранилище сессии позже с помощью стандартной логики персистентности при загрузке.

Установщик предлагает следующие варианты хранилища, если их поддерживают текущая система и целевой диск:

- `native` сохраняет изменения live-сессии непосредственно в каталоге сессии на целевой файловой системе с поддержкой POSIX. Несмотря на название, это **бэкенд персистентности live-сессии** и не связан с нативной установкой. Не предлагается на FAT32 или NTFS.
- DynFileFS создает расширяемое хранилище ext4 на основе файла. Выбранный размер — это логический максимум, а не заранее зарезервированное место. Размер по умолчанию — 4000 МиБ.
- DynBlk создает файловую систему ext4 на тонком блочном устройстве, предоставляемом драйвером ядра DynBlk. Данные сессии хранятся в сегментированных `volumeNNN.db` файлах, которые создаются по мере необходимости, поэтому выбранный размер — это логический максимум, а не фактическое использование диска. По умолчанию новые сессии DynBlk имеют размер 16384 МиБ. Для нешифрованных сессий DynBlk установщик может выбрать кодек сжатия, поддерживаемый и текущей системой, и скопированным initrd на целевом диске.
- VMDK использует драйвер DynBlk для создания стандартного раздельного разреженного хранилища VMDK (`volume.vmdk` и `volume-sNNN.vmdk`). Модель выделения пространства такая же, как у DynBlk, и по умолчанию 16384 МиБ, но сжатие на уровне бэкенда недоступно.
- Raw создает ext4-образ фиксированного размера и сразу резервирует выбранный объем. Размер по умолчанию — 4000 МиБ.

LUKS2 — это отдельный слой шифрования, который может быть применен к Raw, DynFileFS, DynBlk или хранилищу сессии VMDK. Установщик запрашивает подтвержденную парольную фразу только при создании сессии и передает её `minios-session` через стандартный ввод, не помещая её в аргументы командной строки, логи или постоянную конфигурацию. Парольная фраза потребуется при разблокировке зашифрованной сессии при загрузке. LUKS2 предлагается только при наличии совместимой поддержки в текущей среде и скопированном initrd на целевом диске. Сжатие DynBlk отключается при выборе LUKS2.

DynBlk и хранилище VMDK недоступны при включенном UEFI Secure Boot, поскольку внешний модуль ядра DynBlk, используемый этими бэкендами, не подписан MiniOS. Контейнеры Raw ограничены 4000 МиБ на FAT32; DynFileFS, DynBlk и раздельные VMDK не зависят от одного файла размером более 4 ГиБ, хотя для них действуют ограничения самого бэкенда и свободного места.

Поскольку установщик создает и активирует выбранную сессию на целевом диске, он не зависит от `perchmode` и `perchsize` для создания этого хранилища при первой загрузке. Эти параметры загрузки по-прежнему описывают создание и выбор персистентности через initrd вне сценария, когда сессия заранее создана установщиком. Подробнее см. [Управление сессиями](/using-minios/Sessions-and-Persistence), [Персистентность initrd](/reference/boot-process/Persistence-Internals), и [Параметры загрузки](/reference/Boot-Parameters).

## Развертывание через командную строку

`minios-deploy` предназначено для автоматизации, тестирования и восстановления. Ручная разметка и интерактивная настройка проводной сети доступны только в графическом интерфейсе.

Выведите список дисков, доступных для установки:

```bash
minios-deploy list-disks
```

Замените `/dev/sdb` во всех примерах на проверенный целевой диск. Сначала выведите недеструктивный план:

```bash
minios-deploy plan /dev/sdb --mode live --placement free_space \
  --filesystem ext4 --persistence-mode dynfilefs --persistence-size 8000
```

Просмотрите соответствующие команды развертывания без записи на диск:

```bash
sudo minios-deploy install /dev/sdb --mode live --placement free_space \
  --filesystem ext4 --persistence-mode dynfilefs --persistence-size 8000 \
  --security-profile balanced --dry-run
```

Запускайте реальную установку только после проверки плана, идентификации цели и вывода пробного запуска. `--yes` подтверждает выполнение изменений, приводящих к потере данных:

```bash
sudo minios-deploy install /dev/sdb --mode live --placement free_space \
  --filesystem ext4 --persistence-mode dynfilefs --persistence-size 8000 \
  --security-profile balanced --yes
```

Если вы намеренно хотите выполнить нативную конвертацию в существующее свободное пространство, используйте те же параметры хранилища для планирования и установки:

```bash
minios-deploy plan /dev/sdb --mode native --placement free_space \
  --filesystem ext4 --boot-layout auto
sudo minios-deploy install /dev/sdb --mode native --placement free_space \
  --filesystem ext4 --boot-layout auto --security-profile balanced \
  --download-packages --yes
```

Нативная конвертация может не отображаться в справке CLI для образов без поддержки native-install. В CLI также можно указать параметры для учетных записей, локали, часового пояса, клавиатуры, имени хоста, служб и базового `config.conf`. Проверьте доступные параметры для текущего образа:

```bash
minios-deploy install --help
man minios-deploy
```

Избегайте передачи `--password` и `--root-password` в общих средах, так как аргументы командной строки в открытом виде могут быть видны в истории оболочки и списке процессов. Используйте графический установщик или защищенный сценарий настройки.
