# Установщик MiniOS

Установщик MiniOS — это мастер на базе GTK и командная утилита для развертывания системы из работающей live-сессии MiniOS. Запись или копирование MiniOS на съемный носитель уже является методом установки; Установщик MiniOS используется для управляемого развертывания, когда требуется контролируемая структура разделов, настройка персистентности или опциональная конвертация в нативный режим.

## Перед началом

Неправильный выбор целевого диска или разметки может привести к потере данных. Сделайте резервные копии важных файлов, отключите ненужные диски и определите целевой диск по пути устройства, модели и объему. Последнее подтверждение — это последняя возможность безопасно отменить установку.

Диск, на котором запущена live-система MiniOS, исключается из выбора цели. Для общей информации о требуемом объеме см. [Руководство по совместимости оборудования](/getting-started/Hardware-Compatibility).

## Режимы установки

**Live-режим** копирует выбранные сжатые модули MiniOS и загрузочные файлы. Результат остается MiniOS: сохраняется модульная структура live-системы, загрузочная конфигурация MiniOS, процессы управления MiniOS и, при необходимости, персистентность сессии.

**Нативный режим** создает классическую рабочую среду Debian из выбранного образа MiniOS. Выбранные модули разворачиваются в доступную для записи корневую файловую систему, сохраняются выбранная среда рабочего стола и обычные приложения, удаляются live-окружение MiniOS и специфичные для live-режима утилиты, устанавливаются необходимые пакеты Debian, генерируется стандартный initramfs и устанавливается загрузчик. Установщик определяет поддержку нативного режима по загруженному образу. Если отсутствуют необходимые метаданные ядра и архитектурная поддержка EFI, в режиме совместимости доступна только установка в live-режиме.

::: warning Нативный режим меняет способ управления системой
Установленная система сохраняет привычный пользовательский опыт MiniOS — внешний вид, выбранную среду рабочего стола и стандартные приложения — но больше не использует архитектуру live-системы MiniOS. Во время конвертации установщик удаляет `minios-*` пакеты и другие утилиты, связанные с live-режимом, так как сессии, `.sb` модули, модульное управление ядром и загрузочная конфигурация live больше не применяются. После перезагрузки обслуживайте систему как обычный рабочий стол Debian с помощью APT, пакетов ядра Debian, стандартного initramfs и установленного загрузчика. Подробнее см. [О MiniOS](/getting-started/About-MiniOS).
:::

Это развертывание отличается от простой записи ISO, мультизагрузки ISO-файла Ventoy или установки live-системы на основе файлов. Подробнее см. [Методы установки](/installing-minios/Installation-Methods) для различий.

## Запуск графического установщика

Откройте Установщик MiniOS из **MiniOS** категории меню приложений. Также можно запустить из терминала — при необходимости потребуется авторизация администратора:

```bash
minios-installer
```

Мастер установки собирает параметры режима установки, безопасности, расположения, проводной сети, клавиатуры, учетной записи, модулей, хранилища и загрузки. Перед окончательным подтверждением внимательно проверьте схему разметки разделов и сводку операций, так как изменения будут необратимы.

## Размещение и схемы загрузки

Графический установщик предлагает следующие варианты размещения, если целевой диск подходит:

- Стереть всё — создаёт новую таблицу разделов и удаляет все данные на целевом диске.
- Свободное пространство — использует подходящее неразмеченное пространство без уменьшения существующей файловой системы.
- Рядом — уменьшает подходящий, размонтированный последний раздел ext2, ext3, ext4 или NTFS. Грязные, смонтированные, вложенные, неоднозначные и иные небезопасные схемы отклоняются. Установщик может запросить подтверждение перед загрузкой недостающих инструментов для работы с файловыми системами.
- Ручное разметка доступна только для нативных преобразований в графическом интерфейсе на подходящих физических дисках. Изменения применяются только после окончательного подтверждения.

Автоматические схемы загрузки: BIOS/MBR, UEFI/MBR и UEFI/GPT. UEFI работает с GPT или основными MBR-схемами. BIOS поддерживается только на основных MBR, но не на GPT. Сохранение расширенных или логических MBR-схем не поддерживается.

Для **Стереть всё** в режиме Live **Автоматически** выбирает MBR даже при запуске установщика в режиме UEFI. Для Live-установки на MBR сохраняются EFI-файлы и устанавливается загрузчик BIOS, что позволяет использовать оба режима прошивки. Для дисков объёмом 2 ТиБ и более требуется явный выбор **UEFI/GPT**; Live-установки на GPT поддерживают только UEFI. Нативное стирание всего следует отдельной политике, зависящей от прошивки. Установка в свободное пространство и рядом сохраняет существующую таблицу разделов.

В ручном режиме можно создавать, удалять, форматировать и повторно использовать разделы; уменьшать поддерживаемую файловую систему с конца; назначать точки монтирования, EFI-раздел и swap; а также отменять или сбрасывать подготовленные изменения. Не поддерживаются LVM, RAID, нативные корневые LUKS, отображаемые или вложенные хранилища, bcache, ZFS и редактирование подтомов Btrfs. Шифрование LUKS2 для live-сессии с сохранением не шифрует нативную корневую файловую систему.

## Файловые системы

- Live-схемы могут использовать ext2, ext4, Btrfs, FAT32 или NTFS при наличии необходимых инструментов.
- Корневая файловая система, созданная при нативной конвертации, может быть ext2, ext4 или Btrfs. По умолчанию используется ext4 как универсальный вариант.
- Существующие файловые системы ext3 могут быть повторно использованы или уменьшены, если это поддерживается, но ext3 не предлагается для нового форматирования.
- FAT32 ограничен файлами размером до 4 ГиБ и доступен только для live-схем.
- NTFS доступен только для live-схем, однако подходящий раздел NTFS может быть уменьшен для размещения рядом.

Требуемое пространство включает данные выбранных модулей, загрузочные файлы, запрошенную персистентность и резерв файловой системы в 25 процентов. EFI и swap в нативном режиме рассчитываются отдельно.

## Конфигурация и безопасность

Установщик позволяет настроить язык системы, часовой пояс, раскладку клавиатуры, имя пользователя, пароли, группы пользователей, имя хоста, службы, загрузочное меню и выбор модулей. При выборе более высокого уровня системы автоматически включаются все необходимые нижележащие уровни. Пользовательские модули из `minios/modules/` выбираются отдельно, даже если их имена похожи на системные или модуль ядра.

Профили безопасности могут быть `convenient`, `balanced` или `strict`. В режиме Live по умолчанию используется `convenient`; при нативном преобразовании используется `balanced`. Управление SSH и XRDP осуществляется отдельно от выбранного профиля. Перед первым подключением к сети рекомендуется проверить службы удалённого доступа. После нативного преобразования дальнейшая настройка безопасности выполняется стандартными средствами администрирования Debian.

Сетевые настройки включают имя хоста и проводное подключение через DHCP или статический IPv4. Установщик не создаёт и не изменяет Wi-Fi профили. Для нативного преобразования и некоторых параллельных операций может потребоваться доступ к сети (с вашего согласия) для загрузки GRUB, EFI, initramfs, `os-prober`, либо пакетов для изменения размера файловой системы до внесения изменений на диск.

## Сохранение живой сессии

Сохранение применяется только к live-установкам. Когда `minios-session` доступен, Установщик MiniOS может создать и активировать полноценную пронумерованную сессию непосредственно на целевом устройстве до завершения установки. **Автоматическая настройка при первом запуске** пропускает этот шаг; MiniOS затем может создать хранилище сессии позже с помощью своей стандартной логики сохранения при загрузке.

Установщик предлагает следующие типы хранилищ, если их поддерживают работающая система и целевое устройство:

- `native` сохраняет изменения live-сессии напрямую в каталоге сессии на целевой файловой системе с поддержкой POSIX. Несмотря на название, это **бэкенд живого сохранения** и не связан с полноценной установкой. Не поддерживается на FAT32 или NTFS.
- DynFileFS создает расширяемое хранилище ext4 на основе файла. Выбранный размер — это логический максимум, а не заранее зарезервированное пространство. Размер по умолчанию — 4000 Миб.
- DynBlk создает файловую систему ext4 на тонком блочном устройстве, предоставляемом драйвером ядра DynBlk. Данные сессии хранятся в сегментированных `volumeNNN.db` файлах, которые выделяются по мере необходимости, поэтому выбранный размер — это логический максимум, а не заранее выделенное место на диске. По умолчанию новые сессии DynBlk создаются с размером 16384 Миб. Для нешифрованных сессий DynBlk установщик может выбрать кодек сжатия, поддерживаемый как работающей системой, так и initrd, скопированным на целевое устройство.
- VMDK использует драйвер DynBlk для создания стандартного раздельного разреженного хранилища VMDK (`volume.vmdk` и `volume-sNNN.vmdk`). Модель выделения пространства аналогична thin-allocation и по умолчанию составляет 16384 Миб, как у DynBlk, но сжатие на уровне бэкенда недоступно.
- Raw создает ext4-образ фиксированного размера и сразу резервирует выбранную емкость. Размер по умолчанию — 4000 Миб.

LUKS2 — это отдельный слой шифрования, который может использоваться поверх Raw, DynFileFS, DynBlk или VMDK-хранилища сессии. Установщик запрашивает подтвержденную парольную фразу только при создании сессии и передает её в `minios-session` через стандартный ввод, не помещая её в параметры командной строки, логи или постоянные настройки. Парольная фраза потребуется при разблокировке зашифрованной сессии при загрузке. LUKS2 предлагается только если рабочая среда и скопированный initrd целевого устройства поддерживают совместимую работу. Сжатие DynBlk отключается при выборе LUKS2.

DynBlk и хранилище сессий VMDK недоступны при включенном UEFI Secure Boot, так как внешний модуль ядра DynBlk, используемый этими бэкендами, не подписан MiniOS. Контейнеры Raw ограничены 4000 Миб на FAT32; DynFileFS, DynBlk и раздельное хранилище VMDK не зависят от ограничения FAT32 на размер одного файла в 4 ГиБ, хотя для них действуют собственные лимиты бэкенда и свободного места.

Поскольку установщик создает и активирует выбранную сессию непосредственно на целевом устройстве, ему не требуется `perchmode` и `perchsize` для создания этого хранилища при первом запуске. Эти параметры загрузки по-прежнему описывают создание и выбор сохранения сессии через initrd вне сценария сессии, заранее созданной установщиком. Подробнее см. разделы [Управление сессиями](/using-minios/Sessions-and-Persistence), [Сохранение в initrd](/reference/boot-process/Persistence-Internals), и [Параметры загрузки](/reference/Boot-Parameters).

## Развёртывание из командной строки

`minios-deploy` предназначено для автоматизации, тестирования и восстановления. Ручное разбиение и интерактивная настройка проводной сети доступны только в графическом интерфейсе.

Просмотрите список дисков, доступных для установки:

```bash
minios-deploy list-disks
```

Замените `/dev/sdb` во всех примерах на проверенный целевой диск. Сначала выведите недеструктивный план:

```bash
minios-deploy plan /dev/sdb --mode live --placement free_space \
  --filesystem ext4 --persistence-mode dynfilefs --persistence-size 8000
```

Просмотрите подходящие команды для развёртывания без записи на диск:

```bash
sudo minios-deploy install /dev/sdb --mode live --placement free_space \
  --filesystem ext4 --persistence-mode dynfilefs --persistence-size 8000 \
  --security-profile balanced --dry-run
```

Запускайте реальную установку только после проверки плана, идентификатора цели и вывода пробного запуска. `--yes` подтверждает выполнение необратимых изменений:

```bash
sudo minios-deploy install /dev/sdb --mode live --placement free_space \
  --filesystem ext4 --persistence-mode dynfilefs --persistence-size 8000 \
  --security-profile balanced --yes
```

Если вы намеренно хотите выполнить нативную установку в существующее свободное пространство, используйте те же параметры хранилища для планирования и установки:

```bash
minios-deploy plan /dev/sdb --mode native --placement free_space \
  --filesystem ext4 --boot-layout auto
sudo minios-deploy install /dev/sdb --mode native --placement free_space \
  --filesystem ext4 --boot-layout auto --security-profile balanced \
  --download-packages --yes
```

Нативная установка может быть недоступна в справке CLI, если образ не поддерживает native-install. В CLI также принимаются параметры для настройки учётных записей, локали, часового пояса, клавиатуры, имени хоста, служб и базового `config.conf`. Проверьте доступные параметры для текущего образа:

```bash
minios-deploy install --help
man minios-deploy
```

Избегайте использования `--password` и `--root-password` в общих средах, так как аргументы командной строки в открытом виде могут попасть в историю команд или список процессов. Вместо этого используйте графический установщик или защищённый способ настройки.
