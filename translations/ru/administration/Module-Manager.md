# MiniOS Module Manager

MiniOS Module Manager — это графическое приложение для просмотра, создания и управления модулями MiniOS `.sb`. В нём есть две рабочие области: **Модули** для компоновки системы и **Создать** для создания новых модулей.

Запустить приложение можно из меню приложений или командой:

```bash
minios-module-manager
```

Само приложение работает от имени вашего пользователя в системе. Запрос на ввод пароля администратора появляется только при выполнении операций, требующих прав администратора.

## Текущий запуск и следующая загрузка

Рабочая область «Модули» содержит два отдельных представления:

- **Текущий запуск** — это упорядоченный набор модулей, из которых сейчас состоит живая система.
- **Следующая загрузка** — это упорядоченный набор, выбранный текущими правилами загрузки MiniOS.

Изменение одного представления не изменяет другое автоматически. Например, **Активировать для этой сессии** влияет только на текущую систему, а **Добавить в следующую загрузку** копирует модуль в постоянное хранилище модулей без его активации сейчас.

Активация и деактивация модулей в реальном времени доступны только при использовании AUFS в качестве корневой файловой системы. Они недоступны при OverlayFS, даже если ядро поддерживает AUFS. Базовые модули нельзя деактивировать через приложение.

Изменения для следующей загрузки возможны только если MiniOS обнаруживает подходящее постоянное и доступное для записи хранилище модулей. Базовые модули, а также модули на только для чтения или временных носителях удалить нельзя. Фильтры загрузки, такие как `load`, `noload` и `bext`, по-прежнему определяют, какие модули будут выбраны.

## Просмотр модуля

Выберите модуль, чтобы увидеть его источник, сжатый размер и содержимое файловой системы. Если исходный файл доступен, **Извлечь в папку** создаст новую директорию с файлами модуля.

Для просмотра и обычного извлечения не требуются права администратора. Извлечение никогда не заменяет уже существующую папку назначения.

Вы также можете открыть локальный файл `.sb` из файлового менеджера. Открытие файла только позволяет просмотреть его; это не активирует модуль и не добавляет его в следующую загрузку.

## Создание модуля

Рабочая область «Создать» использует последовательность **Настройка**, **Проверка**, **Выполнение** и **Результат**. Успешно созданный модуль остаётся файлом по указанному пути. Он не активируется и не добавляется в следующую загрузку автоматически.

Доступные методы:

- **Пакеты** устанавливает пакеты из репозиториев и выбранные локальные файлы `.deb` вместе с их зависимостями в изолированной среде сборки MiniOS. Для установки пакетов требуется аутентификация администратора.
- **Скрипт установки** запускает проверенный скрипт без интерактивного терминала. Необязательная исходная папка может содержать начальные файлы. Скрипт выполняется с правами администратора, но не сохраняется в итоговом модуле.
- **Интерактивный chroot** открывает временную root-оболочку во встроенном терминале. Введите `exit` для завершения, затем создайте модуль, снова откройте оболочку или отмените изменения. Закрытие или отмена сессии не влияет на работающую систему.
- **Папка** упаковывает содержимое существующей директории. Сама исходная папка не будет вложена внутрь модуля. Обычное преобразование папки не требует root-прав, не изменяет исходные данные и нормализует владельца файлов в модуле до root.
- **Изменения текущей сессии** захватывает подходящие файлы и удаления из текущего записываемого слоя сессии. Используется стандартная политика MiniOS `savechanges`, которая исключает логи, кэш, загрузочные данные и временные системные пути. Для чтения всего слоя требуется аутентификация администратора.

Выбирайте новый путь вывода для каждого процесса. Существующие файлы никогда не перезаписываются. Ход выполнения и диагностика backend отображаются во время операции, захват изменений текущей сессии можно отменить.

Изменения текущей сессии предназначены для стандартного быстрого захвата, а не для детального просмотра всех путей. Живой записываемый слой может содержать личные или конфиденциальные данные. Для явных политик `exact`, `clean` или выбора путей используйте командную строку `savechanges`, как описано в разделе [Создание модулей](/development/Creating-Modules.md).

## Перетаскивание

Перетаскивание используется только для заполнения поля ввода или открытия просмотра:

- Модуль открывает свои детали.
- Файлы `.deb` добавляются в раздел «Пакеты».
- Директория выбирается для режима «Папка».
- Другой обычный файл выбирается как скрипт установки.

Перетаскивание не выполняет код и не изменяет состояния «Текущий запуск» или «Следующая загрузка».
