# MiniOS Store

MiniOS Store предоставляет каталог рецептов приложений на сайте [store.minios.dev](https://store.minios.dev). В MiniOS эти рецепты можно установить напрямую в работающую систему или использовать для создания одного или нескольких модулей SquashFS (`.sb`).

Для просмотра каталога локальный сервер не требуется. Для установки — требуется: веб-интерфейс либо подключается к локальному демону MiniOS Store, либо открывает установленный обработчик URI `minios-store://`.

## Перед установкой

Откройте страницу приложения и ознакомьтесь со следующей информацией перед добавлением его в корзину:

- Названия пакетов и способ установки.
- Скрипт установки, если он отображается.
- Домашняя страница приложения и информация о разработчике.
- Загружает ли рецепт отдельный пакет Debian.

Рецепты могут устанавливать пакеты через APT, загружать пакеты Debian или выполнять shell-скрипты. Все операции установки выполняются с правами root. Считайте рецепт и все его загрузки или репозитории привилегированным кодом.

## Установка приложения

1. Откройте MiniOS Store из меню приложений. Запуск проверяет `https://store.minios.dev` и открывает его в браузере по умолчанию.
2. Выполните поиск или выберите категорию, откройте подробности приложения и ознакомьтесь с пакетами или скриптом.
3. Добавьте одно или несколько приложений в корзину.
4. В live-сессии MiniOS выберите `Module` или `System`. В установленной системе MiniOS автоматически используется режим `System`.
5. Для нескольких приложений в модульном режиме выберите один объединённый модуль или отдельные модули. Объединённому модулю можно также задать собственное имя.
6. Выберите `Install` и следите за ходом выполнения и выводом команд. Страница использует локальный демон при статусе `Connected`; в противном случае будет использоваться обработчик URI, и может появиться запрос аутентификации PolicyKit.

Одновременно может выполняться только одна установка через демон. Закрытие окна прогресса не обязательно останавливает установку; чтобы просмотреть или отменить её, снова откройте индикатор установки.

## Модульный и системный режимы

### Модульный режим

В модульном режиме запускается `apt2sb` или `script2sb` в изолированной среде для сборки модулей. Полученные файлы `.sb` сохраняются в первую доступную для записи директорию из списка ниже:

1. `/run/initramfs/memory/data/minios/modules`
2. `/var/lib/minios-store/modules`

Первый путь — это директория модулей на текущем загрузочном носителе MiniOS. Модуль, созданный там, не активируется в текущей сессии через MiniOS Store. Оставьте модуль в этой директории и перезагрузите систему, чтобы он был загружен при следующем запуске. Результат сохраняется только при условии, что загрузочный носитель доступен для записи и файл не удалён.

Второй путь используется как резервный, если обычная директория модулей недоступна для записи. Модуль в резервной директории не подключается автоматически при следующей live-загрузке. Используйте `Open folder`, затем скопируйте готовый модуль в директорию `minios/modules` на загрузочном носителе MiniOS перед перезагрузкой.

Объединённый модуль содержит все выбранные рецепты. При раздельной упаковке сбой может затронуть только один рецепт, а ранее завершённые модули останутся в целевой директории.

### Системный режим

В системном режиме используется APT или скрипт рецепта напрямую для текущей корневой файловой системы. Изменения применяются сразу в текущей системе, а не в модуле. В live-сессии сохранение изменений после перезагрузки зависит от настроек постоянства сессии. В установленной системе MiniOS Store всегда использует системный режим.

Системный режим не является транзакционным. Неудачная или отменённая операция может оставить изменённые пакеты, состояние репозитория или файлы, изменённые предыдущими командами.

## Локальный сервис и граница доверия

Сервис `minios-store` работает от имени root, так как для сборки модулей и прямой установки пакетов требуются операции mount, overlay, chroot, APT и dpkg. По умолчанию он слушает только на `ws://127.0.0.1:8765`. Веб-интерфейс передаёт полные данные рецепта, включая скрипты и URL-адреса загрузки, этому локальному сервису.

Демон проверяет структуру запроса и поддерживаемый способ установки, но не выполняет независимую аутентификацию или подпись полезной нагрузки рецепта. Страница, имеющая доступ к локальной точке WebSocket, может запрашивать выполнение привилегированных операций установки. Поэтому:

- Оставляйте демон привязанным к `127.0.0.1`. Не открывайте порт `8765` для локальной сети или интернета.
- Не устанавливайте `MINIOS_STORE_HOST` на не-loopback-адрес без дополнительной, проверенной границы безопасности.
- Используйте официальный сайт Store по HTTPS и проверяйте рецепты перед установкой.
- Останавливайте или отключайте сервис, если установка через браузер не требуется.

Управляйте сервисом systemd с помощью:

```bash
sudo systemctl status minios-store
sudo systemctl start minios-store
sudo systemctl stop minios-store
sudo systemctl enable minios-store
sudo systemctl disable minios-store
```

Обработчик URI — это отдельный путь. Он запускает GTK-установщик через PolicyKit и не требует WebSocket-демона. Текущие URI-записи интерпретируются как имена пакетов APT с заданным уровнем модуля и параметрами сжатия. Установщик запускается после авторизации, поэтому проверьте запрос браузера перед подтверждением запроса аутентификации.

## Отмена

Выберите `Cancel` в окне прогресса веб-интерфейса или `Cancel installation` в GTK-установщике. Отмена помечает пакет как отменённый и завершает текущий отслеживаемый дочерний процесс. Оставшиеся рецепты не запускаются.

Отмена — это не откат. Ранее завершённые пакеты или модули сохраняются, а команда, прерванная во время работы APT, dpkg, скрипта, загрузки или сборки модуля, может оставить частичное состояние или неполный выходной файл. После отмены:

1. Ознакомьтесь с итоговым журналом установки.
2. Проверьте целевую директорию модулей на наличие неожиданных или пустых файлов.
3. Для системного режима выполните `sudo dpkg --audit` и при необходимости восстановите конфигурацию пакетов.
4. Удаляйте только те артефакты, которые точно относятся к отменённой операции.

## Поиск и устранение неисправностей

### Store недоступен

Проверьте сетевой доступ к `https://store.minios.dev`. Статус `Offline` также означает, что браузер не подключён к локальному WebSocket-демону; установка может быть выполнена через обработчик URI, если установлен `minios-store-gui`.

### Браузер не может подключиться к демону

Проверьте сервис и его журналы:

```bash
sudo systemctl status minios-store
sudo journalctl -u minios-store
```

Обычная точка подключения — `ws://127.0.0.1:8765`. Конфликт портов, остановленный сервис, отсутствие `python3-websockets` или ограничения браузера могут помешать подключению. Перезапуск браузера не восстановит работу остановленного демона.

### Ошибка аутентификации или отсутствие запроса

Для работы установщика по URI необходимы PolicyKit, `pkexec` и активный агент аутентификации рабочего стола. Запускайте установщик из активной графической сессии и убедитесь, что установлен `minios-store-gui`. Не пытайтесь обойти запрос, открывая root-демон в сети.

### Ошибка сборки модуля

Разверните журнал установки и используйте последнее сообщение об ошибке команды, а не только итоговое. Частые причины: недоступные пакеты, сбои репозитория или DNS, недостаточно свободного места, неподдерживаемый инструмент сжатия, директория модулей только для чтения. Демон сообщает, когда переключается на `/var/lib/minios-store/modules`.

### Приложение отсутствует после установки

Для модульного режима перезагрузите систему после проверки, что файл `.sb` находится в директории `minios/modules` на загрузочном носителе. Файл, оставленный в резервной директории, не загружается автоматически. Для системного режима в live-сессии убедитесь, что сессия постоянная, если приложение исчезло после перезагрузки.

### После отмены установки в системном режиме dpkg остался незавершённым

Проверьте состояние пакетов перед повторной попыткой:

```bash
sudo dpkg --audit
sudo dpkg --configure -a
sudo apt-get -f install
```

Перед подтверждением любых дополнительных действий по восстановлению внимательно ознакомьтесь с предлагаемыми изменениями APT.
