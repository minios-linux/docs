# Обновления программного обеспечения

MiniOS сочетает модули SquashFS с доступом только для чтения и записываемый оверлей среды выполнения. Метод обновления должен соответствовать изменяемому уровню. Обновление пакетов в работающей сессии отличается от замены модулей на носителе MiniOS.

## Обновление пакетов с помощью APT

APT записывает изменения в оверлей среды выполнения. Включите и используйте постоянную сессию перед обновлением, если изменения должны сохраниться после перезагрузки:

```bash
sudo apt update
sudo apt upgrade
```

Без постоянства изменения пакетов исчезнут при завершении работы. С постоянством обновлённые файлы и состояние APT сохраняются в этой сессии, но базовые модули образа `.sb` остаются неизменными. Новая сессия по-прежнему использует версии пакетов из образа.

APT подходит для обслуживания одной постоянной установки. Сначала проверьте доступное место, так как обновлённые файлы хранятся дополнительно к сжатым базовым модулям. MiniOS не поддерживает обновление между выпусками «на месте». Не рассматривайте обновление выпуска Debian как обновление образа MiniOS; сделайте резервную копию данных и используйте образ, созданный для целевого выпуска.

## Обновление программного обеспечения с помощью модулей

Модуль `.sb` — это программное обеспечение только для чтения, загружаемое при запуске. Модули сохраняются, если они размещены в записываемом каталоге MiniOS `modules/` или в источнике модуля с поддержкой постоянства. Для них не требуется сохранять изменения пакетов в сессии.

Проверьте набор модулей для следующей загрузки до и после добавления модуля:

```bash
sb next-boot
sudo sb next-boot add 50-example.sb
```

`sb next-boot add` проверяет и атомарно публикует новый модуль, но не перезаписывает существующий модуль с тем же именем. Сначала удалите заменяемый пользовательский модуль, если обновление должно сохранить то же базовое имя:

```bash
sudo sb next-boot remove 50-example.sb
sudo sb next-boot add 50-example.sb
```

Базовые модули и модули на носителях только для чтения этой командой не удаляются. Создайте или получите обновлённые модули для той же архитектуры, релиза дистрибутива и нижнего уровня стека модулей. Модули с более высоким номером перекрывают нижележащие слои, поэтому старый дополнительный модуль может также перекрывать файлы, предоставляемые новым базовым образом.

Для локально упакованного ПО `apt2sb upgrade` может создать модуль обновления. Подробнее о сборке модулей и уровне зависимостей смотрите в разделе [Создание модулей](/development/Creating-Modules.md).

## Замена модулей образа

Официальные обновления образа заменяют файлы на носителе MiniOS; `apt upgrade` не обновляет их. Рекомендуется заменять полный набор базовых модулей и соответствующие загрузочные файлы из одного выпуска MiniOS или переустанавливать систему с нового образа. Не смешивайте основные, десктопные, прикладные, прошивочные или загрузочные файлы из разных выпусков, если их совместимость не задокументирована.

Перед заменой:

1. Сделайте резервную копию конфигурации MiniOS, данных постоянства, пользовательских модулей и текущих базовых модулей, как описано в разделе [Резервное копирование и восстановление](/administration/Backup-Recovery.md).
2. Зафиксируйте списки активных и загружаемых при следующем запуске модулей с помощью `sb list` и `sb next-boot`.
3. Выполните замену с другой системы или с загрузки, полностью загруженной в RAM, чтобы исходные файлы не использовались.
4. Сохраняйте предыдущие файлы до тех пор, пока новый образ не загрузится, и не будут протестированы необходимое оборудование и приложения.

Сохраняйте базовые имена и порядок модулей, если выпуск требует прямой замены. Поздний источник с тем же базовым именем заменяет более ранний источник в выборе для следующей загрузки; копии с разными именами могут загружаться одновременно и приводить к нежелательному порядку слоёв.

## Обновление ядра

Ядро — это согласованный набор: модуль драйверов `01-kernel.sb`, образ ядра, initramfs и конфигурация загрузчика должны совпадать. Используйте MiniOS Kernel Manager или команду `minios-kernel` вместо обновления только пакета `linux-image` через APT.

Просмотрите и упакуйте ядро из репозитория, затем активируйте его для следующей загрузки:

```bash
sudo minios-kernel list
sudo minios-kernel package --repo <linux-image-package> -o /tmp/kernel-output
sudo minios-kernel activate <kernel-version>
```

Активация обновляет конфигурацию загрузки MiniOS. Перезагрузитесь, чтобы запустить выбранное ядро, затем проверьте его с помощью `uname -r`. Держите как минимум одно проверенное рабочее ядро и его загрузочные файлы до тех пор, пока не будут протестированы оборудование, хранилище, сеть и внешние драйверы. Стандартный модуль ядра MiniOS может содержать дополнительные драйверы, которых нет в ядре из репозитория дистрибутива.

Подробнее о графическом процессе, опциях команд и восстановлении см. [Управление ядром](/administration/Kernel-Management.md).

## Совместимость и восстановление

Сделайте резервную копию данных постоянства перед сменой базового образа или ядра. Файлы пакетов и метаданные из постоянной сессии могут перекрывать новый базовый модуль или описывать версии пакетов, которые больше не соответствуют ему. Сначала протестируйте новый образ в новой сессии, затем протестируйте копию существующей сессии. Сохраняйте исходный образ, модули и резервную копию сессии до тех пор, пока откат не станет ненужным.

После любого обновления проверьте выбранные модули, выполните одну загрузку и проверьте затронутые приложения и оборудование. Если новый базовый образ конфликтует со старыми пользовательскими модулями или постоянством, отключите эти слои и возвращайте их по одному.
