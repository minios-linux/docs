# Поиск и устранение неисправностей

Начните с наблюдения и обратимых тестов. Не выполняйте переразметку, форматирование, восстановление файловой системы, удаление сессии или перезапись загрузочных файлов, пока важные данные не будут сохранены, а неисправное устройство не будет определено по модели, размеру, файловой системе и точке монтирования.

## Первичные проверки

1. Проверьте загруженный ISO-файл с помощью
   [Проверка загрузок](/installation/Verifying-Downloads.md).
2. Запустите чистую загрузку без постоянства. Это позволяет отделить проблемы базовой системы и оборудования от повреждённой или несовместимой сессии.
3. Попробуйте другой USB-порт и, если возможно, другое заведомо рабочее устройство.
4. Запишите точное название пункта загрузочного меню, все добавленные параметры и первую ошибку, а не только итоговый сбой.
5. Проверьте [Совместимость оборудования](/installation/Hardware-Compatibility.md) и руководство по инструменту, которым записывалось устройство.

## Проблемы с загрузкой

Если устройство не отображается в меню загрузки прошивки, проверьте, было ли оно записано для UEFI, устаревшего BIOS или обоих вариантов. Временно отключите функцию быстрой загрузки в прошивке, воспользуйтесь однократным загрузочным меню прошивки и попробуйте другой порт перед повторной записью устройства. Не изменяйте таблицу разделов внутреннего диска для диагностики проблем загрузки с USB.

Если появляется меню загрузки MiniOS, но запуск не удаётся:

- Запустите новую сессию без `perch`, `perchdir` или `perchmode`.
- Удалите необязательные параметры и фильтры модулей.
- Убедитесь, что ISO-образ и записанный носитель не повреждены.
- Зафиксируйте полную ошибку. Параметры `debug` и `timing` добавляют вывод загрузки;
  `rd.break` открывает оболочку initramfs для расширенной диагностики.
- Если данные MiniOS не найдены, проверьте значение `from` и путь к устройству согласно
  [Параметры загрузки](/configuration/Boot-Parameters.md).

Для загрузки ISO по PXE или HTTP используйте специализированное
руководство [Сетевая загрузка](/installation/Network-Boot.md). Сетевая работа на раннем этапе загрузки отделена от NetworkManager в рабочей сессии.

## Проблемы с отображением

Если экран чёрный, разрешение некорректно или наблюдается цикл дисплей-менеджера:

1. Попробуйте загрузочный параметр `text`. Если консоль запускается, базовая система загрузилась, и проблема, скорее всего, связана с графикой, X11 или дисплей-менеджером.
2. Удалите вручную указанный параметр `xorg-driver` или `xorg-resolution`.
3. Запустите новую сессию, чтобы исключить влияние постоянной конфигурации экрана.
4. Запишите модель GPU и загруженный драйвер с помощью `lspci -nnk`.
5. Проверьте ошибки текущей загрузки с помощью `journalctl -b -p warning` и
   `dmesg --level=err,warn`.

Управление разрешением в виртуальной машине, описанное как `virtres` и `novirtres`,
применимо только к окружению Xfce. Подробнее см. в разделе
[Виртуализация](/administration/Virtualization.md) для настройки гостевой системы.

## Проблемы с сетью

Убедитесь, что интерфейс существует, прежде чем менять конфигурацию:

```bash
ip link
ip address
ip route
```

В обычной рабочей сессии проверьте NetworkManager, если он доступен:

```bash
nmcli device status
nmcli connection show
systemctl status NetworkManager --no-pager
```

- Если интерфейс не отображается, зафиксируйте вывод `lspci -nnk` или `lsusb` и проверьте наличие
  отсутствующего микропрограммного обеспечения в `dmesg`.
- Если интерфейс есть, но адрес не назначен, проверьте работу DHCP до ввода статических
  значений.
- Если адрес есть, проверьте шлюз, затем IP-адрес, затем DNS-имя, чтобы
  различить проблемы с каналом, маршрутизацией и DNS.
- Установщик настраивает проводной DHCP или статический IPv4. Существующие профили Wi-Fi не изменяются.
- Загрузочный параметр `ip=` настраивает раннюю загрузку PXE, а не сетевое подключение в постоянной сессии. См. [Сетевая загрузка](/installation/Network-Boot.md).

## Проблемы с постоянством

Сначала загрузитесь без постоянства и сделайте полную копию каталога `minios/changes`.
Не запускайте инструменты восстановления по единственной копии или по активной сессии.

Проверьте состояние сессии с помощью:

```bash
sudo minios-session list
sudo minios-session running
sudo minios-session active
sudo minios-session status
sudo minios-session info
```

Типичные причины включают запуск новой записи, использование метода записи ISO, который не настраивал постоянство, недостаток свободного места, выбор сессии из другой редакции или версии, несовместимость файловой системы и некорректное завершение работы. Подробнее см. в разделе [Управление сессиями](/configuration/Session-Management.md).

Если MiniOS многократно создаёт пустые сессии, не может возобновить DynFileFS или сообщает об ошибках контейнера, следуйте инструкции [Восстановление DynFileFS и dynblk](/configuration/DynFileFS-Recovery.md).
Это руководство начинается с полной копии и проверки в режиме только для чтения. Для сессий LUKS также требуется правильная парольная фраза и initrd с поддержкой постоянства LUKS.

## Проблемы с хранилищем и свободным местом

Определите устройства и точки монтирования, не изменяя их:

```bash
lsblk -o NAME,SIZE,TYPE,FSTYPE,LABEL,UUID,MOUNTPOINTS,MODEL
findmnt
df -hT
df -ih
```

Убедитесь в правильности модели и размера устройства до любых операций. Переполненная файловая система может привести к сбоям обновлений, неполной записи сессии и восстановлению при загрузке. Освобождайте место только перемещением или удалением известных пользовательских данных после создания резервной копии; не удаляйте вручную пронумерованные каталоги постоянства, пока одна из сессий активна. Для операций с сессиями используйте Session Manager или `minios-session`.

Восстановление файловой системы — это следующий этап. Сначала размонтируйте файловую систему, работайте с копией, если возможно, и используйте специализированную утилиту проверки файловой системы. Никогда не форматируйте устройство для диагностики.

## Сбор логов

Запишите редакцию и версию MiniOS, способ загрузки, режим постоянства, оборудование и шаги для воспроизведения проблемы. Полезные команды:

```bash
uname -a
cat /etc/os-release
journalctl -b
journalctl -b -p warning
dmesg
lsblk -f
lspci -nnk
lsusb
```

Перед отправкой логов удалите пароли, приватные ключи, данные Wi-Fi, публичные IP-адреса и другую конфиденциальную информацию. `journalctl -b -1` может показать предыдущую загрузку, если журнал сохраняется.

При повторяющихся сбоях загрузки на записываемых носителях MiniOS установите `EXPORT_LOGS=true` в
конфигурационном файле. MiniOS копирует свои загрузочные логи в `minios/logs`, если носитель доступен для записи. Подробнее см. в разделе [Конфигурационный файл](/configuration/Configuration-File.md).

При отправке воспроизводимой ошибки приложите соответствующие фрагменты и создайте обращение в [трекере ошибок MiniOS](https://github.com/minios-linux/minios-live/issues).
