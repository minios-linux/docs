# Управление сессиями в MiniOS

Сессии MiniOS сохраняют изменения, внесённые в живую систему, между перезагрузками. Каждая сессия — это пронумерованный каталог в `minios/changes/`; модули MiniOS остаются только для чтения, а выбранная сессия предоставляет записываемый слой объединённой файловой системы.

Используйте Менеджер сессий из запущенной системы MiniOS:

```bash
minios-session-manager
```

Эквивалентная утилита командной строки — `minios-session`. Для выполнения команд, изменяющих сессии, требуются права администратора, поэтому в примерах ниже используется `sudo`.

## Режимы сессии

| Режим | Хранилище | Основные ограничения |
|------|-----------|----------------------|
| `native` | Изменения сохраняются напрямую в каталоге сессии | Требуется файловая система POSIX с поддержкой записи, например ext2/3/4, Btrfs, XFS, F2FS или ReiserFS. |
| `dynfilefs` | Расширяемый контейнер ext4, разбитый на вспомогательные файлы | Работает на записываемых POSIX, FAT32, NTFS и exFAT. Требуется бэкенд DynFileFS. |
| `raw` | Контейнер фиксированного размера `changes.img` с ext4 внутри | Работает на записываемых POSIX, FAT32, NTFS и exFAT. |
| `luks` | LUKS2-зашифрованный `changes.luks` с ext4 внутри | Требуются `cryptsetup`, поддержка loop и LUKS-хук initrd MiniOS. |
| `squashfs` | Сжатый снимок в `changes.sb` | Для сохранения требуется POSIX-файловая система постоянства, поддерживающая ссылки, владельцев, режимы, xattr, ACL, capability и whiteout-файлы. |

`dynfilefs`, `raw` и `luks`, созданные с помощью `minios-session`, по умолчанию имеют размер 4000
МиБ. Значения размера выделяются в МиБ; суффиксы `GB` и `TB` преобразуются в 1000
и 1 000 000 МиБ. Session Manager ограничивает размер raw- и LUKS-файлов 4000 МиБ на
FAT32. Не полагайтесь на это как на
гарантию initrd: при превышении лимита запрос на загрузку raw может дойти до выделения
и завершиться ошибкой, а не быть уменьшен автоматически. Операции изменения размера контейнера могут только увеличивать
сессию; уменьшение не поддерживается.

Режим native — самый простой и быстрый вариант на совместимой файловой системе.
Используйте DynFileFS, если файловая система постоянства не поддерживает метаданные Linux.
Используйте raw при необходимости фиксированного выделения, LUKS — если требуется
шифрование сессии, а SquashFS — для точного сжатого снимка.

Выполните следующие команды для анализа реальной файловой системы постоянства и
доступных на ней режимов:

```bash
sudo minios-session info
sudo minios-session status
```

Сессии нельзя создавать на носителях только для чтения. Initrd может прочитать и активировать
существующий снимок SquashFS, сохранённый на записываемых FAT, exFAT или NTFS, поскольку он
извлекает снимок во временный верхний слой ext4. Создание или точное сохранение
снимка отличается: для этого требуется отдельная рабочая область на подходящей
POSIX-файловой системе, сохраняющей метаданные Linux и whiteout-файлы.

## Выбор загрузки

Любой распознанный параметр постоянства включает обработку постоянства. Загрузочные меню MiniOS обычно предоставляют варианты возобновления, создания новой, выбора и загрузки без постоянства. Каноническое описание логики выбора, совместимости, резервирования и активации приведено в [Initrd persistence](./Initrd-Persistence.md).

| Параметр | Значение |
|-----------|----------|
| `perch` | Использовать устаревший путь best-effort для возобновления. Пробует значение по умолчанию из метаданных, но не создаёт замену, если подходящей нет. |
| `perchdir=resume` | Возобновить значение по умолчанию из метаданных и, если оно отсутствует или несовместимо, разрешить initrd создать новую совместимую замену. Это текущее поведение пункта меню возобновления загрузки. |
| `perchdir=new` | Создать новую сессию с новым номером. |
| `perchdir=ask` | Выбрать существующую сессию или создать новую при загрузке. |
| `perchdir=<id>` | Выбрать сессию с этим номером напрямую. |
| `perchdir=<device/path>` | Использовать расположение постоянства на устройстве, включая формы `/dev/...` и `label:...`, обрабатываемые initrd. |
| `perchmode=<mode>` | Установить `native`, `dynfilefs`, `raw`, `luks` или `squashfs`. |
| `perchsize=<size>` | Установить новый или больший размер контейнера; значения без суффикса выделяются в МиБ, а суффиксы `MB`, `GB` и `TB` также поддерживаются. |

Если для новой сессии не указан режим, загрузка использует режим native. На FAT32/NTFS/exFAT создание в native режиме переходит на DynFileFS. Новый контейнер raw или LUKS по умолчанию имеет размер 4000 МиБ; новая сессия DynFileFS без `perchsize` получает размер по доступному пространству с резервом безопасности.
Сессии SquashFS создаются из работающей системы через Session Manager или `minios-session create squashfs`; `perchdir=new perchmode=squashfs` не
создаёт снимок в initrd.

При возобновлении MiniOS проверяет записанную версию, редакцию, файловую систему union и режим. Явный `perchdir=resume` может создать новую сессию вместо использования отсутствующего или несовместимого значения по умолчанию. Простые `perch`, прямой выбор по номеру и другие устаревшие запросы возобновления не создают замену автоматически.
Интерактивный выбор выводит предупреждение перед разрешением несовместимой сессии. Если выбор или активация всё равно не удаются, загрузка продолжается с RAM-верхом и предупреждением о постоянстве.

Хранилище сессий имеет следующий вид:

```text
minios/changes/
|-- session.conf
|-- 1/
|-- 2/
`-- N/
```

`session.conf` хранит значения по умолчанию и текущие ID, а также режим, версию, редакцию, файловую систему union, размер, состояние и специфичные настройки для каждой сессии.
Это постоянные метаданные, фиксируемые реализацией загрузки, но сами по себе не гарантируют текущее состояние во время работы. Не редактируйте их и не перемещайте данные сессий с номерами, пока сессия смонтирована; используйте Session Manager или `minios-session`.

## Активные и запущенные сессии

Эти термины описывают разные состояния:

- **Активная** сессия — это та, которая выбрана по умолчанию для следующей загрузки.
- Концептуально **запущенная** сессия — это сессия, чей writable layer
  фактически обеспечивает сохранение данных для текущей загрузки.

Поле persistent `running=` фиксирует предполагаемое соответствие. Сбой,
ошибка при построении union, копирование хранилища или прерванное завершение работы могут сделать его
устаревшим, даже если текущая загрузка использует RAM или другую сессию. Поэтому для операций,
таких как сохранение SquashFS, требуется защищённое состояние текущей загрузки initrd, связанное с boot-ID, и проверенный смонтированный upper;
они не полагаются только на `running=`. См. [Активное, запущенное и состояние текущей загрузки](./Initrd-Persistence.md).

Активация сессии меняет следующую загрузку, но не переключает текущую
файловую систему union:

```bash
sudo minios-session active
sudo minios-session running
sudo minios-session activate <id>
```

Активная сессия не может быть удалена или преобразована на месте. Запущенная сессия
обычно не может быть удалена, экспортирована, скопирована, изменена по размеру или преобразована. Очистка
также защищает оба идентификатора.

## Справочник команд

Список сессий и просмотр хранилища:

```bash
sudo minios-session list
sudo minios-session active
sudo minios-session running
sudo minios-session info
sudo minios-session status
```

Создание сессий:

```bash
sudo minios-session create
sudo minios-session create native
sudo minios-session create dynfilefs
sudo minios-session create raw 4GB
sudo minios-session create luks 4GB
sudo minios-session create squashfs --policy shutdown
sudo minios-session create squashfs --policy manual --autosave 60
```

`create` без режима выбирает нативный. Создание SquashFS фиксирует текущие
живые изменения и не имеет фиксированного размера. Политика завершения по умолчанию — `shutdown`;
периодическое сохранение по умолчанию отключено.

Сохранение и настройка сессии SquashFS:

```bash
sudo minios-session save <running-squashfs-id>
sudo minios-session settings <squashfs-id> --shutdown on
sudo minios-session settings <squashfs-id> --shutdown off --autosave 0
sudo minios-session settings <squashfs-id> --shutdown on --autosave 60
```

Допустимые интервалы для периодического сохранения: `30`, `60`, `120`, `240` и `480` минут;
`0` отключает периодическое сохранение. Настройки завершения работы и периодичности
независимы.

Экспорт и импорт архивов `.tar.zst`:

```bash
sudo minios-session export <id> /path/to/session.tar.zst
sudo minios-session import /path/to/session.tar.zst
sudo minios-session import /path/to/session.tar.zst --auto-convert
sudo minios-session import /path/to/session.tar.zst --force-mode dynfilefs
```

Принимаются только импорты `.tar.zst`. Пути и содержимое архивов проверяются,
а извлечение ограничено. `--auto-convert` выбирает совместимый режим для
текущей файловой системы. `--force-mode <mode>` явно выбирает доступный
режим. Экспорт, копирование и конвертация не поддерживаются для сессий SquashFS;
сохраните снимок и скопируйте всю неактивную директорию сессии вручную.

Копирование или конвертация сессии:

```bash
sudo minios-session copy <id>
sudo minios-session copy <id> --to-mode raw --size 4GB
sudo minios-session convert <id> dynfilefs --size 4GB
sudo minios-session convert <id> luks --size 4GB --new-session
```

`copy` всегда присваивает новый идентификатор сессии. `convert` по умолчанию заменяет исходную;
используйте `--new-session`, чтобы сохранить исходную. Размер имеет значение только
для цели-контейнера.

Увеличение, удаление или очистка сессий:

```bash
sudo minios-session resize <id> 8GB
sudo minios-session delete <id>
sudo minios-session cleanup
sudo minios-session cleanup --days 30
```

Изменение размера поддерживается для DynFileFS, raw и LUKS сессий и требует размера больше
текущего. Очистка по умолчанию применяется к сессиям старше 30 дней.

Все команды поддерживают `--json`, а другое хранилище сессий можно выбрать
с помощью `--sessions-dir PATH`:

```bash
sudo minios-session --json list
sudo minios-session --sessions-dir /mnt/store/minios/changes list
```

## Поведение сохранения SquashFS

Сессия SquashFS распаковывается в RAM для обеспечения записываемого слоя во время работы. При сохранении создаётся и проверяется точный снимок, который затем атомарно заменяет `changes.sb`. Откат предыдущей версии не сохраняется. Кнопка «Сохранить сейчас» доступна из значка в трее, Менеджера сессий или `minios-session save` независимо от автоматической политики.

Сохранение при завершении работы реализовано через основной триггер завершения MiniOS и бэкенд `minios-squashfs-save`, поэтому оно не зависит от того, открыт или установлен Менеджер сессий. Периодическое сохранение проверяется каждые 30 минут с помощью таймера systemd или службы SysV, обе вызывают один и тот же бэкенд автосохранения. Пересборка снимка нагружает процессор и полностью перезаписывает снимок; рекомендуется выбирать интервалы не менее одного часа.

Во время работы SquashFS с поддержкой RAM новый активированный снимок SquashFS может взять на себя роль текущей цели сохранения. После такой передачи старый запущенный снимок можно удалить без перезагрузки:

```bash
sudo minios-session activate <new-squashfs-id>
sudo minios-session delete <old-running-squashfs-id> --handoff
```

Это исключение применяется только к корректной передаче SquashFS в рамках текущей загрузки. Для других режимов постоянства защита от удаления сохраняется.

## Шифрование

В режиме LUKS файловая система ext4 хранится непосредственно в файле LUKS2 `changes.luks`; таблица разделов или вложенный контейнер DynFileFS отсутствуют. Варианты LUKS доступны только при наличии `/run/initramfs/etc/minios-initramfs-crypt`, `cryptsetup` и `losetup`.

При интерактивном создании LUKS пароль запрашивается дважды. Операции чтения или создания LUKS-данных могут получать пароль из стандартного ввода с помощью `--password-stdin`. Пароли не передаются в аргументах команд или метаданных сессии. При загрузке initrd запрашивает пароль в консоли и не переходит к незашифрованному постоянству при ошибке активации.

Экспорт LUKS содержит расшифрованные логические файлы сессии, а не `changes.luks`. Импорт или преобразование в LUKS создаёт новый зашифрованный контейнер.

## Резервное копирование и восстановление

Для нативных, DynFileFS, raw и LUKS сессий используйте `export` для резервного копирования вместо копирования смонтированной директории сессии. Храните полученный архив на другом устройстве и убедитесь, что его можно просмотреть или импортировать, прежде чем полагаться на него. Импорт всегда создаёт новую сессию с номером; активируйте её вручную, когда она будет готова к использованию. Для процедур резервного копирования и восстановления SquashFS и всего устройства смотрите [Резервное копирование и восстановление](/administration/Backup-Recovery.md).

Для восстановления после заполнения устройства хранения, прерванной записи или многократного создания пустых сессий следуйте специальному [руководству по восстановлению DynFileFS и dynblk](./DynFileFS-Recovery.md).

Начните диагностику без изменения данных сессии:

```bash
sudo minios-session list
sudo minios-session active
sudo minios-session running
sudo minios-session status
sudo minios-session info
```

При загрузке файловые системы контейнеров проверяются до активации на запись. Серьёзные ошибки проверки файловой системы сохраняют контейнер для восстановления вместо монтирования в режиме записи. SquashFS обнаруживает некорректное предыдущее состояние и восстанавливает последний успешно сохранённый снимок. Удаляйте сессии только через Session Manager или `minios-session delete`; не удаляйте директории сессий вручную.
