# Настройка сети

После запуска MiniOS управление проводными и Wi-Fi-соединениями обычно осуществляет NetworkManager. Это отдельный процесс от сетевой настройки initramfs, используемой для загрузки системы по PXE или HTTP-ISO. В частности, параметр PXE `ip=` не создаёт профиль NetworkManager и не задаёт постоянный сетевой адрес для сессии. Подробнее о сетевой настройке на ранних этапах загрузки см. в разделе [Сетевая загрузка](/installation/Network-Boot.md).

## Настройка рабочего стола

Используйте значок сети на панели рабочего стола для выбора Wi-Fi-сети, отключения или повторного подключения устройства, а также для открытия редактора соединений. Для статического адреса по проводному соединению отредактируйте соответствующее подключение, установите метод IPv4 на "Вручную" и введите адрес, префикс, шлюз и DNS-серверы. Для использования DHCP выберите метод "Автоматически (DHCP)".

Текстовый интерфейс предоставляет те же основные операции:

```bash
nmtui
```

Выберите **Редактировать соединение** для изменения профиля и **Активировать соединение** для его включения.

## Командная строка NetworkManager

Показать устройства и сохранённые профили:

```bash
nmcli device status
nmcli connection show
```

Сканировать Wi-Fi и подключиться:

```bash
nmcli radio wifi on
nmcli device wifi list
nmcli device wifi connect "NETWORK_NAME" --ask
```

Последняя команда запросит пароль без его отображения в командной строке. Не вводите пароль от Wi-Fi напрямую в команду, так как он может сохраниться в истории оболочки и быть видимым другим процессам.

Чтобы изменить существующий проводной профиль на DHCP:

```bash
nmcli connection modify "Wired connection 1" \
  ipv4.method auto ipv4.addresses "" ipv4.gateway "" ipv4.dns ""
nmcli connection up "Wired connection 1"
```

Чтобы назначить статический IPv4-адрес:

```bash
nmcli connection modify "Wired connection 1" \
  ipv4.method manual ipv4.addresses 192.0.2.10/24 \
  ipv4.gateway 192.0.2.1 ipv4.dns "1.1.1.1 9.9.9.9"
nmcli connection up "Wired connection 1"
```

Замените имя профиля и адреса на значения вашей локальной сети. При удалённом подключении связь может быть прервана сразу после изменения активного профиля.

## Персистентность

NetworkManager сохраняет системные профили в
`/etc/NetworkManager/system-connections/`. При загрузке в режиме Live без сохранения изменений, все настройки, выполненные через графический интерфейс, `nmcli` или `nmtui`, будут потеряны после выключения. В персистентной сессии они сохраняются между перезагрузками. Подробнее о выборе и сохранении сессий см. в разделе [Управление сессиями](/configuration/Session-Management.md).

Профили не синхронизируются автоматически между отдельными персистентными сессиями. Профили Wi-Fi могут содержать учетные данные, поэтому защищайте носитель сессии и удаляйте пароли перед передачей архива сессии или диагностических данных.

## Предварительная настройка проводного соединения

Компонент live-config сети MiniOS может создать политику статического IPv4 для проводного соединения до запуска сетевых сервисов. Это предназначено для автоматических или установленных систем. Wi-Fi не настраивается этим способом.

Добавьте shell-подобные присваивания в `minios/config.conf` на носителе MiniOS или в `/etc/live/config.conf` в живой системе:

```bash
LIVE_NETWORK_METHOD="static"
LIVE_NETWORK_INTERFACE="enp1s0"
LIVE_NETWORK_ADDRESS="192.0.2.10"
LIVE_NETWORK_PREFIX="24"
LIVE_NETWORK_GATEWAY="192.0.2.1"
LIVE_NETWORK_DNS="1.1.1.1,9.9.9.9"
LIVE_NETWORK_BACKEND="auto"
```

Заключайте значения в кавычки как строки оболочки и не добавляйте пробелы вокруг `=`. Подробнее о расположении файлов и приоритетах см. в разделе [Файл конфигурации](/configuration/Configuration-File.md), а об активации компонента и общих параметрах — в [live-config](/configuration/live-config.md).

Эквивалентные параметры загрузки:

```text
network-method=static network-interface=enp1s0 \
network-address=192.0.2.10 network-prefix=24 \
network-gateway=192.0.2.1 network-dns=1.1.1.1,9.9.9.9 \
network-backend=auto
```

Также поддерживаются длинные формы `live-config.network-*`. Это опции live-config для userspace, а не синтаксис PXE `ip=`.

### Методы

| Метод | Поведение |
|--------|-----------|
| Не задано или `dhcp` | Не вносит изменений и сохраняет существующую сетевую конфигурацию образа. Не создаёт конфигурацию DHCP и не удаляет предыдущий статический профиль MiniOS. |
| `static` | Записывает профиль статического IPv4 для проводного соединения. Префикс по умолчанию — `24`; шлюз и DNS необязательны. |
| `off` | Создаёт профиль NetworkManager без автоподключения с отключённым IPv4 или секцию ifupdown `manual`. Это не переключатель Wi-Fi-радио. |

Только `static` и `off` выбирают интерфейс и записывают конфигурацию. Если `LIVE_NETWORK_INTERFACE` не указан, live-config продолжит только при наличии ровно одного проводного не-loopback интерфейса. Беспроводные интерфейсы исключаются. Используйте `ip link` или `nmcli device status` для получения фактического имени интерфейса в системе с несколькими интерфейсами.

### Бэкенды и валидация

`LIVE_NETWORK_BACKEND` принимает:

| Бэкенд | Поведение |
|--------|-----------|
| `auto` или не задан | Предпочитает NetworkManager, при недоступности использует ifupdown. |
| `nm` | Требует NetworkManager и записывает `/etc/NetworkManager/system-connections/minios-static.nmconnection`. |
| `ifupdown` | Требует ifupdown и записывает `/etc/network/interfaces.d/minios-static`. Если установлен NetworkManager, выбранный интерфейс также помечается как unmanaged в `/etc/NetworkManager/conf.d/99-minios-unmanaged.conf`. |

Имена интерфейсов могут содержать только буквы, цифры, `_`, `.`, `:` и `-`.
Статические адреса и шлюзы должны быть корректными IPv4-адресами. Префикс — целое число от `0` до `32`. DNS — это список IPv4 или IPv6-адресов, разделённых запятыми. Некорректные значения, неоднозначный выбор интерфейса и недоступные бэкенды приводят к ошибке, и отметка об успехе не создаётся.

## Изменение политики live-config с сохранением

В персистентной live-системе сетевой компонент обычно применяется один раз и записывает успех в `/var/lib/live/config/network`. Чтобы применить изменённые статические или off-настройки:

1. Отредактируйте актуальный персистентный `/etc/live/config.conf`.
2. Удалите отметку с помощью `sudo rm /var/lib/live/config/network`.
3. Перезагрузите систему.

Изменение только конфигурации на съёмном носителе не перезапишет существующий персистентный `/etc/live/config.conf`.

Установка `LIVE_NETWORK_METHOD="dhcp"` не является сбросом профиля. Чтобы вернуться от статического профиля MiniOS к обычному DHCP NetworkManager, удалите статическую политику `LIVE_NETWORK_*` из актуальной конфигурации, удалите управляемый профиль и отметку, затем перезагрузите систему:

```bash
sudo rm -f /etc/NetworkManager/system-connections/minios-static.nmconnection
sudo rm -f /var/lib/live/config/network
```

Для бэкенда ifupdown удалите
`/etc/network/interfaces.d/minios-static` и
`/etc/NetworkManager/conf.d/99-minios-unmanaged.conf`. Затем создайте или активируйте профиль DHCP через редактор рабочего стола, `nmtui` или `nmcli`, если NetworkManager не создаёт его автоматически.

## Поведение установщика

Шаг Network в установщике применяется только к проводным сетям. Выбранная статическая настройка IPv4 будет записана для установленной системы. При выборе DHCP сохраняются стандартные параметры по умолчанию, профиль сброса не создаётся. Существующие профили Wi-Fi и настройки Wi-Fi не изменяются.

## Диагностика

Начните с проверки устройства, адреса, маршрута и состояния NetworkManager:

```bash
ip link
ip address
ip route
nmcli general status
nmcli device status
nmcli connection show --active
systemctl status NetworkManager --no-pager
```

Проверьте текущий журнал загрузки на наличие ошибок устройства, прошивки, DHCP и live-config:

```bash
journalctl -b -u NetworkManager
journalctl -b | grep 'live-config: network'
dmesg
```

Для политики live-config также проверьте актуальные настройки, сгенерированный файл и отметку. Основной журнал live-config — `/var/log/live/config.log`.

Проверяйте сбои по порядку: состояние линка, наличие адреса на интерфейсе, маршрут по умолчанию и шлюз, внешний IP-адрес и, наконец, имя DNS. Это позволяет отделить проблемы с устройством или прошивкой от ошибок DHCP, маршрутизации и DNS. Для более широких проверок и сбора логов см. раздел [Устранение неполадок](/administration/Troubleshooting.md).
