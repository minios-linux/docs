# Обнаружение системы в initrd

После загрузки ядра и initramfs загрузчиком, initramfs должен найти дерево данных MiniOS, которое содержит модули системы `.sb`. Это происходит до активации стандартного пользовательского сетевого стека, рабочего стола и постоянной сессии.

## Приоритет источников

Выбор источника происходит по фиксированному приоритету:

1. Явное значение `from=http://...` выбирает HTTP ISO.
2. В противном случае, любое непустое значение `ip=` выбирает загрузку PXE.
3. Далее, `from=askdisk` или `from=askdisk:...` открывает выбор диска.
4. Если ни одно из условий не выполнено, initramfs сканирует локальные блочные устройства.

Два сетевых пути не переключаются на локальные носители. После попытки HTTP ISO или PXE возвращается результат этой сетевой попытки, а не пробуются диски; неработающий или неполный результат приводит к ошибке проверки или последующей настройке.

Этот порядок имеет два важных следствия:

- `from=http://...` имеет приоритет над `ip=`. Необязательный параметр `ip=` затем задаёт статическую адресацию для подключения к HTTP ISO.
- Непустое значение `ip=` имеет приоритет над любым локальным значением `from=`, включая устройство, директорию, путь к ISO или `askdisk`. Не используйте `ip=` только для настройки сети при локальной загрузке системы.

## Локальное обнаружение

Если не указан HTTP-источник и нет непустого `ip=`, MiniOS выполняет 45 проходов обнаружения, примерно один в секунду. Каждый проход обновляет device nodes, получает кандидаты блочных устройств из `blkid`, сортирует их имена и тестирует в этом порядке. Первый кандидат, содержащий подходящий источник MiniOS, сохраняется; последующие устройства не рассматриваются.

Если `from=` пуст, на каждой файловой системе проверяется путь `minios`. Источник считается подходящим, если либо эта директория, либо её непосредственная поддиректория `modules/` содержит хотя бы один файл с расширением по умолчанию `.sb`. Параметр `bext=` изменяет расширение, используемое для этой проверки. Обнаружение не проверяет, является ли найденный набор модулей полным или загрузочным.

Каждый кандидат сначала монтируется только для чтения. После подтверждения пригодности MiniOS пытается сделать выбранный раздел доступным для записи, но невозможность этого не отклоняет уже подходящий источник.

### Локальные формы `from=`

Обычный относительный или абсолютный путь интерпретируется внутри каждой кандидатной файловой системы. Начальные слэши нормализуются при построении пути, поэтому оба варианта ищут одну и ту же директорию:

```text
from=minios
from=/minios
```

Если указанный путь является обычным файлом на кандидатной файловой системе, MiniOS рассматривает его как ISO-образ, монтирует его в режиме только для чтения и проверяет директорию `minios` внутри ISO:

```text
from=/images/minios.iso
```

Пути с указанием устройства поддерживают только следующие формы:

```text
from=/dev/sdb1/minios
from=/dev/sr0/minios
from=/dev/disk/by-label/MINIOS/minios
```

`/dev/<name>/path` поддерживает простое имя устройства, за которым следует путь. Форма с меткой должна быть строго `/dev/disk/by-label/LABEL/path`; метка разрешается с помощью `blkid`, затем оставшийся путь проверяется на этой файловой системе.

Нет соответствующего парсера для путей с UUID, PARTUUID или by-id. Такие формы не поддерживаются:

```text
from=/dev/disk/by-uuid/UUID/minios
from=/dev/disk/by-partuuid/PARTUUID/minios
from=/dev/disk/by-id/ID/minios
```

### Интерактивный выбор

Используйте `askdisk` для выбора раздела и последующей проверки пути на нём:

```text
from=askdisk
from=askdisk:custom:dir
```

В первой форме проверяется `minios` на выбранном разделе. Во второй форме двоеточия становятся разделителями пути, поэтому `askdisk:custom:dir` проверяет `custom/dir`.
Синтаксис со слэшем, например `from=askdisk/custom/dir`, также открывает селектор, но при этом пользовательский путь теряется и проверяется `minios`; не используйте этот вариант.

Отображаемый список устройств обновляется, пока открыт селектор, и не включает swap-файловые системы. При выборе всё равно выполняется стандартная проверка наличия модулей; одного выбранного раздела недостаточно.

## HTTP ISO

HTTP-источник ISO имеет следующий вид:

```text
from=http://server.example/path/minios.iso
```

Распознаётся только обычный HTTP. HTTPS и другие схемы URL не поддерживаются.
Initramfs находит первый обнаруженный не-loopback сетевой интерфейс, поднимает сеть и монтирует удалённый ISO через `httpfs2`. При выборе интерфейса не проверяется наличие линка, доступность или пригодность интерфейса на системе с несколькими NIC.

Когда `ip=` отсутствует, при загрузке HTTP ISO запрашивается DHCP с `udhcpc`. Если указан `ip=`, используются статические поля, ожидаемые парсером PXE:

```text
ip=<client-ip>:<server-ip>:<gateway-ip>:<netmask>[:<port>]
```

Для загрузки HTTP ISO URL по-прежнему определяет HTTP-сервер. Статические поля задают адрес клиента, маску сети, шлюз по умолчанию и ранние записи DNS; необязательное поле порта относится к загрузке файлов PXE и не заменяет порт в URL ISO.

`cache=<MB>` включает httpfs-кэш указанного размера в `/tmp`. Это именно кэш, а не гарантированная полная загрузка. Рабочая система продолжает зависеть от удалённого ISO и сети, если только успешное копирование в RAM не отсоединит источник.

## Загрузка данных по PXE

Любое непустое значение `ip=` выбирает загрузку данных PXE, если сначала не был выбран `from=http://...`. Поддерживаемый синтаксис:

```text
ip=<client-ip>:<server-ip>:<gateway-ip>:<netmask>[:<port>]
```

Маска сети указывается в виде IPv4 с точками. Необязательный HTTP-порт по умолчанию — `7529`.
Общие формы ядра или dracut, такие как `ip=dhcp` и `ip=:::::eth0:dhcp`, не поддерживаются. В этом парсере загрузка данных PXE не имеет формы DHCP.

MiniOS настраивает первый обнаруженный не-loopback интерфейс без проверки наличия рабочего линка. Сначала запрашиваются `PXEFILELIST` и перечисленные файлы MiniOS по HTTP с сервера. TFTP — ограниченный резерв: он выбирается только если первоначальный HTTP-запрос `PXEFILELIST` не удался. Это не является общим переключением интерфейса, резервом на локальные носители или восстановлением после любой частичной неудачи HTTP-загрузки.

## Копирование и отсоединение с помощью `toram=full`

`toram=full` важен для обнаружения, так как может убрать постоянную зависимость от выбранного источника. После обнаружения MiniOS копирует дерево данных в RAM, затем пытается размонтировать источник и переместить копию из RAM на его место. Только успешное размонтирование и перемещение отсоединяют локальный носитель, смонтированный ISO или HTTP ISO.

Существенные ограничения:

- Нет предварительной проверки, что доступной RAM хватит для копирования.
- При включённой персистентности копия верхнего уровня `*` не включает скрытые файлы.
- Если персистентность не запрошена, запись `changes` намеренно пропускается. Эта ветка копирует другие элементы верхнего уровня, включая скрытые файлы.
- Ошибка копирования, размонтирования или перемещения может оставить исходный источник смонтированным. Не думайте, что указание `toram=full` делает безопасным извлечение носителя или потерю сети; убедитесь, что отсоединение прошло успешно.

Перед объединением `toram` с `perch` или `perchdir` ознакомьтесь с разделом [Initrd persistence](/configuration/Initrd-Persistence.md).

## Ошибки и диагностика

Если все 45 локальных проходов неудачны, MiniOS переходит в режим фатальной ошибки и открывает оболочку initramfs вместо запуска live-системы. Сетевые пути не выполняют 45-проходный локальный поиск и не переключаются на локальные носители; в зависимости от частичного результата они могут завершиться ошибкой проверки данных или последующей настройки. Выход из фатальной оболочки не исправляет отсутствие источника и может лишь привести к менее явной ошибке на следующем этапе.

Полезные диагностические параметры:

- `debug` включает трассировку оболочки, дополнительные диагностические сообщения и интерактивные оболочки на нескольких этапах initramfs. Для продолжения выйдите из оболочки на контрольной точке.
- `timing` выводит время между этапами initramfs и итоговое время.
- `rd.break` запрашивает оболочку initramfs перед передачей управления реальному root; выйдите из неё для продолжения загрузки.

В оболочке проверьте `/proc/cmdline`, `/proc/net/dev`, `blkid`, смонтированные файловые системы и `/var/log/livedbg`. Начните с точных значений `from=`, `ip=` и `bext=`, которые отображаются в `/proc/cmdline`.
