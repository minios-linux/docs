# Виртуализация

MiniOS может работать как гостевая система в VirtualBox, VMware, QEMU/KVM и Hyper-V.
В выпусках Toolbox и Ultra также есть программное обеспечение для запуска виртуальных машин QEMU/KVM непосредственно из MiniOS.

На этой странице описано поведение виртуализации, специфичное для MiniOS. Для обычного создания ВМ и настройки гипервизора используйте документацию к соответствующему гипервизору.

## Запуск MiniOS в качестве гостя

### Рекомендуемая схема ВМ

Для максимальной совместимости подключайте загрузочный носитель MiniOS и любой виртуальный диск, на который будет установлена живая система MiniOS, через **IDE или SATA-контроллер**. Эта рекомендация актуальна для VirtualBox, VMware, QEMU/KVM и Hyper-V, если такой контроллер доступен.

Могут работать и другие виртуальные контроллеры хранения, но MiniOS должен иметь доступ к своему live-источнику на этапе initramfs, до того как будет доступно полное дерево модулей ядра из `01-kernel-*.sb`.

### Поддержка устройств хранения на ранних этапах загрузки

MiniOS намеренно включает в initramfs только ограниченный набор драйверов устройств хранения. Текущие сборщики Dracut и LiveKit используют ту же политику:

| Интерфейс хранения | Flux | Standard / Toolbox / Ultra |
|---|---|---|
| IDE / PATA / SATA | Да | Да |
| NVMe | Да | Да |
| USB mass storage / UAS | Да | Да |
| Hyper-V storage (`hv_storvsc`) | Да | Да |
| VirtIO block / SCSI | Нет | Да |
| VMware PVSCSI | Нет | Да |
| Xen block frontend | Нет | Нет |

Обычные драйверы SAS/RAID, такие как `mpt3sas`, `mptspi`, `mptsas`, `megaraid_sas` и `aacraid`, присутствуют в полном дереве модулей ядра, но не включены в initramfs MiniOS.

Это различие имеет значение только до тех пор, пока не найден live-источник MiniOS и не запущена полноценная система. Оборудование, которое работает нормально после загрузки, не обязательно подходит для хранения самого live-источника.

По этой причине **IDE или SATA остаются рекомендуемым выбором для хранения в ВМ**, даже для редакций, в initramfs которых также есть поддержка VirtIO или VMware PVSCSI.

### Интеграция гостевой системы

Ядро уже содержит базовые драйверы виртуального оборудования, используемые основными гипервизорами. В выпусках Toolbox и Ultra добавлены пакеты гостевых сервисов для более тесной интеграции:

| Платформа | Включённая интеграция гостя в Toolbox / Ultra |
|---|---|
| VMware | `open-vm-tools`, `open-vm-tools-desktop` |
| QEMU/KVM | `qemu-guest-agent` |
| VirtualBox | `virtualbox-guest-utils`, `virtualbox-guest-x11` на поддерживаемых базах |
| Hyper-V | `hyperv-daemons` |

Текущее ядро Debian, используемое для amd64 MiniOS, также содержит драйверы гостя VirtualBox, драйверы графики/сети VMware, VirtIO и Hyper-V. Пакеты гостевых сервисов добавляют функции интеграции; они не отвечают за возможность загрузки базовой ВМ.

### Управление разрешением в Xfce

MiniOS предоставляет `/usr/bin/minios-virtual-resolution` через `minios-tools` и запускает его из автозагрузки Xfce. Утилита определяет распространённые виртуальные машины и использует XRandR только если активные гостевые инструменты ещё не управляют дисплеем.

Без переопределения запрашиваемое разрешение — `1280x800`. Используйте `virtres=WIDTHxHEIGHT` для запроса другого разрешения или `novirtres` для отключения этой настройки MiniOS.
После успешной настройки утилита создаёт `~/.config/minios/virtual-resolution-configured`. В постоянной сессии автоматическая настройка больше не будет применяться, пока этот маркер не будет удалён.

## Использование MiniOS как хоста виртуализации

В выпусках Toolbox и Ultra включён стек QEMU/KVM для локальных виртуальных машин:

- `qemu-system-x86`;
- `qemu-utils`;
- `libvirt-daemon-system`;
- `virt-manager`.

В Ultra дополнительно включён стек Docker и `lazydocker` для контейнерных нагрузок.

В этой документации не описывается установка продуктов виртуализации, которые не входят в состав редакции.
