# Виртуализация

MiniOS может работать как гость в VirtualBox, VMware, QEMU/KVM и Hyper-V.
В редакциях Toolbox и Ultra также есть ПО для запуска виртуальных машин QEMU/KVM прямо из MiniOS.

На этой странице описано поведение виртуализации, специфичное для MiniOS. Для создания обычных виртуальных машин и настройки гипервизора используйте документацию самого гипервизора.

## Запуск MiniOS в качестве гостя

### Рекомендуемая схема виртуальной машины

Для максимальной совместимости подключайте загрузочный носитель MiniOS и любой виртуальный диск, на который будет установлена живая система MiniOS, через **контроллер IDE или SATA**. Эта рекомендация актуальна для VirtualBox, VMware, QEMU/KVM и Hyper-V, если такой контроллер доступен.

Другие виртуальные контроллеры хранения тоже могут работать, но MiniOS должен иметь доступ к своему живому источнику на этапе initramfs, до загрузки полного набора модулей ядра из `01-kernel-*.sb`.

### Поддержка хранилищ на ранних этапах загрузки

MiniOS намеренно включает только выбранный набор драйверов хранения данных в initramfs. Текущие сборщики Dracut и LiveKit используют ту же политику:

| Интерфейс хранения | Flux | Standard / Toolbox / Ultra |
|---|---|---|
| IDE / PATA / SATA | Да | Да |
| NVMe | Да | Да |
| USB-накопители / UAS | Да | Да |
| Хранилище Hyper-V (`hv_storvsc`) | Да | Да |
| VirtIO block / SCSI | Нет | Да |
| VMware PVSCSI | Нет | Да |
| Xen block frontend | Нет | Нет |

Типовые драйверы SAS/RAID, такие как `mpt3sas`, `mptspi`, `mptsas`, `megaraid_sas` и `aacraid` присутствуют в полном наборе модулей ядра, но не включены в initramfs MiniOS.

Это различие важно только до того, как будет найден живой источник MiniOS и запущена полноценная система. Оборудование, которое работает нормально после загрузки, не обязательно подходит для хранения самого живого источника.

По этой причине **IDE или SATA остаются рекомендуемым вариантом хранения для виртуальных машин**, даже для редакций, в чьём initramfs уже есть поддержка VirtIO или VMware PVSCSI.

### Интеграция гостевой системы

Ядро уже содержит базовые драйверы виртуального оборудования, используемые основными гипервизорами. В редакциях Toolbox и Ultra добавлены пакеты гостевых сервисов для более тесной интеграции:

| Платформа | Встроенная интеграция гостя в Toolbox / Ultra |
|---|---|
| VMware | `open-vm-tools`, `open-vm-tools-desktop` |
| QEMU/KVM | `qemu-guest-agent` |
| VirtualBox | `virtualbox-guest-utils`, `virtualbox-guest-x11` на поддерживаемых базах |
| Hyper-V | `hyperv-daemons` |

Текущее ядро Debian, используемое в amd64 MiniOS, также содержит драйверы гостя VirtualBox, драйверы графики/сети VMware, VirtIO и Hyper-V. Пакеты гостевых сервисов добавляют функции интеграции; они не отвечают за саму возможность загрузки виртуальной машины.

### Обработка разрешения в Xfce

MiniOS предоставляет `/usr/bin/minios-virtual-resolution` через `minios-tools` и запускает её из автозагрузки Xfce. Утилита определяет распространённые виртуальные машины и использует XRandR только если активные гостевые инструменты ещё не управляют экраном.

Без переопределения запрашиваемое разрешение — `1280x800`. Используйте `virtres=WIDTHxHEIGHT` чтобы запросить другое разрешение или `novirtres` чтобы отключить эту настройку MiniOS.
После успешной настройки утилита создаёт `~/.config/minios/virtual-resolution-configured`. В постоянной сессии автоматическая настройка больше не применяется, пока этот маркер не будет удалён.

## Использование MiniOS в качестве хоста виртуализации

В редакциях Toolbox и Ultra включён стек QEMU/KVM для локальных виртуальных машин:

- `qemu-system-x86`;
- `qemu-utils`;
- `libvirt-daemon-system`;
- `virt-manager`.

В Ultra дополнительно включён стек Docker и `lazydocker` для контейнерных рабочих нагрузок.

В этой документации не рассматривается установка продуктов виртуализации, не входящих в состав редакции.
