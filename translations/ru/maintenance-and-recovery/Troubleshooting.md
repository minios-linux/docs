# Поиск и устранение неисправностей

Начните с наблюдения и обратимых тестов. Не выполняйте переразметку, форматирование, восстановление файловой системы, удаление сессии или замену загрузочных файлов только ради проверки. Сначала сохраните важные данные.

## Первичные проверки

1. [Проверьте загруженный образ](/installing-minios/Verifying-Downloads).
2. Загрузитесь с помощью **Запустить без сохранения**. Если проблема исчезает, исследуйте постоянную сессию или её конфигурацию, а не базовый образ.
3. Удалите пользовательские параметры загрузки и фильтры модулей, если они не нужны для воспроизведения проблемы.
4. Попробуйте другой USB-порт и, если возможно, другое проверенное устройство или компьютер.
5. Запишите первую ошибку и точное название пункта загрузочного меню, а не только последнее сообщение на экране.
6. Проверьте [Совместимость оборудования](/getting-started/Hardware-Compatibility), если один и тот же проверенный образ не работает на одной машине, но работает на другой.

## Устройство не загружает меню MiniOS

Сначала определите, как было создано устройство MiniOS.

- Для образа, записанного в «сыро́м» режиме (`dd`, Etcher, Rufus DD mode или запись образа через Дисковую утилиту), не восстанавливайте отдельные загрузочные файлы. Если копия повреждена, перезапишите всё устройство из проверенного образа.
- Для установки на основе файлов MiniOS создайте загрузочную структуру заново, используя тот же документированный способ установки, а не копируйте файлы GRUB, Syslinux или EFI из другого релиза.
- Ventoy использует собственный загрузчик и структуру. Не устанавливайте загрузчик MiniOS поверх устройства Ventoy; вместо этого используйте процедуру [Ventoy](/installing-minios/installation-tools/Ventoy).
- После нативного преобразования целевая система использует стандартный загрузчик Debian и структуру файловой системы. Она может сохранять внешний вид рабочего стола MiniOS, но инфраструктура live и специфические для live-интерфейса инструменты MiniOS больше не доступны. Перед использованием восстановления или переустановки загрузчика Debian, подходящей для его BIOS/UEFI и разметки разделов, сделайте резервную копию всех важных данных.

Если только что пересозданное устройство по-прежнему не отображается в меню загрузки прошивки, проверьте режим прошивки, поддержку Secure Boot выбранной архитектурой, USB-порт/устройство и [совместимость оборудования](/getting-started/Hardware-Compatibility).

## Меню загрузки MiniOS появляется, но запуск не удаётся

Сначала удалите необязательные параметры. Используйте `debug` и `timing` для получения дополнительного вывода на ранних этапах загрузки. `rd.break` предназначен для продвинутой диагностики initramfs, а не для восстановления.

Если MiniOS не может найти свой источник, смотрите [Обнаружение системы](/reference/boot-process/System-Discovery). В оболочке initramfs полезную информацию для чтения без изменений дают:

```sh
cat /proc/cmdline
blkid
cat /proc/net/dev
findmnt
cat /var/log/livedbg
```

Временный `from=askdisk` может помочь определить устройство, на котором действительно находятся данные MiniOS. После этого используйте документированный синтаксис `from=` вместо угадывания имён устройств.

Для запуска по PXE или HTTP ISO смотрите [Сетевой загрузчик](/reference/boot-process/Network-Boot). Сетевая инициализация на ранних этапах загрузки не связана с NetworkManager в рабочей сессии.

### Ошибки модулей или root-union

См. [Загрузка модулей](/reference/boot-process/Module-Loading) для актуальных правил выбора и порядка модулей. В частности:

- `load=` и `noload=` могут исключить важные базовые или ядровые модули; если совпадают оба, приоритет у `noload=`;
- кандидаты с одинаковым базовым именем занимают одну и ту же позицию для замены;
- наличие файла с именем `.sb` не гарантирует, что это валидный образ SquashFS;
- запущенное ядро должно соответствовать согласованному модулю ядра MiniOS и загрузочным файлам.

После успешной загрузки проверьте фактическое состояние без изменений:

```bash
cat /proc/cmdline
sb list
sb next-boot
findmnt -no FSTYPE,OPTIONS /
findmnt -R /run/initramfs 2>/dev/null
```

## Проблемы с отображением

Если экран чёрный, разрешение некорректно или наблюдается цикл дисплей-менеджера:

1. Попробуйте параметр загрузки `text`. Рабочая консоль позволяет отличить проблему с графикой/рабочим столом от более раннего сбоя загрузки.
2. Удалите вручную заданные параметры `xorg-driver` или `xorg-resolution`.
3. Проверьте работу **Запустить без сохранения**, чтобы исключить влияние постоянной конфигурации дисплея.
4. Запишите модель GPU и драйвер с помощью `lspci -nnk`.
5. Проверьте вывод `journalctl -b -p warning` и `dmesg --level=err,warn`.

Для виртуальных машин см. [Виртуализация](/maintenance-and-recovery/Virtualization).

## Проблемы с сетью

Обычные проводные и Wi-Fi-соединения управляются через NetworkManager; см. [Сетевые подключения](/using-minios/Networking).

Сначала определите, существует ли интерфейс:

```bash
ip link
ip address
ip route
nmcli device status
nmcli connection show
```

- Если интерфейс отсутствует, зафиксируйте вывод `lspci -nnk` или `lsusb` и проверьте наличие ошибок прошивки или драйвера в `dmesg`.
- Если интерфейс есть, но нет адреса, различайте проблемы подключения/DHCP и отсутствие поддержки оборудования.
- Если адрес есть, проверьте сначала шлюз, затем IP-адрес, затем DNS-имя, чтобы разделить сбои канала, маршрутизации и DNS.
- Параметр загрузки `ip=` относится к ранней сетевой загрузке и не настраивает постоянное соединение NetworkManager. См. [Сетевой загрузчик](/reference/boot-process/Network-Boot).

## Проблемы с постоянством данных

Перед изменением подозрительного хранилища постоянства загрузитесь с помощью **Запустить без сохранения**. Не восстанавливайте и не удаляйте единственную копию сессии, пока она активна.

Проверьте, что в данный момент видит MiniOS:

```bash
sudo minios-session list
sudo minios-session running
sudo minios-session active
sudo minios-session status
sudo minios-session info
```

Проверьте выбранный режим загрузки, доступное место для записи, совместимость файловой системы и совместимость сессии. Подробные правила выбора описаны в [Сессии и постоянство](/using-minios/Sessions-and-Persistence) и [Внутреннее устройство постоянства](/reference/boot-process/Persistence-Internals).

Если важная неактивная сессия `native`, `dynfilefs`, `raw` или `luks` всё ещё читается, экспортируйте её **до** экспериментов с хранилищем:

```bash
sudo minios-session export <id> /path/to/session.tar.zst
```

Если Session Manager не может прочитать или экспортировать сессию, прекратите запись на исходное устройство и сохраните офлайн-копию затронутого хранилища перед дальнейшими действиями. MiniOS не определяет универсальную ручную процедуру для восстановления сегментов DynFileFS, ремонта внутренней файловой системы или восстановления метаданных сессии. Такое восстановление зависит от конкретной файловой системы/контейнера и должно выполняться только на копии, если ценность данных это оправдывает.

См. [Резервное копирование MiniOS](/maintenance-and-recovery/Backing-Up-MiniOS) для поддерживаемых сценариев резервного копирования и импорта сессий.

## Проблемы с хранилищем и свободным местом

Проверьте устройства и точки монтирования без внесения изменений:

```bash
lsblk -o NAME,SIZE,TYPE,FSTYPE,LABEL,UUID,MOUNTPOINTS,MODEL
findmnt
df -hT
df -ih
```

Переполненная файловая система может привести к сбоям при установке пакетов, неполному сохранению сессий и другим вторичным ошибкам. Освобождайте место, перемещая или удаляя известные данные только после подтверждения правильной файловой системы. Для удаления сессий используйте Менеджер сессий MiniOS вместо ручного удаления каталогов сессий по номерам.

Восстановление файловой системы — это не универсальная операция MiniOS. Если сама файловая система повреждена, размонтируйте её, сначала сохраните важные данные или образ, и используйте процедуру восстановления, подходящую для этой файловой системы и устройства хранения.

## Изменения пакетов и обновления системы

Если проблемы начались после изменений пакетов APT, помните, что в живой постоянной сессии файлы из модуля только для чтения MiniOS могут быть переопределены. Проверьте работу **Запустить без сохранения**, чтобы сравнить с исходным набором модулей. См. [Обновление MiniOS](/maintenance-and-recovery/Updating-MiniOS) для различий между обслуживанием APT и сменой релизов MiniOS.

## Сбор логов

Полезная информация включает:

```bash
uname -a
cat /etc/os-release
journalctl -b
journalctl -b -p warning
dmesg
lsblk -f
lspci -nnk
lsusb
```

Для повторяющихся сбоев загрузки на записываемых носителях MiniOS команда `EXPORT_LOGS=true` в `config.conf` экспортирует логи загрузки в `minios/log/`. См. [config.conf](/reference/configuration/config.conf).

Перед отправкой логов удалите учётные данные, приватные ключи, Wi-Fi-пароли и другую личную информацию. Для воспроизводимой ошибки приложите соответствующие фрагменты и откройте задачу в [трекере ошибок MiniOS](https://github.com/minios-linux/minios-live/issues).
