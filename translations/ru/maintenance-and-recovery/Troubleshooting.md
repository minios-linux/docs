# Устранение неполадок

Начните с наблюдения и обратимых тестов. Не выполняйте переразметку, форматирование, восстановление файловой системы, не удаляйте сессию и не заменяйте загрузочные файлы только ради проверки. Сначала сохраните важные данные.

## Первичная проверка

1. [Проверьте загруженный образ](/installing-minios/Verifying-Downloads).
2. Загрузитесь **без сохранения изменений**. Если проблема исчезла, проверьте постоянную сессию или её настройки, а не базовый образ.
3. Удалите пользовательские параметры загрузки и фильтры модулей, если они не нужны для воспроизведения проблемы.
4. Попробуйте другой USB-порт и, если возможно, другое проверенное устройство или компьютер.
5. Запишите первую ошибку и точное название пункта загрузочного меню, а не только последнее сообщение на экране.
6. Проверьте [совместимость оборудования](/getting-started/Hardware-Compatibility) если тот же проверенный образ не работает на одном компьютере, но работает на другом.

## Устройство не загружает меню MiniOS

Сначала определите, как было создано устройство MiniOS.

- Если образ был записан напрямую (`dd`, Etcher, Rufus в режиме DD или с помощью Дисковой утилиты), не восстанавливайте отдельные загрузочные файлы. Если копия повреждена, полностью перепишите устройство из проверенного образа.
- Для установки на основе файловой системы MiniOS создайте загрузочную структуру заново с помощью той же задокументированной инструкции, а не копируйте файлы GRUB, Syslinux или EFI из другого выпуска.
- Ventoy использует собственный загрузчик и структуру. Не устанавливайте загрузчик MiniOS поверх устройства Ventoy; используйте [Ventoy](/installing-minios/installation-tools/Ventoy) процедуру.
- После нативного преобразования целевое устройство использует стандартный загрузчик Debian и файловую структуру. Внешний вид рабочего стола MiniOS может сохраниться, но инфраструктура live и специфические для live-интерфейса инструменты MiniOS больше не доступны. Перед восстановлением или переустановкой загрузчика Debian, соответствующей BIOS/UEFI и схеме разделов, создайте резервную копию всех важных данных.

Если только что пересозданное устройство по-прежнему не отображается в меню загрузки прошивки, проверьте режим прошивки, поддержку Secure Boot выбранной архитектурой, USB-порт/устройство и [совместимость оборудования](/getting-started/Hardware-Compatibility).

## Появляется меню загрузки MiniOS, но запуск не удаётся

Сначала уберите необязательные параметры. Используйте `debug` и `timing` для получения более подробного вывода на ранних этапах загрузки. `rd.break` предназначен для продвинутой диагностики initramfs, а не для восстановления.

Если MiniOS не может найти свой источник, смотрите [Обнаружение системы](/reference/boot-process/System-Discovery). В оболочке initramfs полезная информация только для чтения включает:

```sh
cat /proc/cmdline
blkid
cat /proc/net/dev
findmnt
cat /var/log/livedbg
```

Временный `from=askdisk` может помочь определить устройство, на котором действительно находятся данные MiniOS. После этого используйте документированный `from=` синтаксис вместо угадывания имён устройств.

Для загрузки через PXE или HTTP ISO смотрите [Сетевая загрузка](/reference/boot-process/Network-Boot). Сетевая инициализация на ранних этапах загрузки не связана с NetworkManager в рабочем сеансе.

### Сбои модуля или корневого объединения

См. [Загрузка модулей](/reference/boot-process/Module-Loading) для правил выбора и порядка модулей. В частности:

- `load=` и `noload=` могут исключать важные базовые или ядровые модули; `noload=` выигрывает, если совпадают оба;
- кандидаты с одинаковым базовым именем занимают одну и ту же позицию для замены;
- файл с именем `.sb` не гарантирует, что файл является допустимым образом SquashFS;
- запущенное ядро должно соответствовать согласованному модулю ядра и загрузочным файлам MiniOS.

После успешной загрузки проверьте фактическое состояние без внесения изменений:

```bash
cat /proc/cmdline
sb list
sb next-boot
findmnt -no FSTYPE,OPTIONS /
findmnt -R /run/initramfs 2>/dev/null
```

## Проблемы с отображением

Если у вас черный экран, неподходящее разрешение или зацикливание дисплей-менеджера:

1. Попробуйте параметр загрузки `text`. Рабочая консоль позволяет отличить проблему с графикой/рабочим столом от сбоя на этапе загрузки.
2. Удалите вручную указанные параметры `xorg-driver` или `xorg-resolution`.
3. Проверьте **Запуск без сохранения**, чтобы исключить постоянную конфигурацию экрана.
4. Запишите модель GPU и драйвер с помощью `lspci -nnk`.
5. Проверьте `journalctl -b -p warning` и `dmesg --level=err,warn`.

Для виртуальных машин см. [Виртуализация](/maintenance-and-recovery/Virtualization).

## Проблемы с сетью

Обычные проводные и Wi-Fi подключения управляются через NetworkManager; см. [Сетевые подключения](/using-minios/Networking).

Сначала проверьте, существует ли интерфейс:

```bash
ip link
ip address
ip route
nmcli device status
nmcli connection show
```

- Если интерфейс отсутствует, зафиксируйте `lspci -nnk` или `lsusb` и проверьте наличие ошибок прошивки или драйвера в `dmesg`.
- Если интерфейс есть, но адрес не назначен, определите, связана ли проблема с подключением/DHCP или отсутствием поддержки оборудования.
- Если адрес назначен, проверьте шлюз, затем IP-адрес, затем DNS-имя, чтобы выявить проблемы с каналом, маршрутизацией или DNS.
- Параметр загрузки `ip=` относится к ранней загрузке по сети и не настраивает постоянное подключение через NetworkManager. Подробнее см. [Загрузка по сети](/reference/boot-process/Network-Boot).

## Проблемы с сохранением данных

Загрузка **Запустить без сохранения** перед изменением подозрительного хранилища. Не ремонтируйте и не удаляйте единственную копию сессии, пока она активна.

Проверьте, что сейчас видит MiniOS:

```bash
sudo minios-session list
sudo minios-session running
sudo minios-session active
sudo minios-session status
sudo minios-session info
```

Проверьте выбранный режим загрузки, доступное место для записи, совместимость файловой системы и сессии. Подробные правила выбора описаны в [Сессии и сохранение](/using-minios/Sessions-and-Persistence) и [Внутреннее устройство сохранения](/reference/boot-process/Persistence-Internals).

Если важная неактивная `native`, `dynfilefs`, `dynblk`, `raw`, или `luks` сессия всё ещё читается, экспортируйте её **до того, как** начнёте эксперименты с хранилищем:

```bash
sudo minios-session export <id> /path/to/session.tar.zst
```

Если Session Manager не может прочитать или экспортировать сессию, прекратите запись в исходное хранилище и сохраните его офлайн-копию перед дальнейшими действиями. Для отсоединённой dynblk-сессии `dynblk inspect /path/to/volume000.db` и `dynblk check /path/to/volume000.db` предоставляют диагностику формата только для чтения; не запускайте их на томе, который всё ещё подключён. MiniOS не определяет универсальную ручную процедуру восстановления сегментов DynFileFS, реконструкции dynblk-частей, ремонта внутренней файловой системы или восстановления метаданных сессии. Такое восстановление зависит от файловой системы или контейнера и должно выполняться только на копии, если ценность данных это оправдывает.

См. [Резервное копирование MiniOS](/maintenance-and-recovery/Backing-Up-MiniOS) для поддерживаемых сценариев резервного копирования и импорта сессий.

## Проблемы с хранилищем и свободным местом

Проверьте устройства и точки монтирования без внесения изменений:

```bash
lsblk -o NAME,SIZE,TYPE,FSTYPE,LABEL,UUID,MOUNTPOINTS,MODEL
findmnt
df -hT
df -ih
```

Заполненная файловая система может привести к сбоям при установке пакетов, неполному сохранению сессий и другим вторичным ошибкам. Освободите место, перемещая или удаляя только известные данные, предварительно убедившись, что выбрана правильная файловая система. Для удаления сессий используйте Менеджер сессий MiniOS, а не удаляйте каталоги сессий вручную.

Восстановление файловой системы — это не стандартная операция MiniOS. Если повреждена сама файловая система, сначала размонтируйте её, сохраните важные данные или образ, затем используйте процедуру восстановления, подходящую для этой файловой системы и устройства хранения.

## Изменения пакетов и обновления системы

Если проблемы начались после изменений пакетов APT, помните, что живая постоянная сессия может переопределять файлы из модулей MiniOS только для чтения. Проверьте **Запуск без сохранения** чтобы сравнить с исходным набором модулей. Подробнее см. [Обновление MiniOS](/maintenance-and-recovery/Updating-MiniOS) для различия между обслуживанием APT и сменой релизов MiniOS.

## Сбор журналов

Полезная информация включает:

```bash
uname -a
cat /etc/os-release
journalctl -b
journalctl -b -p warning
dmesg
lsblk -f
lspci -nnk
lsusb
```

Для повторяющихся сбоев загрузки на записываемых носителях MiniOS, `EXPORT_LOGS=true` в `config.conf` экспортирует журналы загрузки в `minios/log/`. Подробнее см. [config.conf](/reference/configuration/config.conf).

Перед отправкой журналов удалите учетные данные, приватные ключи, Wi-Fi пароли и другую личную информацию. Для воспроизводимой ошибки приложите соответствующие фрагменты и создайте обращение в [трекере ошибок MiniOS](https://github.com/minios-linux/minios-live/issues).
