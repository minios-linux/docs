# Устранение неполадок

Начните с наблюдения и обратимых тестов. Не изменяйте разметку, не форматируйте, не выполняйте восстановление файловой системы, не удаляйте сессию и не заменяйте загрузочные файлы только ради проверки. Сначала сохраните важные данные.

## Первичные проверки

1. [Проверьте загруженный образ](/installing-minios/Verifying-Downloads).
2. Загрузитесь **Запустить без сохранения**. Если проблема исчезла, проверьте постоянную сессию или её настройки, а не базовый образ.
3. Удалите пользовательские параметры загрузки и фильтры модулей, если они не нужны для воспроизведения проблемы.
4. Попробуйте другой USB-порт и, если возможно, другое заведомо рабочее устройство или компьютер.
5. Запишите первую ошибку и точный пункт загрузочного меню, а не только последнее сообщение на экране.
6. Проверьте [Совместимость оборудования](/getting-started/Hardware-Compatibility) если один и тот же проверенный образ не запускается на одном компьютере, но работает на другом.

## Устройство не доходит до меню загрузки MiniOS

Сначала определите, как был создан загрузочный носитель MiniOS.

- Для образа, записанного в "сырое" состояние (`dd`, Etcher, Rufus режим DD или запись образом через Дисковую утилиту), не восстанавливайте отдельные загрузочные файлы. Если копия повреждена, полностью перепишите устройство из проверенного образа.
- Для установки на основе файлов MiniOS воссоздайте загрузочную структуру тем же документированным способом, а не копируйте файлы GRUB, Syslinux или EFI из другого выпуска.
- Ventoy использует собственный загрузчик и структуру. Не устанавливайте загрузчик MiniOS поверх устройства Ventoy; используйте процедуру [Ventoy](/installing-minios/installation-tools/Ventoy) вместо этого.
- После нативного преобразования на целевом устройстве используется стандартный загрузчик Debian и привычная структура файловой системы. Внешний вид рабочего стола MiniOS может сохраниться, но инфраструктура live-режима и специфические инструменты MiniOS больше не доступны. Перед восстановлением или переустановкой загрузчика Debian, соответствующей BIOS/UEFI и разметке разделов, сделайте резервную копию важных данных.

Если только что пересозданное устройство всё равно не появляется в меню загрузки прошивки, проверьте режим прошивки, поддержку Secure Boot выбранной архитектуры, USB-порт/устройство и [совместимость оборудования](/getting-started/Hardware-Compatibility).

## Меню загрузки MiniOS появляется, но запуск не происходит

Сначала уберите необязательные параметры. Используйте `debug` и `timing` для получения дополнительного вывода на ранних этапах загрузки. `rd.break` предназначен для продвинутой диагностики initramfs, а не для восстановления.

Если MiniOS не может найти свой источник, см. [Обнаружение системы](/reference/boot-process/System-Discovery). В оболочке initramfs полезна следующая информация только для чтения:

```sh
cat /proc/cmdline
blkid
cat /proc/net/dev
findmnt
cat /var/log/livedbg
```

Временный `from=askdisk` может помочь определить устройство, на котором действительно находятся данные MiniOS. После этого используйте документированный синтаксис `from=` вместо угадывания имен устройств.

Для загрузки по PXE или HTTP ISO см. [Сетевой загрузчик](/reference/boot-process/Network-Boot). Сетевая загрузка на ранних этапах не связана с NetworkManager в рабочей сессии.

### Сбои модулей или объединения корня (root-union)

См. [Загрузка модулей](/reference/boot-process/Module-Loading) для правил выбора и порядка загрузки модулей. В частности:

- `load=` и `noload=` могут исключить базовые или критически важные модули ядра; `noload=` выигрывает, если совпадают оба;
- кандидаты с одинаковым базовым именем занимают одну и ту же позицию для замены;
- файл с именем `.sb` не гарантирует, что это валидный образ SquashFS;
- запущенное ядро должно соответствовать согласованной версии модуля ядра MiniOS и загрузочным файлам.

После успешной загрузки проверьте фактическое состояние без внесения изменений:

```bash
cat /proc/cmdline
sb list
sb next-boot
findmnt -no FSTYPE,OPTIONS /
findmnt -R /run/initramfs 2>/dev/null
```

## Проблемы с отображением

Если экран чёрный, разрешение некорректно или наблюдается цикл дисплей-менеджера:

1. Попробуйте параметр загрузки `text`. Рабочая консоль позволяет отличить проблему с графикой/рабочим столом от сбоя на ранней стадии загрузки.
2. Удалите вручную указанные параметры `xorg-driver` или `xorg-resolution`.
3. Проверьте **Запустить без сохранения** чтобы исключить влияние сохранённых настроек отображения.
4. Запишите GPU и драйвер с помощью `lspci -nnk`.
5. Проверьте `journalctl -b -p warning` и `dmesg --level=err,warn`.

Для виртуальных машин см. [Виртуализация](/maintenance-and-recovery/Virtualization).

## Проблемы с сетью

Обычные проводные и Wi-Fi-соединения управляются через NetworkManager; см. [Сетевые подключения](/using-minios/Networking).

Сначала определите, существует ли интерфейс:

```bash
ip link
ip address
ip route
nmcli device status
nmcli connection show
```

- Если интерфейс отсутствует, запишите `lspci -nnk` или `lsusb` и проверьте наличие ошибок прошивки или драйверов в `dmesg`.
- Если интерфейс есть, но адреса нет, различайте проблемы подключения/DHCP и отсутствие поддержки оборудования.
- Если адрес назначен, проверьте шлюз, затем IP-адрес, затем DNS-имя, чтобы отделить проблемы со связью, маршрутизацией и DNS.
- Параметр загрузки `ip=` относится только к ранней сетевой загрузке и не настраивает постоянное соединение через NetworkManager. См. [Сетевой загрузчик](/reference/boot-process/Network-Boot).

## Проблемы с постоянством данных

Загрузитесь **Запустить без сохранения** прежде чем изменять подозреваемое хранилище для постоянства. Не восстанавливайте и не удаляйте единственную копию сессии, пока она активна.

Проверьте, что сейчас видит MiniOS:

```bash
sudo minios-session list
sudo minios-session running
sudo minios-session active
sudo minios-session status
sudo minios-session info
```

Проверьте выбранный режим загрузки, доступное место для записи, совместимость файловой системы и совместимость сессии. Подробные правила выбора описаны в [Сессии и постоянство](/using-minios/Sessions-and-Persistence) и [Внутреннее устройство постоянства](/reference/boot-process/Persistence-Internals).

Если важная неактивная `native`, `dynfilefs`, `raw` или `luks` сессия всё ещё читается, экспортируйте её **до** экспериментов с хранилищем:

```bash
sudo minios-session export <id> /path/to/session.tar.zst
```

Если Session Manager не может прочитать или экспортировать сессию, прекратите запись на исходный носитель и сохраните его офлайн-копию перед дальнейшими действиями. MiniOS не определяет универсальную ручную процедуру для восстановления сегментов DynFileFS, ремонта внутренней файловой системы или восстановления метаданных сессии. Такое восстановление зависит от файловой системы/контейнера и должно выполняться только на копии, если ценность данных это оправдывает.

См. [Резервное копирование MiniOS](/maintenance-and-recovery/Backing-Up-MiniOS) для поддерживаемых сценариев резервного копирования и импорта сессий.

## Проблемы с хранилищем и свободным местом

Проверьте устройства и точки монтирования без внесения изменений:

```bash
lsblk -o NAME,SIZE,TYPE,FSTYPE,LABEL,UUID,MOUNTPOINTS,MODEL
findmnt
df -hT
df -ih
```

Заполненная файловая система может привести к сбоям при установке пакетов, неполному сохранению сессий и другим вторичным ошибкам. Освобождайте место только после подтверждения правильной файловой системы, перемещая или удаляя известные данные. Для удаления сессий используйте Менеджер сессий MiniOS вместо ручного удаления каталогов сессий по номерам.

Восстановление файловой системы — это не универсальная операция MiniOS. Если файловая система повреждена, размонтируйте её, сначала сохраните важные данные или образ, и используйте процедуру восстановления, подходящую для этой файловой системы и устройства хранения.

## Изменения пакетов и обновления системы

Если проблемы появились после изменений пакетов APT, помните, что живая сессия с постоянством может переопределять файлы из модулей только для чтения MiniOS. Проверьте **Запустить без сохранения** чтобы сравнить с исходным набором модулей. См. [Обновление MiniOS](/maintenance-and-recovery/Updating-MiniOS) для различия между обслуживанием APT и сменой выпусков MiniOS.

## Сбор логов

Полезная информация включает:

```bash
uname -a
cat /etc/os-release
journalctl -b
journalctl -b -p warning
dmesg
lsblk -f
lspci -nnk
lsusb
```

При повторяющихся сбоях загрузки на записываемых носителях MiniOS, `EXPORT_LOGS=true` в `config.conf` экспортирует логи загрузки в `minios/log/`. См. [config.conf](/reference/configuration/config.conf).

Перед отправкой логов удалите учетные данные, приватные ключи, пароли Wi-Fi и другую личную информацию. Для воспроизводимой ошибки приложите соответствующие фрагменты и откройте задачу в [трекере задач MiniOS](https://github.com/minios-linux/minios-live/issues).
