# Резервное копирование MiniOS

Резервная копия — это надёжный способ восстановления для MiniOS. Документация не гарантирует универсальную процедуру восстановления повреждённого загрузчика, файловой системы или контейнера с постоянством. Сохраняйте копии, которые можно восстановить, перед изменением релиза, ядра, структуры хранилища или важных сессий.

## Что нужно копировать

Сохраняйте те части, которые нельзя просто восстановить из образа MiniOS:

- личные файлы, включая скрытые данные приложений, которые для вас важны;
- файлы `config.conf`, проверенные файлы `config.conf.d` и намеренные изменения в загрузочном меню или параметрах загрузки;
- созданные пользователем модули `.sb` и пометку о релизе MiniOS, для которого они были собраны;
- постоянные сессии, содержащие необходимое состояние системы или приложений;
- ключи шифрования, данные для восстановления и другие секреты, хранящиеся отдельно от защищаемой ими резервной копии.

Файлы, находящиеся вне слоя сессии, например в отдельном месте для пользовательских данных, необходимо копировать отдельно. Не рассчитывайте, что архив сессии содержит данные, смонтированные из другой файловой системы.

## Экспорт постоянных сессий

Менеджер сессий MiniOS может экспортировать **неактивную** сессию `native`, `dynfilefs`, `raw` или `luks` в проверенный архив `.tar.zst`. Сначала определите нужную сессию:

```bash
minios-session list
minios-session running
```

Затем загрузите другую сессию или выберите **Запуск без сохранения** и экспортируйте неактивную сессию:

```bash
sudo minios-session export <id> /path/to/session.tar.zst
```

Экспорт — это логическая копия содержимого сессии, а не побайтная копия её контейнера хранения. Сохраняйте архив на другом устройстве.

Для LUKS-сессии архив содержит расшифрованные логические файлы. Если данные должны оставаться зашифрованными, защищайте архив отдельно.

### Сессии SquashFS

Текущий Менеджер сессий не экспортирует и не копирует сессии SquashFS. Используйте **Сохранить сейчас** перед завершением работы, чтобы текущий снимок был полным, затем отдельно защитите важные файлы. Если вам нужна полная восстанавливаемая копия всего устройства MiniOS, создайте офлайн-образ устройства.

Не полагайтесь на ручное копирование смонтированного каталога сессии или на восстановление `session.conf`, сегментов DynFileFS или метаданных контейнера в качестве метода резервного копирования.

## Резервное копирование конфигурации и модулей

На записываемых носителях MiniOS сохраняйте файлы `minios/config.conf`, `minios/config.conf.d/` и созданные пользователем модули, размещённые в каталоге `minios/modules/`.
Также зафиксируйте пользовательские параметры загрузки или изменения меню загрузки, которые неочевидны из этих файлов.

Модуль, собранный для одного релиза MiniOS, не гарантированно будет работать с другим.
Сохраняйте исходники или рецепты, необходимые для пересборки важных пользовательских модулей.

## Создание образа всего устройства

Образ всего устройства полезен, если вы хотите сохранить таблицу разделов, загрузочные файлы, модули, конфигурацию, сессии и другие данные вместе. Создавайте его офлайн: выключите MiniOS и создайте образ устройства с другой запущенной системы.

[Дисковая утилита](/installing-minios/installation-tools/Drive-Utility) предоставляет операции **Создать образ** и **Записать образ**. Сохраняйте образ на другом физическом устройстве. Восстановление образа всего устройства перезаписывает выбранную цель, поэтому перед записью проверьте модель и объём целевого устройства.

Образ устройства — это дополнение, а не замена отдельной резервной копии важных личных файлов.

## Восстановление архива сессии

Импорт архива Менеджера сессий создаёт новую сессию с номером; существующая сессия не перезаписывается:

```bash
sudo minios-session import /path/to/session.tar.zst --auto-convert
```

Во время импорта выполняется проверка совместимости. Проверьте импортированную сессию перед её активацией и сохраняйте рабочую сессию до тех пор, пока не убедитесь в работоспособности восстановленной копии.

При переходе на другой релиз MiniOS рекомендуется переносить только выбранные личные данные и настройки. Не рассчитывайте, что старая полная сессия или пользовательский модуль будут совместимы с новым релизом только потому, что их можно туда скопировать.

См. [Сессии и постоянство](/using-minios/Sessions-and-Persistence) для управления сессиями и [Обновление MiniOS](/maintenance-and-recovery/Updating-MiniOS) для перехода между релизами MiniOS.
