# Резервное копирование MiniOS

Резервная копия — это надёжный способ восстановления MiniOS. Документация не гарантирует универсальную процедуру восстановления для повреждённого загрузчика, файловой системы или контейнера с постоянством. Сохраняйте копии, пригодные для восстановления, перед изменением релиза, ядра, структуры хранения или важных сессий.

## Что нужно сохранять

Сохраняйте те части, которые нельзя просто воссоздать из образа MiniOS:

- личные файлы, включая скрытые данные приложений, которые для вас важны;
- `config.conf`, проверенные `config.conf.d` файлы и внесённые вручную изменения в меню загрузки или параметры загрузки;
- созданные пользователем `.sb` модули и пометку о релизе MiniOS, для которого они были собраны;
- постоянные сессии, содержащие нужное вам состояние системы или приложений;
- ключи шифрования, данные для восстановления и другие секреты, хранящиеся отдельно от защищаемой ими резервной копии.

Файлы, расположенные вне слоя сессии, например в отдельном месте хранения пользовательских данных, необходимо сохранять отдельно. Не рассчитывайте, что архив сессии содержит данные, смонтированные из другой файловой системы.

## Экспортировать постоянные сессии

Менеджер сессий MiniOS может экспортировать **неактивную** `native`, `dynfilefs`, `dynblk`, `vmdk` или `raw` сессию, включая поддерживаемые варианты с шифрованием LUKS2, в проверенный `.tar.zst` архив. Сначала определите нужную сессию:

```bash
minios-session list
minios-session running
```

Затем загрузите другую сессию или **Запустить без сохранения** и экспортируйте неактивную сессию:

```bash
sudo minios-session export <id> /path/to/session.tar.zst
```

Экспорт представляет собой логическую копию содержимого сессии, а не побайтную копию её контейнера хранения. Сохраняйте архив на отдельном устройстве.

Если сессия с бэкендом Raw, DynFileFS, DynBlk или VMDK обёрнута в LUKS2, архив будет содержать расшифрованные логические файлы. Если данные должны оставаться зашифрованными, защищайте архив отдельно.

### Сессии SquashFS

Текущий Менеджер сессий не экспортирует и не копирует сессии SquashFS. Используйте **Сохранить сейчас** перед завершением работы, чтобы текущий снимок был полным, а затем отдельно сохраните важные файлы. Если нужна полностью восстанавливаемая копия всего устройства MiniOS, создайте офлайн-образ устройства.

Не полагайтесь на ручное копирование смонтированного каталога сессии или на восстановление `session.conf`, сегментов DynFileFS, файлов-основ DynBlk или другой метаинформации контейнера в качестве метода резервного копирования. Ручное побайтное резервное копирование DynBlk безопасно только при отключённом томе и должно сохранять все существующие `volume*.db` части, включая номера из четырёх и более цифр, в точности как они есть; логическое `minios-session export` предпочтительнее.

## Сохранение конфигурации и модулей

На записываемых носителях MiniOS сохраняйте `minios/config.conf`, `minios/config.conf.d/`, а также созданные пользователем модули, размещённые в каталоге `minios/modules/`.
Также запишите пользовательские параметры загрузки или изменения меню загрузки, которые неочевидны из этих файлов.

Модуль, собранный для одного релиза MiniOS, не гарантированно будет подходить для другого.
Сохраняйте исходники или инструкции, необходимые для пересборки важных пользовательских модулей.

## Создание образа всего устройства

Образ всего устройства полезен, если нужно сохранить таблицу разделов, загрузочные файлы, модули, конфигурацию, сессии и другие данные вместе. Создавайте его офлайн: выключите MiniOS и создайте образ устройства с другой работающей системы.

[Дисковая утилита](/installing-minios/installation-tools/Drive-Utility) предоставляет операции **Создать образ** и **Записать образ**. Сохраняйте образ на другом физическом устройстве. Восстановление образа всего устройства перезапишет выбранную цель, поэтому перед записью проверьте модель и объём целевого устройства.

Образ устройства — это дополнение, а не замена отдельной резервной копии важных личных файлов.

## Восстановление архива сессии

Импорт архива Менеджера сессий создаёт новую сессию с номером; существующая сессия не перезаписывается:

```bash
sudo minios-session import /path/to/session.tar.zst --auto-convert
```

Во время импорта выполняется проверка совместимости. Проверьте импортированную сессию перед её активацией и сохраняйте рабочую сессию до тех пор, пока восстановленная копия не будет протестирована.

При переходе на другой релиз MiniOS рекомендуется переносить только выбранные личные данные и настройки. Не стоит считать, что старая полная сессия или пользовательский модуль совместимы с новым релизом только потому, что их можно туда скопировать.

См. [Сессии и постоянство](/using-minios/Sessions-and-Persistence) для управления сессиями и [Обновление MiniOS](/maintenance-and-recovery/Updating-MiniOS) для перехода между релизами MiniOS.
