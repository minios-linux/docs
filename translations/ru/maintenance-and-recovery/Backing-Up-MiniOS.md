# Резервное копирование MiniOS

Резервная копия — это надёжный способ восстановления MiniOS. Документация не гарантирует универсальную процедуру восстановления для повреждённого загрузчика, файловой системы или контейнера с постоянством. Сохраняйте копии, пригодные для восстановления, перед изменением релиза, ядра, структуры хранения или важных сессий.

## Что нужно сохранять

Сохраняйте те части, которые нельзя просто воссоздать из образа MiniOS:

- личные файлы, включая скрытые данные приложений, которые для вас важны;
- `config.conf`, проверенные `config.conf.d` файлы и внесённые вручную изменения в меню загрузки или параметры загрузки;
- созданные пользователем `.sb` модули и пометку о релизе MiniOS, для которого они были собраны;
- постоянные сессии, содержащие нужное вам состояние системы или приложений;
- ключи шифрования, данные для восстановления и другие секреты, хранящиеся отдельно от защищаемой ими резервной копии.

Файлы, расположенные вне слоя сессии, например в отдельном месте хранения пользовательских данных, необходимо сохранять отдельно. Не рассчитывайте, что архив сессии содержит данные, смонтированные из другой файловой системы.

## Экспортировать постоянные сессии

Менеджер сессий MiniOS может экспортировать **неактивную** `native`, `dynfilefs`, `dynblk`, `vmdk`, или `raw` сессию, включая поддерживаемые варианты с шифрованием LUKS2, в проверенный `.tar.zst` архив. Сначала определите сессию:

```bash
sudo minios-session list
sudo minios-session running
```

Затем загрузите другую сессию или **Запустить без сохранения** и экспортируйте неактивную сессию:

```bash
sudo minios-session export <id> /path/to/session.tar.zst
```

Экспорт представляет собой логическую копию содержимого сессии, а не побайтную копию её контейнера хранения. Сохраняйте архив на отдельном устройстве.

Для сессии, чей бэкенд Raw, DynFileFS, DynBlk или VMDK обёрнут в LUKS2, архив будет содержать расшифрованные логические файлы. Если данные должны оставаться зашифрованными, защищайте архив отдельно.

### Сессии SquashFS

Текущий Менеджер сессий не экспортирует и не копирует сессии SquashFS. Используйте **Сохранить сейчас** перед завершением работы, чтобы текущий снимок был полным, а затем отдельно сохраните важные файлы. Если нужна полностью восстанавливаемая копия всего устройства MiniOS, создайте офлайн-образ устройства.

Не полагайтесь на ручное копирование смонтированного каталога сессии или на восстановление `session.conf`, сегментов DynFileFS, файлов-основ DynBlk или другой метаинформации контейнера в качестве метода резервного копирования. Ручное побайтное резервное копирование DynBlk безопасно только при отключённом томе и должно сохранять все существующие `volume*.db` части, включая номера из четырёх и более цифр, в точности как они есть; логическое `minios-session export` предпочтительнее.

## RAM и образы Ventoy persistence

Перед созданием резервной копии хранилища, используемого для `perchtoram` сессии, обязательно сохраните состояние RAM обратно в исходное хранилище или как новую сессию. В противном случае офлайн-копия исходного носителя будет содержать только последнее сохранённое состояние. Для сохранения требуется исходный записываемый носитель и его идентификатор; подробнее см. в разделе [Сессии и сохранение данных](/using-minios/Sessions-and-Persistence).

Выбранный бэкенд плагина Ventoy Persistence представляет собой одну среду ext4, а не пронумерованную сессию MiniOS, и не может быть экспортирован через Session Manager. Перед копированием полного образа бэкенда с другого устройства корректно завершите его работу; также сохраните его конфигурацию Ventoy. Ведите отдельные резервные копии важных личных файлов.

## Резервное копирование конфигурации и модулей

На записываемом носителе MiniOS сохраните `minios/config.conf`, `minios/config.conf.d/` и созданные пользователем модули, которые находятся в каталоге `minios/modules/`.
Также зафиксируйте пользовательские параметры загрузки или изменения в меню загрузки, которые неочевидны из этих файлов.

Модуль, созданный для одного выпуска MiniOS, не обязательно будет совместим с другим выпуском.
Сохраняйте исходный код или рецепт, необходимый для пересборки важных пользовательских модулей.

## Создание образа всего устройства

Образ всего устройства полезен, если нужно сохранить таблицу разделов, загрузочные файлы, модули, конфигурацию, сессии и другие данные вместе. Создавайте его офлайн: выключите MiniOS и создайте образ устройства с другой запущенной системы.

[Дисковая утилита](/installing-minios/installation-tools/Drive-Utility) предоставляет **Создать образ** и **Записать образ** операции. Сохраняйте образ на отдельное физическое устройство. Восстановление образа всего устройства перезапишет выбранную цель, поэтому перед записью проверьте модель и ёмкость устройства.

Образ устройства — это дополнение, а не замена отдельной резервной копии важных личных файлов.

## Восстановление архива сессии

Импорт архива Session Manager создаёт новую сессию с номером; существующая сессия не будет перезаписана:

```bash
sudo minios-session import /path/to/session.tar.zst --auto-convert
```

Во время импорта выполняется проверка совместимости. Перед активацией проверьте импортированную сессию и сохраните рабочую сессию до тех пор, пока восстановленная копия не будет протестирована.

При переходе на другой релиз MiniOS рекомендуется переносить только выбранные личные данные и настройки. Не следует считать, что старая полная сессия или пользовательский модуль будут совместимы с новым релизом только потому, что их можно скопировать.

Смотрите [Сессии и сохранение данных](/using-minios/Sessions-and-Persistence) для управления сессиями и [Обновление MiniOS](/maintenance-and-recovery/Updating-MiniOS) для перехода между релизами MiniOS.
