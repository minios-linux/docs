# Резервное копирование MiniOS

Резервная копия — это надёжный способ восстановления MiniOS. Документация не гарантирует универсального способа восстановления повреждённого загрузчика, файловой системы или контейнера с постоянными данными. Создавайте копии, которые можно восстановить, перед изменением версии, ядра, структуры хранилища или важных сессий.

## Что нужно сохранять

Сохраняйте те части, которые нельзя просто восстановить из образа MiniOS:

- личные файлы, включая скрытые данные приложений, которые для вас важны;
- `config.conf`, проверенные `config.conf.d` файлы и внесённые вручную изменения в меню загрузки или параметры загрузки;
- созданные пользователем `.sb` модули и пометку о версии MiniOS, для которой они были собраны;
- постоянные сессии, содержащие нужное вам состояние системы или приложений;
- ключи шифрования, данные для восстановления и другие секреты, хранящиеся отдельно от защищаемой ими резервной копии.

Файлы, размещённые вне слоя сессии, например в отдельном разделе для пользовательских данных, нужно сохранять отдельно. Не рассчитывайте, что архив сессии содержит данные, смонтированные из другой файловой системы.

## Экспортировать постоянные сессии

Менеджер сессий MiniOS может экспортировать **неактивную** `native`, `dynfilefs`, или `raw` сессию в проверенный `luks` архив. Сначала определите нужную сессию:`.tar.zst`

```bash
minios-session list
minios-session running
```

Затем загрузите другую сессию или **Запустить без сохранения** и экспортируйте неактивную сессию:

```bash
sudo minios-session export <id> /path/to/session.tar.zst
```

Экспорт создаёт логическую копию содержимого сессии, а не побайтную копию контейнера. Сохраняйте архив на отдельном устройстве.

Для LUKS-сессии архив содержит расшифрованные логические файлы. Если данные должны оставаться зашифрованными, защищайте архив отдельно.

### Сессии SquashFS

Текущий Менеджер сессий не экспортирует и не копирует сессии SquashFS. Используйте **Сохранить сейчас** перед завершением работы, чтобы текущий снимок был полным, а затем отдельно сохраните важные файлы. Если вам нужна полная копия всего устройства MiniOS для восстановления, создайте офлайн-образ устройства.

Не полагайтесь на ручное копирование смонтированной директории сессии или на восстановление `session.conf`, сегментов DynFileFS или метаданных контейнера в качестве метода резервного копирования.

## Резервное копирование конфигурации и модулей

На записываемых носителях MiniOS сохраняйте `minios/config.conf`, `minios/config.conf.d/`, а также созданные пользователем модули, размещённые в `minios/modules/`.
Также зафиксируйте пользовательские параметры загрузки или изменения меню загрузки, которые не очевидны из этих файлов.

Модуль, собранный для одной версии MiniOS, не гарантированно будет работать с другой версией.
Сохраняйте исходный код или рецепт, необходимый для пересборки важных пользовательских модулей.

## Создание образа всего устройства

Образ всего устройства полезен, если нужно сохранить таблицу разделов, загрузочные файлы, модули, конфигурацию, сессии и другие данные вместе. Создавайте такой образ офлайн: выключите MiniOS и создайте образ устройства с другой запущенной системы.

[Дисковая утилита](/installing-minios/installation-tools/Drive-Utility) предоставляет операции **Создать образ** и **Записать образ**. Сохраняйте образ на другом физическом устройстве. Восстановление образа всего устройства полностью перезапишет выбранную цель, поэтому перед записью проверьте модель и объём целевого устройства.

Образ устройства — это дополнение, а не замена отдельной резервной копии важных личных файлов.

## Восстановление архива сессии

Импорт архива Менеджера сессий создаёт новую сессию с номером; существующая сессия не будет перезаписана:

```bash
sudo minios-session import /path/to/session.tar.zst --auto-convert
```

Во время импорта выполняется проверка совместимости. Проверьте импортированную сессию перед её активацией и сохраняйте рабочую сессию до тех пор, пока не убедитесь, что восстановленная копия работает корректно.

При переходе на другую версию MiniOS рекомендуется переносить только выбранные личные данные и настройки. Не рассчитывайте, что старая полная сессия или пользовательский модуль будут совместимы с новой версией только потому, что их можно скопировать.

См. [Сессии и постоянство](/using-minios/Sessions-and-Persistence) для управления сессиями и [Обновление MiniOS](/maintenance-and-recovery/Updating-MiniOS) для перехода между версиями MiniOS.
