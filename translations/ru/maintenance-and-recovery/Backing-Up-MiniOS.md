# Резервное копирование MiniOS

Резервная копия — это надежный способ восстановления для MiniOS. Документация не гарантирует универсальную процедуру восстановления повреждённого загрузчика, файловой системы или контейнера с постоянством. Создавайте копии для восстановления перед изменением релиза, ядра, структуры хранилища или важных сессий.

## Что нужно сохранять в резервной копии

Сохраняйте те части, которые нельзя просто восстановить из MiniOS образа:

- личные файлы, включая скрытые данные приложений, которые для вас важны;
- `config.conf`, проверенные `config.conf.d`файлы и внесённые вами изменения в меню загрузки или параметры загрузки;
- созданные пользователем `.sb`модули и пометку о том, для какой версии MiniOS они были собраны;
- постоянные сессии, содержащие нужное вам состояние системы или приложений;
- ключи шифрования, данные для восстановления и другие секретные данные, которые хранятся отдельно от защищаемой ими резервной копии.

Файлы, находящиеся вне слоя сессии, например в отдельном каталоге пользовательских данных, нужно сохранять отдельно. Не рассчитывайте, что архив сессии содержит данные, смонтированные из другой файловой системы.

## Экспортировать постоянные сессии

Менеджер сессий MiniOS может экспортировать **неактивную** `native`, `dynfilefs`, `dynblk`, `raw` или `luks` сессию в проверенный `.tar.zst` архив. Сначала определите сессию:

```bash
minios-session list
minios-session running
```

Затем загрузите другую сессию или **Запустить без сохранения** и экспортируйте неактивную сессию:

```bash
sudo minios-session export <id> /path/to/session.tar.zst
```

Экспорт — это логическая копия содержимого сессии, а не побайтная копия контейнера хранения. Сохраните её на другом устройстве.

Для LUKS-сессии архив содержит расшифрованные логические файлы. Защитите архив отдельно, если данные должны оставаться зашифрованными.

### Сеансы SquashFS

Текущий менеджер сеансов не экспортирует и не копирует сеансы SquashFS. Используйте **Сохранить сейчас** перед завершением работы, чтобы текущий снимок был полным, затем отдельно защитите важные файлы. Если вам нужна полная копия всего устройства MiniOS с возможностью восстановления, создайте офлайн-образ устройства.

Не полагайтесь на ручное копирование смонтированной директории сеанса или на восстановление `session.conf`, сегментов DynFileFS, резервных файлов dynblk или других метаданных контейнера в качестве метода резервного копирования. Ручное побайтовое резервное копирование dynblk безопасно только при отключённом томе и должно сохранять всю `volume000.db` через `volume063.db` пространство имён в точности как оно есть; предпочтительно использовать логическое `minios-session export`.

## Резервное копирование конфигурации и модулей

На записываемом MiniOS-носителе сохраните `minios/config.conf`, `minios/config.conf.d/`, а также созданные пользователем модули, которые хранятся в `minios/modules/`.
Также запишите пользовательские параметры загрузки или изменения в загрузочном меню, которые не очевидны из этих файлов.

Модуль, созданный для одного выпуска MiniOS, не всегда подходит для другого.
Сохраняйте исходный код или рецепт, необходимый для пересборки важных пользовательских модулей.

## Создать образ всего устройства

Образ всего устройства полезен, если нужно сохранить таблицу разделов, загрузочные файлы, модули, конфигурацию, сессии и другие данные вместе. Создайте его офлайн: выключите MiniOS и создайте образ устройства с другой запущенной системы.

[Дисковая утилита](/installing-minios/installation-tools/Drive-Utility) предоставляет **Создать образ** и **Записать образ** операции. Сохраняйте образ на другом физическом устройстве. Восстановление образа всего устройства перезапишет выбранную цель, поэтому перед записью проверьте модель и объем целевого устройства.

Образ устройства — это дополнение к отдельной резервной копии важных личных файлов, а не её замена.

## Восстановление архива сессии

Импорт архива Session Manager создаёт новую сессию с номером; существующая сессия не будет перезаписана:

```bash
sudo minios-session import /path/to/session.tar.zst --auto-convert
```

Во время импорта выполняется проверка совместимости. Перед активацией проверьте импортированную сессию и сохраните рабочую сессию до тех пор, пока восстановленная копия не будет протестирована.

При переходе на другой релиз MiniOS рекомендуется переносить только выбранные личные данные и настройки. Не стоит считать, что старая полная сессия или пользовательский модуль совместимы с новым релизом только потому, что их можно скопировать.

См. [Сессии и сохранение данных](/using-minios/Sessions-and-Persistence) для управления сессиями и [Обновление MiniOS](/maintenance-and-recovery/Updating-MiniOS) для перехода между релизами MiniOS.
