# Создание пользовательских образов MiniOS

Конструктор образов MiniOS — это приложение на GTK для ремастеринга существующего образа MiniOS. Оно выбирает содержимое из текущей сессии MiniOS, ISO-файла или оптического диска, применяет декларативную настройку и использует `minios-image-compose` для создания проверенного загрузочного ISO-образа.

Конструктор работает внутри MiniOS. Он не изменяет выбранный исходный носитель.

## Выберите подходящий рабочий процесс

Конструктор образов MiniOS ремастерит существующий бинарный образ MiniOS. Он не заменяет следующие рабочие процессы:

- **Сборка MiniOS из исходников:** используйте сборочную систему `minios-live`, если требуется изменить списки пакетов дистрибутива, конфигурацию сборки, слой ядра, загрузочные артефакты или цепочку модулей, собираемых из исходников. См. [Сборка MiniOS](/development/Building-MiniOS).
- **Создание повторно используемого модуля:** используйте `apt2sb`, `script2sb`, `chroot2sb` или другие инструменты для работы с модулями, если результатом должен быть отдельный слой `.sb`. См. [Создание модулей](/preparing-and-customizing/Managing-Modules).
- **Ремастеринг образа:** используйте Конструктор образов MiniOS для выбора существующих модулей, добавления готовых внешних модулей, изменения поддерживаемых настроек образа, при необходимости захвата изменений сессии и публикации нового ISO.

Слой файловой системы проекта предназначен для декларативных файлов в корне образа. Он не выполняет скрипты, не устанавливает пакеты и не открывает chroot. Программное обеспечение, предназначенное для повторного использования, должно быть подготовлено как модуль до добавления в проект Конструктора образов MiniOS.

## Варианты источника

На странице источника принимаются:

- Текущая сессия MiniOS на базе LiveKit или dracut.
- ISO-файл MiniOS.
- Оптический диск MiniOS.

ISO-файлы и оптические диски монтируются только для чтения с помощью `udisksctl`. Инвентаризация источника фиксирует выпуск, версию, архитектуру, поддержку загрузчика, размер, перечень модулей и отпечаток источника. Если источник изменяется после планирования, сборка блокируется, чтобы не продолжать с другими входными данными.

Захват сессии всегда описывает изменения в текущей запущенной сессии MiniOS. При выборе ISO или оптического диска захват доступен только если отпечаток базового модуля этого источника совпадает с примонтированной базой текущей сессии. Выбор внешнего носителя не фиксирует изменения, сделанные в другой системе.

## Требования

Для работы Конструктора образов MiniOS требуется соответствующий бэкенд `minios-image-compose`. Для источников в виде ISO-файлов и оптических дисков необходим `udisks2`. Для чтения только для root `/etc/live/config.conf` и захвата изменяемой сессии могут потребоваться `pkexec` и агент PolicyKit для рабочего стола. Захват сессии требует совместимого `savechanges`, предоставляемого `minios-tools` версии 1.5.0 или новее.

Приложение и бэкенд компоновки работают без привилегий. Авторизация ограничена фиксированным средством чтения live-конфигурации и, при необходимости, доверенным `/usr/bin/savechanges`.

## Рабочий процесс проекта

### Выбор источника

Выберите источник и дождитесь завершения инвентаризации. Проверьте его идентификатор, архитектуру, поддержку загрузки, диагностику и количество модулей. Устраните ошибки источника перед продолжением.

### Выбор содержимого

Выберите модули источника для включения и добавьте любые внешние модули `.sb`. Необходимые базовые и модуль ядра заблокированы. Модули, активные в текущей сессии, но отсутствующие в выбранном источнике, отображаются отдельно и не включаются автоматически.

Дополнительные модули должны быть читаемыми обычными файлами с валидными данными SquashFS. Дубликаты или совпадения имён с учётом регистра и коллизии целей отклоняются, так как во время работы слои определяются по базовому имени.

### Настройка параметров

Выберите путь вывода и требуемую текущую конфигурацию MiniOS. Пустые поля настройки или `Keep current` сохраняют поведение источника. Настраивайте только те параметры, которые необходимо переопределить для нового образа, затем решите, нужно ли захватывать слой изменяемой сессии.

Байты `/etc/live/config.conf` копируются в приватное хранилище сборки с правами 0600. Они не интерпретируются, не отображаются и не логируются. В текущих проектах эта конфигурация обязательна; если в старом проекте она явно отключена, переход к обзору невозможен до исправления.

### Проверка плана

На этапе проверки создаётся новый план на основе текущих входных данных. Проверьте выбранные, исключённые и дополнительные модули, место вывода, оценку требуемого пространства, сводку настроек, профиль захвата, предупреждения и границу привилегий.

В обзоре намеренно не отображаются значения конфигурации, необработанные параметры ядра, приватные пути настройки и выбранные пути захвата. Показываются только количества, базовые имена, отпечатки и дайджесты, если этого достаточно для привязки плана.

Если файл вывода уже существует, замена требует подтверждения. Подтверждение связано с обнаруженным устройством, inode, размером, временем изменения и SHA-256 этого файла. Изменение назначения, отмена или неудачная попытка сбрасывают подтверждение и требуют повторной проверки.

### Сборка и проверка

Перед сборкой все входные данные повторно проверяются, затем запускается `minios-image-compose` с аргументами в приватном рабочем каталоге. ISO-образ остаётся приватным до успешного завершения структурной проверки. Публикация в выбранное место происходит атомарно.

Сохраните проект, если планируется повторно использовать его источник, выбор модулей, параметры вывода и настройки. Файлы проектов имеют формат JSON. Несохранённые изменения требуют подтверждения перед открытием другого проекта или закрытием приложения.

## Захват сессии и приватность

Модули источника, `/etc/live/config.conf` и захват сессии — независимые входные данные. Если достаточно выбора модулей и декларативной настройки, не захватывайте изменяемый слой сессии.

### Не включать изменения сессии

Это рекомендуемый вариант по умолчанию. Конструктор использует выбранные модули, текущую конфигурацию, параметры загрузки и другие настройки образа без копирования слоя изменяемой сессии.

### Включить все изменения сессии

Этот профиль сохраняет каждое поддерживаемое изменяемое изменение от обнаруженного провайдера OverlayFS или AUFS. Он может включать пароли, ключи, токены, данные браузера, идентификатор машины, личные файлы, логи и состояние удалённых файлов. Требуется явное подтверждение, и не рекомендуется использовать этот профиль для образов, предназначенных для других людей, без отдельного аудита.

### Включить только повторно используемые изменения

Этот профиль использует строгий список разрешённых путей для программного обеспечения и безопасные настройки по умолчанию, исключая большинство личных данных, идентификаторов, кэшей и логов. Это снижает риски, но не гарантирует, что разрешённые файлы не содержат секретов. Проверьте готовый образ перед распространением.

### Выбрать изменения сессии вручную

Запустите `Analyze session changes`, затем выберите как минимум один нормализованный путь из инвентаризации в памяти. Выбранная директория включает все вложенные элементы. Точные или родительские исключения имеют приоритет над совпадающими выборами.

Инвентаризация содержит метаданные, включая имена файлов, и поэтому является чувствительной, даже если не содержит содержимого файлов. Она хранится только в памяти и не записывается в проект или логи, не отображается в обзоре. Явные правила включения и исключения отражают намерения проекта и сохраняются; в обзоре показываются только их количество и дайджест.

Запуск нового анализа, обновление или смена источника, отмена или сбой, а также открытие или создание проекта очищают инвентаризацию в памяти. Для анализа и захвата может потребоваться авторизация администратора, но процесс Конструктора образов MiniOS и сборка ISO не получают повышенных привилегий.

## Настройка образа

Поддерживаемые параметры ограничиваются и проверяются бэкендом:

- **Системные параметры по умолчанию:** имя хоста, часовой пояс, целевой systemd по умолчанию, включённые или отключённые сервисы.
- **Безопасность и доступ:** разрешённые sudo, PolicyKit, SSH, XRDP, X11, режимы блокировки экрана и подсказки на экране входа.
- **Данные пользователя:** проверяемые каталоги пользователя относительно корня с поведением либо link, либо bind, но не обоими сразу.
- **Поведение при загрузке:** таймаут от 0 до 300 секунд, меню источника или сгенерированное меню, выбранный пункт по умолчанию.
- **Пункты загрузки:** шаблоны resume, new, choose, fresh и copy-to-RAM можно скрывать, менять порядок, дублировать и настраивать через типизированные параметры сохранения, модуля, запуска, локализации, zRAM и диагностики.
- **Экспертные параметры загрузки:** проверяемые глобальные и индивидуальные параметры ядра для опций, не представленных типизированными контролами.
- **Оформление:** проверяемый PNG-файл для фона загрузки.
- **Слой файловой системы проекта:** одна реальная директория, интерпретируемая относительно корня образа и упаковываемая как root-владеющий модуль SquashFS-оверлея.

Слой файловой системы поддерживает обычные файлы, безопасные относительные симлинки, пустые директории, биты выполнения и временные метки. Узлы устройств, сокеты, FIFO, пересечения файловых систем, абсолютные или выходящие за пределы ссылки и небезопасные имена отклоняются. Привилегированные биты сбрасываются, а владельцы в сгенерированном модуле нормализуются.

Настройка загрузки поддерживает распознаваемые MiniOS GRUB, нативный SYSLINUX и стандартную цепочку SYSLINUX-to-GRUB. Неподдерживаемая или неоднозначная загрузочная конфигурация отклоняется, а не подбирается автоматически. Сборка без настройки загрузки может сохранить исходную структуру, если парсер не понимает её.

## Проверка результата

Перед публикацией `minios-image-compose` проверяет сгенерированный ISO, а не полагается только на успешное завершение `xorriso`. Проверяются:

- Дерево файловой системы ISO и метка тома.
- Загрузочные записи BIOS и UEFI, а также системная область.
- Необходимые загрузочные, ядерные, initramfs, конфигурационные файлы и модули.
- Встроенные настройки и аттестации захвата сессии, если они есть.
- Дайджесты и структура сгенерированных модулей оверлея и захваченной сессии.
- Цели фона загрузки и преобразованная конфигурация загрузки при наличии кастомизации.

Перед сборкой фиксируются идентификатор пути входных данных, режим, время изменения и SHA-256. Изменяемые входные данные при поддержке снапшотятся приватно с помощью reflink; иначе они проверяются на изменения до и после записи ISO. Несовпадение или ошибка проверки блокируют публикацию.

После успешной сборки отдельно запишите контрольную сумму:

```bash
sha256sum custom-minios.iso > custom-minios.iso.sha256
sha256sum -c custom-minios.iso.sha256
```

Структурная проверка не заменяет тест загрузки. Запустите ISO в изолированной виртуальной машине и проверьте оба режима — BIOS и UEFI, если оба должны поддерживаться. Конструктор образов MiniOS может сообщить об установленном QEMU или VirtualBox, но не запускает и не настраивает гипервизор.

## Безопасность и отмена

- Держите исходные носители только для чтения и записывайте результат на файловую систему с достаточным свободным пространством для оценки и временного буфера.
- Не собирайте образ поверх единственного проверенного ISO. Используйте новое имя файла, если только замена не намерена и не подтверждена.
- Проверьте внешние модули перед добавлением. Конструктор образов MiniOS валидирует их структуру SquashFS, но не определяет автора содержимого.
- Для распространяемых образов предпочтительно не захватывать сессию. Если захват необходим, проведите аудит итоговой файловой системы, а не только профиля.
- Считайте файлы проектов чувствительными, если они содержат явные пути к источникам, модулям, файлам вывода или правилам захвата.

Процессы инвентаризации, сборки и проверки выполняются в отдельных группах процессов. При отмене запрашивается завершение и по истечении льготного периода процесс принудительно завершается. Хеширование может завершиться до того, как отмена достигнет безопасной точки, но устаревшие результаты отбрасываются. После начала атомарной публикации процесс завершается, чтобы не оставить файл назначения частично записанным.

Отменённая или неудачная сборка не публикует свой приватный ISO. Предыдущий файл назначения остаётся без изменений, если только проверенная замена не была успешно опубликована атомарно.

## Сборка MiniOS ISO-образов из командной строки

`minios-image-compose` — это консольная утилита, входящая в состав Конструктора образов MiniOS. Она заменила устаревшую утилиту `sb2iso`. Эта команда пересобирает существующее дерево содержимого MiniOS, при необходимости изменяет набор модулей и поддерживаемую конфигурацию, проверяет результат и публикует загрузочный ISO-образ.

Для пошаговой работы над проектом используйте графический [Конструктор образов MiniOS](/preparing-and-customizing/Creating-Custom-MiniOS-Images). Для сценариев, автоматизации или воспроизводимых сборок с командной строки используйте эту команду напрямую. Для полной сборки из исходников используйте [Сборка MiniOS](/development/Building-MiniOS).

### Базовое использование

Из работающей live-сессии MiniOS создайте ISO с найденным исходником MiniOS и `/etc/live/config.conf`:

```bash
minios-image-compose --name ./custom-minios.iso
```

Не добавляйте к полной команде префиксы `sudo` или `pkexec`. Сборка, проверка и публикация выполняются от имени текущего пользователя. Только опциональный захват сессии может запускать доверенный backend `/usr/bin/savechanges` через PolicyKit.

Имя выходного файла по умолчанию — `minios-YYYYMMDD_HHMM.iso`. Существующий файл назначения будет отклонён, если явно не указан `--overwrite`.

### Выбор источника

Без параметра `--source` команда определяет содержимое MiniOS, используемое текущей сессией LiveKit или dracut. Чтобы пересобрать другое примонтированное дерево MiniOS, укажите каталог, содержащий `boot/` и модули MiniOS:

```bash
minios-image-compose \
  --source /media/minios \
  --config ./config.conf \
  --name ./custom-minios.iso
```

Источник используется только для чтения и никогда не изменяется. ISO-файлы и оптические носители должны быть примонтированы перед использованием их дерева содержимого MiniOS с CLI. Графический Конструктор образов MiniOS может монтировать такие источники через `udisksctl`.

### Выбор модулей

Дополнительные модули `.sb` передаются как позиционные аргументы:

```bash
minios-image-compose 06-development.sb 10-site-config.sb \
  --name ./minios-development.iso
```

Команда проверяет каждый модуль как читаемый файл SquashFS, не являющийся симлинком.
Модули, имена которых начинаются с двух цифр и дефиса, размещаются на верхнем уровне MiniOS. Остальные добавленные модули помещаются в `minios/modules/`. Дубликаты или совпадения имён с учётом регистра не допускаются.

Исключайте исходные пути с помощью расширенного регулярного выражения POSIX:

```bash
minios-image-compose --exclude 'firefox|libreoffice|gimp' \
  --name ./minios-lite.iso
```

Обязательные загрузочные файлы, файлы ядра и initramfs, основные модули, выбранное загрузочное меню и выбранная конфигурация не могут быть исключены.

Создайте повторно используемые модули до сборки ISO. Подробнее см. [Создание модулей](/preparing-and-customizing/Managing-Modules) и [Менеджер модулей MiniOS](/preparing-and-customizing/Managing-Modules).

### Конфигурация и манифест

`--config FILE` устанавливает выбранный обычный файл как `minios/config.conf`. По умолчанию используется `/etc/live/config.conf`.

```bash
minios-image-compose --config ./config.conf \
  --manifest ./build.json \
  --volume-label 'MINIOS_LAB' \
  --name ./minios-lab.iso
```

Необязательный манифест должен быть объектом JSON. Метки томов могут содержать от 1 до 32 печатных ASCII-символов; метки, не соответствующие строгому набору ISO 9660 (заглавные буквы, цифры и подчёркивания), вызывают предупреждение.

### Сохранение изменений сессии

Сохранение сессии является необязательным и применяется к доступному для записи слою текущей запущенной сессии MiniOS. Оно допускается только для явного источника, если у этого источника тот же отпечаток базового модуля, что и у работающей системы.

```bash
minios-image-compose --capture-changes clean \
  --name ./minios-with-software.iso
```

Доступные профили:

- `exact` сохраняет все возможные изменения, включая учетные данные, личные данные, логи, состояние браузера и идентификатор машины.
- `clean` использует ограниченный список разрешённых изменений, ориентированный на ПО. Это снижает риск, но не гарантирует отсутствие секретных данных в результате.
- `selected` использует инвентарный список, созданный совместимым интерфейсом или процессом `savechanges`.

```bash
minios-image-compose --capture-changes selected \
  --capture-selection ./session-selection.json \
  --capture-compression zstd \
  --name ./selected-session.iso
```

Для совместного использования ISO предпочтительнее использовать модули и декларативную конфигурацию, а не сохранение сессии. Подробнее о модели приватности и процессе проверки см. в [Конструкторе образов MiniOS](/preparing-and-customizing/Creating-Custom-MiniOS-Images).

### Настройка поведения загрузки

CLI позволяет изменять поддерживаемые схемы GRUB и SYSLINUX:

```bash
minios-image-compose \
  --boot-timeout 5 \
  --default-boot fresh \
  --kernel-args 'audit=1 mitigations=auto' \
  --menu multilang \
  --name ./custom-boot.iso
```

`--default-boot` принимает значения `resume`, `new`, `choose`, `fresh` или `toram`.
`--menu` принимает `multilang` или поддерживаемую локаль, например `en_US`, `ru_RU` или `de_DE`. Аргументы ядра проходят проверку и добавляются без интерпретации shell. Неподдерживаемые или неоднозначные схемы загрузочного меню отклоняются, а не изменяются наугад.

### Добавление оформления или оверлея файловой системы

Замените фон загрузки на проверенный PNG-файл:

```bash
minios-image-compose --boot-background ./art/boot.png \
  --name ./custom-art.iso
```

Упакуйте одну подготовленную структуру каталогов как root-оверлей файловой системы:

```bash
minios-image-compose --overlay-directory "$PWD/image-overlay" \
  --name ./custom-overlay.iso
```

Оверлей применяется относительно корня образа. Он не запускает скрипты, не устанавливает пакеты и не открывает chroot. Небезопасные ссылки, специальные файлы, переходы между файловыми системами и конфликты назначения отклоняются.

### Проверка и публикация

Перед публикацией `minios-image-compose` проверяет дерево файловой системы ISO, метку тома, загрузочные записи BIOS и UEFI, системную область, загрузочные файлы, модули и запрошенные настройки. Сгенерированные оверлеи и модули захваченной сессии извлекаются и сверяются с их метаданными и контрольными суммами.

ISO собирается во временном каталоге на целевой файловой системе и публикуется атомарно только после успешной проверки. Изменение входных данных, сбой проверки, отмена или недостаток места на целевом носителе препятствуют публикации. Предыдущий файл назначения остаётся неизменным, если только явно разрешённая сборка `--overwrite` не будет опубликована атомарно.

Создайте контрольную сумму и выполните отдельную загрузочную проверку после успешной сборки:

```bash
sha256sum custom-minios.iso > custom-minios.iso.sha256
sha256sum --check custom-minios.iso.sha256
```

Структурная проверка не заменяет тестирование загрузки BIOS и UEFI на виртуальной машине или подходящем оборудовании.

### Справочник команд

Для получения информации о точной версии backend используйте установленную справку и вывод помощи:

```bash
minios-image-compose --help
man minios-image-compose
```

Общие параметры:

| Параметр | Назначение |
|---|---|
| `-n`, `--name FILE` | Задать путь вывода. |
| `-e`, `--exclude REGEX` | Исключить совпадающие исходные пути. |
| `--source DIR` | Выбрать явное дерево содержимого MiniOS. |
| `--config FILE` | Выбрать live-конфигурацию, встроенную в ISO. |
| `--manifest FILE` | Включить проверенный JSON-манифест сборки. |
| `--capture-changes MODE` | Захватить изменения сессии `exact`, `clean` или `selected`. |
| `--boot-timeout SECONDS` | Установить таймаут загрузочного меню от 0 до 300 секунд. |
| `--default-boot MODE` | Выбрать действие по умолчанию для сессии MiniOS. |
| `--kernel-args TEXT` | Добавить проверенные глобальные параметры ядра. |
| `--boot-background PNG` | Заменить поддерживаемое оформление загрузки. |
| `--overlay-directory DIR` | Добавить один декларативный слой файловой системы. |
| `--menu TYPE` | Выбрать многоязычное или локализованное меню. |
| `--overwrite` | Явно разрешить замену существующего вывода. |

Команда завершает работу с ненулевым кодом, если возникают ошибки источника, модуля, настройки, хранения, проверки или публикации. Не распространяйте результат, если команда не завершилась успешно и итоговая контрольная сумма и загрузка не были проверены.
