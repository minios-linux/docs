# Создание пользовательских образов MiniOS

Конструктор образов MiniOS — это GTK-приложение для ремастеринга существующего образа MiniOS. Оно позволяет выбрать содержимое из текущей сессии MiniOS, ISO-файла или оптического диска, применить декларативные настройки и`minios-image-compose` создать проверяемый загрузочный ISO-образ.

Конструктор работает внутри MiniOS. Выбранный исходный носитель не изменяется.

## Выберите подходящий рабочий процесс

Конструктор образов MiniOS выполняет ремастеринг существующего бинарного образа MiniOS. Это не замена ни одному из следующих рабочих процессов:

- **Собрать MiniOS из исходных кодов:** используйте `minios-live` систему сборки при изменении списков пакетов дистрибутива, конфигурации сборки, слоя ядра, загрузочных артефактов или цепочки воспроизводимых модулей, собираемых из исходников. Подробнее см. [Сборка MiniOS](/development/Building-MiniOS).
- **Создать повторно используемый модуль:** используйте `apt2sb`, `script2sb`, `chroot2sb`, либо другие инструменты для работы с модулями, если требуется получить отдельный `.sb` слой. Подробнее см. [Создание модулей](/preparing-and-customizing/Managing-Modules#creating-modules).
- **Ремастеринг образа:** используйте Конструктор образов MiniOS для выбора существующих модулей, добавления готовых внешних модулей, изменения поддерживаемых настроек образа, при необходимости сохранения изменений сессии и публикации нового ISO.

Слой файловой системы проекта предназначен для декларативных файлов в корне образа. Он не выполняет скрипты, не устанавливает пакеты и не открывает chroot. Программное обеспечение, предназначенное для повторного использования, должно быть подготовлено в виде модуля до добавления в проект Конструктора образов MiniOS.

## Варианты источника

На странице "Источник" принимаются:

- Текущая сессия LiveKit или dracut MiniOS.
- ISO-файл MiniOS.
- Оптический диск MiniOS.

Источники ISO и оптических дисков монтируются только для чтения с помощью `udisksctl`. В инвентаризации источника фиксируются выпуск, версия, архитектура, поддержка загрузчика, размер, список модулей и отпечаток источника. Если источник изменяется после планирования, сборка блокируется, чтобы не продолжать с другими входными данными.

Захват сессии всегда фиксирует изменения в текущей работающей сессии MiniOS. При выборе ISO или оптического диска захват доступен только если отпечаток базового модуля этого источника совпадает с базой текущей сессии. При выборе внешнего носителя изменения, сделанные в другой системе, не захватываются.

## Требования

Конструктор образов MiniOS требует соответствующий `minios-image-compose` бэкенд. Для источников ISO-файлов и оптических дисков необходим `udisks2`. Для чтения корневого раздела только для чтения `/etc/live/config.conf` и захвата изменяемой сессии может потребоваться `pkexec` и агент PolicyKit для рабочего стола. Для захвата сессии требуется совместимый `savechanges` предоставляемый `minios-tools` версии 1.5.0 или новее.

Приложение и бэкенд компоновки работают без повышенных привилегий. Авторизация ограничивается только чтением live-конфигурации и, при необходимости, доверенными `/usr/bin/savechanges`.

## Рабочий процесс проекта

### Выбор источника

Выберите источник и дождитесь завершения инвентаризации. Проверьте его идентификатор, архитектуру, поддержку загрузки, диагностику и количество модулей. Устраните ошибки источника перед продолжением.

### Выбор содержимого

Выберите исходные модули для включения и добавьте при необходимости внешние `.sb` модули. Обязательные базовые и модуль ядра заблокированы. Модули, активные в текущей сессии, но отсутствующие в выбранном источнике, отображаются отдельно и не добавляются автоматически.

Дополнительные модули должны быть читаемыми обычными файлами с корректными данными SquashFS. Дубликаты, совпадения по регистру или коллизии целей отклоняются, так как во время выполнения слои определяются по базовому имени.

### Настройка параметров

Укажите путь для вывода и необходимую текущую конфигурацию MiniOS. Пустые поля настройки или `Keep current` сохраняют поведение источника. Настраивайте только те параметры, которые нужно изменить в новом образе, затем решите, требуется ли захват слоя изменяемой сессии.

Байты `/etc/live/config.conf` копируются во внутреннее хранилище сборки с правами 0600. Они не интерпретируются, не отображаются и не логируются. Текущие проекты должны содержать эту конфигурацию; старый проект с явным её отключением не может быть отправлен на этап проверки, пока не будет исправлен.

### Проверка плана

На этапе проверки создаётся новый план на основе текущих входных данных. Проверьте выбранные, исключённые и дополнительные модули, место вывода, предполагаемый объём, сводку настроек, профиль захвата, предупреждения и границу привилегий.

На этапе проверки намеренно не отображаются значения конфигурации, необработанные параметры ядра, приватные пути настройки и выбранные пути захвата. Отображаются только количество, базовые имена, отпечатки и дайджесты, если этого достаточно для фиксации плана.

Если файл вывода уже существует, для его замены требуется подтверждение. Подтверждение связано с обнаруженным устройством, inode, размером, временем изменения и SHA-256 этого файла. При изменении назначения, отмене или неудачной попытке подтверждение сбрасывается, и требуется повторная проверка.

### Сборка и проверка

Во время сборки повторно проверяются все используемые входные данные и выполняется `minios-image-compose` с аргументами в приватной рабочей директории. ISO-образ остаётся приватным до успешного завершения структурной проверки. Публикация на выбранное место происходит атомарно.

Сохраните проект, если планируется повторно использовать его источник, выбор модулей, вывод и настройки. Файлы проектов имеют формат JSON. Несохранённые изменения требуют подтверждения перед открытием другого проекта или закрытием приложения.

## Захват сессии и конфиденциальность

Исходные модули, `/etc/live/config.conf`, а также захват сессии — независимые входные параметры. Если достаточно выбора модулей и декларативной настройки, не захватывайте изменяемый слой сессии.

### Не включать изменения сессии

Это рекомендуемый вариант по умолчанию. Конструктор использует выбранные модули, текущую конфигурацию, параметры загрузки и другие настройки образа без копирования слоя изменяемой сессии.

### Включить все изменения сессии

Этот профиль сохраняет все поддерживаемые изменяемые изменения от обнаруженного провайдера OverlayFS или AUFS. Он может включать пароли, ключи, токены, данные браузера, идентификатор машины, личные файлы, журналы и состояние удалённых файлов. Требует явного подтверждения и не рекомендуется для образов, предназначенных для других пользователей, без отдельного аудита.

### Включить только переиспользуемые изменения

Этот профиль использует строгий список разрешённых путей для ПО и безопасные значения по умолчанию, исключая личные данные, идентификаторы, кэш и журналы. Это снижает риск, но не гарантирует отсутствие секретной информации. Проверьте готовый образ перед распространением.

### Выбрать изменения сессии вручную

Запустите `Analyze session changes`, затем выберите хотя бы один нормализованный путь из инвентаризации в памяти. При выборе каталога учитываются все его вложенные элементы. Точные или родительские исключения имеют приоритет над совпадающими включениями.

Инвентаризация содержит метаданные, включая имена файлов, и поэтому является чувствительной, хотя не содержит содержимого файлов. Она хранится только в памяти, не записывается в проект и не попадает в обзор или логи. Явные правила включения и исключения отражают намерения проекта и сохраняются; на этапе проверки отображаются только их количество и дайджест.

При запуске нового анализа, обновлении или смене источника, отмене или ошибке, а также при открытии или создании проекта инвентаризация очищается. Для анализа и захвата может потребоваться авторизация администратора, однако процесс Конструктора образов MiniOS и сборка ISO не выполняются с повышенными правами.

## Настройка образа

Поддерживаемые параметры ограничиваются и проверяются на стороне бэкенда:

- **Системные значения по умолчанию:** имя хоста, часовой пояс, целевой systemd по умолчанию, включённые или отключённые сервисы.
- **Безопасность и доступ:** разрешённые sudo, PolicyKit, SSH, XRDP, X11, режимы блокировки экрана и подсказки.
- **Данные пользователя:** проверяемые каталоги пользователя относительно корня с поддержкой либо ссылок, либо bind-монтажа, но не обоих одновременно.
- **Поведение при загрузке:** таймаут от 0 до 300 секунд, меню источника или сгенерированное меню, выбранная запись по умолчанию.
- **Пункты загрузки:** шаблоны resume, new, choose, fresh и copy-to-RAM можно скрывать, менять порядок, дублировать и настраивать через типизированные параметры для персистентности, модуля, запуска, локализации, zRAM и диагностики.
- **Экспертные параметры загрузки:** проверяемые глобальные и для каждой записи параметры ядра для опций, не представленных отдельными контролами.
- **Внешний вид:** проверяемое PNG-изображение для фона загрузки.
- **Слой файловой системы проекта:** одна реальная директория, интерпретируемая относительно корня образа и упакованная как root-владелец overlay-модуля SquashFS.

Слой файловой системы поддерживает обычные файлы, безопасные относительные символьные ссылки, пустые каталоги, права на выполнение и временные метки. Устройства, сокеты, FIFO, переходы между файловыми системами, абсолютные или выходящие за пределы ссылки и небезопасные имена отклоняются. Привилегии сбрасываются, а владельцы в сгенерированном модуле нормализуются.

Настройка загрузки поддерживает распознаваемые GRUB MiniOS, нативный SYSLINUX и стандартную цепочку SYSLINUX-to-GRUB. Неподдерживаемая или неоднозначная конфигурация загрузки отклоняется, а не подбирается автоматически. Сборка без настройки загрузки может сохранить структуру источника, которую парсер настроек не распознаёт.

## Проверка результата

Перед публикацией `minios-image-compose` проверяет сгенерированный ISO-образ, а не полагается только на успешный `xorriso` выход. Проверяются:

- Дерево файловой системы ISO и метка тома.
- Загрузочные записи BIOS и UEFI и системная область.
- Обязательные загрузочные файлы, ядро, initramfs, конфигурация и содержимое модулей.
- Встроенные настройки и подтверждения захвата сессии, если они присутствуют.
- Дайджесты и структура сгенерированных overlay- и модулей захваченной сессии.
- Целевые изображения фона загрузки и преобразованная конфигурация загрузки при наличии кастомизации.

Перед сборкой фиксируются идентификатор пути входных данных, режим, время изменения и SHA-256. Изменяемые входные данные при поддержке снапшотируются с помощью reflink; иначе они проверяются на изменения до и после записи ISO. Несовпадение или ошибка проверки блокируют публикацию.

После успешной сборки отдельно сохраните контрольную сумму:

```bash
sha256sum custom-minios.iso > custom-minios.iso.sha256
sha256sum -c custom-minios.iso.sha256
```

Структурная проверка не заменяет загрузочный тест. Запустите ISO в изолированной виртуальной машине и проверьте как BIOS, так и UEFI, если оба режима должны поддерживаться. Конструктор образов MiniOS может сообщить об установленном QEMU или VirtualBox, но не запускает и не настраивает гипервизор.

## Безопасность и отмена

- Оставляйте исходные носители только для чтения и записывайте результат на файловую систему с достаточным свободным местом для оценки и временного запаса.
- Не выполняйте сборку поверх единственного проверенного ISO. Используйте новое имя файла вывода, если только замена не является намеренной и подтверждённой.
- Проверьте внешние модули перед добавлением. Конструктор образов MiniOS проверяет их структуру SquashFS, но не устанавливает автора содержимого.
- Для распространяемых образов предпочтительно не захватывать изменения сессии. Если захват необходим, проверьте итоговую файловую систему, а не только имя профиля.
- Обрабатывайте файлы проектов как конфиденциальные, если они содержат явные пути к источникам, модулям, выводу или выбранным правилам захвата.

Инвентаризация, сборка и процессы проверки выполняются в отдельных группах процессов. При отмене запрашивается завершение и через время происходит эскалация. Хеширование может завершиться до безопасной точки отмены, но устаревшие результаты отбрасываются. После начала атомарной публикации процесс завершается полностью, чтобы не оставить целевой файл частично записанным.

Отменённая или неудачная сборка не публикует приватный ISO. Любой предыдущий результат сохраняется, если только проверенная замена не была опубликована атомарно.

## Сборка ISO-образов MiniOS из командной строки

`minios-image-compose` — это командный бэкенд, поставляемый с Конструктором образов MiniOS. Он заменяет устаревшую `sb2iso` утилиту. Команда выполняет ремастеринга существующего дерева содержимого MiniOS, при необходимости изменяет набор модулей и поддерживаемые настройки, проверяет результат и публикует загрузочный ISO.

Используйте графический [Конструктор образов MiniOS](/preparing-and-customizing/Creating-Custom-MiniOS-Images) для пошаговой работы с проектом. Для скриптов, автоматизации или воспроизводимых сборок из командной строки используйте эту команду напрямую. Для полной сборки из исходников используйте [Сборка MiniOS](/development/Building-MiniOS) вместо этого.

### Базовое использование

Из работающей live-сессии MiniOS создайте ISO с обнаруженным источником MiniOS и `/etc/live/config.conf`:

```bash
minios-image-compose --name ./custom-minios.iso
```

Не добавляйте в начало всей команды `sudo` или `pkexec`. Сборка, проверка и публикация выполняются от имени текущего пользователя. Только при необходимости захвата сессии может быть вызван доверенный `/usr/bin/savechanges` бэкенд через PolicyKit.

Имя файла вывода по умолчанию — `minios-YYYYMMDD_HHMM.iso`. Существующий файл назначения не будет перезаписан, если только явно не указан `--overwrite`.

### Выбор источника

Без `--source`, команда определяет дерево содержимого MiniOS, используемое текущей сессией LiveKit или dracut. Для ремастеринга другого смонтированного дерева MiniOS укажите каталог, содержащий `boot/` и модули MiniOS:

```bash
minios-image-compose \
  --source /media/minios \
  --config ./config.conf \
  --name ./custom-minios.iso
```

Источник используется только для чтения и никогда не изменяется. ISO-файлы и оптические носители должны быть смонтированы перед использованием их дерева содержимого MiniOS в CLI. Графический Конструктор образов MiniOS может монтировать эти источники через `udisksctl`.

### Выбор модулей

Дополнительные `.sb` модули передаются как позиционные аргументы:

```bash
minios-image-compose 06-development.sb 10-site-config.sb \
  --name ./minios-development.iso
```

Команда проверяет каждый модуль как читаемый файл SquashFS, который не является символьной ссылкой.
Модули, имена которых начинаются с двух цифр и дефиса, размещаются на верхнем уровне MiniOS. Остальные добавленные модули помещаются в `minios/modules/`. Дубликаты или совпадения имён без учёта регистра отклоняются.

Исключите исходные пути с помощью расширенного регулярного выражения POSIX:

```bash
minios-image-compose --exclude 'firefox|libreoffice|gimp' \
  --name ./minios-lite.iso
```

Обязательные загрузочные файлы, файлы ядра и initramfs, основные модули, выбранное загрузочное меню и выбранная конфигурация не могут быть исключены.

Создайте повторно используемые модули до сборки ISO. Подробнее см. [Создание модулей](/preparing-and-customizing/Managing-Modules#creating-modules) и [Менеджер модулей MiniOS](/preparing-and-customizing/Managing-Modules).

### Конфигурация и манифест

`--config FILE` устанавливает выбранный обычный файл как `minios/config.conf`. По умолчанию — `/etc/live/config.conf`.

```bash
minios-image-compose --config ./config.conf \
  --manifest ./build.json \
  --volume-label 'MINIOS_LAB' \
  --name ./minios-lab.iso
```

Необязательный манифест должен быть объектом JSON. Метки томов содержат от 1 до 32 печатных ASCII-символов; метки вне строгого диапазона ISO 9660 (заглавные буквы, цифры, подчёркивания) вызывают предупреждение.

### Захват изменений сессии

Захват сессии — опциональная функция, применяемая к изменяемому слою текущей сессии MiniOS. Для явного источника он доступен только если отпечаток базового модуля этого источника совпадает с базой текущей системы.

```bash
minios-image-compose --capture-changes clean \
  --name ./minios-with-software.iso
```

Доступные профили:

- `exact` фиксирует все представимые изменения, включая учётные данные, личные данные, логи, состояние браузера и идентификатор машины.
- `clean` использует узкий список разрешённых путей, ориентированный на ПО. Это снижает риск, но не гарантирует отсутствие секретов.
- `selected` использует выборку из инвентаризации, созданную совместимым интерфейсом или `savechanges` рабочим процессом.

```bash
minios-image-compose --capture-changes selected \
  --capture-selection ./session-selection.json \
  --capture-compression zstd \
  --name ./selected-session.iso
```

Для распространения ISO предпочтительнее использовать модули и декларативную настройку, а не захват сессии. Подробнее см. [Конструктор образов MiniOS](/preparing-and-customizing/Creating-Custom-MiniOS-Images) для модели конфиденциальности и проверки.

### Настройка поведения загрузки

CLI позволяет изменять поддерживаемые макеты GRUB и SYSLINUX:

```bash
minios-image-compose \
  --boot-timeout 5 \
  --default-boot fresh \
  --kernel-args 'audit=1 mitigations=auto' \
  --menu multilang \
  --name ./custom-boot.iso
```

`--default-boot` принимает `resume`, `new`, `choose`, `fresh`, или `toram`.
`--menu` принимает `multilang` или поддерживаемую локаль, например `en_US`, `ru_RU`, или `de_DE`. Параметры ядра проверяются и добавляются без интерпретации shell. Неподдерживаемые или неоднозначные макеты загрузочного меню отклоняются, а не изменяются методом подбора.

### Добавление оформления или файлового слоя

Замените фон загрузки на проверенный PNG-файл:

```bash
minios-image-compose --boot-background ./art/boot.png \
  --name ./custom-art.iso
```

Упакуйте одну подготовленную директорию как overlay-модуль с правами root для образа:

```bash
minios-image-compose --overlay-directory "$PWD/image-overlay" \
  --name ./custom-overlay.iso
```

Overlay интерпретируется относительно корня образа. Скрипты не выполняются, пакеты не устанавливаются и chroot не открывается. Небезопасные ссылки, специальные файлы, переходы между файловыми системами и коллизии путей отклоняются.

### Проверка и публикация

Перед публикацией `minios-image-compose` проверяет дерево файловой системы ISO, метку тома, загрузочные записи BIOS и UEFI, системную область, загрузочные файлы, модули и запрошенные настройки. Сгенерированные overlay- и модули захваченной сессии извлекаются и сверяются с их метаданными и дайджестами.

ISO собирается во внутренней директории на целевой файловой системе и публикуется атомарно только после успешной проверки. Изменение входных данных, ошибка проверки, отмена или нехватка места на целевом диске блокируют публикацию. Предыдущий файл назначения остаётся без изменений, если только явно одобренная `--overwrite` сборка не была опубликована атомарно.

После успешной сборки создайте контрольную сумму и выполните отдельный загрузочный тест:

```bash
sha256sum custom-minios.iso > custom-minios.iso.sha256
sha256sum --check custom-minios.iso.sha256
```

Структурная проверка не заменяет тестирование BIOS и UEFI на виртуальной машине или подходящем оборудовании.

### Справочник команд

Используйте установленное руководство и вывод справки для вашей версии бэкенда:

```bash
minios-image-compose --help
man minios-image-compose
```

Общие параметры:

| Параметр | Назначение |
|---|---|
| `-n`, `--name FILE` | Указать путь для вывода. |
| `-e`, `--exclude REGEX` | Исключить подходящие исходные пути. |
| `--source DIR` | Выбрать явное дерево содержимого MiniOS. |
| `--config FILE` | Выбрать live-конфигурацию, встроенную в ISO. |
| `--manifest FILE` | Включить проверенный JSON-манифест сборки. |
| `--capture-changes MODE` | Захватить `exact`, `clean`, или `selected` изменения сессии. |
| `--boot-timeout SECONDS` | Установить таймаут загрузочного меню от 0 до 300 секунд. |
| `--default-boot MODE` | Выбрать действие по умолчанию для сессии MiniOS. |
| `--kernel-args TEXT` | Добавить глобальные параметры ядра после проверки. |
| `--boot-background PNG` | Заменить поддерживаемое оформление загрузки. |
| `--overlay-directory DIR` | Добавить один декларативный слой файловой системы. |
| `--menu TYPE` | Выбрать многоязычное или локализованное меню. |
| `--overwrite` | Явно разрешить замену существующего вывода. |

Команда завершает работу с ненулевым кодом, если возникают ошибки с источником, модулями, настройками, хранилищем, проверкой или публикацией. Не распространяйте результат, если команда не завершилась успешно и итоговая контрольная сумма и загрузка не были проверены.
