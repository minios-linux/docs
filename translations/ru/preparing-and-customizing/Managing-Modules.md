# Управление модулями

Менеджер модулей MiniOS — это графическое приложение для просмотра, создания и управления модулями MiniOS`.sb` модулей. В нём есть две рабочие области: **Модули** для составления системы и **Создать** для создания новых модулей.

Запустить его можно из меню приложений или командой:

```bash
minios-module-manager
```

Само приложение работает от имени вашего пользователя в системе. Запрос на аутентификацию администратора появляется только при операциях, которые этого требуют.

## Текущий запуск и следующий запуск

Рабочая область «Модули» содержит два отдельных представления:

- **Текущий запуск** — это упорядоченный набор модулей, из которых сейчас состоит живая система.
- **Следующая загрузка** — это упорядоченный набор, выбранный текущими правилами загрузки MiniOS.

Изменение одного представления не меняет другое автоматически. Например, **Активировать для этой сессии** влияет только на текущую систему, а **Добавить в следующий запуск** копирует модуль в постоянное хранилище модулей без его активации сейчас.

Подробные правила загрузки, включая уровни-источники, замену по имени, числовой порядок и `load=` , `noload=` и `bext=` фильтрацию, смотрите в [Загрузка модулей initrd](/reference/boot-process/Module-Loading). В этом руководстве также объясняется, почему списки «Текущий запуск» и «Следующая загрузка» могут отличаться.

Активация и деактивация модулей во время работы доступны только если корневая файловая система использует AUFS. Они недоступны на OverlayFS, даже если ядро поддерживает AUFS. Базовые модули нельзя деактивировать через приложение.

Изменения для следующей загрузки доступны только если MiniOS находит подходящее постоянное и доступное для записи хранилище модулей. Базовые модули и модули на только для чтения или временных носителях удалить нельзя. Фильтры загрузки, такие как `load` , `noload` и `bext` по-прежнему определяют, какие модули будут выбраны.

## Просмотр модуля

Выберите модуль, чтобы увидеть путь к исходному файлу, сжатый размер и содержимое файловой системы. Если исходный файл доступен, **Извлечь в папку** создаст новую директорию с файлами модуля.

Для просмотра не требуются права администратора. **Извлечь в папку** запрашивает аутентификацию администратора, чтобы сохранить владельцев, права доступа и специальные файлы. Извлечение никогда не заменяет существующую папку и не изменяет исходный модуль.

Также можно открыть локальный `.sb` файл через файловый менеджер. Открытие файла только просматривает его, не активирует и не добавляет в следующий запуск. В системах Xfce с установленной интеграцией Thunar MiniOS действия файлового менеджера используют тот же модульный бэкенд для явной активации и деактивации; они не обходят различие между «Текущий запуск» и «Следующая загрузка».

## Создание модуля

Рабочая область «Создать» использует последовательность **Настроить**, **Проверить**, **Выполнить**, и **Результат**. Успешно созданный модуль остаётся файлом по указанному пути. Он не активируется и не добавляется в следующий запуск автоматически.

Доступные методы:

- **Пакеты** устанавливает пакеты из репозиториев и выбранные локальные `.deb` файлы с зависимостями в изолированной среде сборки MiniOS. Для установки пакетов требуются права администратора.
- **Скрипт установки** запускает проверенный скрипт без интерактивного терминала. Необязательная папка-источник может содержать начальные файлы. Скрипт выполняется с правами администратора, но не сохраняется в итоговом модуле.
- **Интерактивный chroot** открывает временную root-оболочку во встроенном терминале. После завершения введите `exit` , затем создайте модуль, снова откройте оболочку или отмените изменения. Закрытие или отмена сессии не влияет на работающую систему.
- **Папка** упаковывает содержимое существующей директории. Сама исходная папка не включается внутрь модуля. Графический процесс запрашивает права администратора для чтения защищённых файлов и сохранения атрибутов файловой системы; исходная папка не изменяется. Папки, извлечённые с сохранением владельцев, распознаются автоматически и сохраняют свои права. Для старой извлечённой папки без информации об источнике выберите **Сохранять владельцев источника** , если нужно сохранить владельцев.
- **Изменения текущей сессии** захватывают подходящие файлы и удаления из текущего слоя сессии с возможностью записи. Используется стандартная политика MiniOS `savechanges` , которая исключает журналы, кэш, загрузочные данные и временные пути. Для чтения полного слоя с возможностью записи требуются права администратора.

Для каждого процесса выберите новый путь вывода. Существующие файлы никогда не перезаписываются. Прогресс и диагностика бэкенда отображаются во время выполнения операции, а захват изменений сессии можно отменить.

Для других папок стандартный процесс «Папка» меняет обычные UID и GID (1000–60000) на root вне `/home` и `/opt`, сохраняет системные ID и делает стандартные папки верхнего уровня принадлежащими root. Владельцы, потерянные при предыдущем извлечении без прав, этим способом не восстанавливаются.

«Изменения текущей сессии» предназначены для удобного стандартного захвата, а не для просмотра каждого включённого пути. В живом слое с возможностью записи могут быть личные или конфиденциальные данные. Для явных `exact` , `clean` или политик приватности по выбранным путям используйте командную строку `savechanges` , описанную в [Захват изменений текущей сессии](/preparing-and-customizing/Managing-Modules#capture-current-session-changes).

## Перетаскивание

Перетаскивание только заполняет поле ввода или открывает просмотр:

- Модуль открывает свои детали.
- `.deb` файлы добавляются в «Пакеты».
- Папка выбирается для «Папка».
- Другой обычный файл выбирается как скрипт установки.

Перетаскивание не выполняет код и не изменяет «Текущий запуск» или «Следующая загрузка».

## Создание модулей

Модули MiniOS — это только для чтения образы файловой системы SquashFS, обычно с расширением `.sb` . При загрузке MiniOS выстраивает выбранные модули в слоистую корневую файловую систему. Файлы в слое с более высоким приоритетом могут дополнять или скрывать файлы из нижних слоёв. Эта модульная живая схема — часть определяющей архитектуры MiniOS, описанной в [О MiniOS](/getting-started/About-MiniOS) и [Режимы загрузки](/using-minios/Boot-Modes) . После нативного преобразования слоистый `.sb` корень заменяется обычной файловой системой Debian с возможностью записи. Программное обеспечение для управления модулями MiniOS удаляется, так как модульные процессы больше не применяются, а выбранная среда рабочего стола и обычные приложения остаются установленными как стандартные пакеты.

В этом руководстве описаны актуальные командные процессы MiniOS Tools. Для графического приложения см. [Менеджер модулей MiniOS](/preparing-and-customizing/Managing-Modules) . Для полного процесса сборки образа и архитектуры системы см. [Сборка MiniOS](/development/Building-MiniOS) . Списки пакетов, используемые при сборке MiniOS, описаны в [документации CondinAPT](/development/CondinAPT).

### Безопасность и границы привилегий

Не для каждой операции с модулями нужны права root:

| Операция | Привилегии |
|---|---|
| Просмотр «Текущий запуск» или «Следующая загрузка» через `sb` | Без root |
| Просмотр модуля через `sb inspect` | Без root |
| Обычное использование командной строки `dir2sb` и `sb2dir` преобразование | Без root |
| Сохранение владельцев или разрешение специальных файлов при преобразовании | Root |
| Сборка через `apt2sb` , `script2sb` или `chroot2sb` | Root |
| Захват сессии через `savechanges` | Root |
| Активация, деактивация, добавление в следующий запуск или удаление из следующего запуска | Root |

Сборщики используют изолированный union и не устанавливают пакеты или изменения скриптов в работающий root. Создание также не активирует результат и не выбирает его для следующей загрузки.

Графические процессы «Папка» и «Извлечь в папку» запрашивают права администратора для работы с защищёнными файлами и сохранения атрибутов файловой системы.

Текущие конвертеры и сборщики используют публикацию без перезаписи. Уже существующая цель, включая символическую ссылку, не перезаписывается. Выберите новый путь вывода или вручную удалите старый результат.

Используйте `--help` вывод каждой команды как ссылку на установленную версию. Текущие `apt2sb` , `script2sb` , `chroot2sb` , `dir2sb` и `savechanges` процессы поддерживают `zstd` (по умолчанию)`gzip` , `lzo` , `lz4` и `xz` . Выбранный компрессор должен быть доступен в системе.

### Имена модулей и уровни фильтрации

Имена часто начинаются с числа, например `06-browser.sb` , так как порядок слоёв влияет на разрешение конфликтов. Модуль должен содержать пути относительно корня системы, например `usr/bin/example` , а не отдельную папку с этим деревом.

Для точных уровней-источников, поведения при совпадении имён, числового порядка и `bext=` , `load=` и `noload=` семантики см. [Загрузка модулей initrd](/reference/boot-process/Module-Loading) . В частности, используйте уникальное имя файла, если модуль не должен заменять слот с тем же именем из предыдущего уровня-источника.

Опция `--level LEVEL` на `apt2sb` , `script2sb` и `chroot2sb` ограничивает базовые слои, используемые для построения union. С `--level 3` используются слои с номерами до `03` , а более высокие слои отбрасываются. Это позволяет сделать модуль менее зависимым от дополнительных слоёв, но увеличивает число зависимостей в результате.

### Создание модуля из пакетов

`apt2sb` устанавливает пакеты из репозиториев или доступные локальные `.deb` файлы во временный union и сохраняет результат. Требуется поддерживаемая живая сессия MiniOS и права root.

```bash
sudo apt2sb install chromium chromium-sandbox
sudo apt2sb install -y --level 3 -n 06-browser.sb chromium chromium-sandbox
sudo apt2sb install -y --no-install-recommends ./example_amd64.deb -n 06-example.sb
```

Без `--name` имя результата формируется по первому пакету. Полезные параметры APT: `--install-recommends` , `--no-install-recommends` , `--install-suggests` , `--no-install-suggests` , `--allow-downgrades` и `--target-release RELEASE` . Опция target-release применяется только к `install` .

Для захвата обновлений уже установленных пакетов:

```bash
sudo apt2sb upgrade -y -n upgrades.sb
```

### Создание модуля из скрипта

`script2sb` копирует скрипт установки во временный chroot, делает его исполняемым, запускает от root без интерактивного терминала, удаляет его и сохраняет изменения файловой системы. Если скрипт завершился с ошибкой, модуль не создаётся.

```bash
sudo script2sb --script ./install-example.sh -n 06-example.sb
sudo script2sb --script ./install-example.sh --directory ./seed-root --level 3 -n 06-example.sb
```

Необязательная `--directory DIR` копирует всё содержимое источника, включая скрытые файлы, в корень модуля до запуска скрипта. Структурируйте папку-источник как дерево файловой системы:

```text
seed-root/
`-- usr/
    `-- share/
        `-- applications/
            `-- example.desktop
```

Проверьте скрипт перед запуском. Он выполняется с правами администратора и может запускать любые команды. Используйте `chroot2sb` , если установка требует вопросов или ручных действий.

### Создание модуля в интерактивном режиме

`chroot2sb` создаёт временный union и открывает в нём root-оболочку. Установите пакеты или измените файлы, затем выйдите из оболочки для сохранения изменений:

```bash
sudo chroot2sb --level 3 -n 06-custom.sb
sudo chroot2sb --directory ./seed-root -c xz -n 06-custom.sb
```

Введённые в оболочке команды не воспроизводятся при загрузке модуля; модуль — это снимок итогового состояния файловой системы. История команд оболочки не сохраняется. Если имя не указано, оно формируется по текущей дате и времени.

Раздельный `prepare` , `shell` , `finish` и `cancel` жизненный цикл используется для защищённых графических интерфейсов. Для обычного терминала используйте одну интерактивную команду, показанную выше.

### Создание модуля из директории

`dir2sb` упаковывает содержимое подготовленной директории в новый модуль. Требуются оба аргумента:

```bash
dir2sb my-app-root 06-my-app.sb
dir2sb --comp xz my-app-root 06-my-app-xz.sb
```

Обычное преобразование не требует root, не изменяет источник, меняет обычные UID и GID (1000–60000) на root вне `/home` и `/opt` , сохраняет системные ID и делает стандартные папки верхнего уровня принадлежащими root. Устройства, сокеты и FIFO отклоняются, цель никогда не перезаписывается. `--keep-ownership` сохраняет всех владельцев источника, а `--allow-special` разрешает специальные файлы; обе опции требуют root.

`sb2dir` записывает `.minios-module-origin.json` в извлечённой папке. Если при извлечении были сохранены владельцы, `dir2sb` распознаёт эту запись и автоматически сохраняет владельцев и специальные файлы при повторной упаковке; сама запись не включается в новый модуль. Папка, извлечённая без сохранения владельцев, не может быть перепакована, так как исходные владельцы неизвестны. Извлеките исходный модуль снова с привилегированными опциями.

### Захват изменений текущей сессии

`savechanges` читает основной слой с возможностью записи в работающей сессии MiniOS. Требуются права root, так как этот слой может содержать файлы, доступные только root. Путь к изменениям определяется автоматически:

```bash
sudo savechanges session-changes.sb
sudo savechanges --comp xz session-changes-xz.sb
```

Без `--profile` применяется историческая политика MiniOS, исключающая пустые папки, кэш, журналы, загрузочные данные, временные пути, псевдофайловые системы и отдельные файлы сессии и системы. Это удобно для традиционного создания модулей, но не гарантирует приватности.

Явные профили:

- `exact` сохраняет все представимые изменения, включая пользовательские данные, журналы, кэш, идентификационные файлы, учётные данные и поддерживаемые метаданные об удалениях. Не поддерживаемые объекты файловой системы отклоняются, а не теряются без уведомления.
- `clean` использует ограниченный список путей, ориентированный на ПО. Исключаются данные home и root, журналы, кэш, идентификаторы, сетевые настройки, учётные данные, произвольная системная конфигурация и `/usr/local` . Это снижает риск раскрытия приватных данных, но не гарантирует, что разрешённый файл не содержит секретов.
- `selected` включает только проверенные относительные пути из файла инвентаризации и выбора. Явные исключения имеют приоритет. Этот профиль подходит, если модуль должен содержать строго определённый набор изменений сессии.

Примеры:

```bash
sudo savechanges --profile exact exact-session.sb
sudo savechanges --profile clean --comp xz software-session.sb
sudo savechanges --inventory-json session-inventory.json
sudo savechanges --profile selected --selection selection.json selected-session.sb
```

Файл выбора должен иметь строгую структуру JSON:

```json
{
  "product_kind": "minios-session-selection",
  "schema_version": 1,
  "include_paths": ["etc/default", "opt/my-app"],
  "exclude_paths": ["opt/my-app/private"]
}
```

Пути нормализованы, не пустые и заданы относительно корня изменений. Сначала сгенерируйте и проверьте инвентаризацию; каждый включённый путь должен соответствовать данным инвентаризации. Инвентаризация хранит метаданные, такие как путь, тип, категория, чувствительность и размер, но не читает и не сохраняет содержимое файлов, цели символических ссылок или секретные значения. Выводы и инвентаризации для явных профилей — в режиме `0600` ; модули по старой политике — в режиме `0644` .

Захват сессии может сохранять поддерживаемые удаления файлов и непрозрачность директорий для активного бэкенда AUFS или OverlayFS. Исключаются временные монтирования, вложенные файловые системы, служебные данные union и сам вывод. Существующая цель никогда не перезаписывается.

### Просмотр и извлечение модулей

Просмотрите модуль без монтирования или извлечения:

```bash
sb inspect 06-example.sb
sb inspect 06-example.sb --json
```

Просмотр не требует root и работает вне работающей сессии MiniOS.

Извлеките модуль в новую папку:

```bash
sb2dir 06-example.sb example-root
```

Обычное извлечение не требует root и не изменяет исходный модуль. Целевая папка не должна существовать. Специальные файлы отклоняются, если только `--allow-special` не выбран с достаточными правами.

Чтобы папку можно было корректно перепаковать, извлеките с правами администратора и сохранением владельцев и специальных файлов:

```bash
sudo sb2dir --keep-ownership --allow-special 06-example.sb example-root
```

Извлечение записывает источник модуля в `.minios-module-origin.json` в новой папке. При извлечении без сохранения владельцев отмечается, что владельцы не сохранены; такую папку нельзя передать обратно в `dir2sb` . Сохраняйте запись об источнике при привилегированном извлечении до перепаковки.

Папки, созданные текущими `sb2dir` — это обычные директории. `rmsbdir` , `sb rm` и `sb rmdir` — устаревшие команды совместимости, которые всегда отказываются от удаления; они не размонтируют и не удаляют ничего рекурсивно. Перед удалением извлечённой папки проверьте её содержимое стандартными средствами.

### Управление модулями в текущей и следующей загрузке

«Текущий запуск» и «Следующая загрузка» — независимые композиции. Подробнее см. [построение union и активация во время работы](/reference/boot-process/Module-Loading#union-construction) о границе загрузки/работы и различиях между списками.

Показать модули, реально составляющие текущий корень AUFS или OverlayFS, от самого низкого к самому высокому приоритету:

```bash
sb list
sb list --json
```

Показать модули, выбранные текущими правилами загрузки:

```bash
sb next-boot
sb next-boot --json
```

Эти запросы не требуют root. Канонические [правила уровней-источников и замены](/reference/boot-process/Module-Loading#candidate-tiers) определяют, из какого источника берётся каждый файл для «Следующей загрузки».

Чтобы сделать пользовательский модуль доступным при следующей загрузке:

```bash
sudo sb next-boot add 50-extra.sb
```

MiniOS использует подходящее постоянное хранилище с возможностью записи, подготавливает и проверяет копию, публикует её атомарно без замены существующего модуля. Имя файла должно соответствовать текущим фильтрам загрузки. Для удаления выбранного пользовательского модуля используйте его точное имя:

```bash
sudo sb next-boot remove 50-extra.sb
```

Удаление невозможно для базовых модулей и модулей на только для чтения или временных носителях.

Активация во время работы — отдельная операция только для текущей сессии:

```bash
sudo sb activate 50-extra.sb
sudo sb deactivate 50-extra.sb
```

Активация и деактивация работают только если `/` сейчас — union AUFS. Они недоступны на OverlayFS, и поддержки ядра AUFS недостаточно. Ни одна из команд не меняет «Следующую загрузку».

Диспетчер конвертеров совместимости требует оба аргумента:

```bash
sudo sb conv my-app-root 06-my-app.sb
sudo sb conv 06-my-app.sb example-root
```

Прямое использование `dir2sb` и `sb2dir` предпочтительнее, так как обычное преобразование можно выполнять без root.
