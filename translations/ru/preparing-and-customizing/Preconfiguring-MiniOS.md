# Предварительная настройка MiniOS

Конфигуратор MiniOS — это графический редактор для настройки MiniOS live-конфигурации. Он проверяет изменения и сохраняет конфигурацию для следующей загрузки. Ранний выбор хранилища для кэша/логов применяется через `minios-boot`; остальные компоненты live-config запускаются позже. Сохранение не изменяет текущую систему напрямую.

## Запуск конфигуратора

Откройте Конфигуратор MiniOS через меню приложений или выполните команду:

```bash
minios-configurator
```

Целевой файл по умолчанию — `/etc/live/config.conf`. Чтобы отредактировать другой обычный файл, укажите его путь:

```bash
minios-configurator /path/to/config.conf
```

Для сохранения требуется аутентификация через PolicyKit. Символические ссылки и не обычные целевые файлы не поддерживаются.

## Конфигурация носителя и среды выполнения

MiniOS может читать конфигурацию из двух мест:

- `minios/config.conf` и `minios/config.conf.d/*.conf` на live-носителе
- `/etc/live/config.conf` и `/etc/live/config.conf.d/*.conf` в корневой файловой системе среды выполнения

Конфигуратор MiniOS редактирует только выбранный файл. Если путь не указан, редактируется файл среды выполнения `/etc/live/config.conf`; файл на носителе напрямую не открывается. MiniOS синхронизирует более новую конфигурацию между файловой системой среды выполнения и доступными для записи MiniOS носителями при загрузке. Носители только для чтения не принимают изменения среды выполнения, а постоянная конфигурация среды выполнения может оставаться независимой от копии на носителе.

При загрузке MiniOS синхронизирует файлы на носителе и в среде выполнения по времени изменения. Для новых политик хранения, более поздние `config.conf.d` фрагменты перекрывают основной файл, `LIVE_CONFIG_CMDLINE` затем применяется основной файл, а фактическая командная строка ядра имеет наивысший приоритет.
Используйте `-i` чтобы наложить распознанные параметры из текущей командной строки ядра в редакторе:

```bash
minios-configurator --inherit-cmdline /etc/live/config.conf
```

Выбранный файл остаётся целью для сохранения. Неизвестные параметры ядра игнорируются.

## Когда применяются настройки

Каждый элемент управления указывает, когда он используется. Сохранение никогда не применяет настройку к текущей сессии.

### Применяется после перезагрузки

Имя хоста, язык системы, часовой пояс, раскладка клавиатуры, цель загрузки, выбор сервисов, режим модулей, работа с пользовательскими директориями на носителях, параметры отладки, экспорт логов и три расширенные настройки хранения читаются при следующей загрузке. Для применения изменений перезагрузите систему после сохранения.

В разделе **Расширенные**, **Хранение системных логов**, **Кэш загрузки APT**, и **Кэш браузера** доступны варианты `persistent` (по умолчанию) или `volatile`. Их `volatile` настройки применяются только для стабильной, надёжной `perch` сессии. Логи из `minios-boot` и `live-config` остаются постоянными, даже если обычные логи временные. Состояние пакетов APT и профили браузера сохраняются; только выбранные логи и кэши перемещаются в ограниченное хранилище RAM. Настройка браузера выполняется после создания live-пользователя. Конфигуратор предупреждает, если в текущем initrd отсутствует `perch-storage-v1` необходимый маркер для этих настроек. Подробнее см. [Производительность](/maintenance-and-recovery/Performance#reduce-cache-and-log-writes-with-perch) перед выбором размера RAM для маломощных машин.

### Используются только для новой сессии

Создание учетной записи, пароли пользователя и root, `noroot`, политика sudo и PolicyKit, политика SSH и XRDP, доступ к X11, подсказки к паролям и блокировка экрана — это одноразовые настройки. В постоянной сессии обычно сохраняются завершённые `live-config` компоненты в каталоге `/var/lib/live/config/`, поэтому изменение этих значений и перезагрузка той же сессии не приведёт к повторному созданию аккаунта или изменению состояния безопасности. Чтобы применить их как начальные параметры, начните новую сессию.

Профили безопасности — это предустановки редактора. Сохраняется не имя профиля, а отдельные параметры безопасности, которые остаются доступными для редактирования.

## Пользовательские директории и постоянство

Связывание и монтирование пользовательских директорий как bind — взаимоисключающие методы. Оба используют существующий доступный для записи локальный носитель данных MiniOS и безопасный путь относительно носителя. Эти функции недоступны при `toram`, `toram=full`, или `toram=trim`, и MiniOS не объединяет автоматически две заполненные директории.

`perchmode` и `perchsize` — это параметры загрузки initramfs, а не настройки Конфигуратора MiniOS. Новые параметры управления кэшем/логами не выбирают и не создают `perch` сессию. Конфигуратор MiniOS не создаёт, не разблокирует, не изменяет размер и не восстанавливает контейнер постоянства. Для зашифрованного постоянства он сообщает, присутствует ли маркер шифрования в initramfs.

## Поведение при сохранении

В обзоре отображаются только изменённые значения, а пароли скрыты. При сохранении обновляются только изменённые ключи, при этом сохраняются комментарии, порядок, неизвестные ключи, права владельца, разрешения и расширенные атрибуты. Запись происходит атомарно.

Полную справку по переменным и параметрам загрузки смотрите в разделе [Конфигурационный файл](/reference/configuration/config.conf), [Параметры загрузки](/reference/Boot-Parameters), и [live-config](/reference/configuration/live-config).
