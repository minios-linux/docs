# Предварительная настройка MiniOS

Конфигуратор MiniOS — это графический редактор для живой конфигурации MiniOS. Он проверяет изменения и сохраняет конфигурацию для следующей загрузки. Ранние параметры хранения кэша/журналов применяются `minios-boot`; остальные компоненты live-config запускаются позже. Сохранение не изменяет текущую систему напрямую.

## Запуск конфигуратора

Откройте Конфигуратор MiniOS через меню приложений или выполните команду:

```bash
minios-configurator
```

Целевой файл по умолчанию — `/etc/live/config.conf`. Чтобы изменить другой обычный файл, укажите его путь:

```bash
minios-configurator /path/to/config.conf
```

Для сохранения требуется аутентификация PolicyKit. Символические ссылки и не обычные целевые файлы не поддерживаются.

## Медиа и конфигурация среды выполнения

MiniOS может читать конфигурацию из двух мест:

- `minios/config.conf` и `minios/config.conf.d/*.conf` на live-носителе
- `/etc/live/config.conf` и `/etc/live/config.conf.d/*.conf` в корневой файловой системе среды выполнения

Конфигуратор MiniOS редактирует только выбранный файл. Если путь не указан, редактируется файл среды выполнения `/etc/live/config.conf`; файл на носителе напрямую не открывается. MiniOS синхронизирует более новую конфигурацию между файловой системой среды выполнения и доступными для записи MiniOS носителями при загрузке. На носителях только для чтения изменения среды выполнения не сохраняются, а постоянная конфигурация среды выполнения может оставаться независимой от копии на носителе.

При загрузке MiniOS синхронизирует файлы на носителе и в среде выполнения по времени изменения. Для новых политик хранения сначала применяются `config.conf.d` фрагменты, которые перекрывают основной файл, `LIVE_CONFIG_CMDLINE` затем основной файл, а последней применяется фактическая командная строка ядра.
Используйте `-i` для наложения распознанных параметров из текущей командной строки ядра в редакторе:

```bash
minios-configurator --inherit-cmdline /etc/live/config.conf
```

Выбранный файл остается целью для сохранения. Неизвестные параметры ядра игнорируются.

## Когда применяются параметры

Каждый элемент управления указывает, когда он используется. Сохранение никогда не применяет параметр к текущей сессии.

### Применяется после перезагрузки

Имя хоста, язык, часовой пояс, раскладка клавиатуры, целевой режим загрузки, выбор сервисов, режим модуля, работа с пользовательскими директориями, параметры отладки, экспорт логов и три расширенные настройки хранения данных читаются при следующей загрузке. Перезагрузите систему после сохранения, чтобы изменения вступили в силу.

В **Расширенных**, **Режиме модуля** принимаются значения `simple` или `merged`. Если `LIVE_MODULE_MODE` отсутствует в выбранной конфигурации, текущий Конфигуратор MiniOS предлагает `merged` как эффективное значение по умолчанию. В объединённом режиме live-config обновляет пользователей, кэши и состояние пакетов, чтобы конфигурация из стека модулей была интегрирована в работающую live-систему.

В **Расширенных**, **Хранении системных логов**, **Кэше загрузки APT**, и **Кэше браузера** можно выбрать `persistent` (по умолчанию) или `volatile`. Их `volatile` настройки применяются только для стабильной, надёжной `perch` сессии. Логи из `minios-boot` и `live-config` сохраняются постоянно, даже если обычные логи временные. Состояние пакетов APT и профили браузера также сохраняются; только выбранные логи и кэши перемещаются в ограниченное хранилище RAM. Настройка браузера выполняется после создания live-пользователя. Конфигуратор предупреждает, если в используемом initrd отсутствует `perch-storage-v1` необходимый маркер для этих настроек. Подробнее см. [Производительность](/maintenance-and-recovery/Performance#reduce-cache-and-log-writes-with-perch) перед выбором размера RAM для маломощных устройств.

### Используются только для новой сессии

Создание учётной записи, пароли пользователя и root, `noroot`, политика sudo и PolicyKit, политика SSH и XRDP, доступ к X11, подсказки к паролям и блокировка экрана — это однократные параметры. В постоянной сессии обычно сохраняются завершённые `live-config` компоненты в каталоге `/var/lib/live/config/`, поэтому изменение этих значений и перезагрузка той же сессии не пересоздаёт учётную запись или параметры безопасности. Для их применения как начальных настроек начните новую сессию.

Профили безопасности — это предустановки редактора. Имя профиля не сохраняется; сохраняются отдельные параметры безопасности, которые остаются доступными для редактирования.

## Пользовательские директории и постоянство

Связывание и bind-монтирование пользовательских директорий взаимоисключающие. Оба варианта используют существующий доступный для записи локальный носитель данных MiniOS и безопасный путь относительно носителя. Они недоступны при `toram`, `toram=full`, или `toram=trim`, и MiniOS не объединяет автоматически два заполненных дерева директорий.

`perchmode` и `perchsize` — это параметры загрузки initramfs, а не настройки Конфигуратора MiniOS. Новые параметры хранения кэша/журналов не выбирают и не создают `perch` сессию. Конфигуратор MiniOS не создаёт, не разблокирует, не изменяет размер и не восстанавливает контейнер постоянства. Для зашифрованного постоянства он сообщает, присутствует ли маркер шифрования initramfs.

## Поведение при сохранении

На этапе проверки отображаются только изменённые значения, а пароли скрываются. При сохранении обновляются только изменённые ключи, при этом сохраняются комментарии, порядок, неизвестные ключи, права владельца, разрешения и расширенные атрибуты. Запись происходит атомарно.

Полную справку по переменным и параметрам загрузки смотрите в разделах [Файл конфигурации](/reference/configuration/config.conf), [Параметры загрузки](/reference/Boot-Parameters), и [live-config](/reference/configuration/live-config).
