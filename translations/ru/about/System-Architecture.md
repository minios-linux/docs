# Архитектура системы MiniOS

MiniOS загружает операционную систему только для чтения, собранную из модулей SquashFS, и добавляет один доступный для записи слой для текущей сессии. За поиск носителя, выбор модулей и хранилища, построение корневой файловой системы, применение ранней конфигурации и передачу управления установленной init-системе отвечает initramfs.

## Обнаружение загрузки

BIOS или UEFI-загрузчик загружает ядро Linux и initramfs MiniOS из `minios/boot/`. Затем initramfs ищет на блочных устройствах каталог `minios`, содержащий модули `.sb`. Вместо этого параметр загрузки `from=` может указывать каталог, блочное устройство и путь, локальный ISO-файл или интерактивный выбор `askdisk`. Локальный ISO монтируется в режиме loop перед использованием его каталога `minios`.

На этом же этапе обнаружения поддерживаются источники HTTP ISO и PXE. Дополнительная ранняя сетевая загрузка используется только для **загрузки MiniOS по сети** (PXE / HTTP ISO). Это не постоянная настройка сети для сессии. См. [Загрузка по сети](/installation/Network-Boot.md).

После обнаружения `toram=trim` может скопировать выбранные модули и необходимые данные в RAM, а `toram=full` копирует дерево данных носителя. Подробнее о выборе источника, фильтрации и опциях копирования в RAM см. в разделе [Параметры загрузки](/configuration/Boot-Parameters.md).

## Состав модулей

Каждый файл `.sb` — это файловая система SquashFS только для чтения. Встроенные модули хранятся непосредственно в `minios/`; дополнительные модули могут храниться в `minios/modules/`, включая долговременное хранение модулей на устройстве с поддержкой записи. Initramfs обнаруживает оба расположения, применяет фильтры `load=` и `noload=`, сортирует выбранные файлы по числовому префиксу имени и монтирует их только для чтения.

Типичный образ Xfce содержит следующие роли в указанном порядке, хотя точные имена и номера зависят от сборки и модулей, пропущенных для данной цели:

```text
00-core-<arch>.sb
01-kernel-<version>-<arch>.sb
02-firmware-<arch>.sb
03-gui-base-<arch>.sb
04-xfce-desktop-<arch>.sb
05-apps-<arch>.sb or the next applicable module
```

Поздние модули имеют больший приоритет и могут заменять пути, предоставленные более ранними модулями. Модуль может зависеть от файлов из любого модуля с меньшим номером, поэтому набор файлов модулей — это упорядоченная композиция, а не просто коллекция независимых пакетов.

## AUFS и OverlayFS

MiniOS использует объединённую файловую систему (union filesystem), чтобы представить модули и слой для записи как единую корневую файловую систему. Если запущенное ядро поддерживает AUFS, выбирается именно она, в противном случае используется OverlayFS. `union=aufs` запрашивает AUFS, но всё равно переключается на OverlayFS, если AUFS недоступна; `union=overlayfs` выбирает OverlayFS.

Между этими двумя реализациями есть важное различие в работе:

- AUFS начинает с ветки для записи и добавляет смонтированные модули как ветки только для чтения. MiniOS может активировать или деактивировать модуль в работающем корне, если монтирование AUFS поддерживает такую операцию.
- OverlayFS получает полный упорядоченный список `lowerdir` при монтировании корня, а также `upperdir` и `workdir`. Набор нижних модулей не может быть изменён на лету через Менеджер модулей.

Поэтому Менеджер модулей разделяет **Текущие** — смонтированный набор модулей, и **Следующая загрузка** — модули, выбранные текущим носителем и правилами загрузки. Добавление или удаление долговременного модуля обычно влияет только на следующую загрузку. Создание или открытие модуля не активирует его. Активация и деактивация модулей во время работы доступны только с AUFS.

## Слой для записи и сессии

Без постоянства слой для записи размещается в памяти и исчезает при завершении работы. При использовании постоянства этот слой помещается в пронумерованную сессию в каталоге `minios/changes/`. `session.conf` хранит информацию о сессии по умолчанию для следующей загрузки, сессии, используемой текущей загрузкой, метаданные совместимости, состояние и параметры, зависящие от режима.

| Режим | Хранилище для записи | Примечания |
|------|----------------------|------------|
| `native` | Файлы хранятся непосредственно в каталоге сессии | Требуется файловая система POSIX с поддержкой метаданных Linux. |
| `dynfilefs` | Расширяемая файловая система ext4, разбитая на резервные файлы | Поддерживаются файловые системы POSIX, а также носители FAT32, NTFS или exFAT. |
| `raw` | Фиксированный по размеру `changes.img` с ext4 | Поддерживаются файловые системы POSIX, а также носители FAT32, NTFS или exFAT. |
| `luks` | LUKS2 `changes.luks` с ext4 | Требуется cryptsetup и initramfs, собранный с поддержкой шифрования MiniOS. Пароль запрашивается при загрузке. |
| `squashfs` | Сжатый снимок `changes.sb` | Распаковывается в RAM для использования; при сохранении пересобирается и атомарно заменяет снимок. Файловая система для постоянства должна сохранять метаданные Linux при сохранении. |

Активная сессия будет использоваться по умолчанию при следующей загрузке. Текущая сессия — это та, которая уже смонтирована в текущий корень. Активация другой сессии не заменяет текущий слой для записи. Проверка совместимости сессии включает версию MiniOS, редакцию, объединённую файловую систему и режим постоянства.

См. [Управление сессиями](/configuration/Session-Management.md) для команд создания, выбора, изменения размера, шифрования, конвертации, экспорта и восстановления.

## Приоритет конфигурации

Медиа-конфигурация находится в `minios/config.conf`, с дополнительными фрагментами в
`minios/config.conf.d/`. Рабочие копии — это `/etc/live/config.conf` и
`/etc/live/config.conf.d/` в составленном корне.

При загрузке MiniOS сравнивает время изменения файлов и копирует более новую версию медиа-файла
в рабочий корень. Если носитель доступен для записи и рабочая копия новее, она
копируется обратно на носитель. Фрагментированные файлы синхронизируются по имени файла в обоих направлениях. Если часы были переведены назад после предыдущей синхронизации,
MiniOS избегает замены временных меток и только дополняет отсутствующие назначения.

Параметры командной строки ядра перекрывают соответствующие значения, считанные из рабочей
конфигурации для этой загрузки. Это означает, что фактический порядок для явно
поддерживаемой настройки: сначала параметр загрузки, затем синхронизированная рабочая/медиа-конфигурация,
затем встроенное значение по умолчанию. Постоянные изменения в рабочей конфигурации могут стать
медиа-конфигурацией, если источник доступен для записи; для ISO-носителей только для чтения
это обновление невозможно.

См. [Файл конфигурации](/configuration/Configuration-File.md) и
[live-config](/configuration/live-config.md) для поддерживаемых настроек.

## Завершение работы и жизненный цикл сохранения

При обычном завершении работы системе сначала предоставляется возможность сбросить сервисы и
данные сессии. Сессия SquashFS с включённым сохранением при завершении работы пересобирается и
проверяется до отключения файловой системы. Бэкенд сохранения записывает маркер завершения
именно для текущей сессии; initramfs завершения работы проверяет этот маркер и помечает сессию как «грязную», если требуемое сохранение не удалось.

Далее initramfs завершения работы отсоединяет неиспользуемые loop-устройства, отмонтирует старый корень
и слой для записи, отмечает успешную сессию как чистую, отмонтирует носитель
и закрывает LUKS-мэппинг, принадлежащий MiniOS. После этого оптический носитель можно извлечь до
выключения питания или перезагрузки. Ручное и периодическое сохранение SquashFS используют тот же механизм создания снимков, но только настроенная политика завершения работы блокирует финализацию как чистую при отсутствии сохранения на этапе завершения работы.

## Дерево носителя

Актуальный образ организован следующим образом. Необязательные каталоги появляются только при наличии
контента, созданного соответствующей функцией.

```text
/
|-- .disk/                         ISO metadata
|-- EFI/                           UEFI boot files
`-- minios/
    |-- 00-core-<arch>.sb          base userspace
    |-- 01-kernel-<version>-<arch>.sb
    |-- 02-firmware-<arch>.sb
    |-- NN-<name>-<arch>.sb        ordered system modules
    |-- boot/                      kernels, initramfs, GRUB, and Syslinux data
    |-- changes/                   session metadata and numbered sessions
    |-- modules/                   additional next-boot modules
    |-- config.conf                main media configuration
    |-- config.conf.d/             optional configuration fragments
    |-- kernels/                   optional inactive kernel repository
    |-- userdata/                  optional linked or bound user directories
    `-- log/                       optional exported boot logs
```

Загруженные пути под `/run/initramfs/memory/` являются монтированиями реализации, а не
второй постоянной копией этого дерева.
