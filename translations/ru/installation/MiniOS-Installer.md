# Использование MiniOS Installer

MiniOS Installer — это мастер на GTK и командная утилита для установки MiniOS из live-сессии MiniOS. Программа устанавливает систему на выбранный диск; это не то же самое, что запись ISO-образа на загрузочный носитель.

## Перед началом

Неправильный выбор целевого диска или разметки может привести к потере данных. Создайте резервные копии важных файлов, отключите ненужные диски и определите целевой диск по пути устройства, модели и объёму. Последнее подтверждение — это последняя возможность безопасно отменить установку.

Диск, на котором запущена текущая live-система MiniOS, не предлагается для установки. Для общей информации по объёму ознакомьтесь с [руководством по совместимости оборудования](Hardware-Compatibility.md#system-requirements).

## Режимы установки

Live-режим копирует выбранные сжатые модули MiniOS и загрузочные файлы. В результате сохраняется модульная структура live-системы с возможностью использования постоянства сессии MiniOS.

В нативном режиме выбранные модули разворачиваются в стандартную корневую файловую систему Linux, настраивается целевой диск, устанавливаются необходимые пакеты, создаётся initramfs и устанавливается загрузчик. Установщик определяет поддержку нативного режима по загруженному образу. Если отсутствуют необходимые метаданные ядра и архитектурный контракт EFI, режим совместимости позволяет только live-установку.

## Запуск графического установщика

Откройте меню приложений, выберите раздел "Система", затем "Установить MiniOS". Также можно запустить из терминала:

```bash
sudo minios-installer
```

Мастер собирает параметры режима установки, безопасности, местоположения, проводной сети, клавиатуры, учётной записи, модулей, хранилища и загрузки. Перед финальным подтверждением внимательно проверьте схему разделов и итоговое описание операций.

## Размещение и схемы загрузки

Графический установщик предлагает следующие варианты размещения, если целевой диск подходит:

- Стереть всё — создаёт новую таблицу разделов и удаляет все данные на целевом диске.
- Свободное пространство — использует подходящее неразмеченное пространство без уменьшения существующих файловых систем.
- Рядом — уменьшает последний подходящий, размонтированный раздел ext2, ext3, ext4 или NTFS. Грязные, смонтированные, вложенные, неоднозначные и иные небезопасные схемы отклоняются. При необходимости установщик может запросить загрузку недостающих утилит для работы с файловыми системами.
- Ручная разметка доступна только для нативной установки через графический интерфейс на подходящие физические диски. Изменения применяются только после финального подтверждения.

Автоматические схемы загрузки: BIOS/MBR, UEFI/MBR и UEFI/GPT. UEFI поддерживается с GPT или основной MBR-разметкой. BIOS поддерживается только на основной MBR, но не на GPT. Расширенные или логические MBR-схемы сохранения не поддерживаются.

В ручном режиме можно создавать, удалять, форматировать и переиспользовать разделы; уменьшать поддерживаемую файловую систему с конца; назначать точки монтирования, EFI-раздел и swap; а также отменять или сбрасывать подготовленные изменения. Не поддерживаются LVM, RAID, нативный корень LUKS, отображаемые или вложенные хранилища, bcache, ZFS и редактирование подтомов Btrfs. Постоянство сессии LUKS не шифрует корневую файловую систему в нативном режиме.

## Файловые системы

- Live-схемы могут использовать ext2, ext4, Btrfs, FAT32 или NTFS при наличии необходимых утилит.
- Корневые файловые системы в нативном режиме могут быть ext2, ext4 или Btrfs. По умолчанию используется ext4.
- Существующие файловые системы ext3 могут быть переиспользованы или уменьшены, если это поддерживается, но ext3 не предлагается для нового форматирования.
- FAT32 ограничен файлами размером до 4 ГиБ и доступен только для live-схем.
- NTFS доступен только для live-схем, хотя подходящий раздел NTFS может быть уменьшен для размещения рядом.

Требуемое пространство включает выбранные модули, загрузочные файлы, запрошенное постоянство и резерв файловой системы в 25 процентов. EFI и swap в нативном режиме рассчитываются отдельно.

## Конфигурация и безопасность

Установщик может настроить локаль, часовой пояс, клавиатуру, имя пользователя, пароли, группы пользователей, имя хоста, службы, загрузочное меню и выбор модулей. Выбор более высокого модуля MiniOS включает все необходимые нижележащие слои.

Профили безопасности: `convenient`, `balanced` и `strict`. В live-режиме по умолчанию используется `convenient`; в нативном — `balanced`. Управление SSH и XRDP осуществляется отдельно от выбранного профиля. Проверьте службы удалённого доступа перед первым подключением к сети.

Сетевые настройки включают имя хоста и проводной DHCP или статический IPv4. Установщик не создаёт и не изменяет Wi-Fi-профили. Для нативной и параллельной установки может потребоваться доступ к сети (с вашего согласия) для загрузки GRUB, EFI, initramfs, `os-prober` или пакетов для изменения размера файловых систем до внесения изменений на диск.

## Постоянство live-сессии

Постоянство применяется только к live-установкам:

- Нативное постоянство сохраняет изменения напрямую на целевой файловой системе с поддержкой POSIX. Не предлагается для FAT32 или NTFS.
- DynFileFS использует расширяемый контейнер.
- Raw — это контейнер фиксированного размера.
- LUKS использует зашифрованный образ, создаваемый initrd при первой загрузке. Пароль запрашивается при загрузке и никогда не передаётся и не сохраняется установщиком.

Для контейнерных режимов по умолчанию используется 4000 МиБ. Контейнеры Raw и LUKS не могут превышать 4000 МиБ на FAT32; DynFileFS не ограничен этим лимитом на размер одного файла. LUKS предлагается только если и запущенный initrd, и каждый копируемый исходный initrd поддерживают необходимое шифрование.

В результате в меню загрузки появятся параметры `perchmode` и `perchsize`. Подробнее о значении этих параметров во время загрузки см. в разделе [Параметры загрузки](/configuration/Boot-Parameters.md).

## Установка из командной строки

`minios-deploy` предназначен для автоматизации, тестирования и восстановления. Ручная разметка и интерактивная настройка проводной сети доступны только в графическом интерфейсе.

Вывести список дисков, доступных для установки:

```bash
minios-deploy list-disks
```

Замените `/dev/sdb` во всех примерах на проверенный целевой диск. Сначала выведите недеструктивный план:

```bash
minios-deploy plan /dev/sdb --mode live --placement free_space \
  --filesystem ext4 --persistence-mode dynfilefs --persistence-size 8000
```

Посмотреть соответствующие команды развертывания без записи на диск:

```bash
sudo minios-deploy install /dev/sdb --mode live --placement free_space \
  --filesystem ext4 --persistence-mode dynfilefs --persistence-size 8000 \
  --security-profile balanced --dry-run
```

Запускайте реальную установку только после проверки плана, идентификатора цели и вывода пробного запуска. `--yes` подтверждает выполнение деструктивных изменений:

```bash
sudo minios-deploy install /dev/sdb --mode live --placement free_space \
  --filesystem ext4 --persistence-mode dynfilefs --persistence-size 8000 \
  --security-profile balanced --yes
```

Для нативной установки в существующее свободное пространство используйте одинаковые параметры хранилища для планирования и установки:

```bash
minios-deploy plan /dev/sdb --mode native --placement free_space \
  --filesystem ext4 --boot-layout auto
sudo minios-deploy install /dev/sdb --mode native --placement free_space \
  --filesystem ext4 --boot-layout auto --security-profile balanced \
  --download-packages --yes
```

Нативный режим может отсутствовать в справке CLI, если образ не поддерживает native-install. В CLI также можно указать параметры для учётных записей, локали, часового пояса, клавиатуры, имени хоста, служб и базового `config.conf`. Проверьте доступные параметры для текущего образа:

```bash
minios-deploy install --help
man minios-deploy
```

Избегайте использования `--password` и `--root-password` в общих средах, так как аргументы командной строки в открытом виде могут быть видны в истории оболочки и списке процессов. Вместо этого используйте графический установщик или защищённый процесс конфигурирования.
