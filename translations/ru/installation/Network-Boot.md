# Сетевой загрузчик

На этой странице описано, **как загрузить MiniOS по сети**: PXE (kernel + initrd + данные MiniOS) и HTTP ISO (`from=http://…`). Это единственная цель использования сети внутри initramfs MiniOS.

Речь **не** идет о:

- Настройке NetworkManager или постоянного статического IP после загрузки системы
- Wi‑Fi в initrd
- [live-config](/configuration/live-config.md) (поздний userspace)

Сетевая работа после загрузки системы осуществляется отдельно. Для постоянного проводного статического IP используйте шаг Network в установщике, NetworkManager или ifupdown — не параметр PXE `ip=`.

Связанные темы: [Параметры загрузки](/configuration/Boot-Parameters.md) (`ip`, `from`, `cache`).

## Обзор

| Режим | Что загружается | Как получаются данные MiniOS |
|-------|-----------------|------------------------------|
| **PXE** | Ядро + initrd с сетевого сервера загрузки | Непустой `ip=` без `from=http://…` → initrd загружает файлы MiniOS с PXE data server |
| **HTTP ISO** | Ядро + initrd с локального носителя **или** PXE | `from=http://…/minios.iso` → initrd поднимает сеть и монтирует ISO через `httpfs2` |
| **Локальный носитель** | USB / ISO / диск | Нет сетевого initrd; только локальный поиск |

Сборщики initramfs: **LiveKit** (`livekit-mos`) или **dracut** (`dracut-mos`). Оба используют одни и те же сетевые помощники LiveKit для ранней загрузки.

```text
find_data()
  ├─ from=http://…     → configure network (ip= static, otherwise DHCP) → mount ISO (httpfs2)
  ├─ ip=… (non-empty)  → configure network → PXE download of MiniOS data
  └─ else              → search local disks/ISO only (no network)
```

`from=http://…` имеет приоритет над `ip=`. В этом режиме `ip=` задаёт статическую
адресацию для HTTP ISO подключения. В противном случае любой непустой `ip=` выбирает
**PXE data path** и пропускает локальные носители. Не добавляйте `ip=` при обычной загрузке с USB/ISO
только чтобы "задать статический адрес". Ни один из сетевых путей не возвращается к локальному
носителю, если обнаружение или загрузка не удались.

## Требования

| Требование | Примечания |
|------------|------------|
| Проводной Ethernet (или virtio/vmxnet в ВМ) | Используется первый обнаруженный не-loopback интерфейс; наличие линка и доступность не проверяются, выбора `BOOTIF` / `ethdevice` в initrd нет |
| Initrd с сетевыми модулями | Собирается для вариантов пакетов, отличных от внутреннего значения `minimum` (`--network`, часто `--cloud`) |
| Без использования Wi‑Fi | Беспроводные интерфейсы не поддерживаются в сетевой загрузке |
| Предпочтение NIC без firmware blobs | Карты, требующие прошивки, часто не работают в initrd |
| Рекомендуются образы **Standard** или больше | В редакции **Flux** отсутствуют сетевые модули NIC, поэтому PXE / HTTP ISO фактически не поддерживаются |
| Только HTTP для URL ISO | `from=http://…` работает; **`https://` не поддерживается** |

Инструменты в initrd: busybox `ifconfig`, `route`, `udhcpc`, `wget`, `tftp`, и `@mount.httpfs2`. NetworkManager в initrd отсутствует.

## PXE-загрузка

### Последовательность

1. Прошивка / PXE-сервер загружает **ядро** и **initrd** MiniOS (pxelinux, iPXE и др. — вне самого MiniOS).
2. В командной строке ядра указывается непустой **`ip=`** (и обычно `boot=live` для полной загрузки MiniOS).
3. Initrd настраивает статический адрес из `ip=`, связывается с **сервером** (поле server), скачивает список файлов, затем пакеты/файлы MiniOS.
4. Система продолжает загрузку в live root как обычно.

### Параметр `ip=`

```text
ip=<client-ip>:<server-ip>:<gateway-ip>:<netmask>[:<port>]
```

| Поле | Назначение |
|------|------------|
| client-ip | Адрес, назначаемый через busybox `ifconfig` |
| server-ip | Хост для HTTP/TFTP данных MiniOS; также записывается как DNS-сервер в initrd |
| gateway-ip | Шлюз по умолчанию; также записывается как DNS-сервер |
| netmask | Маска подсети IPv4 в виде точечной записи (не префикс CIDR) |
| port | Необязательный HTTP-порт для списка файлов и самих файлов (по умолчанию **7529**) |

Примеры:

```text
ip=192.168.1.10:192.168.1.1:192.168.1.1:255.255.255.0
ip=192.168.1.10:192.168.1.1:192.168.1.1:255.255.255.0:8080
```

### Как происходит загрузка файлов

1. **HTTP** (предпочтительно):
   `http://<server-ip>:<port>/PXEFILELIST?<kernel-release>:<machine>`
   затем каждый путь из этого файла с того же хоста/порта.
2. **TFTP**: busybox `tftp` используется только если начальный HTTP-запрос к
   `PXEFILELIST` не удался. Если позже произойдет ошибка загрузки файла по HTTP, переключение на TFTP не происходит.

Порт по умолчанию — **7529**, если пятое поле не указано.

### Чем `ip=` не является

| Ожидание | Реальность |
|----------|------------|
| Формы ядра / dracut (`ip=dhcp`, `ip=:::::eth0:dhcp`, …) | **Не поддерживается** — неверно интерпретируется как адрес клиента |
| Статический IP для всей live-сессии | **Не поддерживается** — после загрузки интерфейсом управляет NetworkManager (или аналогичный) |
| Статический IP при загрузке данных MiniOS с USB/ISO | **Не используйте** — без `from=http://…` это приведёт к загрузке данных через PXE |
| Отдельный список DNS | В initrd в качестве DNS используются только шлюз и сервер |

## Загрузка HTTP ISO (`from=http://…`)

Загрузка данных MiniOS из удаленного ISO без полного PXE-списка файлов:

```text
from=http://192.168.1.1/path/minios.iso
```

Поведение:

1. Initrd поднимает сеть:
   - Если задан **`ip=`** → статическая настройка как выше
   - Если **`ip=`** не указан → **DHCP** через busybox `udhcpc`
2. Монтирует удаленный ISO с помощью **`httpfs2`**
3. Продолжает искать содержимое MiniOS на этом монтировании

Необязательный **`cache=`** (в мегабайтах) включает кэш загрузки httpfs, например `cache=512`.

Для этого пути удаленного ISO принимается только **`http://`**. **`https://` не поддерживается.**

## После запуска live-системы

| Элемент | После switch_root |
|---------|-------------------|
| IP/маршруты ядра на NIC | Могут остаться до перенастройки интерфейса в userspace |
| DNS initrd (`resolv.conf`) | Не является постоянной политикой сессии |
| Сетевая сессия | Обычно **NetworkManager** на стандартных образах MiniOS |
| Значение `ip=` | Только для ранней загрузки — не сохраняется как статический профиль |

Если корень продолжает использоваться через **httpfs**, перенастройка NIC NetworkManager может нарушить работу live root. Планируйте сетевые загрузки с учетом этого (например, копируйте в RAM / избегайте изменения интерфейса, через который идет загрузка).

Поздний userspace **live-config** может кратковременно поднимать сеть только для загрузки удаленных хуков/preseed (`Setup_network`). Это не связано с PXE/`ip=` и постоянной адресацией.

## Типичные ошибки

1. Указание `ip=` в командной строке USB/ISO "для статического IP" → система пытается загрузить данные по PXE вместо локального носителя, если только `from=http://…` не выбран для загрузки HTTP ISO.
2. Использование `ip=dhcp` или другого синтаксиса ядра `ip=` → неверный парсер, неправильная настройка адреса.
3. Ожидание поддержки Wi‑Fi или выбора между несколькими NIC (`BOOTIF`) в initrd → не реализовано.
4. Использование образа **Flux** для PXE/HTTP ISO → в initrd отсутствуют сетевые модули.
5. Предоставление ISO только по HTTPS → `from=http://…` не сработает.
6. Путаница с настройкой статического адреса через установщик/NetworkManager после входа в систему.

## Краткая сводка по надёжности

| Сценарий | Оценка |
|----------|--------|
| PXE + `ip=…` + HTTP-список на :7529 (или TFTP после неудачного HTTP-запроса списка), простое проводное / virtio | Поддерживаемая цель |
| `from=http://…iso` + DHCP (или `ip=`), тот же класс NIC | Обычно работает |
| Обычная загрузка с USB/ISO | Сеть в initrd не используется |
| Статический адрес для сессии через `ip=` | Не поддерживается |
| Несколько NIC / NIC с прошивкой / Wi‑Fi / `https://` / редакция Flux | Слабо или не поддерживается |

## Справка по реализации

| Компонент | Расположение в дереве MiniOS |
|-----------|------------------------------|
| Точка входа init | `linux-live/initramfs/livekit-mos/init` |
| Сеть + PXE + HTTP ISO | `linux-live/initramfs/livekit-mos/lib/livekitlib` (`init_network_ip`, `download_data_pxe`, `mount_data_http`, `find_data`) |
| Сборщик LiveKit (`--network`) | `linux-live/initramfs/livekit-mos/mkinitrfs` |
| Модуль Dracut MiniOS | `linux-live/initramfs/dracut-mos/90minios/` |
| При передаче `-n` | `linux-live/build-initramfs` (не-minimum) |
