# Сессии и постоянство данных

Сессии MiniOS сохраняют изменения, внесённые в работающую систему, между перезагрузками. Каждая сессия — это отдельный каталог с номером в `minios/changes/`; модули MiniOS остаются только для чтения, а выбранная сессия предоставляет записываемый слой объединённой файловой системы.

Используйте Менеджер сессий MiniOS из запущенной системы MiniOS:

```bash
minios-session-manager
```

Эквивалентная утилита командной строки — `minios-session`. Для выполнения команд, изменяющих данные, требуются права администратора, поэтому в примерах ниже используется `sudo`.

## Режимы сессий

| Режим | Хранилище | Основные ограничения |
|------|---------|------------------|
| `native` | Изменения сохраняются непосредственно в каталоге сессии | Требуется файловая система POSIX с поддержкой записи, например ext2/3/4, Btrfs, XFS, F2FS или ReiserFS. |
| `dynfilefs` | Расширяемый контейнер ext4, разделённый на базовые файлы | Работает на файловых системах POSIX с поддержкой записи, FAT32, NTFS и exFAT. Требуется бэкенд DynFileFS. |
| `raw` | Фиксированный размер `changes.img` с ext4 | Работает на файловых системах POSIX с поддержкой записи, FAT32, NTFS и exFAT. |
| `luks` | LUKS2-зашифрованный `changes.luks` с ext4 | Требуется `cryptsetup`, поддержка loop и initrd LUKS hook MiniOS. |
| `squashfs` | Сжатый снимок в `changes.sb` | Для сохранения требуется файловая система POSIX с поддержкой постоянства, способная сохранять ссылки, владельцев, режимы, xattrs, ACL, capabilities и whiteouts. |

`dynfilefs`, `raw`, и `luks` создан с помощью `minios-session` по умолчанию 4000 МиБ. Размер указывается в МиБ; `GB` и `TB` суффиксы преобразуются в 1000 и 1 000 000 МиБ. Менеджер сессий MiniOS ограничивает размер raw и LUKS-файлов до 4000 МиБ на FAT32. Не полагайтесь на это как на общее правило для initrd: если размер raw-контейнера превышает лимит, запрос может дойти до выделения и завершиться ошибкой, а не быть уменьшён автоматически. Операции изменения размера контейнера поддерживают только увеличение; уменьшение не поддерживается.

Режим native — самый простой и быстрый выбор на совместимой файловой системе.
Используйте DynFileFS, если файловая система не поддерживает хранение метаданных Linux.
Используйте raw, если требуется фиксированный размер, LUKS — для шифрования сессии, а SquashFS — для точного сжатого снимка.

Выполните следующие команды для проверки реальной файловой системы постоянства и доступных на ней режимов:

```bash
sudo minios-session info
sudo minios-session status
```

Создать сессию на носителе только для чтения невозможно. Initrd может прочитать и активировать существующий снимок SquashFS, сохранённый на FAT, exFAT или NTFS с поддержкой записи, поскольку он извлекает снимок во временный верхний слой ext4. Создание или точное сохранение снимка отличается: для этого требуется отдельная рабочая область на подходящей файловой системе POSIX, сохраняющей метаданные Linux и whiteouts объединения.

## Выбор загрузки

Любой распознанный параметр персистентности активирует обработку персистентности. MiniOS загрузочные меню обычно предоставляют варианты возобновления, создания новой сессии, выбора и неперсистентного запуска. Каноническое описание семантики селектора, совместимости, резервного режима и активации приведено в разделе [Initrd persistence](/reference/boot-process/Persistence-Internals).

| Параметр | Значение |
|-----------|---------|
| `perch` | Использовать устаревший путь возобновления по принципу "лучшее из возможного". Пробует использовать метаданные по умолчанию, но не создаёт замену, если подходящей нет. |
| `perchdir=resume` | Возобновить метаданные по умолчанию и, если они отсутствуют или несовместимы, разрешить initrd создать новую совместимую замену. Это текущее поведение возобновления в загрузочном меню. |
| `perchdir=new` | Создать новую сессию с уникальным номером. |
| `perchdir=ask` | Выбрать существующую сессию или создать новую во время загрузки. |
| `perchdir=<id>` | Выбрать указанную сессию по номеру напрямую. |
| `perchdir=<device/path>` | Использовать место для персистентности на устройстве, включая формы `/dev/...` и `label:...`, обрабатываемые initrd. |
| `perchmode=<mode>` | Установить `native`, `dynfilefs`, `raw`, `luks` или `squashfs`. |
| `perchsize=<size>` | Задать новый или больший размер контейнера; простые значения указываются в MiB, а также принимаются суффиксы `MB`, `GB` и `TB`. |

Если для новой сессии не указан режим, загрузка использует нативный режим. На FAT32/NTFS/exFAT создание в нативном режиме по умолчанию переключается на DynFileFS. Новый контейнер raw или LUKS по умолчанию имеет размер 4000 MiB; новая сессия DynFileFS без `perchsize` получает размер, рассчитанный из доступного пространства с учётом резервного запаса.
Сессии SquashFS захватываются из работающей системы с помощью Менеджера сессий MiniOS или `minios-session create squashfs`; `perchdir=new perchmode=squashfs` не создаёт снимок в initrd.

При возобновлении MiniOS проверяет записанную версию, редакцию, файловую систему union и режим. Буквальный `perchdir=resume` может создать новую сессию вместо использования отсутствующего или несовместимого значения по умолчанию. Простое `perch`, прямой выбор по номеру и другие устаревшие запросы возобновления не создают такую замену автоматически.
При интерактивном выборе отображается предупреждение перед разрешением несовместимой сессии. Если выбор или активация всё равно не удаются, загрузка продолжается с RAM верхним слоем и предупреждением о персистентности.

Хранилище сессий имеет следующий вид:

```text
minios/changes/
|-- session.conf
|-- 1/
|-- 2/
`-- N/
```

`session.conf` хранит идентификаторы по умолчанию и текущей сессии, а также режим, версию, редакцию, файловую систему union, размер, состояние и специфические настройки для каждой сессии.
Это персистентные метаданные, фиксируемые реализацией загрузки, но сами по себе не являются доказательством текущего состояния во время работы. Не редактируйте их и не перемещайте данные сессий с номерами, пока сессия смонтирована; используйте Менеджер сессий MiniOS или `minios-session`.

## Активные и запущенные сессии

Эти термины описывают разные состояния:

- **Активная** сессия — это сессия, выбранная по умолчанию для следующей загрузки.
- Концептуально **запущенная** сессия — это сессия, writable-слой которой фактически обеспечивает персистентность для текущей загрузки.

Поле `running=` в персистентных данных фиксирует это предполагаемое соотношение. Сбой, неудачная сборка union, копирование хранилища или прерванное завершение работы могут сделать его устаревшим, даже если текущая загрузка использует RAM или другую сессию. Операции, такие как сохранение SquashFS, требуют защищённого состояния текущей загрузки, связанного с идентификатором загрузки, и проверенного смонтированного верхнего слоя initrd; они не доверяют только `running=`. Подробнее см. [Активное, запущенное и состояние текущей загрузки](/reference/boot-process/Persistence-Internals).

Активация сессии меняет выбор для следующей загрузки, но не переключает текущую файловую систему union:

```bash
sudo minios-session active
sudo minios-session running
sudo minios-session activate <id>
```

Активная сессия не может быть удалена или преобразована на месте. Запущенная сессия обычно не может быть удалена, экспортирована, скопирована, изменена по размеру или преобразована. Очистка также защищает оба идентификатора.

## Справочник команд

Список сессий и просмотр содержимого хранилища:

```bash
sudo minios-session list
sudo minios-session active
sudo minios-session running
sudo minios-session info
sudo minios-session status
```

Создание сессий:

```bash
sudo minios-session create
sudo minios-session create native
sudo minios-session create dynfilefs
sudo minios-session create raw 4GB
sudo minios-session create luks 4GB
sudo minios-session create squashfs --policy shutdown
sudo minios-session create squashfs --policy manual --autosave 60
```

`create` без указания режима выбирает нативный режим. Создание SquashFS фиксирует текущие изменения в live-режиме и не имеет фиксированного размера. Политика сохранения при завершении работы по умолчанию — `shutdown`; периодическое сохранение по умолчанию отключено.

Сохранение и настройка сессии SquashFS:

```bash
sudo minios-session save <running-squashfs-id>
sudo minios-session settings <squashfs-id> --shutdown on
sudo minios-session settings <squashfs-id> --shutdown off --autosave 0
sudo minios-session settings <squashfs-id> --shutdown on --autosave 60
```

Допустимые интервалы для периодического сохранения: `30`, `60`, `120`, `240` и `480` минут; `0` отключает периодическое сохранение. Настройки завершения работы и периодичности независимы друг от друга.

Экспорт и импорт архивов `.tar.zst`:

```bash
sudo minios-session export <id> /path/to/session.tar.zst
sudo minios-session import /path/to/session.tar.zst
sudo minios-session import /path/to/session.tar.zst --auto-convert
sudo minios-session import /path/to/session.tar.zst --force-mode dynfilefs
```

Принимаются только импорты `.tar.zst`. Пути и содержимое архива проверяются, а извлечение ограничено. `--auto-convert` выбирает совместимый режим для текущей файловой системы. `--force-mode <mode>` явно выбирает доступный режим. Экспорт, копирование и преобразование не поддерживаются для сессий SquashFS; сохраните снимок и скопируйте всю неактивную директорию сессии вручную.

Копирование или преобразование сессии:

```bash
sudo minios-session copy <id>
sudo minios-session copy <id> --to-mode raw --size 4GB
sudo minios-session convert <id> dynfilefs --size 4GB
sudo minios-session convert <id> luks --size 4GB --new-session
```

`copy` всегда присваивает новый идентификатор сессии. `convert` по умолчанию заменяет исходную сессию; используйте `--new-session` для сохранения исходной. Размер имеет значение только для контейнера-назначения.

Увеличение, удаление или очистка сессий:

```bash
sudo minios-session resize <id> 8GB
sudo minios-session delete <id>
sudo minios-session cleanup
sudo minios-session cleanup --days 30
```

Изменение размера поддерживается для сессий DynFileFS, raw и LUKS и требует указания размера, превышающего текущий. Очистка по умолчанию применяется к сессиям старше 30 дней.

Все команды принимают `--json`, а другое хранилище сессий можно выбрать с помощью `--sessions-dir PATH`:

```bash
sudo minios-session --json list
sudo minios-session --sessions-dir /mnt/store/minios/changes list
```

## Поведение сохранения SquashFS

Сессия SquashFS распаковывается в RAM для текущего writable-слоя. При сохранении создаётся и проверяется точный снимок, который затем атомарно заменяет `changes.sb`.
Откаты предыдущих версий не сохраняются. Кнопка "Сохранить сейчас" доступна через значок в трее, Менеджер сессий MiniOS или `minios-session save` вне зависимости от автоматической политики.

Сохранение при завершении работы реализуется через основной триггер завершения работы MiniOS и бэкенд `minios-squashfs-save`, поэтому не зависит от того, открыт или установлен Менеджер сессий MiniOS. Периодическое сохранение проверяется каждые 30 минут с помощью systemd-таймера или SysV-демона, оба используют тот же бэкенд автосохранения. Пересборка снимка нагружает процессор и записывает полный снимок; рекомендуется использовать интервалы не менее одного часа.

Во время работы сессии SquashFS на базе RAM, только что захваченный и активированный снимок SquashFS может получить права на текущую цель сохранения. После передачи старый запущенный снимок можно удалить без перезагрузки:

```bash
sudo minios-session activate <new-squashfs-id>
sudo minios-session delete <old-running-squashfs-id> --handoff
```

Это исключение применяется только к валидной передаче текущей загрузки SquashFS. Для других режимов персистентности защита от удаления сохраняется.

## Шифрование

В режиме LUKS файловая система ext4 хранится непосредственно в контейнере LUKS2 `changes.luks`; таблица разделов или вложенный контейнер DynFileFS отсутствуют. Варианты LUKS доступны только если `/run/initramfs/etc/minios-initramfs-crypt`, `cryptsetup` и `losetup` присутствуют.

При создании LUKS в интерактивном режиме пароль вводится дважды. Операции чтения или создания LUKS-данных могут получать пароль из стандартного ввода с помощью `--password-stdin`.
Пароли не передаются в аргументах команд или метаданных сессии. При загрузке initrd запрашивает пароль в консоли и не переходит к нешифрованному режиму, если активация не удалась.

Экспорт LUKS содержит расшифрованные логические файлы сессии, а не `changes.luks`.
Импорт или преобразование в LUKS создаёт новый зашифрованный контейнер.

## Резервные копии и сбойные сессии

Для сессий в нативном режиме, DynFileFS, raw и LUKS используйте `export` для резервного копирования вместо копирования смонтированной директории сессии. Храните полученный архив на другом устройстве и убедитесь, что его можно импортировать, прежде чем полагаться на него. Импорт всегда создаёт новую сессию с номером; активируйте её вручную, когда она будет готова к использованию.
Для процедур резервного копирования SquashFS и всего устройства см. [Резервное копирование MiniOS](/maintenance-and-recovery/Backing-Up-MiniOS).

Если сессия выходит из строя после заполнения хранилища, прерывания записи или многократного создания пустых сессий, прекратите любые изменения на этом носителе. Сначала экспортируйте читаемую неактивную сессию, если это возможно, затем следуйте разделу [Диагностика](/maintenance-and-recovery/Troubleshooting).

Начните диагностику без изменения данных сессии:

```bash
sudo minios-session list
sudo minios-session active
sudo minios-session running
sudo minios-session status
sudo minios-session info
```

При загрузке файловые системы контейнеров проверяются до активации в режиме записи. Серьёзные ошибки проверки файловой системы сохраняют контейнер для восстановления вместо монтирования в режиме записи. SquashFS обнаруживает незавершённое предыдущее состояние и восстанавливает последний успешно сохранённый снимок. Удаляйте сессии только через Менеджер сессий MiniOS или `minios-session delete`; не удаляйте директории сессий вручную.
