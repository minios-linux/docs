# Сессии и постоянство данных

MiniOS сессии сохраняют изменения, внесённые в работающую систему, между перезагрузками. Каждая сессия — это отдельный каталог с номером внутри `minios/changes/`; модули MiniOS остаются неизменными, а выбранная сессия предоставляет записываемый слой объединённой файловой системы.

Используйте Менеджер сессий MiniOS из запущенной системы MiniOS:

```bash
minios-session-manager
```

Эквивалентная утилита командной строки — `minios-session`. Для выполнения команд, изменяющих систему, требуются права администратора, поэтому в примерах ниже используется `sudo`.

## Режимы сессий

| Режим | Хранилище | Основные ограничения |
|------|-----------|----------------------|
| `native` | Изменения сохраняются напрямую в каталоге сессии | Требуется записываемая POSIX-файловая система, такая как ext2/3/4, Btrfs, XFS, F2FS или ReiserFS. |
| `dynfilefs` | Расширяемый контейнер ext4, разбитый на резервные файлы | Работает на записываемых POSIX, FAT32, NTFS и exFAT файловых системах. Требуется бэкенд DynFileFS. |
| `raw` | Контейнер фиксированного размера `changes.img` с ext4 | Работает на записываемых POSIX, FAT32, NTFS и exFAT файловых системах. |
| `luks` | LUKS2-зашифрованный `changes.luks` с ext4 | Требуются `cryptsetup`, поддержка loop и initrd LUKS-хук MiniOS. |
| `squashfs` | Сжатый снимок в `changes.sb` | Для сохранения требуется POSIX-файловая система постоянства, способная сохранять ссылки, владельцев, режимы, xattrs, ACL, capabilities и whiteouts. |

`dynfilefs`, `raw` и `luks`, созданные с помощью `minios-session`, по умолчанию имеют размер 4000 МиБ. Значения размера указываются в МиБ; суффиксы `GB` и `TB` преобразуются в 1000 и 1 000 000 МиБ соответственно. Менеджер сессий MiniOS ограничивает raw- и LUKS-файлы 4000 МиБ на FAT32. Не полагайтесь на это как на общее правило initrd: при превышении лимита запрос на создание raw-контейнера может дойти до выделения пространства и завершиться ошибкой, а не автоматическим уменьшением размера. Операции по изменению размера контейнера могут только увеличивать сессию; уменьшение не поддерживается.

Режим native — самый простой и быстрый выбор для совместимой файловой системы.
Используйте DynFileFS, если файловая система постоянства не поддерживает метаданные Linux.
Используйте raw для фиксированного размера, LUKS — если требуется шифрование сессии, а SquashFS — для точной сжатой копии.

Выполните следующие команды, чтобы проверить реальную файловую систему постоянства и доступные на ней режимы:

```bash
sudo minios-session info
sudo minios-session status
```

Ни одна сессия не может быть создана на носителе только для чтения. Initrd может прочитать и активировать существующий снимок SquashFS, сохранённый на записываемом FAT, exFAT или NTFS, поскольку он извлекает снимок во временный верхний слой ext4. Создание или точное сохранение снимка отличается: его приватная рабочая область должна находиться на подходящей POSIX-файловой системе, которая сохраняет метаданные Linux и whiteouts объединения.

## Выбор загрузки

Любой распознанный параметр постоянства включает обработку постоянства. Меню загрузки MiniOS обычно предлагают варианты продолжения, создания новой, выбора и загрузки без постоянства. Каноническое описание селектора, совместимости, резервных вариантов и семантики активации приведено в разделе [Initrd persistence](/reference/boot-process/Persistence-Internals).

| Параметр | Значение |
|----------|----------|
| `perch` | Использовать устаревший путь продолжения по принципу «лучшее из возможного». Пробует значение по умолчанию из метаданных, но не создаёт замену, если подходящей нет. |
| `perchdir=resume` | Продолжить сессией по умолчанию из метаданных и, если она отсутствует или несовместима, разрешить initrd создать новую совместимую замену. Это текущее поведение загрузочного меню для продолжения. |
| `perchdir=new` | Создать новую сессию с новым номером. |
| `perchdir=ask` | Выбрать существующую сессию или создать новую при загрузке. |
| `perchdir=<id>` | Выбрать напрямую сессию с этим номером. |
| `perchdir=<device/path>` | Использовать место для постоянства на устройстве, включая формы `/dev/...` и `label:...`, обрабатываемые initrd. |
| `perchmode=<mode>` | Установить `native`, `dynfilefs`, `raw`, `luks` или `squashfs`. |
| `perchsize=<size>` | Установить новый или больший размер контейнера; значения без суффикса — в МиБ, принимаются суффиксы `MB`, `GB` и `TB`. |

Если для новой сессии не указан режим, загрузка использует native. На FAT32/NTFS/exFAT создание в режиме native автоматически переключается на DynFileFS. Новый контейнер raw или LUKS по умолчанию имеет размер 4000 МиБ; новая сессия DynFileFS без `perchsize` определяется по доступному пространству с учётом резервного запаса.
Сессии SquashFS создаются из работающей системы через Менеджер сессий MiniOS или `minios-session create squashfs`; `perchdir=new perchmode=squashfs` не создаёт снимок в initrd.

При продолжении работы MiniOS проверяет записанные версию, редакцию, объединённую файловую систему и режим. Буквальный `perchdir=resume` может создать новую сессию вместо отсутствующей или несовместимой по умолчанию. Простое `perch`, прямой выбор по номеру и другие устаревшие запросы продолжения не создают такую замену автоматически.
При интерактивном выборе перед использованием несовместимой сессии появляется предупреждение. Если выбор или активация всё равно не удаётся, загрузка продолжается с RAM верхним слоем и предупреждением о постоянстве.

Хранилище сессий имеет следующий вид:

```text
minios/changes/
|-- session.conf
|-- 1/
|-- 2/
`-- N/
```

`session.conf` хранит значения по умолчанию и идентификаторы текущей сессии, а также режим, версию, редакцию, объединённую файловую систему, размер, состояние и параметры режима для каждой сессии.
Это постоянные метаданные, фиксируемые загрузчиком, но сами по себе не гарантируют актуальное состояние во время работы. Не редактируйте их и не перемещайте данные сессий с номерами, пока сессия смонтирована; используйте Менеджер сессий MiniOS или `minios-session`.

## Активные и запущенные сессии

Эти термины обозначают разные состояния:

- **Активная** сессия — это та, которая выбрана по умолчанию для следующей загрузки.
- В концепции **запущенная** сессия — это сессия, чей записываемый слой фактически обеспечивает постоянство для текущей загрузки.

Постоянное поле `running=` фиксирует это предполагаемое соответствие. Сбой, неудачное построение union, копирование хранилища или прерванное завершение работы могут сделать его неактуальным, даже если текущая загрузка использует RAM или другую сессию. Поэтому для операций, таких как сохранение SquashFS, требуется защищённое состояние текущей загрузки, связанное с идентификатором загрузки initrd, и проверенный смонтированный upper; одному только `running=` не доверяют. Подробнее см. [Активное, запущенное и текущее состояние загрузки](/reference/boot-process/Persistence-Internals).

Активация сессии меняет выбор для следующей загрузки, но не переключает текущую объединённую файловую систему:

```bash
sudo minios-session active
sudo minios-session running
sudo minios-session activate <id>
```

Активную сессию нельзя удалить или преобразовать на месте. Запущенную сессию обычно нельзя удалить, экспортировать, скопировать, изменить размер или преобразовать. Очистка также защищает оба идентификатора.

## Справочник команд

Список сессий и просмотр хранилища:

```bash
sudo minios-session list
sudo minios-session active
sudo minios-session running
sudo minios-session info
sudo minios-session status
```

Создание сессий:

```bash
sudo minios-session create
sudo minios-session create native
sudo minios-session create dynfilefs
sudo minios-session create raw 4GB
sudo minios-session create luks 4GB
sudo minios-session create squashfs --policy shutdown
sudo minios-session create squashfs --policy manual --autosave 60
```

`create` без указания режима выбирает native. Создание SquashFS фиксирует текущие изменения в live-системе и не имеет фиксированного размера. Политика завершения работы по умолчанию — `shutdown`; периодическое сохранение по умолчанию выключено.

Сохранение и настройка сессии SquashFS:

```bash
sudo minios-session save <running-squashfs-id>
sudo minios-session settings <squashfs-id> --shutdown on
sudo minios-session settings <squashfs-id> --shutdown off --autosave 0
sudo minios-session settings <squashfs-id> --shutdown on --autosave 60
```

Допустимые интервалы для периодического сохранения: `30`, `60`, `120`, `240` и `480` минут; `0` отключает периодическое сохранение. Настройки завершения работы и периодического сохранения независимы.

Экспорт и импорт архивов `.tar.zst`:

```bash
sudo minios-session export <id> /path/to/session.tar.zst
sudo minios-session import /path/to/session.tar.zst
sudo minios-session import /path/to/session.tar.zst --auto-convert
sudo minios-session import /path/to/session.tar.zst --force-mode dynfilefs
```

Принимаются только импорты `.tar.zst`. Пути и содержимое архива проверяются, а извлечение ограничено. `--auto-convert` выбирает совместимый режим для текущей файловой системы. `--force-mode <mode>` явно выбирает доступный режим. Экспорт, копирование и преобразование не поддерживаются для сессий SquashFS; сохраните снимок и скопируйте весь неактивный каталог сессии вручную.

Копирование или преобразование сессии:

```bash
sudo minios-session copy <id>
sudo minios-session copy <id> --to-mode raw --size 4GB
sudo minios-session convert <id> dynfilefs --size 4GB
sudo minios-session convert <id> luks --size 4GB --new-session
```

`copy` всегда присваивает новый идентификатор сессии. По умолчанию `convert` заменяет исходную сессию; используйте `--new-session` для сохранения исходной. Размер имеет значение только для контейнера-приёмника.

Увеличение, удаление или очистка сессий:

```bash
sudo minios-session resize <id> 8GB
sudo minios-session delete <id>
sudo minios-session cleanup
sudo minios-session cleanup --days 30
```

Изменение размера поддерживается для сессий DynFileFS, raw и LUKS и требует размера больше текущего. Очистка по умолчанию удаляет сессии старше 30 дней.

Все команды принимают `--json`, а другое хранилище сессий можно выбрать с помощью `--sessions-dir PATH`:

```bash
sudo minios-session --json list
sudo minios-session --sessions-dir /mnt/store/minios/changes list
```

## Поведение сохранения SquashFS

Сессия SquashFS распаковывается в RAM для работы с записываемым слоем. При сохранении создаётся и проверяется точный снимок, затем `changes.sb` заменяется атомарно.
Откаты по поколениям не сохраняются. Кнопка "Сохранить сейчас" доступна из значка в трее, Менеджера сессий MiniOS или `minios-session save` вне зависимости от автоматической политики.

Сохранение при завершении работы реализовано через основной триггер завершения MiniOS и бэкенд `minios-squashfs-save`, поэтому не зависит от того, открыт или установлен Менеджер сессий MiniOS. Периодическое сохранение проверяется каждые 30 минут с помощью таймера systemd или службы SysV, обе вызывают тот же бэкенд автосохранения. Пересоздание снимка нагружает процессор и полностью перезаписывает снимок; рекомендуется устанавливать интервалы не менее одного часа.

Во время работы сессии на базе RAM-backed SquashFS, только что захваченный и активированный снимок SquashFS может получить права на текущую цель сохранения. После передачи старый активный снимок можно удалить без перезагрузки:

```bash
sudo minios-session activate <new-squashfs-id>
sudo minios-session delete <old-running-squashfs-id> --handoff
```

Это исключение действует только для корректной передачи текущей загрузки SquashFS. Для других режимов постоянства удаление защищено.

## Шифрование

В режиме LUKS файловая система ext4 хранится непосредственно в LUKS2-файле `changes.luks`; разделов или вложенного контейнера DynFileFS нет. Варианты LUKS доступны только при наличии `/run/initramfs/etc/minios-initramfs-crypt`, `cryptsetup` и `losetup`.

При интерактивном создании LUKS пароль запрашивается дважды. Операции чтения или создания LUKS-данных могут получать пароль из стандартного ввода через `--password-stdin`.
Пароли не передаются в аргументах команд или метаданных сессии. При загрузке initrd запрашивает пароль в консоли и не переходит к нешифрованному постоянству, если активация не удалась.

Экспорт LUKS содержит расшифрованные логические файлы сессии, а не `changes.luks`.
Импорт или преобразование в LUKS создаёт новый зашифрованный контейнер.

## Резервное копирование и неудачные сессии

Для сессий native, DynFileFS, raw и LUKS используйте `export` для создания резервных копий, а не копируйте смонтированный каталог сессии. Храните полученный архив на другом устройстве и убедитесь, что его можно импортировать, прежде чем полагаться на него. Импорт всегда создаёт новую сессию с новым номером; активируйте её вручную, когда она будет готова к использованию.
Для SquashFS и процедур резервного копирования всего устройства смотрите [Резервное копирование MiniOS](/maintenance-and-recovery/Backing-Up-MiniOS).

Если сессия выходит из строя после заполнения хранилища, прерывания записи или при многократном создании пустых сессий, прекратите любые изменения на этом носителе. Сначала экспортируйте читаемую неактивную сессию, если это возможно, затем следуйте инструкции по [Устранению неполадок](/maintenance-and-recovery/Troubleshooting).

Начинайте диагностику без изменения данных сессии:

```bash
sudo minios-session list
sudo minios-session active
sudo minios-session running
sudo minios-session status
sudo minios-session info
```

При загрузке файловые системы контейнеров проверяются до активации на запись. Серьёзные ошибки проверки файловой системы сохраняют контейнер для восстановления, а не монтируют его для записи. SquashFS определяет незавершённое предыдущее состояние и восстанавливает последний успешно сохранённый снимок. Удаляйте сессии только через Менеджер сессий MiniOS или `minios-session delete`; не удаляйте каталоги сессий вручную.
