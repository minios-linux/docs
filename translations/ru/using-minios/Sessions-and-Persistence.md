# Сессии и постоянство данных

Сессии MiniOS сохраняют изменения, внесённые в работающую систему, между перезагрузками. Каждая сессия — это отдельный каталог с номером в `minios/changes/`; модули MiniOS остаются только для чтения, а выбранная сессия предоставляет записываемый слой объединённой файловой системы.

Используйте Менеджер сессий MiniOS из запущенной системы MiniOS:

```bash
minios-session-manager
```

Эквивалентная утилита командной строки — `minios-session`. Для выполнения команд, изменяющих данные, требуются права администратора, поэтому в примерах ниже используется `sudo`.

## Режимы сессий

| Режим | Хранение | Основные ограничения |
|------|---------|------------------|
| `native` | Изменения сохраняются напрямую в каталоге сессии | Требуется доступная для записи POSIX-файловая система, например ext2/3/4, Btrfs, XFS, F2FS или ReiserFS. |
| `dynfilefs` | Масштабируемый ext4-контейнер, разбитый на поддерживающие файлы | Работает на доступных для записи POSIX, FAT32, NTFS и exFAT. Требуется бэкенд DynFileFS. |
| `dynblk` | Тонкий ext4 на блочном устройстве ядра с поддержкой через`volumeNNN.db` файлы | Требуются dynblk CLI, модуль ядра и поддержка initrd. Виртуальный размер по умолчанию — 16 ГиБ, максимум — 512 ГиБ. |
| `raw` | Фиксированный`changes.img` с ext4 | Работает на доступных для записи POSIX, FAT32, NTFS и exFAT. |
| `luks` | LUKS2-зашифрованный`changes.luks` с ext4 | Требуются`cryptsetup`, поддержка loop и MiniOS initrd LUKS hook. |
| `squashfs` | Сжатый снимок в`changes.sb` | Для сохранения требуется POSIX-файловая система, поддерживающая сохранение ссылок, владельцев, режимов, xattr, ACL, capability и whiteout. |

`dynfilefs`, `raw`, и `luks` создан с помощью `minios-session` по умолчанию 4000 МиБ; `dynblk` по умолчанию 16 ГиБ. Размеры выделяются в МиБ; `GB` и `TB` суффиксы конвертируются в 1000 и 1 000 000 МиБ. Менеджер сессий MiniOS ограничивает размер raw и LUKS-файлов до 4000 МиБ на FAT32. Ёмкость dynblk виртуальная и тонкая, а не выделяется заранее, но реальные записи ограничены свободным пространством нижележащей файловой системы и ресурсами dynblk. Операции изменения размера контейнера поддерживают только увеличение; уменьшение не поддерживается.

Режим Native — самый простой и быстрый вариант на совместимой файловой системе.
Используйте DynFileFS, если файловая система не поддерживает метаданные Linux.
Используйте dynblk, если нужен реальный блочный девайс ядра с тонкими файлами; драйвер может подключать несколько независимых томов dynblk одновременно, а Менеджер сессий использует путь устройства, возвращённый драйвером, а не предполагает, что`/dev/dynblk0` свободен.
Используйте raw для фиксированного размера, LUKS — для шифрования сессии, а SquashFS — для точного сжатого снимка.

Выполните следующие команды для проверки реальной файловой системы и доступных режимов:

```bash
sudo minios-session info
sudo minios-session status
```

Сессии нельзя создавать на носителях только для чтения. initrd может читать и активировать существующий снимок SquashFS, сохранённый на доступных для записи FAT, exFAT или NTFS, так как он извлекает снимок во временный ext4 upper. Создание или точное сохранение снимка отличается: для этого требуется staging-область на подходящей POSIX-файловой системе, сохраняющей метаданные Linux и whiteout.

## Выбор загрузки

Любой распознанный параметр персистентности включает её обработку. Обычно загрузочные меню MiniOS предлагают варианты продолжения, создания новой, выбора и без сохранения. Официальное описание семантики выбора, совместимости, отката и активации приведено в[Персистентность initrd](/reference/boot-process/Persistence-Internals).

| Параметр | Значение |
|-----------|---------|
| `perch` | Использовать устаревший путь восстановления по принципу «лучшее из возможного». Пробует метаданные по умолчанию, но не создаёт замену, если подходящей нет. |
| `perchdir=resume` | Восстанавливает метаданные по умолчанию и, если они отсутствуют или несовместимы, позволяет initrd создать новую совместимую замену. Это текущее поведение загрузочного меню при восстановлении. |
| `perchdir=new` | Создать новую сессию с номером. |
| `perchdir=ask` | Выбрать существующую сессию или создать новую при загрузке. |
| `perchdir=<id>` | Выбрать эту сессию с указанным номером напрямую. |
| `perchdir=<device/path>` | Использовать место для персистентности на устройстве, включая`/dev/...` и `label:...`форматы, поддерживаемые initrd. |
| `perchmode=<mode>` | Установить`native`, `dynfilefs`, `dynblk`, `raw`, `luks`, или `squashfs`. |
| `perchsize=<size>` | Установить новый или больший размер контейнера; значения без суффикса — в МиБ, а`MB`, `GB`, и `TB`суффиксы поддерживаются. |

Если для новой сессии не задан режим, загрузка использует native. На FAT32/NTFS/exFAT создание по умолчанию переходит на DynFileFS. Новый контейнер raw или LUKS по умолчанию — 4000 МиБ; новая сессия DynFileFS без`perchsize` определяет размер по доступному месту с резервом. Новая сессия dynblk без`perchsize` использует 16 ГиБ по умолчанию драйвера; явное увеличение dynblk ограничено 512 ГиБ.
Сессии SquashFS захватываются из работающей системы с помощью Менеджер сессий MiniOS или`minios-session create squashfs`; `perchdir=new perchmode=squashfs`не создаёт снимок в initrd.

При восстановлении MiniOS проверяет записанные версию, редакцию, union-файловую систему и режим. Явный`perchdir=resume`может создать новую сессию вместо отсутствующей или несовместимой по умолчанию. Простой`perch`, прямой выбор по номеру и другие устаревшие запросы восстановления не создают замену автоматически.
При интерактивном выборе перед разрешением несовместимой сессии выводится предупреждение. Если выбор или активация не удались, загрузка обычно продолжается с RAM upper и предупреждением о персистентности.

Хранилище сессий имеет следующий вид:

```text
minios/changes/
|-- session.conf
|-- 1/
|-- 2/
`-- N/
```

`session.conf`сохраняет значения по умолчанию и текущие ID, а также режим, версию, редакцию, union-файловую систему, размер, состояние и специфичные настройки для каждой сессии.
Это персистентные метаданные, зафиксированные реализацией загрузки, но сами по себе не подтверждают текущее состояние в рантайме. Не редактируйте и не перемещайте данные сессий с номерами во время монтирования; используйте Менеджер сессий MiniOS или`minios-session`.

## Активные и запущенные сессии

Эти термины обозначают разные состояния:

- **активная** сессия — это та, которая по умолчанию выбрана для следующей загрузки.
- Концептуально, **запущенная** сессия — это та, чей writable-слой фактически обеспечивает сохранение данных для текущей загрузки.

Поле persistent `running=` фиксирует предполагаемое соответствие. В случае сбоя, неудачной сборки union, копирования хранилища или прерванного завершения работы оно может устареть, даже если текущая загрузка использует RAM или другую сессию. Поэтому для операций, таких как сохранение SquashFS, требуется защищённое состояние текущей загрузки, привязанное к boot-ID и проверенный смонтированный верхний слой initrd; только `running=` недостаточно. Подробнее см. [Активная, запущенная и текущая загрузка](/reference/boot-process/Persistence-Internals#active-running-and-current-boot-state).

Активация сессии меняет следующую загрузку, но не переключает текущую файловую систему union:

```bash
sudo minios-session active
sudo minios-session running
sudo minios-session activate <id>
```

Активную сессию нельзя удалить или преобразовать на месте. Запущенную сессию обычно нельзя удалить, экспортировать, скопировать, изменить размер или преобразовать. Очистка также защищает оба идентификатора.

## Справочник команд

Список сессий и просмотр хранилища:

```bash
sudo minios-session list
sudo minios-session active
sudo minios-session running
sudo minios-session info
sudo minios-session status
```

Создание сессий:

```bash
sudo minios-session create
sudo minios-session create native
sudo minios-session create dynfilefs
sudo minios-session create raw 4GB
sudo minios-session create luks 4GB
sudo minios-session create squashfs --policy shutdown
sudo minios-session create squashfs --policy manual --autosave 60
```

`create`без указания режима выбирает native. Создание SquashFS захватывает текущие изменения в live-системе и не имеет фиксированного размера. Политика завершения по умолчанию —`shutdown`; периодическое сохранение по умолчанию выключено.

Сохранение и настройка сессии SquashFS:

```bash
sudo minios-session save <running-squashfs-id>
sudo minios-session settings <squashfs-id> --shutdown on
sudo minios-session settings <squashfs-id> --shutdown off --autosave 0
sudo minios-session settings <squashfs-id> --shutdown on --autosave 60
```

Допустимые интервалы для периодического сохранения:`30`, `60`, `120`, `240`, и `480` минут; `0`отключает периодическое сохранение. Настройки завершения и периодичности независимы.

Экспорт и импорт`.tar.zst`архивов:

```bash
sudo minios-session export <id> /path/to/session.tar.zst
sudo minios-session import /path/to/session.tar.zst
sudo minios-session import /path/to/session.tar.zst --auto-convert
sudo minios-session import /path/to/session.tar.zst --force-mode dynfilefs
sudo minios-session import /path/to/session.tar.zst --force-mode dynblk
```

Принимаются только`.tar.zst`импорты. Пути и содержимое архива проверяются, извлечение ограничено.`--auto-convert`выбирает совместимый режим для текущей файловой системы.`--force-mode <mode>`явно выбирает доступный режим. Экспорт, копирование и конвертация не поддерживаются для сессий SquashFS; сохраните снимок и скопируйте весь неактивный каталог сессии.

Копирование или конвертация сессии:

```bash
sudo minios-session copy <id>
sudo minios-session copy <id> --to-mode raw --size 4GB
sudo minios-session copy <id> --to-mode dynblk --size 16GB
sudo minios-session convert <id> dynfilefs --size 4GB
sudo minios-session convert <id> dynblk --size 16GB --new-session
sudo minios-session convert <id> luks --size 4GB --new-session
```

`copy`всегда назначает новый ID сессии.`convert`по умолчанию заменяет исходник; используйте`--new-session`для сохранения исходника. Размер актуален только для контейнеров-целей.

Увеличение, удаление или очистка сессий:

```bash
sudo minios-session resize <id> 8GB
sudo minios-session delete <id>
sudo minios-session cleanup
sudo minios-session cleanup --days 30
```

Изменение размера поддерживается для сессий DynFileFS, dynblk, raw и LUKS и требует указания размера больше текущего. Изменение размера dynblk сначала увеличивает виртуальное блочное устройство, затем расширяет ext4; новая виртуальная ёмкость не выделяется заранее. Очистка по умолчанию применяется к сессиям старше 30 дней.

Все команды принимают`--json`, а другой каталог хранилища сессий можно выбрать через`--sessions-dir PATH`:

```bash
sudo minios-session --json list
sudo minios-session --sessions-dir /mnt/store/minios/changes list
```

## Поведение сохранения SquashFS

Сессия SquashFS распаковывается в RAM для текущего слоя с возможностью записи. При сохранении создаётся и проверяется точный снимок, который затем атомарно заменяет `changes.sb`.
Откат предыдущих версий не сохраняется. Сохранить сейчас можно из значка в трее, через Менеджер сессий MiniOS или `minios-session save` вне зависимости от автоматической политики.

Сохранение при завершении работы реализовано через основной триггер завершения MiniOS и `minios-squashfs-save` бэкенд, поэтому оно не зависит от того, открыт или установлен Менеджер сессий MiniOS. Периодическое сохранение проверяется каждые 30 минут с помощью таймера systemd или службы SysV, которые оба вызывают тот же бэкенд автосохранения. Пересоздание снимка требует ресурсов процессора и полностью перезаписывает снимок; рекомендуется устанавливать интервалы не менее одного часа.

Во время работы сессии на базе RAM-поддерживаемого SquashFS новый захваченный и активированный снимок SquashFS может взять на себя управление текущей целью сохранения. После передачи старый запущенный снимок можно удалить без перезагрузки:

```bash
sudo minios-session activate <new-squashfs-id>
sudo minios-session delete <old-running-squashfs-id> --handoff
```

Это исключение применяется только к корректной передаче текущей загрузки SquashFS. Другие режимы персистентности во время работы остаются защищёнными от удаления.

## Шифрование

В режиме LUKS файловая система ext4 хранится непосредственно в контейнере LUKS2 `changes.luks`; таблица разделов или вложенный контейнер DynFileFS отсутствуют. Варианты LUKS доступны только если `/run/initramfs/etc/minios-initramfs-crypt`, `cryptsetup` и `losetup` присутствуют.

При создании LUKS в интерактивном режиме пароль вводится дважды. Операции чтения или создания LUKS-данных могут получать пароль из стандартного ввода с помощью `--password-stdin`.
Пароли не передаются в аргументах команд или метаданных сессии. При загрузке initrd запрашивает пароль в консоли и не переходит к нешифрованному режиму, если активация не удалась.

Экспорт LUKS содержит расшифрованные логические файлы сессии, а не `changes.luks`.
Импорт или преобразование в LUKS создаёт новый зашифрованный контейнер.

## Резервные копии и сбойные сессии

Для сессий native, DynFileFS, dynblk, raw и LUKS используйте`export`для резервного копирования вместо копирования смонтированного каталога сессии. Храните полученный архив на другом устройстве и убедитесь, что его можно импортировать, прежде чем полагаться на него. Импорт всегда создаёт новую сессию с номером; активируйте её вручную, когда она будет готова.
Для SquashFS и резервного копирования всего устройства см. раздел[Резервное копирование MiniOS](/maintenance-and-recovery/Backing-Up-MiniOS).

Если сессия выходит из строя после переполнения хранилища, прерывания записи или при многократном создании пустых сессий, прекратите любые изменения на затронутом устройстве. Сначала экспортируйте доступную неактивную сессию, затем следуйте разделу[Диагностика](/maintenance-and-recovery/Troubleshooting).

Начните диагностику без изменения данных сессии:

```bash
sudo minios-session list
sudo minios-session active
sudo minios-session running
sudo minios-session status
sudo minios-session info
```

При загрузке файловые системы контейнеров проверяются до активации на запись. Серьёзные ошибки проверки файловой системы сохраняют контейнер для восстановления, а не монтируют его для записи. SquashFS обнаруживает незавершённое предыдущее состояние и восстанавливает последний успешно сохранённый снимок. Удаляйте сессии только через Менеджер сессий MiniOS или`minios-session delete`; не удаляйте каталоги сессий вручную.
