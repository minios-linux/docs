# Сессии и постоянство данных

Сессии MiniOS сохраняют изменения, внесённые в работающую систему, между перезагрузками. Каждая сессия — это отдельный каталог с номером в `minios/changes/`; модули MiniOS остаются только для чтения, а выбранная сессия предоставляет записываемый слой объединённой файловой системы.

Используйте Менеджер сессий MiniOS из запущенной системы MiniOS:

```bash
minios-session-manager
```

Эквивалентная утилита командной строки — `minios-session`. Для выполнения команд, изменяющих данные, требуются права администратора, поэтому в примерах ниже используется `sudo`.

## Режимы сессии

| Режим | Хранилище | Основные ограничения | MiniOS уровень LUKS2 |
|------|---------|------------------|--------------------|
| `native` | Изменения сохраняются непосредственно в каталоге сессии | Требуется доступная для записи файловая система, сохраняющая метаданные Linux и поддерживающая операции, которые определяет MiniOS. Вместимость соответствует свободному месту на носителе; `perchsize` не применяется. | Нет |
| `dynfilefs` | Расширяемый ext4 `virtual.dat` на базе сегментных файлов формата 400 | Работает на доступных для записи файловых системах POSIX, FAT32, NTFS и exFAT. Основные данные занимают мало места, но индекс отображения увеличивается пропорционально заявленной логической ёмкости. | Да |
| `dynblk` | Тонкий ext4 на блочном устройстве ядра с поддержкой `volumeNNN.db` файлов | Требуются CLI DynBlk, модуль ядра и поддержка initrd. Размер, создаваемый при загрузке, по умолчанию до 16 ГиБ; максимальный размер формата — 512 ГиБ. Бюджет разреженного отображения RAM выделяется отдельно. | Да |
| `raw` | Один `changes.img` файл с ext4 | Фиксированная логическая ёмкость, увеличение только вручную. Работает на доступных для записи файловых системах POSIX, FAT32, NTFS и exFAT; для FAT32 ограничение — 4000 МиБ. | Да |
| `squashfs` | Сжатый снимок в `changes.sb`; рабочий верхний слой для записи собирается в RAM | `perchsize` не применяется. Существующие снимки можно восстановить с поддерживаемых носителей с записью, а для точного сохранения требуется staging на файловой системе с поддержкой POSIX. | Нет |

Raw, DynFileFS и DynBlk могут опционально использовать слой шифрования LUKS2. Бэкенд хранилища определяется режимом сессии, а метаданные сессии фиксируют шифрование отдельно. DynFileFS и raw, созданные с помощью `minios-session` по умолчанию имеют размер 4000 МиБ; для DynBlk по умолчанию 16 ГиБ. Размеры выделяются в МиБ; `GB` и `TB` суффиксы преобразуют в 1000 и 1 000 000 МиБ. Для raw на FAT32 действует ограничение 4000 МиБ, независимо от шифрования. Данные полезной нагрузки DynFileFS увеличиваются по мере необходимости, но индекс формата 400 рассчитан на всю логическую ёмкость и требует около 2 МиБ RAM плюс примерно 2 МиБ базового хранилища на каждый ГиБ. Ёмкость DynBlk тонкая, а отображение в реальном времени — разреженное: плотные отображения требуют около 8 МиБ/ГиБ, а неиспользуемая виртуальная ёмкость не занимает места. Драйвер DynBlk автоматически выделяет бюджет отображения примерно 25% от доступного RAM, максимум 4096 МиБ; MiniOS не меняет эту политику. Фактическая запись ограничивается свободным местом нижележащей файловой системы и ресурсами бэкенда. Операции изменения размера контейнера могут только увеличивать сессию; уменьшение не поддерживается.

Режим Native — самый простой и быстрый вариант для совместимой файловой системы.
Используйте DynFileFS, если файловая система для хранения не поддерживает метаданные Linux.
Используйте DynBlk, если нужен полноценный блочный девайс ядра с тонкими файлами-бэкендами; драйвер может подключать несколько независимых томов DynBlk одновременно, а Session Manager использует путь к устройству, возвращённый драйвером, а не предполагает, что `/dev/dynblk0` свободен.
Используйте raw при необходимости фиксированного выделения, добавьте LUKS2 для шифрования сессии, а для точного сжатого снимка используйте SquashFS.

Выполните следующие команды, чтобы проверить фактическую файловую систему для хранения и доступные на ней режимы:

```bash
sudo minios-session info
sudo minios-session status
```

Сессии нельзя создавать на носителях только для чтения. initrd может прочитать и активировать существующий снимок SquashFS, сохранённый на записываемых FAT, exFAT или NTFS, поскольку он извлекает снимок во временный верхний слой ext4. Для создания или точного сохранения снимка требуется отдельная staging-область на подходящей файловой системе POSIX, поддерживающей метаданные Linux и белые метки union.

## Выбор загрузки

Любой распознанный параметр персистентности включает обработку персистентности. MiniOS загрузочные меню обычно предоставляют варианты возобновления, создания новой, выбора и без сохранения данных. Официальное описание семантики выбора, совместимости, резервного режима и активации приведено в [Персистентность initrd](/reference/boot-process/Persistence-Internals).

| Параметр | Значение |
|-----------|---------|
| `perch` | Использовать устаревший режим возобновления по принципу best-effort. Пробует использовать значение по умолчанию из метаданных, но не создаёт новый, если подходящий не найден. |
| `perchdir=resume` | Возобновить значение по умолчанию из метаданных и, если оно отсутствует или несовместимо, разрешить initrd создать новый совместимый вариант. Это текущее поведение возобновления через загрузочное меню. |
| `perchdir=new` | Создать новую сессию с уникальным номером. |
| `perchdir=ask` | Выбрать существующую сессию или создать новую при загрузке. |
| `perchdir=<id>` | Непосредственно выбрать сессию с указанным номером. |
| `perchdir=<device/path>` | Использовать расположение персистентности на устройстве, включая `/dev/...` и `label:...` форматы, обрабатываемые initrd. |
| `perchmode=<mode>` | Установить `native`, `dynfilefs`, `dynblk`, `raw` или `squashfs`. |
| `perchencrypt=luks` | Зашифровать новую сессию Raw, DynFileFS или DynBlk с помощью LUKS2. Для существующих сессий шифрование определяется только метаданными. |
| `perchcomp=<codec>` | Выбрать сжатие бэкенда DynBlk для новой сессии DynBlk. Сжатие принудительно устанавливается в `none` при использовании DynBlk внутри LUKS2. |
| `perchsize=<size>` | Установить новый или больший размер контейнера; простые значения задаются в MiB, допускаются суффиксы `MB`, `GB`, и `TB`. |

Если для новой сессии не указан режим, загрузка использует нативный режим. На FAT32/NTFS/exFAT при создании в нативном режиме происходит откат к DynFileFS. Новый raw-контейнер по умолчанию имеет размер 4000 MiB. Новые загрузочные сессии DynFileFS и DynBlk без `perchsize` используют до 16 ГиБ; если после резервирования места остаётся меньше, размер автоматически уменьшается. DynFileFS также учитывает накладные расходы индекса и лимит RAM. Явное увеличение DynBlk ограничено 512 ГиБ.
Сессии SquashFS можно сохранить из работающей системы с помощью Менеджер сессий MiniOS или `minios-session create squashfs`. При настройке через initrd создаются только метаданные сессии нулевого поколения, а верхний слой для записи размещается в RAM. Запущенная система создаёт первый `changes.sb` снимок по требованию или при завершении работы.

При возобновлении MiniOS проверяет записанную версию, редакцию, файловую систему union и режим. Явное указание `perchdir=resume` позволяет создать новую сессию вместо использования отсутствующего или несовместимого варианта по умолчанию. Простое `perch`, прямой выбор по номеру и другие устаревшие запросы возобновления не создают такой вариант автоматически.
При интерактивном выборе перед разрешением несовместимой сессии отображается предупреждение. Если выбор или активация всё равно не удаются, загрузка продолжается с верхним слоем RAM и предупреждением о персистентности.

Хранилище сессий имеет следующий вид:

```text
minios/changes/
|-- session.conf
|-- 1/
|-- 2/
`-- N/
```

`session.conf` фиксирует значения по умолчанию и активные идентификаторы, а также режим, версию, редакцию, файловую систему union, размер, состояние и специфические для режима параметры каждой сессии.
Это персистентные метаданные, которые записываются реализацией загрузки, но сами по себе не подтверждают текущее состояние системы. Не редактируйте их и не перемещайте данные сессий с номерами, пока сессия смонтирована; используйте Менеджер сессий MiniOS или `minios-session`.

## Активные и запущенные сессии

Эти термины обозначают разные состояния:

- **активная** сессия — это та, которая по умолчанию выбрана для следующей загрузки.
- Концептуально, **запущенная** сессия — это та, чей writable-слой фактически обеспечивает сохранение данных для текущей загрузки.

Поле persistent `running=` фиксирует предполагаемое соответствие. В случае сбоя, неудачной сборки union, копирования хранилища или прерванного завершения работы оно может устареть, даже если текущая загрузка использует RAM или другую сессию. Поэтому для операций, таких как сохранение SquashFS, требуется защищённое состояние текущей загрузки, привязанное к boot-ID и проверенный смонтированный верхний слой initrd; только `running=` недостаточно. Подробнее см. [Активная, запущенная и текущая загрузка](/reference/boot-process/Persistence-Internals#active-running-and-current-boot-state).

Активация сессии меняет следующую загрузку, но не переключает текущую файловую систему union:

```bash
sudo minios-session active
sudo minios-session running
sudo minios-session activate <id>
```

Активную сессию нельзя удалить или преобразовать на месте. Запущенную сессию обычно нельзя удалить, экспортировать, скопировать, изменить размер или преобразовать. Очистка также защищает оба идентификатора.

## Справочник команд

Список сессий и просмотр хранилища:

```bash
sudo minios-session list
sudo minios-session active
sudo minios-session running
sudo minios-session info
sudo minios-session status
```

Создание сессий:

```bash
sudo minios-session create
sudo minios-session create native
sudo minios-session create dynfilefs
sudo minios-session create raw 4GB
sudo minios-session create raw 4GB --encryption luks
sudo minios-session create squashfs --policy shutdown
sudo minios-session create squashfs --policy manual --autosave 60
```

`create` без указания режима выбирает native. Создание SquashFS фиксирует текущие изменения в реальном времени и не имеет фиксированного размера. Политика завершения работы по умолчанию — `shutdown`; периодическое сохранение по умолчанию отключено.

Сохранение и настройка сессии SquashFS:

```bash
sudo minios-session save <running-squashfs-id>
sudo minios-session settings <squashfs-id> --shutdown on
sudo minios-session settings <squashfs-id> --shutdown off --autosave 0
sudo minios-session settings <squashfs-id> --shutdown on --autosave 60
```

Допустимые интервалы периодического сохранения: `30`, `60`, `120`, `240`, и `480` минут; `0` отключает периодическое сохранение. Настройки завершения работы и периодичности независимы друг от друга.

Экспорт и импорт `.tar.zst` архивов:

```bash
sudo minios-session export <id> /path/to/session.tar.zst
sudo minios-session import /path/to/session.tar.zst
sudo minios-session import /path/to/session.tar.zst --auto-convert
sudo minios-session import /path/to/session.tar.zst --force-mode dynfilefs
sudo minios-session import /path/to/session.tar.zst --force-mode dynblk
sudo minios-session import /path/to/session.tar.zst --force-mode raw --force-encryption luks
```

Принимаются только `.tar.zst` импорты. Пути и содержимое архивов проверяются, а извлечение ограничено. `--auto-convert` выбирает совместимый режим для текущей файловой системы. `--force-mode <mode>` явно выбирает доступный режим. Экспорт, копирование и преобразование не поддерживаются для сессий SquashFS; сохраните снимок и скопируйте полностью неактивный каталог сессии.

Копирование или преобразование сессии:

```bash
sudo minios-session copy <id>
sudo minios-session copy <id> --to-mode raw --size 4GB
sudo minios-session copy <id> --to-mode dynblk --size 16GB
sudo minios-session clone <id>
sudo minios-session convert <id> dynfilefs --size 4GB
sudo minios-session convert <id> dynblk --size 16GB --new-session
sudo minios-session convert <id> raw --to-encryption luks --size 4GB --new-session
```

`copy` — это логическое копирование файловой системы с присвоением нового идентификатора сессии. Можно изменить бэкенд, ёмкость или шифрование, а также будут созданы новые идентификаторы ext4 и LUKS. `clone` физически копирует отсоединённый бэкенд и сохраняет его LUKS-заголовок, keyslots, LUKS UUID и ext4 UUID. `convert` по умолчанию заменяет исходный экземпляр; используйте `--new-session` чтобы сохранить исходник. Размер имеет значение только для контейнера-назначения.

Увеличение, удаление или очистка сессий:

```bash
sudo minios-session resize <id> 8GB
sudo minios-session delete <id>
sudo minios-session cleanup
sudo minios-session cleanup --days 30
```

Изменение размера поддерживает DynFileFS, DynBlk и raw-сессии, включая зашифрованные варианты, и требует размера больше текущего. При изменении размера DynBlk сначала увеличивается виртуальное блочное устройство, затем расширяется файловая система ext4; новая виртуальная ёмкость не выделяется заранее. Очистка по умолчанию применяется к сессиям старше 30 дней.

Все команды поддерживают `--json`, а для выбора другого хранилища сессий используйте `--sessions-dir PATH`:

```bash
sudo minios-session --json list
sudo minios-session --sessions-dir /mnt/store/minios/changes list
```

## Поведение сохранения SquashFS

Сессия SquashFS распаковывается в RAM для текущего слоя с возможностью записи. При сохранении создаётся и проверяется точный снимок, который затем атомарно заменяет `changes.sb`.
Откат предыдущих версий не сохраняется. Сохранить сейчас можно из значка в трее, через Менеджер сессий MiniOS или `minios-session save` вне зависимости от автоматической политики.

Сохранение при завершении работы реализовано через основной триггер завершения MiniOS и `minios-squashfs-save` бэкенд, поэтому оно не зависит от того, открыт или установлен Менеджер сессий MiniOS. Периодическое сохранение проверяется каждые 30 минут с помощью таймера systemd или службы SysV, которые оба вызывают тот же бэкенд автосохранения. Пересоздание снимка требует ресурсов процессора и полностью перезаписывает снимок; рекомендуется устанавливать интервалы не менее одного часа.

Во время работы сессии на базе RAM-поддерживаемого SquashFS новый захваченный и активированный снимок SquashFS может взять на себя управление текущей целью сохранения. После передачи старый запущенный снимок можно удалить без перезагрузки:

```bash
sudo minios-session activate <new-squashfs-id>
sudo minios-session delete <old-running-squashfs-id> --handoff
```

Это исключение применяется только к корректной передаче текущей загрузки SquashFS. Другие режимы персистентности во время работы остаются защищёнными от удаления.

## Шифрование

LUKS2 — это дополнительный уровень поверх Raw `changes.img`, DynFileFS `virtual.dat`, либо напрямую на устройстве DynBlk. Доступно только если `/run/initramfs/etc/minios-initramfs-crypt` содержит `luks-layer-v1` и доступны инструменты и возможности выбранного backend.

При интерактивном создании LUKS пароль запрашивается дважды. Операции чтения или создания данных LUKS могут получать пароль из стандартного ввода с помощью `--password-stdin`.
Пароли не передаются в аргументах команд или метаданных сессии. При загрузке initrd запрашивает пароль в консоли. После трёх неверных попыток загрузка прерывается; MiniOS не продолжает работу с открытым текстом, RAM, другим backend или новой сессией по тому же запросу.

Зашифрованные экспорты содержат расшифрованные файлы логических сессий, а не зашифрованный backend. Импорт, копирование или преобразование в LUKS создаёт новый зашифрованный backend с новыми идентификаторами.

## Резервные копии и неудачные сессии

Для нативных, DynFileFS, DynBlk и raw-сессий, включая зашифрованные варианты, используйте `export` для логических резервных копий вместо копирования смонтированной директории сессии. Храните полученный архив на другом устройстве и убедитесь, что его можно импортировать, прежде чем полагаться на него. Импорт всегда создает новую сессию с номером; активируйте её вручную, когда она будет готова к использованию.
Для SquashFS и процедур резервного копирования всего устройства см. [Резервное копирование MiniOS](/maintenance-and-recovery/Backing-Up-MiniOS).

Если сессия завершилась с ошибкой после заполнения хранилища, прерывания записи или при повторном создании пустых сессий, прекратите любые изменения в этом хранилище. Сначала экспортируйте читаемую неактивную сессию, если это возможно, затем следуйте разделу [Устранение неполадок](/maintenance-and-recovery/Troubleshooting).

Начните диагностику, не изменяя данные сессии:

```bash
sudo minios-session list
sudo minios-session active
sudo minios-session running
sudo minios-session status
sudo minios-session info
```

При загрузке файловые системы контейнера проверяются до активации на запись. В случае серьезных ошибок проверки файловой системы контейнер сохраняется для восстановления, а не монтируется в режиме записи. SquashFS обнаруживает незавершенное предыдущее состояние и восстанавливает последний успешно сохраненный снимок. Удаляйте сессии только через Менеджер сессий MiniOS или `minios-session delete`; не удаляйте директории сессий вручную.
