# Сессии и постоянство данных

Сессии MiniOS сохраняют изменения, внесённые в работающую систему, между перезагрузками. Каждая сессия — это отдельный каталог с номером в `minios/changes/`; модули MiniOS остаются только для чтения, а выбранная сессия предоставляет записываемый слой объединённой файловой системы.

Используйте Менеджер сессий MiniOS из запущенной системы MiniOS:

```bash
minios-session-manager
```

Эквивалентная утилита командной строки — `minios-session`. Для выполнения команд, изменяющих данные, требуются права администратора, поэтому в примерах ниже используется `sudo`.

## Режимы сессий

| Режим | Хранилище | Основные ограничения |
|------|---------|------------------|
| `native` | Изменения сохраняются непосредственно в каталоге сессии | Требуется файловая система POSIX с поддержкой записи, например ext2/3/4, Btrfs, XFS, F2FS или ReiserFS. |
| `dynfilefs` | Расширяемый контейнер ext4, разделённый на базовые файлы | Работает на файловых системах POSIX с поддержкой записи, FAT32, NTFS и exFAT. Требуется бэкенд DynFileFS. |
| `raw` | Фиксированный размер `changes.img` с ext4 | Работает на файловых системах POSIX с поддержкой записи, FAT32, NTFS и exFAT. |
| `luks` | LUKS2-зашифрованный `changes.luks` с ext4 | Требуется `cryptsetup`, поддержка loop и initrd LUKS hook MiniOS. |
| `squashfs` | Сжатый снимок в `changes.sb` | Для сохранения требуется файловая система POSIX с поддержкой постоянства, способная сохранять ссылки, владельцев, режимы, xattrs, ACL, capabilities и whiteouts. |

`dynfilefs`, `raw`, и `luks` создан с помощью `minios-session` по умолчанию 4000 МиБ. Размер указывается в МиБ; `GB` и `TB` суффиксы преобразуются в 1000 и 1 000 000 МиБ. Менеджер сессий MiniOS ограничивает размер raw и LUKS-файлов до 4000 МиБ на FAT32. Не полагайтесь на это как на общее правило для initrd: если размер raw-контейнера превышает лимит, запрос может дойти до выделения и завершиться ошибкой, а не быть уменьшён автоматически. Операции изменения размера контейнера поддерживают только увеличение; уменьшение не поддерживается.

Режим native — самый простой и быстрый выбор на совместимой файловой системе.
Используйте DynFileFS, если файловая система не поддерживает хранение метаданных Linux.
Используйте raw, если требуется фиксированный размер, LUKS — для шифрования сессии, а SquashFS — для точного сжатого снимка.

Выполните следующие команды для проверки реальной файловой системы постоянства и доступных на ней режимов:

```bash
sudo minios-session info
sudo minios-session status
```

Создать сессию на носителе только для чтения невозможно. Initrd может прочитать и активировать существующий снимок SquashFS, сохранённый на FAT, exFAT или NTFS с поддержкой записи, поскольку он извлекает снимок во временный верхний слой ext4. Создание или точное сохранение снимка отличается: для этого требуется отдельная рабочая область на подходящей файловой системе POSIX, сохраняющей метаданные Linux и whiteouts объединения.

## Выбор загрузки

Любой распознанный параметр персистентности включает обработку персистентности. Меню загрузки MiniOS обычно предлагают варианты возобновления, создания новой, выбора и неперсистентного режима. Каноническое описание семантики выбора, совместимости, резервирования и активации приведено в разделе [Персистентность initrd](/reference/boot-process/Persistence-Internals).

| Параметр | Значение |
|-----------|---------|
| `perch` | Использовать устаревший путь возобновления по принципу наилучшего соответствия. Пробует метаданные по умолчанию, но не создает замену, если подходящего варианта нет. |
| `perchdir=resume` | Возобновить метаданные по умолчанию и, если они отсутствуют или несовместимы, разрешить initrd создать новую совместимую замену. Это текущее поведение возобновления через меню загрузки. |
| `perchdir=new` | Создать новую сессию с уникальным номером. |
| `perchdir=ask` | Выбрать существующую сессию или создать новую при загрузке. |
| `perchdir=<id>` | Выбрать эту сессию по номеру напрямую. |
| `perchdir=<device/path>` | Использовать расположение персистентности на устройстве, включая `/dev/...` и `label:...` форматы, поддерживаемые initrd. |
| `perchmode=<mode>` | Установить `native`, `dynfilefs`, `raw`, `luks`, или `squashfs`. |
| `perchsize=<size>` | Установить новый или больший размер контейнера; простые значения задаются в MiB, а `MB`, `GB`, и `TB` суффиксы также принимаются. |

Если для новой сессии не указан режим, загрузка использует нативный режим. На FAT32/NTFS/exFAT при создании контейнера по умолчанию используется DynFileFS. Новый контейнер raw или LUKS по умолчанию имеет размер 4000 MiB; новая сессия DynFileFS без `perchsize` определяется по доступному пространству с учетом резервного запаса.
Сессии SquashFS захватываются с работающей системы с помощью Менеджер сессий MiniOS или `minios-session create squashfs`; `perchdir=new perchmode=squashfs` не создает снимок в initrd.

При возобновлении MiniOS проверяет сохранённую версию, редакцию, файловую систему union и режим. Буквальный `perchdir=resume` может создать новую сессию вместо использования отсутствующего или несовместимого варианта по умолчанию. Простое `perch`, прямой выбор по номеру и другие устаревшие запросы возобновления не создают такую замену автоматически.
При интерактивном выборе отображается предупреждение перед разрешением несовместимой сессии. Если выбор или активация всё равно не удаются, загрузка обычно продолжается с верхним уровнем RAM и предупреждением о персистентности.

Хранилище сессий имеет следующий вид:

```text
minios/changes/
|-- session.conf
|-- 1/
|-- 2/
`-- N/
```

`session.conf` сохраняет идентификаторы по умолчанию и текущей сессии, а также режим, версию, редакцию, файловую систему union, размер, состояние и параметры для каждого режима.
Это персистентные метаданные, которые фиксируются реализацией загрузки, но сами по себе не подтверждают текущее состояние во время работы. Не редактируйте их и не перемещайте данные сессий с номерами, пока сессия смонтирована; используйте Менеджер сессий MiniOS или `minios-session`.

## Активные и запущенные сессии

Эти термины обозначают разные состояния:

- **активная** сессия — это та, которая по умолчанию выбрана для следующей загрузки.
- Концептуально, **запущенная** сессия — это та, чей writable-слой фактически обеспечивает сохранение данных для текущей загрузки.

Поле persistent `running=` фиксирует предполагаемое соответствие. В случае сбоя, неудачной сборки union, копирования хранилища или прерванного завершения работы оно может устареть, даже если текущая загрузка использует RAM или другую сессию. Поэтому для операций, таких как сохранение SquashFS, требуется защищённое состояние текущей загрузки, привязанное к boot-ID и проверенный смонтированный верхний слой initrd; только `running=` недостаточно. Подробнее см. [Активная, запущенная и текущая загрузка](/reference/boot-process/Persistence-Internals#active-running-and-current-boot-state).

Активация сессии меняет следующую загрузку, но не переключает текущую файловую систему union:

```bash
sudo minios-session active
sudo minios-session running
sudo minios-session activate <id>
```

Активную сессию нельзя удалить или преобразовать на месте. Запущенную сессию обычно нельзя удалить, экспортировать, скопировать, изменить размер или преобразовать. Очистка также защищает оба идентификатора.

## Справочник команд

Список сессий и просмотр хранилища:

```bash
sudo minios-session list
sudo minios-session active
sudo minios-session running
sudo minios-session info
sudo minios-session status
```

Создание сессий:

```bash
sudo minios-session create
sudo minios-session create native
sudo minios-session create dynfilefs
sudo minios-session create raw 4GB
sudo minios-session create luks 4GB
sudo minios-session create squashfs --policy shutdown
sudo minios-session create squashfs --policy manual --autosave 60
```

`create` без указания режима выбирает нативный. Создание SquashFS фиксирует текущие изменения в live-режиме и не имеет фиксированного размера. Политика завершения работы по умолчанию — `shutdown`; периодическое сохранение по умолчанию отключено.

Сохранение и настройка сессии SquashFS:

```bash
sudo minios-session save <running-squashfs-id>
sudo minios-session settings <squashfs-id> --shutdown on
sudo minios-session settings <squashfs-id> --shutdown off --autosave 0
sudo minios-session settings <squashfs-id> --shutdown on --autosave 60
```

Допустимые интервалы для периодического сохранения: `30`, `60`, `120`, `240`, и `480` минут; `0` отключает периодическое сохранение. Настройки завершения работы и периодического сохранения независимы.

Экспорт и импорт `.tar.zst` архивов:

```bash
sudo minios-session export <id> /path/to/session.tar.zst
sudo minios-session import /path/to/session.tar.zst
sudo minios-session import /path/to/session.tar.zst --auto-convert
sudo minios-session import /path/to/session.tar.zst --force-mode dynfilefs
```

Принимаются только `.tar.zst` импортированные архивы. Пути и содержимое архива проверяются, а извлечение ограничено. `--auto-convert` выбирает совместимый режим для текущей файловой системы. `--force-mode <mode>` явно выбирает доступный режим. Экспорт, копирование и преобразование не поддерживаются для сессий SquashFS; сохраните снимок и скопируйте всю неактивную директорию сессии.

Копирование или преобразование сессии:

```bash
sudo minios-session copy <id>
sudo minios-session copy <id> --to-mode raw --size 4GB
sudo minios-session convert <id> dynfilefs --size 4GB
sudo minios-session convert <id> luks --size 4GB --new-session
```

`copy` всегда присваивает новый идентификатор сессии. `convert` по умолчанию заменяет исходную; используйте `--new-session` чтобы сохранить исходную. Размер имеет значение только для контейнера назначения.

Увеличение, удаление или очистка сессий:

```bash
sudo minios-session resize <id> 8GB
sudo minios-session delete <id>
sudo minios-session cleanup
sudo minios-session cleanup --days 30
```

Изменение размера поддерживается для сессий DynFileFS, raw и LUKS и требует размера больше текущего. Очистка по умолчанию применяется к сессиям старше 30 дней.

Все команды принимают `--json`, а другое хранилище сессий можно выбрать с помощью `--sessions-dir PATH`:

```bash
sudo minios-session --json list
sudo minios-session --sessions-dir /mnt/store/minios/changes list
```

## Поведение сохранения SquashFS

Сессия SquashFS распаковывается в RAM для текущего слоя с возможностью записи. При сохранении создаётся и проверяется точный снимок, который затем атомарно заменяет `changes.sb`.
Откат предыдущих версий не сохраняется. Сохранить сейчас можно из значка в трее, через Менеджер сессий MiniOS или `minios-session save` вне зависимости от автоматической политики.

Сохранение при завершении работы реализовано через основной триггер завершения MiniOS и `minios-squashfs-save` бэкенд, поэтому оно не зависит от того, открыт или установлен Менеджер сессий MiniOS. Периодическое сохранение проверяется каждые 30 минут с помощью таймера systemd или службы SysV, которые оба вызывают тот же бэкенд автосохранения. Пересоздание снимка требует ресурсов процессора и полностью перезаписывает снимок; рекомендуется устанавливать интервалы не менее одного часа.

Во время работы сессии на базе RAM-поддерживаемого SquashFS новый захваченный и активированный снимок SquashFS может взять на себя управление текущей целью сохранения. После передачи старый запущенный снимок можно удалить без перезагрузки:

```bash
sudo minios-session activate <new-squashfs-id>
sudo minios-session delete <old-running-squashfs-id> --handoff
```

Это исключение применяется только к корректной передаче текущей загрузки SquashFS. Другие режимы персистентности во время работы остаются защищёнными от удаления.

## Шифрование

В режиме LUKS файловая система ext4 хранится непосредственно в контейнере LUKS2 `changes.luks`; таблица разделов или вложенный контейнер DynFileFS отсутствуют. Варианты LUKS доступны только если `/run/initramfs/etc/minios-initramfs-crypt`, `cryptsetup` и `losetup` присутствуют.

При создании LUKS в интерактивном режиме пароль вводится дважды. Операции чтения или создания LUKS-данных могут получать пароль из стандартного ввода с помощью `--password-stdin`.
Пароли не передаются в аргументах команд или метаданных сессии. При загрузке initrd запрашивает пароль в консоли и не переходит к нешифрованному режиму, если активация не удалась.

Экспорт LUKS содержит расшифрованные логические файлы сессии, а не `changes.luks`.
Импорт или преобразование в LUKS создаёт новый зашифрованный контейнер.

## Резервные копии и неудачные сессии

Для сессий native, DynFileFS, raw и LUKS используйте `export` для создания резервных копий вместо копирования смонтированной директории сессии. Храните полученный архив на другом устройстве и убедитесь, что его можно импортировать, прежде чем полагаться на него. Импорт всегда создает новую сессию с номером; активируйте её вручную, когда она будет готова к использованию.
Для процедур резервного копирования SquashFS и всего устройства см. [Резервное копирование MiniOS](/maintenance-and-recovery/Backing-Up-MiniOS).

Если сессия выходит из строя после заполнения хранилища, прерывания записи или многократного создания пустых сессий, прекратите любые изменения на этом носителе. Сначала экспортируйте читаемую неактивную сессию, если это возможно, затем следуйте разделу [Устранение неполадок](/maintenance-and-recovery/Troubleshooting).

Начинайте диагностику без изменения данных сессии:

```bash
sudo minios-session list
sudo minios-session active
sudo minios-session running
sudo minios-session status
sudo minios-session info
```

При загрузке файловые системы контейнеров проверяются до активации слоя с возможностью записи. Серьёзные ошибки проверки файловой системы сохраняют контейнер для восстановления, не монтируя его с записью. SquashFS обнаруживает незавершённое предыдущее состояние и восстанавливает последний успешно сохранённый снимок. Удаляйте сессии только через Менеджер сессий MiniOS или `minios-session delete`; не удаляйте директории сессий вручную.
