# Сессии и постоянство данных

Сессии MiniOS сохраняют изменения, внесённые в работающую систему, между перезагрузками. Каждая сессия — это отдельный каталог с номером в `minios/changes/`; модули MiniOS остаются только для чтения, а выбранная сессия предоставляет записываемый слой объединённой файловой системы.

Используйте Менеджер сессий MiniOS из запущенной системы MiniOS:

```bash
minios-session-manager
```

Эквивалентная утилита командной строки — `minios-session`. Для выполнения команд, изменяющих данные, требуются права администратора, поэтому в примерах ниже используется `sudo`.

## Режимы сессии

| Режим | Хранилище | Основные ограничения | MiniOS уровень LUKS2 |
|------|---------|------------------|--------------------|
| `native` | Изменения сохраняются напрямую в каталоге сессии | Требуется файловая система с поддержкой записи, сохраняющая метаданные Linux и операции, которые определяет MiniOS. Вместимость соответствует свободному месту на носителе; `perchsize` не применяется. | Нет |
| `dynfilefs` | Расширяемая ext4 `virtual.dat`на базе файлов сегментов формата 400 | Работает на файловых системах с поддержкой записи: POSIX, FAT32, NTFS и exFAT. Полезная нагрузка минимальна, но индекс сопоставления масштабируется в зависимости от объявленной логической ёмкости. | Да |
| `dynblk` | Тонкий ext4 на блочном устройстве ядра, поддерживаемый `volumeNNN.db` файлами | Требуются CLI DynBlk, модуль ядра и поддержка initrd. Размер, создаваемый при загрузке, по умолчанию до 16 ГиБ; максимальный размер определяется через `dynblk limits`. Для сопоставлений на диске используется ограниченный кэш метаданных. | Да |
| `vmdk` | Тонкий ext4 на стандартном разрежённом VMDK, предоставляемый драйвером DynBlk | Использует `volume.vmdk` и `volume-sNNN.vmdk`. Без сжатия. Требуется `vmdk-session-v1` в активном маркере возможностей initrd. Такой же ручной лимит по умолчанию 16 ГиБ, как у DynBlk; проверьте через `dynblk limits --format vmdk` для получения ограничений. | Да |
| `raw` | Одиночный `changes.img` файл с ext4 | Фиксированная логическая ёмкость с возможностью явного увеличения. Работает на файловых системах с поддержкой записи: POSIX, FAT32, NTFS и exFAT; для FAT32 ограничение — 4000 МиБ. | Да |
| `squashfs` | Сжатый снимок в `changes.sb`; рабочий writable upper восстанавливается в RAM | `perchsize` не применяется. Существующие снимки можно восстановить с поддерживаемых носителей с записью, а для точного сохранения требуется staging-файловая система с поддержкой POSIX. | Нет |

Raw, DynFileFS, DynBlk и VMDK могут опционально использовать слой шифрования LUKS2. Бэкенд хранения остаётся режимом сессии, а метаданные сессии фиксируют шифрование отдельно. DynFileFS и raw, созданные с помощью `minios-session` по умолчанию 4000 МиБ; DynBlk и VMDK — 16 ГиБ. Размеры указываются в МиБ; `GB` и `TB` суффиксы преобразуются в 1000 и 1 000 000 МиБ. Для raw на FAT32 действует лимит 4000 МиБ, независимо от шифрования. Данные полезной нагрузки DynFileFS увеличиваются по мере необходимости, но индекс формата 400 рассчитывается на всю логическую ёмкость и занимает примерно 2 МиБ RAM плюс примерно 2 МиБ места на носителе на каждый ГиБ. DynBlk хранит таблицы сопоставления на диске и ограниченный кэш метаданных в RAM, по умолчанию 1 МиБ вместо процента от RAM. Его векторы extent/file и каталоги увеличиваются с количеством частей, а заполнение полезной нагрузки не требует полной резидентной карты. Проверить лимит установленной ёмкости можно через `dynblk limits --format dynblk`. Фактическая запись ограничивается свободным местом на нижележащей файловой системе и ресурсами бэкенда. Операции изменения размера контейнера поддерживают только увеличение сессии; уменьшение не поддерживается.

Режим Native — самый простой и быстрый выбор для совместимой файловой системы.
Используйте DynFileFS, если файловая система для постоянства не поддерживает метаданные Linux.
Используйте DynBlk, если требуется настоящее блочное устройство ядра с тонкими файлами-бэкендами; драйвер может подключать несколько независимых томов DynBlk одновременно, а Session Manager использует путь к устройству, возвращённый драйвером, а не предполагает, что `/dev/dynblk0` свободен.
Используйте raw при необходимости фиксированного выделения, добавьте LUKS2 для шифрования сессии, а для точного сжатого снимка используйте SquashFS.

Выполните следующие команды, чтобы проверить файловую систему для постоянства и доступные на ней режимы:

```bash
sudo minios-session info
sudo minios-session status
```

Невозможно создать сессию на носителе только для чтения. Initrd может прочитать и активировать существующий снимок SquashFS, сохранённый на записываемых FAT, exFAT или NTFS, так как он извлекает снимок во временный верхний слой ext4. Создание или точное сохранение снимка отличается: для этого требуется staging-рабочее пространство на подходящей файловой системе POSIX, сохраняющей метаданные Linux и union whiteouts.

## Выбор загрузки

Любой распознанный параметр постоянства включает обработку постоянства. В меню загрузки MiniOS обычно доступны варианты продолжения, создания новой, выбора и загрузки без постоянства. Каноническое описание селектора, совместимости, резервного режима и семантики активации приведено в [Постоянство initrd](/reference/boot-process/Persistence-Internals).

| Параметр | Значение |
|-----------|---------|
| `perch` | Использовать устаревший путь восстановления по принципу best-effort. Он пробует метаданные по умолчанию, но не создаёт замену, если подходящей нет. |
| `perchdir=resume` | Возобновить метаданные по умолчанию и, если они отсутствуют или несовместимы, разрешить initrd создать новую совместимую замену. Это текущее поведение пункта восстановления в меню загрузки. |
| `perchdir=new` | Создать новую сессию с номером. |
| `perchdir=ask` | Выбрать существующую сессию или создать новую при загрузке. |
| `perchdir=<id>` | Выбрать сессию с этим номером напрямую. |
| `perchdir=<device/path>` | Использовать место для постоянства на устройстве, включая `/dev/...` и `label:...`формы, обрабатываемые initrd. |
| `perchmode=<mode>` | Установить `native`, `dynfilefs`, `dynblk`, `vmdk`, или `raw`.`squashfs`. |
| `perchencrypt=luks` | Зашифровать новую сессию Raw, DynFileFS, DynBlk или VMDK с помощью LUKS2. Для существующих сессий шифрование определяется только метаданными. |
| `perchcomp=<codec>` | Выбрать сжатие бэкенда DynBlk для новой сессии DynBlk. Сжатие принудительно устанавливается в `none` при использовании DynBlk с LUKS2. |
| `perchsize=<size>` | Установить новый или больший размер контейнера; значения без суффикса — в МиБ, а `MB`, `GB`, и `TB`суффиксы принимаются. |

Если для новой сессии не указан режим, при загрузке используется native. На FAT32/NTFS/exFAT создание в native автоматически переключается на DynFileFS. Новый raw-контейнер по умолчанию — 4000 МиБ. Новые сессии DynFileFS, DynBlk и VMDK без `perchsize` используют до 16 ГиБ; если после резервирования остаётся меньше места, размер уменьшается автоматически. DynFileFS также учитывает накладные расходы на индекс и лимит RAM. Явное увеличение DynBlk ограничено лимитом бэкенда, который можно узнать через `dynblk limits --format dynblk`.
Сессии SquashFS можно захватить из работающей системы с помощью Менеджер сессий MiniOS или `minios-session create squashfs`. Настройка initrd создаёт только метаданные сессии нулевого поколения и хранит writable upper в RAM. Рабочая система создаёт первый `changes.sb` снимок по требованию или при завершении работы.

При восстановлении MiniOS проверяет записанную версию, редакцию, файловую систему union и режим. Прямой `perchdir=resume` может создать новую сессию вместо отсутствующей или несовместимой по умолчанию. Простые `perch`, прямой выбор по номеру и другие устаревшие запросы восстановления не создают замену автоматически.
При интерактивном выборе перед разрешением несовместимой сессии выводится предупреждение. Если выбор или активация всё равно не удаются, загрузка продолжается с временным upper RAM и предупреждением о постоянстве.

Хранилище сессий имеет следующий вид:

```text
minios/changes/
|-- session.conf
|-- 1/
|-- 2/
`-- N/
```

`session.conf`сохраняет ID по умолчанию и текущий, а также режим, версию, редакцию, файловую систему union, размер, состояние и специфичные настройки для каждой сессии.
Это постоянные метаданные, записанные реализацией загрузки, но сами по себе не являются доказательством текущего состояния во время работы. Не редактируйте и не перемещайте данные сессий с номерами вручную, пока сессия смонтирована; используйте Менеджер сессий MiniOS или `minios-session`.

## Активные и запущенные сессии

Эти термины обозначают разные состояния:

- **активная** сессия — это та, которая по умолчанию выбрана для следующей загрузки.
- Концептуально, **запущенная** сессия — это та, чей writable-слой фактически обеспечивает сохранение данных для текущей загрузки.

Поле persistent `running=` фиксирует предполагаемое соответствие. В случае сбоя, неудачной сборки union, копирования хранилища или прерванного завершения работы оно может устареть, даже если текущая загрузка использует RAM или другую сессию. Поэтому для операций, таких как сохранение SquashFS, требуется защищённое состояние текущей загрузки, привязанное к boot-ID и проверенный смонтированный верхний слой initrd; только `running=` недостаточно. Подробнее см. [Активная, запущенная и текущая загрузка](/reference/boot-process/Persistence-Internals#активное-работающее-и-текущее-состояние-загрузки).

Активация сессии меняет следующую загрузку, но не переключает текущую файловую систему union:

```bash
sudo minios-session active
sudo minios-session running
sudo minios-session activate <id>
```

Активную сессию нельзя удалить или преобразовать на месте. Запущенную сессию обычно нельзя удалить, экспортировать, скопировать, изменить размер или преобразовать. Очистка также защищает оба идентификатора.

## Справочник команд

Список сессий и просмотр хранилища:

```bash
sudo minios-session list
sudo minios-session active
sudo minios-session running
sudo minios-session info
sudo minios-session status
```

Создание сессий:

```bash
sudo minios-session create
sudo minios-session create native
sudo minios-session create dynfilefs
sudo minios-session create raw 4GB
sudo minios-session create raw 4GB --encryption luks
sudo minios-session create squashfs --policy shutdown
sudo minios-session create squashfs --policy manual --autosave 60
```

`create` без указания режима выбирает native. Создание SquashFS фиксирует текущие изменения в live-системе и не имеет фиксированного размера. Политика завершения работы по умолчанию — `shutdown`; периодическое сохранение по умолчанию отключено.

Сохранить и настроить сессию SquashFS:

```bash
sudo minios-session save <running-squashfs-id>
sudo minios-session settings <squashfs-id> --shutdown on
sudo minios-session settings <squashfs-id> --shutdown off --autosave 0
sudo minios-session settings <squashfs-id> --shutdown on --autosave 60
```

Допустимые интервалы для периодического сохранения: `30`, `60`, `120`, `240`, и `480` минут; `0` отключает периодическое сохранение. Настройки завершения работы и периодического сохранения независимы.

Экспорт и импорт `.tar.zst` архивов:

```bash
sudo minios-session export <id> /path/to/session.tar.zst
sudo minios-session import /path/to/session.tar.zst
sudo minios-session import /path/to/session.tar.zst --auto-convert
sudo minios-session import /path/to/session.tar.zst --force-mode dynfilefs
sudo minios-session import /path/to/session.tar.zst --force-mode dynblk
sudo minios-session import /path/to/session.tar.zst --force-mode raw --force-encryption luks
```

Принимаются только `.tar.zst` импортированные архивы. Пути и содержимое проверяются, а извлечение ограничено. `--auto-convert` выбирает совместимый режим для текущей файловой системы. `--force-mode <mode>` явно выбирает доступный режим. Экспорт, копирование и конвертация не поддерживаются для сессий SquashFS; сохраните снимок и скопируйте весь неактивный каталог сессии.

Копирование или преобразование сессии:

```bash
sudo minios-session copy <id>
sudo minios-session copy <id> --to-mode raw --size 4GB
sudo minios-session copy <id> --to-mode dynblk --size 16GB
sudo minios-session clone <id>
sudo minios-session convert <id> dynfilefs --size 4GB
sudo minios-session convert <id> dynblk --size 16GB --new-session
sudo minios-session convert <id> raw --to-encryption luks --size 4GB --new-session
```

`copy` — это логическое копирование файловой системы, всегда присваивается новый ID сессии. Можно изменить бэкенд, ёмкость или шифрование; создаются новые идентификаторы ext4 и LUKS.`clone` физически копирует отсоединённый бэкенд и сохраняет заголовок LUKS, keyslots, LUKS UUID и ext4 UUID.`convert` по умолчанию заменяет исходник; используйте `--new-session` для сохранения исходника. Размер актуален только для контейнера-назначения.

Увеличение, удаление или очистка сессий:

```bash
sudo minios-session resize <id> 8GB
sudo minios-session delete <id>
sudo minios-session cleanup
sudo minios-session cleanup --days 30
```

Изменение размера поддерживается для DynFileFS, DynBlk, VMDK и raw-сессий, включая зашифрованные, и требует размера больше текущего. Для DynBlk сначала увеличивается виртуальное блочное устройство, затем расширяется файловая система ext4; новая виртуальная ёмкость не выделяется заранее. Очистка по умолчанию применяется к сессиям старше 30 дней.

Все команды принимают `--json`, а для выбора другого хранилища сессий используйте `--sessions-dir PATH`:

```bash
sudo minios-session --json list
sudo minios-session --sessions-dir /mnt/store/minios/changes list
```

## Поведение сохранения SquashFS

Сессия SquashFS распаковывается в RAM для текущего слоя с возможностью записи. При сохранении создаётся и проверяется точный снимок, который затем атомарно заменяет `changes.sb`.
Откат предыдущих версий не сохраняется. Сохранить сейчас можно из значка в трее, через Менеджер сессий MiniOS или `minios-session save` вне зависимости от автоматической политики.

Сохранение при завершении работы реализовано через основной триггер завершения MiniOS и `minios-squashfs-save` бэкенд, поэтому оно не зависит от того, открыт или установлен Менеджер сессий MiniOS. Периодическое сохранение проверяется каждые 30 минут с помощью таймера systemd или службы SysV, которые оба вызывают тот же бэкенд автосохранения. Пересоздание снимка требует ресурсов процессора и полностью перезаписывает снимок; рекомендуется устанавливать интервалы не менее одного часа.

Во время работы сессии на базе RAM-поддерживаемого SquashFS новый захваченный и активированный снимок SquashFS может взять на себя управление текущей целью сохранения. После передачи старый запущенный снимок можно удалить без перезагрузки:

```bash
sudo minios-session activate <new-squashfs-id>
sudo minios-session delete <old-running-squashfs-id> --handoff
```

Это исключение применяется только к корректной передаче текущей загрузки SquashFS. Другие режимы персистентности во время работы остаются защищёнными от удаления.

## Шифрование

LUKS2 — это дополнительный уровень поверх Raw `changes.img`, DynFileFS `virtual.dat`, либо напрямую на устройстве DynBlk. Доступно только если `/run/initramfs/etc/minios-initramfs-crypt` содержит `luks-layer-v1` и доступны инструменты и возможности выбранного backend.

При интерактивном создании LUKS пароль запрашивается дважды. Операции чтения или создания данных LUKS могут получать пароль из стандартного ввода с помощью `--password-stdin`.
Пароли не передаются в аргументах команд или метаданных сессии. При загрузке initrd запрашивает пароль в консоли. После трёх неверных попыток загрузка прерывается; MiniOS не продолжает работу с открытым текстом, RAM, другим backend или новой сессией по тому же запросу.

Зашифрованные экспорты содержат расшифрованные файлы логических сессий, а не зашифрованный backend. Импорт, копирование или преобразование в LUKS создаёт новый зашифрованный backend с новыми идентификаторами.

## Резервные копии и неудачные сессии

Для сессий native, DynFileFS, DynBlk, VMDK и raw, включая зашифрованные, используйте `export` для логического резервного копирования, а не копируйте смонтированный каталог сессии. Сохраняйте полученный архив на другом устройстве и убедитесь, что его можно импортировать, прежде чем полагаться на него. Импорт всегда создаёт новую сессию с номером; активируйте её вручную, когда она будет готова к использованию.
Для процедур резервного копирования SquashFS и всего устройства см. [Резервное копирование MiniOS](/maintenance-and-recovery/Backing-Up-MiniOS).

Если сессия выходит из строя после заполнения хранилища, прерывания записи или при повторном создании пустых сессий, прекратите любые изменения на этом хранилище. Сначала экспортируйте читаемую неактивную сессию, если возможно, затем следуйте разделу [Устранение неполадок](/maintenance-and-recovery/Troubleshooting).

Начните диагностику, не изменяя данные сессии:

```bash
sudo minios-session list
sudo minios-session active
sudo minios-session running
sudo minios-session status
sudo minios-session info
```

При загрузке файловые системы контейнеров проверяются до активации на запись. При серьёзных ошибках проверки файловой системы контейнер сохраняется для восстановления, а не монтируется для записи. SquashFS определяет незавершённое предыдущее состояние и восстанавливает последний успешно сохранённый снимок. Удаляйте сессии только через Менеджер сессий MiniOS или `minios-session delete`; не удаляйте каталоги сессий вручную.

## Возврат неиспользуемого DynBlk и хранилища VMDK

В Session Manager щёлкните правой кнопкой мыши по сессии DynBlk или VMDK и выберите **Освободить место...**.
Диалоговое окно работает как для активной, так и для неактивной сессии. Для
plaintext-сессии сначала производится обрезка внутреннего ext4, затем драйверу отправляется запрос на освобождение
места. Неактивная сессия временно подключается и затем отключается;
устройство активной сессии остаётся подключённым.

```sh
minios-session reclaim 3 --json
# Explicitly permit live-data relocation (additional flash writes):
minios-session reclaim 3 --compact --json
```

Флажок компактирования **по умолчанию отключён**, в том числе на exFAT. 
Автоматического перехода к компактированию нет. В зашифрованных сессиях освобождается только пространство, уже
известное драйверу; эта операция не включает discard через LUKS и не
раскрывает схему выделения. Ошибки устройства и неудачная обрезка останавливают операцию.

### Низкоуровневые команды драйвера

С текущим бэкендом DynBlk (native или split VMDK) удаление целых зерен
делает их размещение повторно используемым. На файловой системе ext4 освобождённые диапазоны
также могут автоматически освобождаться через hole punching. В exFAT автоматическая очистка только усекает
полностью свободные хвосты файлов. **Автоматическая очистка никогда не перемещает активные данные.**

Используйте `fstrim` на смонтированной внутренней файловой системе изменений (не на объединённом AUFS/OverlayFS
корне), чтобы получить отчёт об удалённых блоках, затем `dynblk reclaim /dev/dynblkN --execute` для
очистки без перемещения данных. Выбирайте фактическое устройство сессии, а не предполагаемый индекс.
Чтобы вручную запросить ресурсоёмкую компактацию на месте, добавьте `--compact`.
Это работает без конвертации образа или изменения размера виртуальной файловой системы;
другие операции чтения/записи могут выполняться между этапами освобождения. Это не автоматический режим.
Опциональная `--scan-zeroes` читает отображённые зерна и по умолчанию не включена.

Эти команды также доступны в CLI initrd DynBlk после пересборки. Автоматическая
компактация при запуске не активируется. Для зашифрованных сессий сохраняется текущая политика удаления;
инструменты не включают прозрачно передачу discard для dm-crypt.
Только для чтения или `cache=unsafe` вложения не могут быть освобождены. Сообщаемые освобождённые
диапазоны и усечённые длины не совпадают с фактическим свободным пространством файловой системы.

## Рабочие процессы сессий VMDK

VMDK — это отдельный режим сессии, а не новый кодек сжатия. Создание, активация,
изменение размера, экспорт/импорт, копирование, клонирование и преобразование выполняются с помощью тех же команд Session Manager, что и для других контейнерных режимов:


```sh
minios-session create vmdk 16384 --activate
minios-session copy 3 --to-mode vmdk --size 16384
minios-session import /path/to/session.tar.zst --force-mode vmdk
```

Архивы сессий содержат логические файлы и метаданные, а не произвольное внешнее
VMDK-подключение. Управляемые сессии VMDK используют канонический`volume.vmdk` дескриптор
и все его`volume-sNNN.vmdk` дочерние файлы. Не переименовывайте части или копируйте активный образ
в обход драйвера. Переключение между нативным DynBlk и VMDK требует явного
копирования/преобразования; изменение`session_mode` вручную не является преобразованием.

Установщик предлагает VMDK только при поддержке со стороны среды выполнения и отклоняет исходные
образы, у которых скопированные initrd не содержат`vmdk-session-v1` необходимой функциональности. Обновите CLI,
драйвер, инструменты сессии и загрузочные скрипты одновременно перед созданием сессий VMDK.
