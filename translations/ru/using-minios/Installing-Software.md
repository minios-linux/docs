# Установка программного обеспечения

Магазин приложений MiniOS предоставляет каталог рецептов приложений по адресу [store.minios.dev](https://store.minios.dev). В live-среде MiniOS эти рецепты можно установить непосредственно в работающую систему или использовать для создания одного или нескольких SquashFS (`.sb`) модулей.

На этой странице описан процесс установки ПО в live-среде MiniOS. При установке на диск сохраняются выбранные рабочий стол и обычные приложения, но удаляется программное обеспечение, специфичное для live-режима MiniOS. После установки используйте стандартный процесс управления пакетами Debian.

Для просмотра каталога локальный сервер не требуется. Для установки требуется: веб-интерфейс либо подключается к локальному демону Магазина приложений MiniOS, либо открывает установленный `minios-store://` обработчик URI.

## Перед установкой

Откройте страницу приложения и ознакомьтесь со следующей информацией перед добавлением в корзину:

- Названия пакетов и способ установки.
- Скрипт установки, если он отображается.
- Домашняя страница приложения и информация о разработчике.
- Скриншоты и графика приложения, если они предоставлены. Это лишь метаданные для оформления, а не гарантия надежности рецепта.
- Загружает ли рецепт отдельный пакет Debian.
- Любая дополнительная лицензия ПО, отображаемая рецептом. Рецепты, требующие принятия лицензии, нельзя установить, пока вы явно не примете условия.

Рецепты могут устанавливать пакеты APT, загружать пакеты Debian или выполнять shell-скрипты. Операции установки выполняются с правами root. Рассматривайте рецепт и все его загрузки или репозитории как доверенный код.

## Установка приложения

1. Откройте Магазин приложений MiniOS из меню приложений. Запуск проверяет `https://store.minios.dev` и открывает его в браузере по умолчанию.
2. Выполните поиск или выберите категорию, откройте детали приложения и ознакомьтесь с пакетами или скриптом.
3. Добавьте одно или несколько приложений в корзину.
4. В live-сессии MiniOS выберите `Module` или `System`.
5. В режиме модулей при необходимости выберите уровень сборки. **По умолчанию в рецепте** сохраняет заданный для рецепта уровень; **Авто** использует все загруженные модули как базу сборки и создает модуль без номера; числовой уровень от `01` до `09` использует только модули до этого уровня включительно. Предпочитайте вариант По умолчанию в рецепте, если не требуется избегать зависимостей от более высоких необязательных слоев.
6. Если выбрано несколько приложений в режиме модулей, выберите один общий модуль или отдельные модули. Общему модулю можно также задать собственное имя.
7. Примите все лицензии рецептов, для которых требуется явное согласие.
8. Нажмите `Install` и следите за ходом установки и выводом команд. Страница использует локальный демон, если его статус `Connected`; в противном случае будет использоваться обработчик URI и может появиться запрос аутентификации PolicyKit.

Одновременно может выполняться только одна партия установки через демон. Закрытие окна прогресса не обязательно останавливает установку; чтобы просмотреть или отменить ее, снова откройте индикатор установки.

## Режимы модулей и системы

### Режим модуля

В режиме модуля выполняется `apt2sb` или `script2sb` в изолированной среде сборки модулей. Полученные `.sb` файлы записываются в первый доступный для записи путь из списка ниже:

1. `/run/initramfs/memory/data/minios/modules`
2. `/var/lib/minios-store/modules`

Первый путь — это каталог модулей эффективного дерева данных MiniOS. При обычной загрузке с возможностью записи он находится на накопителе, но после копирования системы `toram` он может быть размещён на RAM; Store проверяет только возможность записи, а не долговечность. Созданный модуль не активируется в текущей сессии. Он будет загружен при следующей загрузке только если скопирован на постоянное `minios/modules/` хранилище и разрешён фильтрами загрузки. Используйте в Менеджере модулей функцию **Добавить к следующей загрузке** или `sudo sb next-boot add /path/to/module.sb` когда подходящее постоянное хранилище доступно.

Второй путь — это резервный вариант, используемый, если обычный каталог модулей недоступен для записи. Модуль в резервном каталоге не будет автоматически добавлен к следующей живой загрузке. Используйте `Open folder`, затем скопируйте готовый модуль в каталог `minios/modules` на записываемом загрузочном носителе MiniOS перед перезагрузкой.

Объединённый модуль содержит все выбранные рецепты. При раздельной упаковке сбой может затронуть только один рецепт, а ранее завершённые модули останутся в целевом каталоге.

### Режим системы

В режиме системы используется APT или скрипт рецепта напрямую для корневой файловой системы. Изменения применяются к текущей live-системе, а не приводят к созданию модуля. Сохранятся ли эти изменения после перезагрузки, зависит от настроек сохранения сессии.

Режим системы не является транзакционным. Неудачная или отмененная операция может оставить измененные пакеты, состояние репозитория или файлы, измененные предыдущими командами.

## Локальный сервис и граница доверия

Служба `minios-store` работает с правами root, поскольку для сборки модулей и прямой установки пакетов требуются операции mount, overlay, chroot, APT и dpkg. По умолчанию она слушает только на `ws://127.0.0.1:8765`. Веб-интерфейс передает полные данные рецепта, включая скрипты и URL загрузки, этому локальному сервису.

Демон проверяет структуру запроса и поддерживаемый способ установки, но не выполняет независимую аутентификацию или подпись содержимого рецепта. Страница, имеющая доступ к локальной точке WebSocket, может запрашивать привилегированные действия по установке. Поэтому:

- Оставляйте демон привязанным к `127.0.0.1`. Не открывайте порт `8765` в локальную сеть или интернет.
- Не указывайте `MINIOS_STORE_HOST` на не-loopback-адрес, если только не реализована дополнительная, проверенная граница безопасности.
- Получайте доступ к Магазину приложений MiniOS только через официальный сайт по HTTPS и проверяйте рецепты перед установкой.
- Останавливайте или отключайте сервис, если установка через браузер не требуется.

Управляйте сервисом systemd с помощью:

```bash
sudo systemctl status minios-store
sudo systemctl start minios-store
sudo systemctl stop minios-store
sudo systemctl enable minios-store
sudo systemctl disable minios-store
```

Обработчик URI — это отдельный путь. Он запускает GTK-установщик через PolicyKit и не требует WebSocket-демона. Текущие ссылки Магазина содержат полный закодированный рецепт, поэтому рецепты APT, скрипты и загружаемые DEB-файлы могут использовать этот резервный путь; явные согласия с лицензиями передаются отдельно и повторно проверяются локальным установщиком. Старый формат `recipes=id:level:compression` остается для совместимости и интерпретируется как рецепт APT. Установщик запускается после авторизации, поэтому проверьте запрос браузера перед подтверждением аутентификации.

## Отмена установки

Выберите `Cancel` в окне прогресса веб-интерфейса или `Cancel installation` в GTK-установщике. Отмена помечает партию как отменённую и завершает текущий дочерний процесс. Оставшиеся рецепты не запускаются.

Отмена — это не откат. Уже установленные пакеты или модули сохраняются, а команда, прерванная во время работы APT, dpkg, скрипта, загрузки или сборки модуля, может оставить частичное состояние или неполный файл. После отмены:

1. Просмотрите итоговый журнал установки.
2. Проверьте целевую директорию модулей на наличие неожиданных или пустых файлов.
3. Для режима системы выполните `sudo dpkg --audit` и при необходимости восстановите конфигурацию пакетов.
4. Удаляйте только те артефакты, которые точно относятся к отменённой операции.

## Устранение неполадок

### Магазин приложений MiniOS недоступен

Проверьте сетевой доступ к `https://store.minios.dev`. Статус `Offline` также означает, что браузер не подключен к локальному WebSocket-демону; установка может быть выполнена через обработчик URI, если `minios-store-gui` установлен.

### Браузер не может подключиться к демону

Проверьте работу сервиса и его журналы:

```bash
sudo systemctl status minios-store
sudo journalctl -u minios-store
```

Обычная точка подключения — `ws://127.0.0.1:8765`. Конфликт портов, остановленный сервис, отсутствие `python3-websockets`, либо ограничения браузера могут помешать подключению. Перезапуск браузера не восстанавливает работу остановленного демона.

### Ошибка аутентификации или отсутствие запроса

Для работы установщика URI требуется PolicyKit, `pkexec`, а также активный агент аутентификации рабочего стола. Запустите установщик из активной графической сессии и убедитесь, что `minios-store-gui` установлен. Не пытайтесь обойти запрос, открывая root-демон в сети.

### Ошибка при сборке модуля

Разверните журнал установки и используйте ошибку последней команды, а не только итоговое сообщение. Частые причины: недоступные пакеты, сбои репозитория или DNS, недостаточно свободного места, неподдерживаемый инструмент сжатия, или директория модулей доступна только для чтения. Демон сообщает, если был переключен на `/var/lib/minios-store/modules`.

### Приложение отсутствует после установки

В режиме модулей перезагрузите систему после того, как убедитесь, что файл `.sb` находится в директории `minios/modules` загрузочного носителя. Файл, оставшийся в резервной директории, не будет загружен автоматически. В режиме системы для live-сессии проверьте, что сессия поддерживает сохранение, если приложение исчезло после перезагрузки.

### После отмены установки система осталась с незавершённым dpkg

Проверьте состояние пакетов перед повторной попыткой:

```bash
sudo dpkg --audit
sudo dpkg --configure -a
sudo apt-get -f install
```

Перед подтверждением любой дополнительной операции по восстановлению ознакомьтесь с предлагаемыми изменениями APT.
