# Установка программного обеспечения

Магазин приложений MiniOS предоставляет каталог рецептов приложений на [store.minios.dev](https://store.minios.dev). В MiniOS live-среде эти рецепты можно установить напрямую в работающую систему или использовать для создания одного или нескольких SquashFS (модулей `.sb`).

На этой странице описан процесс установки программного обеспечения в MiniOS live-режиме. При нативной установке сохраняются выбранные окружения рабочего стола и обычные приложения, но удаляется программное обеспечение, специфичное для MiniOS, предназначенное для live-работы. Для установленной системы используйте стандартный процесс управления пакетами Debian.

Для просмотра каталога локальный сервер не требуется. Для установки — требуется: веб-интерфейс либо подключается к локальному демону Магазина приложений MiniOS, либо открывает установленный обработчик URI `minios-store://`.

## Перед установкой

Откройте страницу приложения и ознакомьтесь со следующей информацией перед добавлением его в корзину:

- Названия пакетов и способ установки.
- Скрипт установки, если он отображается.
- Домашняя страница приложения и сведения о разработчике.
- Загружает ли рецепт отдельный пакет Debian.

Рецепты могут устанавливать пакеты через APT, загружать пакеты Debian или выполнять shell-скрипты. Все операции установки выполняются с правами root. Рассматривайте рецепт и все его загрузки или репозитории как привилегированный код.

## Установка приложения

1. Откройте Магазин приложений MiniOS из меню приложений. Запуск проверяет `https://store.minios.dev` и открывает его в браузере по умолчанию.
2. Найдите или выберите категорию, откройте детали приложения и ознакомьтесь с пакетами или скриптом.
3. Добавьте одно или несколько приложений в корзину.
4. В live-сессии MiniOS выберите `Module` или `System`.
5. Для нескольких приложений в модульном режиме выберите один объединённый модуль или отдельные модули. Объединённому модулю можно также задать собственное имя.
6. Выберите `Install` и следите за ходом установки и выводом команд. Страница использует локальный демон, если его статус — `Connected`; иначе будет предпринята попытка использовать обработчик URI, и может появиться запрос аутентификации PolicyKit.

Одновременно может выполняться только одна установка через демон. Закрытие окна прогресса не обязательно останавливает установку; чтобы просмотреть или отменить её, снова откройте индикатор установки.

## Режимы модулей и системы

### Режим модуля

В режиме модуля запускается `apt2sb` или `script2sb` в изолированной среде для сборки модулей. Полученные файлы `.sb` записываются в первое доступное для записи место из списка ниже:

1. `/run/initramfs/memory/data/minios/modules`
2. `/var/lib/minios-store/modules`

Первый путь — это директория модулей на текущем загрузочном носителе MiniOS. Модуль, созданный там, не активируется в текущей сессии Магазином приложений MiniOS. Оставьте модуль в этой директории и перезагрузите систему, чтобы он был загружен при следующем запуске. Результат сохраняется только если загрузочный носитель доступен для записи и файл не удалён.

Второй путь используется как резервный, если обычная директория модулей недоступна для записи. Модуль в резервной директории не будет автоматически подключён при следующей загрузке live-сессии. Используйте `Open folder`, затем скопируйте готовый модуль в директорию `minios/modules` на записываемом загрузочном носителе MiniOS перед перезагрузкой.

Объединённый модуль содержит все выбранные рецепты. При раздельной упаковке сбой может затронуть только один рецепт, а успешно собранные ранее модули останутся в целевой директории.

### Системный режим

В системном режиме используется APT или скрипт рецепта напрямую для работающей корневой файловой системы. Изменения применяются к текущей live-системе, а не приводят к созданию модуля. Сохранятся ли эти изменения после перезагрузки, зависит от настроек сохранения сессии.

Системный режим не является транзакционным. Неудачная или отменённая операция может оставить изменённые пакеты, состояние репозиториев или файлы, изменённые предыдущими командами.

## Локальный сервис и границы доверия

Сервис `minios-store` работает с правами root, поскольку для сборки модулей и прямой установки пакетов требуются операции mount, overlay, chroot, APT и dpkg. По умолчанию он слушает только на `ws://127.0.0.1:8765`. Веб-интерфейс отправляет полные данные рецепта, включая скрипты и URL-адреса загрузки, этому локальному сервису.

Демон проверяет структуру запроса и поддерживаемый способ установки, но не выполняет независимую аутентификацию или подпись полезной нагрузки рецепта. Страница, имеющая доступ к локальной точке WebSocket, может инициировать привилегированную установку. Поэтому:

- Оставляйте демон привязанным к `127.0.0.1`. Не открывайте порт `8765` для локальной сети или интернета.
- Не устанавливайте `MINIOS_STORE_HOST` на не-loopback-адрес без дополнительной, проверенной меры безопасности.
- Используйте Магазин приложений MiniOS только через официальный сайт по HTTPS и проверяйте рецепты перед установкой.
- Останавливайте или отключайте сервис, если установка через браузер не требуется.

Управляйте сервисом systemd с помощью:

```bash
sudo systemctl status minios-store
sudo systemctl start minios-store
sudo systemctl stop minios-store
sudo systemctl enable minios-store
sudo systemctl disable minios-store
```

Обработчик URI — отдельный путь. Он запускает GTK-установщик через PolicyKit и не требует WebSocket-демона. Текущие записи URI интерпретируются как имена пакетов APT с указанием уровня модуля и параметров сжатия. Установщик запускается после авторизации, поэтому проверьте запрос браузера перед подтверждением запроса аутентификации.

## Отмена установки

Выберите `Cancel` в веб-диалоге прогресса или `Cancel installation` в GTK-установщике. Отмена помечает партию как отменённую и завершает текущий отслеживаемый дочерний процесс. Оставшиеся рецепты не запускаются.

Отмена — это не откат. Уже установленные пакеты или модули сохраняются, а команда, прерванная во время работы APT, dpkg, скрипта, загрузки или сборки модуля, может оставить частичное состояние или незавершённый выходной файл. После отмены:

1. Ознакомьтесь с итоговым журналом установки.
2. Проверьте целевую директорию модулей на наличие неожиданных или файлов нулевого размера.
3. Для режима системы выполните `sudo dpkg --audit` и при необходимости восстановите конфигурацию пакетов.
4. Удаляйте только те артефакты, которые вы точно отнесли к отменённой операции.

## Устранение неполадок

### Магазин приложений MiniOS не в сети

Проверьте сетевой доступ к `https://store.minios.dev`. Статус `Offline` также означает, что браузер не подключён к локальному WebSocket-демону; установка может быть выполнена через обработчик URI, если установлен `minios-store-gui`.

### Браузер не может подключиться к демону

Проверьте сервис и его журналы:

```bash
sudo systemctl status minios-store
sudo journalctl -u minios-store
```

Обычная точка подключения — `ws://127.0.0.1:8765`. Конфликт порта, остановленный сервис, отсутствие `python3-websockets` или ограничения браузера могут препятствовать подключению. Перезапуск браузера не восстановит работу остановленного демона.

### Ошибка аутентификации или отсутствие запроса

Для работы установщика по URI необходимы PolicyKit, `pkexec` и активный агент аутентификации рабочего стола. Запускайте установщик из активной графической сессии и убедитесь, что установлен `minios-store-gui`. Не пытайтесь обойти запрос, открывая root-демон по сети.

### Ошибка сборки модуля

Разверните журнал установки и используйте сообщение об ошибке последней команды, а не только итоговое описание. Частые причины: недоступные пакеты, сбои репозитория или DNS, недостаточно свободного места, неподдерживаемый инструмент сжатия, директория модулей только для чтения. Демон сообщает, когда переключается на `/var/lib/minios-store/modules`.

### Приложение отсутствует после установки

Для режима модуля перезагрузите систему после того, как убедитесь, что файл `.sb` находится в директории `minios/modules` на загрузочном носителе. Файл, оставшийся в резервной директории, не загружается автоматически. Для режима системы в live-сессии проверьте, что сессия настроена на сохранение, если приложение исчезло после перезагрузки.

### После отмены установки система оставила dpkg в незавершённом состоянии

Проверьте состояние пакетов перед повторной попыткой:

```bash
sudo dpkg --audit
sudo dpkg --configure -a
sudo apt-get -f install
```

Перед подтверждением дополнительных действий по восстановлению внимательно изучите предлагаемые изменения APT.
