# Установка программного обеспечения

Магазин приложений MiniOS предоставляет каталог рецептов приложений по адресу [store.minios.dev](https://store.minios.dev). В MiniOS live-среде эти рецепты можно установить непосредственно в работающую систему или использовать для сборки одного или нескольких SquashFS (`.sb`) модулей.

На этой странице описан процесс установки программ в MiniOS live-режиме. При установке на диск сохраняются выбранная среда рабочего стола и обычные приложения, но удаляется специфичное для MiniOS программное обеспечение, предназначенное для работы в live-режиме. Для дальнейшей работы с установленной системой используйте стандартные средства управления пакетами Debian.

Для просмотра каталога локальный сервер не требуется. Для установки — требуется: веб-интерфейс либо подключается к локальному демону Магазина приложений MiniOS, либо открывает установленный `minios-store://` обработчик URI.

## Перед установкой

Откройте страницу приложения и ознакомьтесь со следующей информацией перед добавлением в корзину:

- Названия пакетов и способ установки.
- Скрипт установки, если он отображается.
- Домашняя страница приложения и информация о разработчике.
- Загружает ли рецепт отдельный пакет Debian.

Рецепты могут устанавливать пакеты APT, загружать пакеты Debian или выполнять shell-скрипты. Все операции установки выполняются с правами root. Рассматривайте рецепт и все его загрузки или репозитории как доверенный код.

## Установка приложения

1. Откройте Магазин приложений MiniOS через меню приложений. Запуск проверяет `https://store.minios.dev` и открывает его в браузере по умолчанию.
2. Выполните поиск или выберите категорию, откройте сведения о приложении и ознакомьтесь с пакетами или скриптом.
3. Добавьте одно или несколько приложений в корзину.
4. В live-сессии MiniOS выберите `Module` или `System`.
5. Если выбрано несколько приложений в модульном режиме, выберите один общий модуль или отдельные модули. Общему модулю можно задать собственное имя.
6. Нажмите `Install` и следите за ходом установки и выводом команд. Страница использует локальный демон, если его статус — `Connected`; в противном случае будет использоваться обработчик URI и может появиться запрос аутентификации PolicyKit.

Одновременно может выполняться только одна установка через демон. Закрытие окна прогресса не обязательно останавливает установку; чтобы просмотреть или отменить процесс, откройте индикатор установки повторно.

## Модульный и системный режимы

### Модульный режим

В модульном режиме выполняется `apt2sb` или `script2sb` в изолированной среде для сборки модулей. Полученные `.sb` файлы сохраняются в первую доступную для записи директорию из списка:

1. `/run/initramfs/memory/data/minios/modules`
2. `/var/lib/minios-store/modules`

Первый путь — это директория модулей на текущем загрузочном носителе MiniOS. Модуль, созданный там, не активируется в текущей сессии Магазином приложений MiniOS. Оставьте модуль в этой директории и перезагрузите систему, чтобы он был загружен при следующем запуске. Результат сохраняется только если загрузочный носитель поддерживает запись и файл не удалён.

Второй путь используется, если обычная директория модулей недоступна для записи. Модуль в резервной директории не будет автоматически подключён при следующей загрузке live-системы. Используйте `Open folder`, затем скопируйте готовый модуль в директорию `minios/modules` на записываемом загрузочном носителе MiniOS перед перезагрузкой.

Общий модуль содержит все выбранные рецепты. При раздельной упаковке сбой может затронуть только один рецепт, а успешно созданные ранее модули останутся в целевой директории.

### Системный режим

В системном режиме APT или скрипт рецепта применяется напрямую к корневой файловой системе. Изменения вступают в силу сразу в текущей live-системе, а не формируют отдельный модуль. Сохранятся ли эти изменения после перезагрузки, зависит от настроек сохранения сессии.

Системный режим не является транзакционным. В случае сбоя или отмены операции пакеты, состояние репозиториев или файлы, изменённые предыдущими командами, могут остаться изменёнными.

## Локальный сервис и границы доверия

Служба `minios-store` работает с правами root, так как для сборки модулей и установки пакетов напрямую требуются операции mount, overlay, chroot, APT и dpkg. По умолчанию она слушает только на `ws://127.0.0.1:8765`. Веб-интерфейс отправляет полные данные рецепта, включая скрипты и URL-адреса загрузки, этому локальному сервису.

Демон проверяет структуру запроса и поддерживаемый способ установки, но не выполняет независимую аутентификацию или подпись содержимого рецепта. Страница, имеющая доступ к локальной точке WebSocket, может запросить выполнение привилегированных операций. Поэтому:

- Оставляйте демон привязанным к `127.0.0.1`. Не открывайте порт `8765` в локальную сеть или интернет.
- Не указывайте `MINIOS_STORE_HOST` на не-loopback-адрес, если не реализована дополнительная проверенная граница безопасности.
- Используйте Магазин приложений MiniOS только через официальный сайт по HTTPS и проверяйте рецепты перед установкой.
- Остановите или отключите сервис, если установка через браузер не требуется.

Управляйте службой systemd с помощью:

```bash
sudo systemctl status minios-store
sudo systemctl start minios-store
sudo systemctl stop minios-store
sudo systemctl enable minios-store
sudo systemctl disable minios-store
```

Обработчик URI — это отдельный путь. Он запускает GTK-установщик через PolicyKit и не требует WebSocket-демона. Текущие URI рассматриваются как имена пакетов APT с указанием уровня модуля и настроек сжатия. Установщик запускается после авторизации, поэтому проверьте запрос браузера перед подтверждением аутентификации.

## Отмена установки

Выберите `Cancel` в окне прогресса веб-интерфейса или `Cancel installation` в GTK-установщике. При отмене партия помечается как отменённая, и текущий дочерний процесс завершается. Оставшиеся рецепты не будут запущены.

Отмена — это не откат. Уже установленные пакеты или модули останутся, а если команда была прервана во время работы APT, dpkg, скрипта, загрузки или сборки модуля, могут остаться частичные изменения или неполный файл. После отмены:

1. Просмотрите итоговый журнал установки.
2. Проверьте целевую директорию модулей на наличие неожиданных или пустых файлов.
3. В системном режиме выполните `sudo dpkg --audit` и при необходимости восстановите конфигурацию пакетов.
4. Удаляйте только те артефакты, которые вы определили как относящиеся к отменённой операции.

## Устранение неполадок

### Магазин приложений MiniOS недоступен

Проверьте сетевой доступ к `https://store.minios.dev`. Статус `Offline` также означает, что браузер не подключён к локальному WebSocket-демону; установка может быть выполнена через обработчик URI, если `minios-store-gui` установлен.

### Браузер не может подключиться к демону

Проверьте работу сервиса и его журналы:

```bash
sudo systemctl status minios-store
sudo journalctl -u minios-store
```

Обычная точка подключения — `ws://127.0.0.1:8765`. Конфликт портов, остановленный сервис, отсутствие `python3-websockets` или ограничения браузера могут помешать подключению. Перезапуск браузера не восстановит работу остановленного демона.

### Ошибка аутентификации или отсутствие запроса

Для работы установщика через URI требуется PolicyKit, `pkexec`, а также активный агент аутентификации рабочего стола. Запускайте установщик из активной графической сессии и убедитесь, что `minios-store-gui` установлен. Не пытайтесь обойти запрос, открывая root-демон в сети.

### Ошибка сборки модуля

Разверните журнал установки и используйте последнее сообщение об ошибке, а не только итоговую сводку. Частые причины: недоступные пакеты, сбои репозитория или DNS, недостаточно свободного места, неподдерживаемый инструмент сжатия или директория модулей только для чтения. Демон сообщает, если переключился на `/var/lib/minios-store/modules`.

### Приложение отсутствует после установки

В модульном режиме перезагрузите систему после того, как убедитесь, что файл `.sb` находится в директории `minios/modules` на загрузочном носителе. Если файл остался в резервной директории, он не будет загружен автоматически. В системном режиме на live-сессии проверьте, включено ли сохранение сессии, если приложение исчезло после перезагрузки.

### После отмены установки система оставила dpkg в незавершённом состоянии

Проверьте состояние пакетов перед повторной попыткой:

```bash
sudo dpkg --audit
sudo dpkg --configure -a
sudo apt-get -f install
```

Перед подтверждением любых дополнительных действий по восстановлению внимательно изучите предлагаемые изменения APT.
